## 2. B. 개선이 필요한 로직 (잔여)

### B-2. 씬 트리 GPU 자동 초기화 갭

- **어떤 코드가 문제인가 (정확한 발췌)**

  **문제 ① — 루트가 초기화되지 않는다**: `root_`는 `initialized_`가 false인 채로 계속된다.
  ```cpp
  // Scene.cpp:17-21 — SetName/SetScene만, root_.Initialize(&device) 호출이 없다
  Scene::Scene()
  {
      root_.SetName("Root");
      root_.SetScene(this);	// root_가 씬 소속이 되어야 AddChild의 씬 전파·OnEnter가 동작한다.
  }
  ```

  **문제 ② — 자동 초기화 가드가 영원히 false**: `AddChild`의 조건식은 `initialized_`를 요구하는데, root_는 물론이고 일반 GameObject도 `Initialize()`를 호출한 적이 없으면 false다.
  ```cpp
  // GameObject.cpp:75-76 — "씬 초기화 이후 추가 → 즉시 GPU 초기화"
  if (initialized_ && pScene_ != nullptr && pScene_->GetWindow() != nullptr)
      _pChild->Initialize(pScene_->GetGraphicDevice());   // ← 이 줄이 실행된 적이 없다
  ```

  **문제 ③ — Initialize가 pMesh_를 처리하지 않는다**: Material만 초기화된다.
  ```cpp
  // GameObject.cpp:199-214
  void GameObject::Initialize(GraphicDevice* _pDevice)
  {
      // 기본 Material GPU 초기화 (이미 초기화됐으면 스킵)
      if (pMaterial_ != nullptr && !initialized_ && _pDevice != nullptr)
      {
          pMaterial_->Initialize(_pDevice);
      }
      // ↑ pMesh_는 아무 처리도 없음 — Mesh는 팩토리(InitializeAs*2D)로 생성됨
      initialized_ = true;
      for (int i = 0; i < children_.Size(); ++i)
          children_[i].pObject_->Initialize(_pDevice);
  }
  ```

  **결과 — 사용자가 손으로 우회해야 한다**:
  ```cpp
  // Tutorial 32 — 수동 우회 (자동 초기화가 동작했다면 불필요한 코드)
  if (pMat->Initialize(&g_cDevice) == false) { ... }
  ```

- **영향도**: **중간(기능)** — "Mesh+Material만 설정하면 자동 드로우"라는 v4 설계 의도(`Scene/GameObject.cpp:180` 주석) 미달.
- **난이도**: 중간
- **어떻게 수정할지 (코드 수정 방법)**

  **수정 ① — 씬이 디바이스를 확보하는 시점에 root_를 1회 초기화** (예: `SetWindow` 또는 최초 `RenderScene` 진입부):
  ```cpp
  // Scene.cpp — (예) 씬에 윈도우/디바이스가 주입되는 시점
  void Scene::SetWindow(Window* _pWindow)   // 또는 RenderScene 시작부에 1회 가드
  {
      pWindow_ = _pWindow;
      if (!rootInitialized_ && _pWindow != nullptr)
      {
          root_.Initialize(_pWindow->GetGraphicDevice());
          rootInitialized_ = true;
      }
  }
  ```
  → 이후 `AddChild`의 가드(문제 ②)가 true가 되어 **"AddChild만 하면 자동 GPU 초기화"**가 동작한다.

  **수정 ② — Mesh에 디바이스 재초기화 진입점 추가, Initialize에서 pMesh_도 처리**:
  ```cpp
  // Mesh.h — 기존 팩토리(InitializeAs*2D 등)와 별개인 멱등 재초기화 진입점
  bool Initialize(GraphicDevice* _pDevice);   // 이미 GPU 생성됐으면 no-op

  // GameObject.cpp — pMesh_도 함께 초기화 (문제 ③ 해소)
  void GameObject::Initialize(GraphicDevice* _pDevice)
  {
      if (!initialized_ && _pDevice != nullptr)
      {
          if (pMaterial_ != nullptr) pMaterial_->Initialize(_pDevice);
          if (pMesh_ != nullptr)     pMesh_->Initialize(_pDevice);
      }
      initialized_ = true;
      for (int i = 0; i < children_.Size(); ++i)
          children_[i].pObject_->Initialize(_pDevice);
  }
  ```
  → 튜토리얼 32의 `pMat->Initialize(&g_cDevice)` 수동 우회 제거 가능.
- **위험**: 기존 수동 초기화 코드와 **2회 Initialize** 가능 → `initialized_` 가드(이미 존재) + `Mesh::Initialize` 멱등성 확인 필요.
- **비유**: 장난감(메시/재질)을 상자(씬)에 넣으면 "자동으로 꺼내서 준비해 주는 로봇"이 있다고 했다. 그런데 상자 뚜껑(루트)이 안 열려서 로봇이 영영 안 움직인다. 결국 사람이 손으로 일일이 "장난감, 준비해!"라고 외쳐야 한다(수동 초기화). → 뚜껑(루트)을 한 번 열어주면(문제 ① 해결) 이후엔 자동이다.

### B-4. 2D 그리기 시스템 2중화

- **근거 (재검증)**
  - 경로 A: 예약/스태틱 — `DeclareStatic/RenderStatic/RenderDynamic`+`FlushStatic/Dynamic`+Fill 6종. (`Graphics/Renderer2D.h:63-70`, `Scene/Scene2D.h:42-63`)
  - 경로 B: 메시 — `DrawMesh(Mesh*, Material*, world)` (GameObject::RenderSelf → Scene2D::DrawMesh → Renderer2D::DrawMesh). (`Scene/GameObject.cpp:165-172`, `Graphics/Renderer2D.h:83`)
  - **갱신 (2026-08-17)**: 이번 GPU 변환 통일로 경로 B는 "예약 배칭"이 아닌 **독립적인 GPU 즉시 드로우 경로**가 되어, 경로 A(정적 UI 배칭 — CPU 변환 유지)와 목적이 명확히 분리됨. "단일 내부 배칭 코어로 흡수"보다 **병렬 유지**가 정당화됨 (uGUI/Slate + 메시 렌더링 구조와 동일).
- **영향도**: 낮음~중간(구조) — 동작엔 문제 없음, API가 2벌이라 학습/유지보수 비용.
- **난이도**: 높음 (하위 호환 유지 필요)
- **제안**: 통합보다, 각 경로의 책임(정적 UI 배칭 vs 움직이는 메시)을 문서/튜토리얼로 명확히 안내. 인스턴싱(C-3) 도입 시 메시 경로가 배칭 그룹핑을 얻게 되면 자연스럽게 정리 가능.
- **위험**: 즉시 모드(Begin/End/DrawRect) + 예약 API + 메시 API를 모두 유지해야 해 과도한 리팩토링은 회귀 위험.
- **비유**: 같은 일을 하는 부서가 두 개다. A부서는 "예약표를 내면 우리가 대신 그려줘요", B부서는 "메시를 주면 우리가 그려줘요". 결국 그리는 건 한 곳인데, 부서가 둘이라 새 직원(게임 개발자)은 **두 부서 규칙을 다 배워야** 한다.

### B-8. [참고] 오브젝트별 b1 업로드

- **근거 (재검증)**: 오브젝트마다 `objectCb_.Update` + b1 바인딩. (`Graphics/Renderer3D.cpp:200-203`)
- **갱신 (2026-08-17)**: 2D 메시 경로도 동일하게 b1 업로드 — `Renderer2D::objectCb_` 도입, 배치 경로는 b1=단위행렬 고정. (`Graphics/Renderer2D.cpp:492-498`)
- **영향도**: 정보 — 오브젝트별 월드 행렬은 매 드로우 달라지므로 불가피. C-3 인스턴싱 도입 시 흡수 가능.
- **비유**: 그림마다 "이건 화면 어디에 놓을까"를 새로 계산하는 건 원래 해야 할 일이다. 나쁜 게 아니라 당연한 것.

## 3. C. 드로우 최적화 가능 (잔여)

### C-1. 2D 스태틱 지오메트리의 GPU 정적 버퍼화

- **근거 (재검증, 최신 코드 기준)**: `DeclareStatic`(선언 1회)은 지오메트리를 `staticCache_`에 저장하지만, `FlushStatic`이 **매 프레임** 그 지오메트리를 CPU 배치(`vertices_/indices_`)로 복사(`PushTriangles`)하고 버킷 경계마다 `Flush()`가 `vertexBuffer_.Update()`로 **전체 업로드**를 반복한다. — 스태틱 지오메트리는 변경이 없는 한 매 프레임 같은 데이터를 다시 그린다. (`Graphics/Renderer2D.cpp:226-246` FlushStatic, `:527-528` 업로드, `:195-203` DeclareStatic)
- **설계 의도 (사용자 확정)**: DeclareStatic 경로는 **언제든 가변** 가능하다 — 런타임 중간에 추가/제거/변경을 자유롭게 할 수 있어야 한다. 단, **가변이 발생한 시점에만 업데이트 1회**를 하고 이후에는 고정이다. (`dirtyFlag_` 처리 방향 — SetMeshStaticLevel과 같은 "언제든 치우고 놓기" 구조)
- **영향도**: 중간 — 스태틱 도형 수가 많을수록 프레임당 CPU 복사 + 업로드 바이트 증가.
- **난이도**: 중간
- **어떻게 수정할지 (코드 수정 방법)**

  **수정 전 코드** — 스태틱이 매 프레임 재조립된다:
  ```cpp
  // Renderer2D.h:120-124 — 슬롯은 CPU 지오메트리만 보관 (GPU 위치 정보 없음)
  struct StaticSlot
  {
      FillResult geometry_;	// 채움 결과 (프레임 간 재사용 — 변경 없음)
      RenderLayer layer_;		// 렌더 버킷 (선언 시 고정)
  };

  // Renderer2D.cpp:226-246 — 매 프레임: 캐시 → CPU 배치 복사 → Flush()에서 전체 업로드
  void Renderer2D::FlushStatic()
  {
      _s32 drawnCount = 0;
      for (RenderLayer pass : kFlushOrder)
      {
          for (DrawItem& item : staticItems_)
          {
              if (item.layer_ != pass) continue;
              StaticSlot* pSlot = FindStatic(item.key_);
              if (pSlot == nullptr) continue;
              FillResult& geo = pSlot->geometry_;
              PushTriangles(item.pTexture_, geo.vertices_.Source(), (_u32)geo.vertices_.Size(),
                  geo.indices_.Source(), (_u32)geo.indices_.Size());   // ← 매 프레임 CPU 복사
              ++drawnCount;
          }
          Flush();   // ← 매 프레임 vertexBuffer_.Update() (업로드 반복)
      }
      staticItems_.Clear();
      ...
  }

  // Renderer2D.cpp:526-528 — Flush()가 매 프레임 스태틱을 포함해 전체를 다시 업로드
  vertexBuffer_.Update(pDevice_, vertices_.Source(), UINT(vertexCount));
  indexBuffer_.Update(pDevice_, indices_.Source(), UINT(indexCount));
  ```

  **수정 후 코드 — 가변 지원 + dirtyFlag_ 기반 "변경 시에만 업로드"**:
  ```cpp
  // Renderer2D.h — StaticSlot 확장 (GPU 세그먼트 범위 + 자기 id 보관)
  struct StaticSlot
  {
      _u64 id_ = 0;			// staticId (슬롯이 자기 id를 보관 — 중간 제거에도 id 안정)
      FillResult geometry_;	// 채움 결과 (선언 시 1회 — 이후 변경은 재선언)
      RenderLayer layer_;		// 렌더 버킷 (선언 시 고정)
      _u32 vertexOffset_ = 0;	// 누적 배열에서 정점 시작 위치
      _u32 vertexCount_ = 0;	// 정점 개수
      _u32 indexOffset_ = 0;	// 누적 배열에서 인덱스 시작 위치
      _u32 indexCount_ = 0;	// 인덱스 개수
  };

  // (private 멤버 추가)
  jc::Vector<VertexPTC> staticVertices_;	// 스태틱 누적 정점 (가변 — 추가/제거 가능)
  jc::Vector<_u32> staticIndices_;		// 스태틱 누적 인덱스
  VertexBuffer staticVertexBuffer_;		// 스태틱 전용 GPU 버퍼 (DYNAMIC — 가변 대응)
  IndexBuffer staticIndexBuffer_;			// 스태틱 전용 GPU 인덱스 버퍼
  bool staticGpuCreated_ = false;			// GPU 버퍼 생성 여부 (최초 FlushStatic에서)
  bool staticGpuDirty_ = false;			// 누적 배열 변경 → 다음 FlushStatic에서 업로드

  // Renderer2D.cpp — FindStatic: id_ 비교 선형 검색 (슬롯이 id를 보관하므로 중간 제거에도 안정)
  Renderer2D::StaticSlot* Renderer2D::FindStatic(_u64 _staticId)
  {
      if (_staticId == 0) return nullptr;
      for (_s32 i = 0; i < staticCache_.Size(); ++i)
      {
          if (staticCache_[i].id_ == _staticId) return &staticCache_[i];
      }
      return nullptr;   // 제거된 슬롯의 id → nullptr (예약 시 스킵)
  }

  // Renderer2D.cpp — DeclareStatic: 언제든 호출 가능 — 누적 배열에 복사 + dirty 표시
  _u64 Renderer2D::DeclareStatic(const RenderParams& _params)
  {
      StaticSlot slot;
      slot.layer_ = _params.layer_;
      BuildFill(_params.fill_, _params, slot.geometry_);

      // 누적 배열에 복사 (인덱스 재배치 — GPU 버퍼 순서 = 선언 순서)
      const _u32 baseVertex = (_u32)staticVertices_.Size();
      const _u32 baseIndex = (_u32)staticIndices_.Size();
      for (_s32 i = 0; i < slot.geometry_.vertices_.Size(); ++i)
          staticVertices_.PushBack(slot.geometry_.vertices_[i]);
      for (_s32 i = 0; i < slot.geometry_.indices_.Size(); ++i)
          staticIndices_.PushBack(baseVertex + (_u32)slot.geometry_.indices_[i]);
      slot.vertexOffset_ = baseVertex;
      slot.vertexCount_ = (_u32)slot.geometry_.vertices_.Size();
      slot.indexOffset_ = baseIndex;
      slot.indexCount_ = (_u32)slot.geometry_.indices_.Size();

      _u64 id = staticIdProvider_.Acquire();
      slot.id_ = id;
      staticCache_.PushBack(jc::Move(slot));
      staticGpuDirty_ = true;	// 새 지오메트리 → 다음 FlushStatic에서 업로드 (가변 시점 1회)
      return id;
  }

  // Renderer2D.cpp — 신규: 스태틱 제거 ("가구 치우기") — 슬롯 실제 제거 + 누적 배열 재구축
  void Renderer2D::RemoveStatic(_u64 _staticId)
  {
      _s32 index = -1;
      for (_s32 i = 0; i < staticCache_.Size(); ++i)
      {
          if (staticCache_[i].id_ == _staticId) { index = i; break; }
      }
      if (index < 0) return;

      staticCache_.RemoveAt(index);	// 슬롯 진짜 제거 (메모리 회수 — 비활성 잔존 없음)
      RebuildStaticBuffer();			// 누적 배열 재구축 + 오프셋 재계산 + dirty
  }

  // Renderer2D.cpp — 신규: 남은 슬롯만 누적 배열에 다시 쌓는다. (가변 시점 1회 비용)
  void Renderer2D::RebuildStaticBuffer()
  {
      staticVertices_.Clear();
      staticIndices_.Clear();
      for (_s32 i = 0; i < staticCache_.Size(); ++i)
      {
          StaticSlot& slot = staticCache_[i];
          const _u32 baseVertex = (_u32)staticVertices_.Size();
          const _u32 baseIndex = (_u32)staticIndices_.Size();
          for (_s32 v = 0; v < slot.geometry_.vertices_.Size(); ++v)
              staticVertices_.PushBack(slot.geometry_.vertices_[v]);
          for (_s32 k = 0; k < slot.geometry_.indices_.Size(); ++k)
              staticIndices_.PushBack(baseVertex + (_u32)slot.geometry_.indices_[k]);
          slot.vertexOffset_ = baseVertex;
          slot.vertexCount_ = (_u32)slot.geometry_.vertices_.Size();
          slot.indexOffset_ = baseIndex;
          slot.indexCount_ = (_u32)slot.geometry_.indices_.Size();
      }
      staticGpuDirty_ = true;
  }

  // Renderer2D.cpp — FlushStatic: dirty일 때만 업로드, 이후 바인딩 + 세그먼트 DrawIndexed
  void Renderer2D::FlushStatic()
  {
      if (staticItems_.Empty() || staticVertices_.Empty())
      {
          staticItems_.Clear();
          return;
      }

      // 가변 대응: 변경이 있었을 때만 GPU 버퍼를 (재)업로드한다. 이후 프레임은 업로드 없음.
      if (staticGpuDirty_)
      {
          if (!staticGpuCreated_ || staticVertexBuffer_.Count() < staticVertices_.Size())
          {
              // 첫 생성 또는 크기 부족(가변 추가) — 2배 성장으로 재생성 (ComPtr 대입 — 기존 자동 해제)
              _u32 capacity = staticVertexBuffer_.Count();
              if (capacity < staticVertices_.Size()) capacity = (_u32)staticVertices_.Size() * 2;
              if (!staticVertexBuffer_.Create(pDevice_, staticVertices_.Source(), sizeof(VertexPTC),
                  capacity, true)) { staticItems_.Clear(); return; }
              if (!staticIndexBuffer_.Create(pDevice_, staticIndices_.Source(),
                  staticIndices_.Size(), true)) { staticItems_.Clear(); return; }
              staticGpuCreated_ = true;
          }
          else
          {
              // 크기 충분 — 내용만 갱신 (부분 업데이트는 VertexBuffer API에 오프셋이 없어 전체 업로드)
              staticVertexBuffer_.Update(pDevice_, staticVertices_.Source(), (_u32)staticVertices_.Size());
              staticIndexBuffer_.Update(pDevice_, staticIndices_.Source(), (_u32)staticIndices_.Size());
          }
          staticGpuDirty_ = false;
      }

      GraphicContext& context = pDevice_->GetContext();
      ApplyFrameStates();	// 셰이더 + b0(뷰프로젝션)

      // 배치 경로와 동일: 스태틱 정점도 CPU 변환 완료이므로 b1=단위행렬, b2=흰색 고정
      ObjectConstants object;
      object.world_ = mat4::Identity();
      objectCb_.Update(pDevice_, object);
      context.SetConstantBuffer(ShaderStage::ssVertex, 1, objectCb_.Raw());

      MaterialConstants material;	// 기본값 = 흰색
      materialCb_.Update(pDevice_, material);
      context.SetConstantBuffer(ShaderStage::ssPixel, 2, materialCb_.Raw());

      staticVertexBuffer_.Bind(pDevice_);
      staticIndexBuffer_.Bind(pDevice_);
      context.IASetPrimitiveTopology(D3D11_PRIMITIVE_TOPOLOGY_TRIANGLELIST);

      // 배칭: 같은 텍스처 + 누적 배열에서 연속인 세그먼트를 한 묶음으로 DrawIndexed
      _s32 drawnCount = 0;
      _u32 batchStart = 0, batchCount = 0, batchIndexEnd = 0;
      Texture* pBatchTexture = nullptr;

      auto FlushBatch = [&]()
      {
          if (batchCount == 0) return;
          pBatchTexture->Bind(pDevice_, 0);
          ++drawCallCount_;
          context.DrawIndexed(batchCount, batchStart, 0);
          batchStart = batchCount = batchIndexEnd = 0;
          pBatchTexture = nullptr;
      };

      for (RenderLayer pass : kFlushOrder)
      {
          for (DrawItem& item : staticItems_)
          {
              if (item.layer_ != pass) continue;
              StaticSlot* pSlot = FindStatic(item.key_);
              if (pSlot == nullptr) continue;	// 제거된 슬롯의 예약 → 스킵

              // 텍스처가 바뀌거나 버퍼에서 연속이 아니면 이전 묶음을 먼저 그린다.
              if (pBatchTexture != nullptr &&
                  (pBatchTexture != item.pTexture_ || batchIndexEnd != pSlot->indexOffset_))
              {
                  FlushBatch();
              }
              if (batchCount == 0)
              {
                  batchStart = pSlot->indexOffset_;
                  pBatchTexture = item.pTexture_;
              }
              batchCount += pSlot->indexCount_;
              batchIndexEnd = pSlot->indexOffset_ + pSlot->indexCount_;
              ++drawnCount;
          }
          FlushBatch();	// 버킷 경계 — 버킷 간 절대 섞이지 않음
      }
      staticItems_.Clear();
      if ((++sLogFrame % 60) == 1)
          _LogDebug_("[sgf] Renderer2D::FlushStatic — 스태틱 세그먼트 드로우 (%d건)", drawnCount);
  }

  // Renderer2D.cpp — Finalize: 선언 세트(슬롯+누적 배열+플래그)를 함께 정리
  void Renderer2D::Finalize()
  {
      staticCache_.Clear();
      staticVertices_.Clear();	// 누적 배열도 함께 — 재초기화 시 이전 씬 정점이 남으면
      staticIndices_.Clear();	//     GPU 버퍼가 이전 것까지 포함해 생성되는 버그 발생
      staticGpuCreated_ = false;
      staticGpuDirty_ = false;
      BatchRenderer::Finalize();
  }
  ```
- **왜 이렇게 수정하나**: 스태틱 지오메트리는 "가변이 없는 한 변하지 않는" 데이터다. 지금은 **매 프레임 같은 데이터를 CPU에 복사하고 GPU에 다시 업로드**한다. 변경 시점(`dirtyFlag_`)에만 업로드하면 "대부분의 프레임 = 바인딩 + DrawIndexed만"이 된다. 동시에 **가변 구조를 지원**한다 — `DeclareStatic`은 언제든 호출 가능(누적 배열에 추가 + dirty), `RemoveStatic`으로 **슬롯을 실제로 제거**하고 남은 슬롯만 누적 배열을 재구축한다(메모리 회수 — 비활성 잔존 없음). `SetMeshStaticLevel`과 같은 "언제든 치우고 놓기" 패턴이 이 경로에도 그대로 성립한다. GPU 버퍼는 DYNAMIC 유지 — `Update`로 내용 갱신, 크기 부족 시 2배 성장 재생성(ComPtr 대입 — 기존 리소스 자동 해제).
- **위험 (검증 포인트)**:
  - **id 매핑 변경**: 기존 `id-1 = 인덱스` 직접 매핑은 중간 제거 시 뒤 슬롯들의 id가 깨지므로, 슬롯이 자기 `id_`를 보관하고 `FindStatic`이 선형 검색을 한다 (O(슬롯 수) — 수십~수백 개 규모에서 무시 가능, 기존 "선형 검색 없음" 주석과 트레이드오프).
  - **RemoveStatic 비용**: 슬롯 제거 + 누적 배열 재구축 + (다음 프레임) GPU 업로드 — O(스태틱 전체). "가변 시점에만 1회"라는 설계와 부합하며, 가구 치우기는 드문 이벤트다.
  - **크기 부족 재생성**: 가변 추가가 반복되면 버퍼 재생성이 반복될 수 있음 — 2배 성장으로 상각. `VertexBuffer::Update`는 오프셋 없는 전체 업로드라 변경 시 전체를 다시 업로드함 (부분 업데이트 API 없음 — 허용, "변경 시 1회"라는 설계와 부합).
  - **같은 프레임 내 제거 후 예약**: `RemoveStatic` 후 같은 프레임의 `RenderStatic(제거된 id)`는 `FindStatic`이 nullptr → 스킵. 예약이 먼저였으면 제거된 항목은 다음 FlushStatic에서 동일하게 nullptr → 스킵. (모든 경로 안전)
  - `staticItems_`가 **선언 순서와 다른 순서**로 예약되면 버퍼 연속 조건이 깨져 배칭이 분리될 수 있음 (드로우콜 증가 — 기능 문제 아님, `GetDrawCallCount`로 검증). `RemoveStatic` 후 재구축되면 순서가 압축되는데, 이때도 연속 배칭이 재구성된다.
- **비유**: 벽에 걸린 액자(변하지 않는 그림)를 **매초마다 새로 그려서 다시 걸어둔다**. 그림은 안 변하는데. **그림이 바뀐 날에만 새로 걸어두고**(dirtyFlag), 이후에는 그대로 두면 매초 그릴 시간과 종이가 아낀다. 액자를 내리면(RemoveStatic) **목록에서 지우고 남은 액자들을 다시 빽빽하게 정리한다**(재구축).

### C-3. 인스턴싱 미사용 (2D/3D 공통 — 대상 확장됨)

- **근거 (재검증)**
  - `Draw`가 오브젝트마다 `Material::Bind + Mesh::Bind + DrawIndexed`. (`Graphics/Renderer3D.cpp:183-207`)
  - **갱신 (2026-08-17)**: 2D `DrawMesh`도 동일 구조(즉시 드로우)로 전환되어 오브젝트당 1콜 — C-3의 대상이 **3D → 2D/3D 공통**으로 확장됨. (`Graphics/Renderer2D.cpp:455-503`)
  - 이전 배칭 구조에서 2D 메시는 여러 오브젝트가 1콜이었으나, GPU 변환 통일로 인해 이제 2D 메시 배칭 상실 (설계 결정 수용). 인스턴싱 도입 시 2D/3D 모두 드로우콜 복원 가능.
- **영향도**: 낮음~중간 — 현재 오브젝트 수가 적어 실질 영향 적음. 수백 개 시점에 유효.
- **난이도**: 높음 (인스턴스 버퍼 + 셰이더 변경 + 배칭 그룹핑)
- **제안**: `(meshKey, materialKey)`로 정렬해 동일 그룹을 `DrawIndexedInstanced`로. 셰이더 b1을 인스턴스별 월드 배열로 확장. 2D는 텍스처/정점 포맷이 단순해(VertexPTC) 먼저 적용 가능.
- **위험**: 셰이더/정점 포맷 변경 필요 → 2D/3D 렌더 회귀 위험. 대규모 확장 전 보류 권장. (plan 문서 Phase 3)
- **비유**: 똑같은 캐릭터 100명을 그릴 때, 지금은 100번 "이 캐릭터 그려! 이 캐릭터 그려! ..."라고 외친다. 한 번에 "**이 캐릭터 100명 그려! (위치는 이 리스트대로)**"라고 하면 한 번의 지시로 끝난다.

### C-4. 2D 텍스처 아틀라스 미사용

- **근거 (재검증)**: 배칭이 텍스처별로 분리됨 (텍스처 전환마다 Flush). (`Graphics/Renderer2D.h` 배칭 규칙 주석)
- **영향도**: 낮음 — 현재 콘텐츠 규모에선 미미.
- **난이도**: 높음 (아틀라스 로드 + UV 재계산)
- **제안**: 아틀라스 1장 + sub-UV로 스프라이트 드로우콜 통합. `DrawSprite`/`Fill::Texture`의 UV 인자 활용 가능.
- **위험**: 텍스처 필터(Clamp) 경계 이음새 처리 필요.
- **비유**: 풀 한 포기마다 서로 다른 그림 파일을 꺼내서 그린다. 파일을 바꿀 때마다 "준비" 시간이 걸린다. 모든 풀 그림을 **한 장의 큰 종이에 모아두고**, 잘라서 쓰면 파일을 바꾸는 횟수가 줄어든다.
