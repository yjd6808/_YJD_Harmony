# jc/jnet 로딩 시스템 구현 계획

## 개요
- 문서: `D:\Programming\jc-jnet-구현문서-기술스택-수도코드.md`, `D:\Programming\jc-jnet-테스트문서-jc_gtest-jnet_gtest.md`
- 목표: jc(FileLoader/IDataSource) + jnet(HttpClient/WinHttpTransport) + 브리지 + 테스트

## 역할 분담 (에이전트 병렬)
1. **Agent-A: jc 기반 타입** - Uri, MemoryStream 정식화
2. **Agent-B: jc FileLoader 코어** - LoadDefine, ILoadListener, LoadResult, IDataSource, FileDataSource, LoadJob, FileLoader
3. **Agent-C: jnet Http 코어** - HttpDefine, HttpHeaders, HttpRequest, HttpResponse, HttpResult, HttpJob, IHttpTransport, WinHttpTransport, HttpClient, HttpEventListener
4. **Agent-D: 브리지 + 빌드** - HttpDataSource/InstallHttpDataSource, Props/jnet.props(winhttp.lib), Directory.Build.props 확인, ThirdParty 구조 검토
5. **Agent-E: 테스트** - jc_gtest 확장(Uri/MemoryStream/FileDataSource/FileLoader + LoaderTestHelper), jnet_gtest 신설(MockHttpServer, HttpTestHelper, HttpHeaders/Client/Bridge 테스트), PCH

## 의존 방향
jnet -> jc 단방향, jc는 jnet 모름

## 기술 스택 준수
- C++17, MSVC x64, WinHTTP 동기 모드, jc ThreadPool, Atomic/NormalLock/TreeMap/Vector, IdProvider, SharedPtr

## 검증
- Scripts\BuildProject\jc.bat -P x64 -C Debug
- Scripts\BuildProject\jnet.bat -P x64 -C Debug
- jc_gtest / jnet_gtest 실행

## 유의사항
- 전역 가변 상태 0, Update 스레드에서만 콜백, 예외 미사용, NonCopyableNonMovable, dbg_new
- ThirdParty WinHttp는 OS 제공 winhttp.lib이므로 별도 바이너리 불필요, Props 중앙 관리로 링크
