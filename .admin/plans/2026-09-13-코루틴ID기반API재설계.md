# 코루틴 ID 기반 API 재설계

- 날짜: 2026-09-13
- 배경: `generation_` + `CoHandle` + raw 포인터 + `Checked` 분리 등 중복 메커니즘을 `_u64` 단일 id로 통합
- 대상: `Projects/jc/Sources/jc/Threading/Coroutine.{h,cpp,Impl.asm}`, `Natvis/Coroutine.natvis`, `jc_gtest`, `jcr`, `jc_gbench`
- 전제(완료): `transfer_` → `switchData_` 개명 + 상세 주석

## 0. 설계 확정 사항 (논의 결론)

| 항목 | 결론 |
|---|---|
| 식별자 | `_u64` 단조 카운터 단일 id. `generation_` 삭제. `IdProviderReuse` 미사용 (재사용 키는 ABA 부활) |
| 검증 | `usingById_` 맵 조회. 역참조 없이 판별 (cstCustom UAF 해결) |
| 실행 API | `CoId CoRun(fn, CoDesc)` 단일 함수. `CoRunH`/`CoResumeH`/`CoHandle` 삭제 |
| 재개 API | `bool CoResume(id)` + `bool CoResume(id, in, &out)` 오버로드. `CoResumeV` 흡수 |
| 예외 | `CoDesc::onException` + 전역 폴백 + 보관. `rethrow` 플래그·`Checked` 분리 없음 |
| 스택 지정 | `CoStackSpec` 팩토리 (`Low/Mid/High/Custom`). 무효 조합 구조적 봉쇄 |
| 스코프 가드 | `CoScoped` → `CoScope` 개명 + `CoScopeRule`(Quiet/Assert). `cancelRequested_` 유지 |

## 1. 식별 체계

### Before / After

```cpp
// before: CoContext (16B)
_u32 id_;            // 디버그 번호
_u32 threadId_;
_u32 generation_;    // 재사용 판별
_u32 _padGen_;

// after: CoContext (16B, 레이아웃 동일)
_u64 id_;            // 발번 즉시 고유. 재사용 없음
_u32 threadId_;
_u32 _pad_;
```

```cpp
// before
using CoHandle = ...; // {pCtx, generation} + IsAlive 역참조

// after
using CoId = _u64;              // 0은 무효 id
```

- `CoMgr::nextId_`: `_u32` → `_u64`. 소진 불가 (초당 1,000개 발급 시 약 5.8억 년).
- `Clear()` 포함 어떤 경로에서도 `nextId_` 리셋 금지 (리셋하면 id 재사용 → ABA).
- `stacksByBase_` → `usingByBase_` 개명 (TreeMap 유지. 주소 범위 조회에 순서 필요).
- `usingById_` (`jc::HashMap<_u64, CoContext*>`) 추가. `AllocCtx` 삽입, `FreeCtx` 삭제, `Clear` 비우기.
- `FreeCtx`의 `generation_++` 삭제. `InitCtx`의 `id_ = 0` 리셋 + `AllocCtx` 재부여 순서 유지 (필수).
- id 유일성은 스레드 범위. 핸들에 `pCtx`가 함께 있었듯 id 검증도 owning 스레드에서 수행.

### 검증 방식

```cpp
// CoResume(id) 내부
CoContext** pp = usingByBase_...; // 아님. id 맵으로:
CoContext** ppFound = usingById_.Find(_id);
if (ppFound == nullptr || *ppFound == nullptr) { stale → coeStaleHandle }
```

- 맵에 있으면 살아있음 (`csEnd`는 `FreeCtx`에서 즉시 제거되므로 별도 state 검사 불필요).
- `cstCustom`(`delete`됨) 죽은 id 조회가 UAF 없이 처리됨.

## 2. CoDesc + CoRun

```cpp
struct CoStackSpec
{
    static CoStackSpec Mid()              { return {}; }
    static CoStackSpec Low();
    static CoStackSpec High();
    static CoStackSpec Custom(_u32 _size);

    CoStackTier tier = cstMid;
    _u32 size = 0; // cstCustom일 때만 사용
};

using FnCoException = void(*)(CoId _id, std::exception_ptr _ex);

struct CoDesc
{
    CoStackSpec spec;
    void* userData = nullptr;
    CoContext** ppOut = nullptr;       // 관찰·직접채널용. 재개에 사용 금지
    FnCoException onException = nullptr;
};

CoId CoRun(FnCoroutine _fn, const CoDesc& _desc = {});
```

- 헤더 `CoRun` 인라인은 `CoRunInternal` (cpp static) 호출로 축소. TEB 세팅·스위치 본체는 cpp로 이동.
- `t_coStartUserData` 핸드오프 제거. 내부에서 `userData` 직접 세팅.
- `CoAllocCtx`는 `extern "C"` 공개 API라 시그니처 유지.
- `CoRunFn` 템플릿은 헤더 잔류, 내부에서 `CoDesc{...}` 조립.
- `ResolveTier`는 검증 백스톱으로 유지.
- `ppOut` 계약: 재개에 사용 금지 (주석 명시). id가 신원, 포인터는 뷰.

## 3. CoResume

```cpp
bool CoResume(CoId _id);
bool CoResume(CoId _id, _u64 _inTransferData, _u64* _pOut);
```

- id 불변이라 반환은 생사 신호 `bool`만. `false`는 종료·실패 포함, 구분은 `CoGetLastError()` (`coeNone`이면 정상 종료).
- `CoYield()` / `CoYield(_u64)`는 현행 유지 (이미 오버로드 공존).
- `while (pCtx)` 관용구는 `while (CoResume(id))`로 전환.
- 검증 순서: 맵 미조회 → `coeStaleHandle`, 자기 자신(`found == currentCtx_`) → `coeInvalidState`,
  `csYield` 아님 → `coeInvalidState` (raw `CoAllocCtx` 후 resume은 기존보다 엄격해짐).
- 타 스레드 resume은 맵에 안 보여 `coeStaleHandle`로 보고 (진단 정밀도 한계. 안전성은 유지).
  `Resume_WrongThread` 테스트 기대값 변경.
- `CoValidateResume` 삭제 (맵 조회 + 상태 + 자기 검사로 대체).

## 4. 예외 처리

- `CoEntry` catch 방화벽 유지 (제거 불가. asm 경계 unwind 실측 근거).
- 처리 순서: `onException` → 전역 핸들러 → 보관 (기존 take/clear).
- 전달은 소비형 (move, 정확히 1회). 핸들러 정상 복귀 후 보관에 남기지 않음.
- 전역 핸들러는 thread_local (`CoSetExceptionHandler`). 동기화 없음.
- 콜백 호출 위치: 스위치 복귀 후 스케줄러 스택 (`CoResume`/`CoRunInternal` 복귀 지점). 코루틴 스택 위 호출 금지.
- `CoRunChecked` / `CoResumeChecked` 삭제 (콜백으로 흡수).
- Debug 전용: 꺼내지 않고 버려지는 보관 예외 경고 (`CoEntry` 진입 정리 지점).

## 5. CoScope (CoScoped 개명 + 소멸 정책)

```cpp
enum class CoScopeRule
{
    CancelQuiet,  // 살아있으면 조용히 취소·drain (현행 동작)
    CancelAssert, // 살아있으면 Debug assert 후 drain
};

class CoScope
{
public:
    explicit CoScope(CoId _id, CoScopeRule _rule = CoScopeRule::CancelQuiet);
    ~CoScope(); // 정책에 따라 처리
    bool Resume();
    void Cancel(); // 취소 요청 후 끝까지 drain
    // Done() 없음. 생사 확인은 CoResume 반환 + CoGetLastError로 수행
};

// 사용 예시 (헤더 주석에도 동일 예시 기재):
//   {
//       CoScope sc(CoRun(Worker));
//       while (CoResume(sc.Id())) {}
//   } // 소멸 시 살아있으면 정책에 따라 처리
//   {
//       CoScope sc(CoRun(Service), CoScopeRule::CancelAssert);
//       sc.Cancel(); // 명시 종료. 소멸 시 assert 없음
//   }
```

- `CoHandle` 삭제에 종속되어 id만 보관. `Done()`은 맵 미조회 판별.
- `CancelAssert` = `CancelQuiet` + 디버그 검사. assert 후에도 drain까지 수행 (release 동작 동일).
- 기본값 `CancelQuiet` (현행 동작 유지. 엄격함은 opt-in).
- `cancelRequested_` → `isCancelRequested_` 개명 (CoContext 멤버, asm 구조체, `InitCtx` 리셋 포함).
  주의: 코딩 컨벤션(private 멤버 suffix `_`)에서 벗어나나 소유자 지시로 적용.
  `CoCancelRequested()` 함수명은 유지.
- `CoScope` 헤더 주석에 사용 예시 코드 포함 (위 예시).
- 사용처: `06_Coroutine_14_Api.cpp`, `CoroutineTest.cpp` (`Api_ScopedCancel`).
