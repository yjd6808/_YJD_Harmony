## 0. TL;DR

**RenderingPipeline 신설 없이** `GraphicDevice`(수명·생성/소유·표면·프레임) / `GraphicContext`(바인딩·상태·드로우)로 D3D11 경계를 그대로 흡수했다. 레거시 호환 Shim을 전량 제거하고 `Create=Device / Bind·Update=Context`를 타입으로 강제, §7 두 샘플이 수정 없이 컴파일·실행되는 상태를 달성했다.

```
[Before - v3]                          [After - 최종]
main / Renderer2D / Renderer3D         main (튜토리얼)
  bool setter 혼용                       gd.Create* · gd.BeginFrame/Present
  ->Context() Raw 우회 12곳              gc.Set*(enum·핸들) · gc.Draw*
GraphicDevice ─── GraphicContext       GraphicDevice ─────── GraphicContext
  (표면·상태·레거시 혼재)                수명·소유·표면·프레임  바인딩·상태·드로우
        ▼                                        ▼                     ▼
     D3D11 / DXGI                      ID3D11Device·DXGI      ID3D11DeviceContext
```

## 1. 목표 코드 (완료 기준)

```cpp
Window window;
window.Create(jc::String(L"Triangle"), 800, 600);
InputManager input;
window.ConnectInput(&input);

GraphicDevice& gd = GraphicDevice::Get();
gd.Initialize();
gd.CreateSwapChain(window.Handle(), 800, 600, PixelFormat::pfRgba8);
GraphicContext& gc = gd.Context();

gd.CreateShader(jc::String(hlsl));
gd.CreateVertexBuffer<VertexPC>(vertices, 3);
gd.CreateIndexBuffer(indices, 3);
gc.SetTopology(PrimitiveTopology::ptTriangleList);
gc.SetRasterizer(CullMode::cmNone, FillMode::fmSolid);
gc.SetDepth(DepthMode::dmDisabled);
gc.SetBlend(BlendMode::bmNone);

while (window.PumpMessage())
{
    gd.BeginFrame(color(0x14, 0x14, 0x1F));
    gc.DrawIndexed(3, 0, 0);
    gd.Present(true);
    input.NextFrame();
}
gd.Finalize();
window.Destroy();
```

## 11. Q&A 발췌

- **왜 `Create*`가 `gd`인가** — 디바이스 자식, 컨텍스트 N개 문제·이상 수명 방지, `ID3D11Device::Create*` 스레드 안전과 일치.
- **왜 `BeginFrame/Present`가 `gd`인가** — DXGI 연산, `gc`에 두면 절반만 유효한 API.
- **왜 생성자 public** — WARP/오프스크린 지역 인스턴스·기존 `GraphicDevice*` 코드 호환.
- **왜 지연 초기화 금지** — 정적 소멸 순서 비결정성, `Finalize` 멱등 백스톱.
- **RenderingPipeline과 차이** — 책임 동일·집만 다름, `current`를 `gc`가 들어 두 개의 진실 해소.
