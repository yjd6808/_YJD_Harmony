## A. 07 — 실패 경로의 에러 보고 / VEH 자동 등록 / 오용 방어

### 문서 요약
1. `g_cCoLastError`가 파일 전역이라 사용자가 실패 원인을 읽을 방법이 없음.
2. `InitStack`이 커밋 실패를 무시하고 void로 진행 → 커밋 안 된 스택 진입 후 첫 push에서 AV.
3. 코루틴 밖 `CoYield()`는 null 역참조 크래시.
4. `CoVEH`를 사용자가 직접 등록해야 해서 빼먹으면 첫 확장 때 종료.

### 수정 (before → after)
- `CoError` 공개 enum + 스레드별 `t_coLastError` + `CoGetLastError()`(읽으면 지움) + `CoErrorString()` 추가.
- `InitStack`/`InitCtx`를 bool로 바꿔 실패 전파. 풀 재사용 재커밋 실패 시 풀로 되돌리고 nullptr.
- asm `CoYield` → `CoYieldImpl`로 숨기고 헤더 inline `CoYield()`가 검사 (Debug assert, Release no-op).
- `CoMgr` 생성자에서 `std::call_once`로 `CoVEH`를 FIRST 1회 자동 등록. `Config.cpp` 전역 VEH는 `STATUS_GUARD_PAGE_VIOLATION` 명시적 제외.
- 보너스 수정 (테스트가 찾아냄): `CoRun` 할당 실패 경로가 `mov rax,rcx`로 깨진 rcx를 돌려줘 쓰레기 포인터를 반환했음. `xor ecx,ecx` 후 FIN으로 고침.

### 개선점
- 모든 실패가 원인 코드와 함께 nullptr로 돌아옴. VEH 등록 누락 실수 원천 제거.

### 검증
- gtest `Error_NullFunction` (coeNullFunction 후 coeNone), `Error_SuccessClearsError`, `Veh_AutoRegistered` (등록 없이 10KB 확장) 통과.
- jcr `06_Coroutine_07_ErrorVeh.cpp` 동일 시나리오 예제.

### 원문 대비 편차
- 없음. 문서 After 그대로. `CoYield` 래퍼 방식도 문서안 그대로.

## B. 05 — CoResume 안전장치 (threadId / state / ABA)

### 문서 요약
`CoResume`은 null 검사만 해서 (a) 다른 스레드 resume 시 남의 풀 오염 및 해제된 메모리 실행, (b) csRun/csEnd resume 시 스택 오염, (c) 종료 후 재사용된 주소로 엉뚱한 코루틴 실행(ABA)이 전부 정의되지 않은 점프로 이어짐.

### 수정 (before → after)
- `CoStack::magic_` 추가 (AllocStack에서 `CO_STACK_MAGIC` 기록). 해제된 메모리 가려내기용.
- `CoContext::generation_` 추가 (FreeCtx마다 ++. InitCtx에서 리셋 안 함).
- `CoValidateResume()` 추가: null/magic/스레드/상태(csInit·csYield만)/자기 자신 검사. Debug에선 using_ 포함 여부까지. asm `CoResume` 진입 시 호출, 실패 시 `FIN_NULL`으로 nullptr 반환.
- `CoHandle{pCtx, generation}` + `IsAlive()` + `CoRunH()` + `CoResumeH()` 추가. FreeCtx에서 `generation_++`, `state_=csEnd`, `fn_=nullptr`.
- asm `CoContext`/`CoStack` 구조체에 동일 필드 추가 (EQU 동기화).

### 개선점
- 잘못된 resume 4종이 전부 nullptr + 에러 코드로 바뀜. ABA는 세대로 판별.

### 검증
- gtest `Resume_WrongThread` (coeWrongThread, 본문 미실행), `Resume_Self` (coeInvalidState), `Resume_StaleHandle` (같은 주소 재사용 확인 후 coeStaleHandle) 통과.
- jcr `06_Coroutine_05_Safety.cpp` 동일 시나리오 예제.

### 원문 대비 편차
- 문서안 `CoResume(CoHandle)` 오버로드는 컴파일 불가라 `CoResumeH`로 명명. (`CoResume`이 extern "C" asm이라 C++ 오버로드를 걸 수 없음. 코드 주석에 이유 기록)
- `CoDetach/CoAttach`(스레드 간 명시적 이동)는 미구현. 암묵적 이동 금지만 강제하고 필요해지면 후속으로 뺌.

## C. 06 — cstCustom 크기 정규화 / 풀 오염

### 문서 요약
`AllocStack`이 티어만 바꾸고 크기는 그대로 둬서 (1) 5000B 요청이 5000B 스택을 받아 정렬이 깨지고, (2) 그 ctx가 cstLow 풀에 들어가 다음 사용자를 오염시키고, (3) 크기 0이면 원인도 안 보이고 실패함. 판별 로직이 `AllocStack`/`AllocCtx`에 중복.

### 수정 (before → after)
- `CoMgr::ResolveTier()` 단일화: 고정 티어는 티어 크기 그대로, 작은 custom은 티어로 올리되 크기도 티어 크기로, 진짜 큰 custom은 페이지 올림 + 풀 제외, 크기 0은 `coeInvalidStackSize`로 거부.
- `AllocStack`은 판별 없이 예약만 + 페이지 정렬 assert. `AllocCtx` 풀 경로에 크기 일치 assert.
- `CoMinStackPages()` 헬퍼 추가. 단 cstLow(4p)가 최소 구성(6p)을 못 담는 건 문서대로 확인만 하고 크기 변경은 안 함 (아래 편차 참고).

### 개선점
- 풀 오염 원천 제거. custom 실패 원인이 보임.

### 검증
- gtest `Custom_RoundUp` (5000→Low/16KB/페이지정렬), `Custom_ZeroRejected`, `Custom_NoPoolMix` (오염된 풀에서 6KB 정상), `Custom_LargeNoPool` (300000→페이지올림 + 해제 확인) 통과.
- jcr `06_Coroutine_06_Custom.cpp` 동일 시나리오 예제.

### 원문 대비 편차
- `CO_STACK_SIZE_LOW` 16KB→32KB 상향 및 InitStack 클램프 실패화는 미적용. Low 생성을 실패시키면 기존 TC_CO07이 깨지고 메모리 동작이 바뀌어서, 클램프 유지 + `CoMinStackPages`로 수식만 문서화함. 티어별 상수는 필요해지면 후속.
- 테스트 중 실측: Low(4p)에서 10KB 성장은 VEH 예산 부족으로 죽음. 성장 테스트는 Mid로 하고, Low 예산 문제는 15 예산 항목에 기록.

## D. 01 + 02 + 03 + 08 — asm 세트 (FRAME / TEB / MXCSR)

### 문서 요약
- 01: asm 4개에 unwind 정보가 없어 코루틴 밖으로 예외가 나가면 언와인더가 트램폴린에서 꼬임. 디버거 콜스택도 깨짐.
- 02: TEB DeallocationStack 미스왑으로 CRT/언와인더가 엉뚱한 범위 참조. (A안: NOACCESS 가드존 + VEH 일관 처리, B안: 스왑 없이 제약 문서화)
- 03: ExpandStack 후 gs:[16] 미갱신으로 확장 영역에서 throw하면 프로세스 종료. `__chkstk`도 옛 한계로 프로브.
- 08: MXCSR/x87 CW 미보존으로 반올림 모드가 코루틴 간 샌 틈. CET 바이너리에선 즉사.

### 수정 (before → after)
- `CoRun/CoYieldImpl/CoResume`에 `FRAME` + `.pushreg/.setframe/.allocstack/.endprolog` 추가.
- 진입 레이아웃 변경: `push 0`(가짜 반환주소) + `sub 40`(트램폴린 프레임) + `[rsp+32]` ctx 백업. `fn_` 대신 `CoEntry`로 점프. 트램폴린은 `CoFnEndTrampoline_Resume` 라벨에서 시작.
- `CoEntry` (noexcept): fn을 try/catch로 감싸 예외를 `t_coPendingException`에 보관. `CoRunChecked/CoResumeChecked`가 nullptr 때 스케줄러 스택에서 다시 던짐. `CoClearPendingException()`으로 버림.
- TEB: gs8 mov 교환 유지, gs16은 yield 때 stack_에 동기화 후 스레드값 복원 / resume 때 스레드값 저장 후 stack_ 현재값 로드. DeallocationStack은 비상 밴드 상단 설치 (아래 02 편차 참고).
- `CoRegs`에 `gs1478_/mxcsr_/fpucw_` 추가. CoRun 저장 + Yield/Resume 교체 + 트램폴린 복원 (`stmxcsr/fnstcw/ldmxcsr/fldcw`).
- `CoMgr` 생성자에서 섀도우 스택 감지 시 assert. `/CETCOMPAT:NO` 전제 주석.
- `ExpandStack` 시그니처 `(CoStack*)` → `(CoContext*)` 변경 (TEB 갱신용) + 성공 시 `__writegsqword(0x10)`.

### 개선점
- 예외가 트램폴린을 못 넘음 (boost.context와 동일). 확장 영역 throw/catch 동작. 반올림 모드 격리. CET 프로세스에서 조기 차단.

### 검증
- gtest `Exception_ThrowInsideCaughtOutside`, `Teb_StackRangesInside`, `GuardZone_IsPageGuard`, `Teb_StackLimitAfterGrowth` (확장+throw/catch), `Abi_MxcsrPreserved` (코루틴 DOWN 유지 + 스레드 NEAR 유지 + 종료 후 복원) 통과.
- jcr `06_Coroutine_01_Exception.cpp`, `02_Teb.cpp`, `03_StackLimit.cpp`, `08_Mxcsr.cpp` 예제.

### 원문 대비 편차 (실측 근거, 중요)
1. **02는 A안으로 시작했다가 B안 변형으로 확정.** A안(NOACCESS 가드존) 그대로 두면 커널이 예외 배달용 CONTEXT를 못 밀어넣어 VEH 전에 즉사함을 실측. 최종: 가드존은 PAGE_GUARD 유지 + DeallocationStack은 예약 하단이 아니라 비상 밴드 상단(`pEmergencyTop_`) 설치. 예약 하단 설치는 커널이 가드 폴트를 직접 확장해 VEH가 안 불림을 실측으로 확인.
2. **03은 문서안(ExpandStack에서 TEB 갱신) + yield 동기화 병행.** 실측 결과 커널이 가드 폴트를 직접 확장하는 경우가 있어 `pStackLimit_`만 믿을 수 없으므로, yield 시점에 살아있는 TEB 값을 stack_에 동기화하고 resume이 그 값을 읽음. `Teb_StackLimitAfterGrowth` + `Growth_YieldSyncsLimit`로 감시.
3. **`std::exception_ptr` 소유권 함정 (신규 발견).** take 때 보관분을 풀어버리면 unwind 중 마지막 소유자가 사라져 객체가 유실(릭)됨을 3회 반복 실측으로 확인. 그래서 take는 소유권을 유지한 채 던지고, `CoClearPendingException()`으로 버리게 설계. 순수 왕복 대조 실험으로 무죄 입증 후 확정.

## E. 04 — EmergencyPages

### 문서 요약
오버플로우 가드를 치면 디스패치 공간이 없어 이중 폴트로 강제 종료. 사용자 `__except`나 덤프 코드가 돌지 못함.

### 수정 (before → after)
- 예약 아래에 비상 패드(`EmergencyPadPages()` = 전체의 1/4, 상한 4장. Mid/High 16KB, Low 4KB)를 RW 커밋. `pReserveBase_` 필드 추가 (해제는 여기서부터).
- 오버플로우 가드 1페이지 GUARD 유지. `pEmergencyTop_` = 예약 하단 + 1페이지. 일반 확장 하한 + DeallocationStack 설치값.
- `CoNoteStackOverflow()` (잡았다고 표시) + `CoMgr::ResetOverflow()`/`CoResetStackOverflow()` (rsp 기준으로 가드존 재설치) 추가.
- CoVEH 오버플로우 분기는 `overflowed_=true` + `STATUS_STACK_OVERFLOW` (NONCONTINUABLE 유지. 커널과 동일) 변환.

### 개선점
- 오버플로우가 잡을 수 있는 예외가 됨 (확립된 프레임에서 직접 찍으면 catch 확인). 표시·복구 API 제공.

### 검증
- gtest `Overflow_LayoutCheck` (패드 RW, 가드 GUARD, 크기), `Overflow_DirectTouchCaught` (catch + 표시 + 복구) 통과.
- jcr `06_Coroutine_04_Emergency.cpp` 예제.

### 원문 대비 편차 (실측 근거, 중요)
1. **NOACCESS 바닥안은 폐기.** RSP 추적형 하강(__chkstk)에서는 배달 push가 NOACCESS에 막혀 죽음을 실측. GUARD로 복원.
2. **커널이 성장을 다 먹음 (실측 확정).** TEB Base/Limit 교체 상태에서 가드 폴트는 커널이 조용히 확장해서 우리 VEH/ExpandStack이 안 불림 (`Diag_WhoExpands`: limit은 yield 동기화로 움직이고 guard는 그대로). 그래서 깊은 점진 하강(재귀)은 바닥에서 배달 공간 없이 AV로 죽을 수 있음. 잡히는 건 확립된 프레임에서의 직접 터치. 예제·주석에 한계 명시.
3. 비상 밴드 RW 사전 커밋안(문서 04 원안)은 위 이유로 패드 방식으로 변경. 덤프 스레드 분리(문서 15 연계)는 미적용.

## F. 15 — VEH 자체 방어

### 문서 요약
VEH 안에서 나는 폴트는 디버깅이 거의 불가. 가드 예산 초과, 플래그 고착, 오판, 파라미터 OOB, TLS 소멸 후 접근, 외부 VEH 간섭, 확장 실패 무시, 로깅 재귀, 배달 실패가 시나리오로 정리됨.

### 수정 (before → after)
- `s_inCoVEH` bool → `t_coVehDepth` 카운터 + `CoVehScope` RAII. 2중 초과면 오버플로우 확정.
- 정밀 범위 함수 (`CoIsGrowableGuard/CoIsOverflowGuard/CoIsOnStack`) 도입. 사용자 PAGE_GUARD·남의 스택 읽기·비실행 ctx는 손대지 않고 통과.
- `currentCtx_` 비어 있으면 주소 역조회로 보완. magic 불일치는 `__debugbreak`. 실행 중 상태가 아니면 통과.
- 확장 실패는 항상 오버플로우 확정 (조용히 넘기면 다음 페이지 AV).
- `CoMgr::t_alive_` + 소멸자 (TLS 소멸 후 매니저 접근 차단. Clear에서는 내리지 않음. Clear는 풀 비우기라 재사용되기 때문).
- `FreeCtx`에 실행 중 반납 assert. `CoOnAfterLaunch`에 Debug 가드존 커밋 검증 (가드 비트가 아니라 커밋 여부만 봄. 커널이 가드를 조용히 먹기 때문).
- `CO_VEH_PATH(__declspec(safebuffers))` + `noinline` + `noexcept` 적용. VEH 경로 로깅 금지 주석.
- Debug 전용 VEH 깊이 통계 (`CoVehStats` + `GetVehStats()`).

### 개선점
- VEH 오판·고착 경로 제거. 예산 실측 수단 확보.

### 검증
- gtest `Veh_ThreadExitDuringClear` (스레드 종료 무사), `Veh_StatsSmoke` (API 동작) 통과. 기존 18개 전부 통과로 회귀 없음 확인.
- jcr `06_Coroutine_15_Veh.cpp` 통계 출력 예제.

### 원문 대비 편차
- `CoExpandResult` enum 평가는 bool 유지. 실패 시 오버플로우 확정이라는 동작은 동일하게 구현됨.
- 덤프 스레드 분리(Config 전역 VEH 개조)는 범위 밖이라 미적용.
- 강제 재진입 테스트(`pageGuardCount_=1`)는 프로세스를 죽일 수 있어 자동 테스트에서 제외. 문서에만 근거 남김.

## 실측으로 뒤집힌 설계 판단 4건

1. **02 A안(NOACCESS) → B안 변형.** NOACCESS 가드존은 커널 배달 push 실패로 VEH 전 즉사. GUARD 유지 + Dealloc을 밴드 상단으로.
2. **exception_ptr 소유권.** take 때 풀면 unwind 중 유실(릭). 소유 유지 + 명시적 clear 설계로 변경.
3. **커널 성장 가로채기.** TEB 교체 상태에선 가드 폴트를 커널이 조용히 확장. 우리 ExpandStack은 백업 경로. yield 동기화로 정합성 유지.
4. **SUCCEED() 릭 오탐.** 구버전 gtest의 SUCCEED가 CRT 덤프에 잡힘. 테스트는 EXPECT_*만 사용.

## 성능 영향 (실측)

- `BM_Switch_Jc` 45.8ns → 48.5ns (+2.7ns, 약 6%). 원인은 resume 검사 1회 + MXCSR 4개. 문서 05 예측(2~4ns) 범위 안.

### 10. xchg LOCK 제거

```asm
; before (CoYield)
	lea     rbx,    FIN
	xchg    rbx,    [rax + OFFSET_COCTX_REGS + OFFSET_COREGS_RIP]  ; LOCK!

; after
	mov     rbx,    [rax + OFFSET_COCTX_REGS + OFFSET_COREGS_RIP]
	lea     r10,    FIN
	mov     [rax + OFFSET_COCTX_REGS + OFFSET_COREGS_RIP],  r10
```
- `movdqu` → `movaps` + `_padAlign_[8]` (xmm6_ 112로 16 정렬) + static_assert + AllocCtx 16정렬 assert.
- rbp `xchg rbx,rbp`는 레지스터 간이라 LOCK 없음. 대상 아님.
- 검증: obj 내 xchg 0개, movaps 20개. Switch 48.5 → 44.8ns. gtest 전 통과.

```cpp
// Coroutine.cpp
static thread_local std::exception_ptr t_coPendingException;

void CoEntry(CoContext* _pCtx) noexcept
{
	t_coPendingException = nullptr;	// 묵은 보관분 정리
	try { _pCtx->fn_(_pCtx); }
	catch (...)
	{
		t_coPendingException = std::current_exception();
		t_coLastError = coeException;
	}
}

bool CoTakePendingException()
{
	if (!t_coPendingException)
		return false;
	t_coLastError = coeNone;
	// 소유권을 유지한 채 던진다. 풀어버리면 unwind 중 유실(릭)됨. catch 뒤 clear.
	std::rethrow_exception(t_coPendingException);
	return true;
}

void CoClearPendingException()
{
	t_coPendingException = nullptr;
	t_coLastError = coeNone;
}
```

```cpp
{

	if (pCtx == nullptr || !pCtx->stack_.overflowed_)
		return false;
	CoStack& st = pCtx->stack_;
	char* rsp = (char*)_AddressOfReturnAddress();
	char* pNewLimit = (char*)(((uintptr_t)rsp & ~(uintptr_t)(CO_PAGE_SIZE - 1)) - CO_PAGE_SIZE);

	if (pNewGuard < st.pEmergencyTop_)
		return false;

		PAGE_READWRITE | PAGE_GUARD, &old))
		return false;

	st.pGuardLimit_ = pNewGuard;
	st.overflowed_  = false;
	__writegsqword(0x10, (_u64)pNewLimit);
```

```cpp
	DecayFn* pFn = dbg_new DecayFn(std::forward<Fn_>(_fn));
```
