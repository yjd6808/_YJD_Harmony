## 4. 핵심 클래스/시그니처

### `IoDefine.h` 요약

```cpp
using IoHandle = _u32;                       // 0 = InvalidIoHandle
enum IoState  { isNone, isPending, isOpening, isTransferring, isCompleted, isCancelled, isFailed };
enum IoError  { ieNone, ieInvalidUri, ieUnsupportedScheme, ieOpenFailed, ieReadFailed,
                 ieWriteFailed, ieHttpStatusFailed, ieMemoryLimit, ieCancelledByUser, ieShutdown };
struct IoErrorDetail { _s32 channelError_; _s32 httpStatus_; };   // R4: 손실 없음
using IoCallback = Action<const IoResult&>;
struct TransferPolicy { _s32 readUnit_; _s32 progressIntervalMs_; };
struct LoadOptions   { String baseAlias_; TransferPolicy policy_; };   // 요청 단위 오버라이드
```

### `IoResult.h` — 사용자 예제 그대로 동작
```cpp
struct IoHttpPart { _s32 status_; HttpHeaders headers_; MemoryStreamPtr body_; };
class IoResult {
public:
    IoHandle handle_; IoState state_; IoError error_; IoErrorDetail detail_;
    IoHttpPart http_;              // _r.http_.status_/headers_/body_
    MemoryStreamPtr data_;         // 메모리 목적지 결과
    bool IsSuccess() const { return error_ == ieNone; }
    MemoryStreamPtr TakeData();
    bool IsTaken() const;
};
```

### `IoDaemon` 조립 (단일 정의)
```cpp
class IoDaemon : NonCopyableNonMovable {
    PathResolver resolver_;                    // 1) 이름공간
    IoJobEngine  engine_;                      // 2) 공용 엔진
    FileService  files_{ resolver_, engine_ }; // 3a) 파일 창구
    HttpService  http_  { resolver_, engine_ }; // 3b) HTTP 창구
public:
    bool Initialize(const IoDaemonConfig& = {});
    PathResolver& Resolver() { return resolver_; }
    FileService&  Files()    { return files_; }
    HttpService&  Http()     { return http_; }
    IoState GetState(IoHandle) const;
    bool   GetProgress(IoHandle, OUT IoProgress&) const;   // 완료 후에도 링 캐시 응답
    bool   Cancel(IoHandle);
    void   CancelAll();
    int    GetActiveCount() const;
    void   GetActiveSnapshot(OUT Vector<IoProgress>&) const;
    void   Update();                                          // 메인스레드 통지 펌프
    void   SetListener(IIoListener*, bool _transferOwnership=false);
};
```

### `IoJobEngine` 핵심
- `Submit(Source, Dest, uri, policy, cb, isHttp) -> IoHandle` (워커 실행, `activeJobs_` 등록)
- `FailImmediate(err, uri, cb) -> IoHandle` (즉시 실패 큐 적재 — 조립 검증 실패)
- `RunSync(Source, Dest, uri, policy, isHttp) -> IoResultPtr` (접수 스레드 인라인 + `thread_local` 청크 버퍼)
- `Pump()` (진행 합삭 → 완료 큐 순차 통지)
- `Cancel(h)`: `TrySetState(pending→cancelled)` 선점, 아니면 `cancelRequested_` 협조 플래그

### `TransferJob::PumpTransferJob` — 유일한 복사 루프
```cpp
void PumpTransferJob(const TransferJobPtr& job, _byte* workBuf, _s32 workBufLen, const Atomic<bool>& shutdown) {
    if (!job->TrySetState(isPending, isOpening)) return;
    IoSourceInfo sinfo;
    if (!job->spSource_->Open(OUT sinfo)) { FailJob(job, source->GetLastError(), source->GetLastErrorDetail()); return; }
    // ... totalBytes_/spDest_::Open → state isTransferring
    // loop: shutdown/cancel → source->Read → dest->Write → transferredBytes_.Add
    // → source->Close → dest->Commit (or Abort)
    // → TakeResult() (메모리)
}
```

### `PathResolver` 핵심 API
- `Mount(alias, dir)` — 재호출 = 재바인딩 (`${exe}`, `${cwd}`, `${다른별칭}` 토큰, 8회 순환 가드)
- `Unmount`, `SetDefaultAlias`, `AddSearchDir`/`RemoveSearchDir` (priority 오름차순, priority 0 = 주 디렉토리)
- `Resolve(path)` / `Resolve(path, aliasOverride)` / `ResolveWritable(path)`
- `IsAbsolutePath`/`TryParseAlias`: 1글자 prefix는 드라이브 문자로 간주, 별칭은 2글자 이상 + `/` 다음
- 스냅샷 COW: `GetSnapshot()` 찰나 락 → 락프리 해석 (재바인딩 무오염)

## 9. 알려진 한계 / 후속 작업

1. **HttpDataSource 삭제됨** — 그 존재 이유(파일 로더에 HTTP를 꽂는 브리지) 자체가 해결됨. 대신 `daemon.Http().DownloadAsync(url, "save:/path")`로 통일.
2. **hcHeadersReceived 공개 옵션 삭제** — 헤더만 받고 스트리밍하려면 `HttpService::Send(req, false)` 사용.
3. **자동 `progress_/completed_/cancelled_/failed_` 합산 리스너 매크로** — 사용자 코드에서 IIoListener 직접 구현 (4개 가상함수, 기본 빈 본문).
4. **HttpClient의 별칭 처리** — `HttpService::Download(url, "save:/path")`만 PathResolver 사용. URL 본체(`http://...`)는 해석하지 않음 (의도적).
