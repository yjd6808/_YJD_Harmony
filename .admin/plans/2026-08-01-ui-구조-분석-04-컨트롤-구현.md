# SGCL UI 전체 구조 분석 - 04. 컨트롤 구현 (UIElement 파생 컨트롤)

> 작성일: 2026-08-01
> 위치: `Projects/sgcl/Classes/sgcl/Game/UI/`
> 컨트롤은 UIGroup 파생이 아닌 **UIElement 직접 파생**이며, 텍스처 모드가 `SGA`(레거시)/`THEME`(런타임 베이크) 두 가지로 동작한다.
> 공통 규칙: `Load()`에서 `LoadLegacy()`(SGA) 성공 시 SGA 모드, 실패 시 `BuildThemeVisuals()`(THEME 모드)로 폴백. `Unload()`에서 리소스 해제.

## 1. 공통 텍스처 로드 규칙 (모든 컨트롤)

```
Load()                        (e.g. UIButton.cpp:250-263)
 ├─ mode = eUITextureModeSGA 로 시도
 │    LoadLegacy() 성공(≥1 스프라이트) → SGA 모드 확정, BuildThemeVisuals 호출 안 함
 │    실패(0 스프라이트)          → THEME 모드로 폴백
 ├─ BuildThemeVisuals()  (THEME 모드)
 │    - UIAssetKey 시맨틱별로 resolver_.Resolve(타입, state, theme) → styleHash
 │    - themeBinding_.BindScale9 / BindFixed 로 TextureSet에서 스프라이트 획득
 │    - 마지막에 setContentSize(uiSize_) 복구 (※ setSpriteFrame이 크기 리셋)
 │    - 변형을 위해 원본 스프라이트 컬러를 반투명하게 두지 않고 RefreshThemeVisuals() 유지
 └─ OnThemeStyleChanged / RefreshThemeVisuals(): 스튜디오 편집 시 재해석+재바인딩
Unload()                       (e.g. UIButton.cpp:382-405)
 └─ themeBinding_.Clear() + 스프라이트 해제, UIProgressBar는 자식 노드 삭제
```

## 10. 레거시 SGA 모드 관련 주의점

- `LoadLegacy()` 는 `ImageManager`에서 `eMax` 장을 잘라 로드 (예: UIButton은 eMax=9장)
- **SGA 성공 시 THEME 시각요소는 만들지 않는다** — 모드 혼용 금지
- 이미지 파일이 없는 환경(신규 리소스 폴더)에선 전부 THEME 모드로 동작 → 빌드 후 UI가 안 나오면 `mode` 로그로 SGA/THEME 확인
- THEME 모드의 `RefreshThemeVisuals` 는 `UIStyleOverride` 지역 오버라이드가 있으면 재해석 → 스튜디오 편집 실시간 반영
