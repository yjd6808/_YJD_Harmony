## 1. 개발 규칙 (작업 중 상시 준수)

### 1-1. 제1규칙 — 문자열/TCHAR (모든 변환 작업의 최우선 기준)

1. jc 포함 전 프로젝트의 문자열 처리는 프로젝트 설정(Unicode/MultiByte)을 따라가는 `jc::String` / `const jc::_char*` / `_T()` 리터럴 기반이다. 양쪽 설정에서 분기 없이 컴파일·동작해야 한다.
2. narrow 고정은 데이터/API 자체가 narrow인 경우에만 허용한다: CRT 모드 문자열, MBCS 경로 narrow 오버로드, `_Extern` C-ABI, 파일 내용(바이트), 와이어/프로토콜 narrow 바이트, narrow 전용 외부 API 인자. 이때도 `StringUtilA` 등 명시 타입 + 경계 변환(`StringConvert`)을 쓴다.
3. WinAPI는 제네릭으로 호출한다 (`FormatMessage`/`FindFirstFile` 등, A/W 접미 직접 호출 금지). W 전용 API(WinHTTP 등)는 `String` 직접 전달이 원칙이며, MultiByte에서 깨지는 줄은 해당 줄에 한해 인라인 분기한다 (변환 헬퍼 신설 금지).
4. 인코딩 경계는 한 곳에서만 넘는다. narrow 리터럴=UTF-8, OS narrow=ANSI 로 보고, UTF-8↔`String`은 `FromUtf8`/`ToUtf8`, ANSI↔`String`은 `FromAnsi`/`ToAnsi`를 쓴다.
5. 새 `const char*` 파라미터/멤버를 만들지 않는다 (2항의 narrow 경계 제외).

### 1-2. 빌드 검증 규칙

- 모든 빌드 작업은 아래 2경로 스크립트로 Unicode/MultiByte **양쪽 성공**을 검증한다.
  - `Scripts\BuildProject\{프로젝트명}.bat` (Unicode)
  - `Scripts\BuildProject-Multibyte\{프로젝트명}.bat` (내부 `Build.ps1 -Multibyte` → `/p:CharacterSet=MultiByte`)
- 문자셋 전환 시 `-Rebuild` 권장 (Intermediate 캐시 혼용 방지).
- **주의**: `Output\x64\Debug\`와 `Intermediate\`가 문자셋 공유라 MB 빌드가 Unicode 산출물을 덮어쓴다. MB 검증 후에는 Unicode로 다시 빌드해서 트리를 기본 상태로 복구한다.

### 1-3. 세션 규칙 R9 (이번 전환 작업 세션 한정 — 원 플랜 §6-1에 R9로 기록)

## 5. 함정 / 노하우 (재작업 방지)

1. `StaticString::CopyFrom` 1인자 배열 오버로드는 삭제된 상태 — 배열 인자 함정 때문에. 다시 만들지 말 것
2. gtest 1.8.1: `TYPED_TEST`는 `TYPED_TEST_CASE` + 파일 상단 `typedef ::testing::Types<char,wchar_t>` 필요
3. 새 `.cpp`를 프로젝트에 추가하면 `.vcxproj` `ClCompile` 등록 확인 (`StringConvert.cpp` 누락 전례)
4. jc `assert` (`jc_assert_msg`) 발동 시 프로세스가 EXIT 3으로 종료되고 gtest 요약이 안 찍힘 — 멈춘 지점의 바로 앞 `[ RUN ]`이 범인
5. gtest 로그는 UTF-16으로 떨어짐. 분석 시 `utf-16`으로 읽어 `utf-8`로 변환 후 grep (`$env:TEMP\gtest_*.txt` 활용 전례)
   - 검증 절차 (아래 §6-2 with 동일): exe 출력을 파일로 리다이렉트 → UTF-16→UTF-8 변환 → 집계.
     합격 기준 4개 모두 충족: ① 프로세스 EXIT 0 ② `RUN` 수 == `OK` 수 (기준 시점 415) ③ `FAILED` 0건 ④ `[ PASSED ] 415 tests.` 존재.
     `RUN`은 있는데 `OK`/`FAILED`가 없으면 해당 테스트에서 assert·크래시로 중단된 것 → 멈춘 지점 바로 앞 `[ RUN ]`부터 원인 추적 (함정 4번).
     `OK`만 세지 말고 `RUN` 수도 함께 셀 것 (중단 시 `OK`만 보면 통과처럼 보임)
6. CRT leak 덤프 (`Dumping objects`, `normal block`)는 테스트 실패가 아님. `FAILED` 카운트로 판단
7. `ThreadLocal<int>` 해쉬맵 초기화 로그 등 한글 로그가 섞여 있어 파싱 시 인코딩 주의
8. `Console.h`처럼 헤더에 `printf`/`putchar`가 남아 있으면 MultiByte 빌드는 통과해도 Unicode에서 깨짐 — 양쪽 "실행"까지는 아니더라도 양쪽 "빌드"는 필수
