# size 템플릿 구현 — 계획

- 작성일: 2026-08-22
- 작업 이름: size-템플릿-구현
- 요청: jc/Math.h의 size 구조체 유무 확인, 없으면 개발. size<T> 템플릿 + using size_f=_f32, size_u=_u32, 내부 operator 다양하게 구현. cc::size(cocos2d-x) 충돌 가능성 고려. 각 프로젝트별 배치파일 충돌 확인 및 수정.

---

## 1. 현재 상태 (조사 완료)

### 1-1. jc/Math.h 기존 size

- 위치: Math.h:226 `struct size { _f32 width_, height_; ... }` — 비템플릿, _f32 고정
- 사용처: `rect` (pos_+size_), vec2 변환, 10여 곳
- 기존 operator: +, -, *(_f32), /(_f32), +=, -=, *=, ==, !=, Area, IsZero, IsPositive, ToVec2, FromVec2, Zero/One, scalar*size
- 반환: FloatEqual 기반 비교

### 1-2. 충돌 조사

- jc: `jc::size` (lowercase) in namespace jc
- cocos2d-x: `cocos2d::Size` (PascalCase) + alias `cc::Size`? 실제 cocos는 `cocos2d::Size` 대문자 S. lowercase `size`와는 C++ case-sensitive상 직접 충돌 없음.
- 다만 sgcl이 `using namespace jc; using namespace cocos2d;` 동시 사용 시, `size` vs `Size`는 구분되나, `SIZE` (Windows tagSIZE) 매크로와 혼동 가능. Windows는 `SIZE` 대문자 전체.
- std::size(C++17 함수)와는 타입 vs 함수로 구분되나, unqualified `size` 사용 시 ADL 혼선 가능 — `jc::size_f` 명시 권장.
- 대책: jc::size 템플릿은 `jc` 네임스페이스 내부에만 정의, 전역 using 금지 문서화. 하위 호환용 `using size = size_f;`는 제공하지 않음(템플릿명과 충돌) — 기존 `size` 사용처는 `size_f`로 마이그레이션.

### 1-3. 배치 파일 목록

- `Scripts/BuildProject/*.bat`: jc, jcr, jc_gtest, jnet, sg, sgf, sgfr, sgcl, sge, sgs_* 등 20+개
- sgcl은 cocos2d-x 기반 → libcocos2d.dll 사전 빌드 필요 (`ThirdParty/Cocos2d-x/Output/...`)
- 검증 대상: jc, sgf, sgfr 우선 (sgcl은 cocos 의존성으로 선택적)

## 2. 설계

### 2-1. Math.h size<T> 템플릿

```cpp
template <typename T>
struct size {
  T width, height;
  constexpr size() : width(0), height(0) {}
  constexpr size(T w, T h) : width(w), height(h) {}
  // vec2 변환은 size_f에만: template<> specialization 또는 enable_if
  // generic: size(const vec2&) -> size_f 전용, size_u는 explicit
  // width/height 타입 일반화

  // 사칙연산 (동타입)
  constexpr size operator+(const size& o) const { return {width+o.width, height+o.height}; }
  constexpr size operator-(const size& o) const { return {width-o.width, height-o.height}; }
  constexpr size operator*(T s) const { return {width*s, height*s}; }
  constexpr size operator/(T s) const { return {width/s, height/s}; }
  constexpr size operator*(const size& o) const { return {width*o.width, height*o.height}; } // element-wise (선택)
  constexpr size operator/(const size& o) const { return {width/o.width, height/o.height}; }

  size& operator+=(const size& o) { width+=o.width; height+=o.height; return *this; }
  size& operator-=(const size& o) { width-=o.width; height-=o.height; return *this; }
  size& operator*=(T s) { width*=s; height*=s; return *this; }
  size& operator/=(T s) { width/=s; height/=s; return *this; }

  // 비교: 정수 exact, 부동소수 epsilon
  bool operator==(const size& o) const { if constexpr (std::is_floating_point_v<T>) return FloatEqual(width,o.width) && FloatEqual(height,o.height); else return width==o.width && height==o.height; }
  bool operator!=(const size& o) const { return !(*this==o); }

  // 유틸
  T Area() const { return width*height; }
  bool IsZero() const { ... } // float epsilon
  bool IsEmpty() const { return IsZero(); }
  bool IsPositive() const { return width>0 && height>0; }
  vec2 ToVec2() const requires std::is_same_v<T,_f32> { return vec2(width,height); } // or generic
  static constexpr size Zero() { return {0,0}; }
  static constexpr size One() { return {1,1}; }

  // 변환
  template<typename U> explicit operator size<U>() const { return {static_cast<U>(width), static_cast<U>(height)}; }
};

using size_f = size<_f32>;
using size_u = size<_u32>;
using size_i = size<_s32>; // 편의를 위해 추가
// 하위 호환: 기존 `size`는 size_f로 alias 불가(템플릿명 충돌) → rect 등 기존 사용처를 size_f로 변경
```

- scalar * size: `template<typename T> constexpr size<T> operator*(T s, const size<T>& sz) { return sz*s; }`
- rect: `size size_;` → `size_f size_;` (또는 `size<_f32>`)
- 문서 주석: sgcl에서 `jc::size_f` 명시 사용 권장, `using namespace cocos2d; using namespace jc;` 동시 사용 금지

### 2-2. 기존 size 유지 여부

- 기존 `struct size { _f32 ... }` 제거 → 템플릿으로 교체. `rect` 등 5곳 수정 필요.
- 검색으로 `size` 사용처 전수 교체 검증.

### 2-3. 배치파일 충돌 확인

- 각 `.bat` 실행: `Scripts\BuildProject\jc.bat -C Debug -P x64` 등
- 예상 충돌: `size`가 Windows `SIZE` 매크로와? 없음. `std::size`와? 네임스페이스 분리로 안전.
- sgcl 빌드는 cocos 미빌드 시 실패 가능 — 로그 확인 후 필요 시 `Scripts\Build-Cocos.bat` 선행
