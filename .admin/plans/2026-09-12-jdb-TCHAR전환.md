# jdb TCHAR 전환 (B안, 2026-09-12)

> 모체: `.admin/plans/2026-09-12-TCHAR전환-작업현황-인계.md` §4-4
> 계기: sgs_auth MB 첫 빌드에서 jdb 구형 shim(`IDatabase.h:73`) C2679 1건 실패
> 사용자 결정: A-API 고정 해제, MySQL은 Unicode 예외처리 유지, jdb 전체 TCHAR 기반 동작

## 1. 제1규칙 적용

- narrow 잔류 허용은 L5 드라이버 C-ABI 경계뿐이다. 그 외부는 `_char`/`String`/`_T()`로 일원화한다.
- ODBC는 제네릭 매크로(`SQLExecDirect` 등) + `SQLTCHAR`로 호출한다 (A/W 직접 호출 금지).
- MySQL은 `#ifndef _UNICODE` 제외 + `jc_assert_msg` 후 실패 반환 패턴을 유지한다 (28번).

## 2. 층별 범위

- L1 표면: `jdb/IDatabase.h` shim(`const char*`→`const _char*`, `StringView` 소유 연결),
  `sgs/QueryDefine_AUTH.h` `Script` 3곳(`const _char*` + `_T()`)
- L2 식별자: `jdb/QueryDefine.h` `BindField` 2종, `REGISTER_QRY_STRUCT` 호출부 컬럼 리터럴 `_T()`화,
  `jdb/StatementType.h` `StatementName` → `const _char*` + `%hs`→`%s`
- L3 인터페이스: `jdb/IQuery.h` 필드명 4종(`GetColIndex`/`GetRawString`/`GetDateTime`/`GetNumber`) → `const _char*`,
  `MySQL/MysqlQuery.h` + `SQLServer/SqlServerQuery.h` 오버라이드 일치 수정.
  단 `GetRawString` 반환형(드라이버 원시 바이트)은 읽기 경로 측량 후 결정한다.
- L4 빌더: 양 `StatementBuilder.h` `Setter<const char*>` 3종 → `const _char*`, `FromUtf8` 래핑 정리
- L5 드라이버: `SqlServerConnection.cpp`(`SQLDriverConnectA` 1곳 + `SQLExecDirectA` 1곳),
  `SqlServerQuery.cpp`(`SQLExecDirectA` 5곳) → 제네릭 + `SQLTCHAR*`, `ToAnsi` 제거 후 `String` 직접 전달.
  MySQL 구현(`MySQL/*.cpp`)은 MB 전용이라 손대지 않는다.
