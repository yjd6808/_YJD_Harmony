## 2. 해소 상세

### 해소 상세 — A-1 (2D 메시 GPU 리소스 미사용)

- **어떻게 수정했나**
  - `Renderer2D::DrawMesh` 전면 교체: CPU 미러 읽기 → 배칭(`PushTriangles`) 경로를 **즉시 드로우**로 변경
    1. `ApplyFrameStates()` — 셰이더 + b0(뷰프로젝션) 장착
    2. `_pMesh->Bind(context)` — VB/IB/InputLayout/토폴로지 장착 (GPU 리소스 사용)
    3. 텍스처 해석 (기존 로직 유지) + `pTexture->Bind(pDevice_, 0)`
    4. b2(틴트) 갱신 → 5. b1(월드 행렬) 갱신 → 6. `_pMesh->Draw(context)` (DrawIndexed)
  - `Mesh::Build2DPrimitive`: CPU 미러(`cpuVertices_/cpuIndices_`) 저장 루프 제거 — 임시 인덱스 배열로 GPU 초기화만 수행.
  - `Mesh`에서 StaticLevel/bake 캐시(`bakedVertices_/bakedIndices_`) 전부 제거 — GPU 메시가 유일한 그리기 데이터.
- **왜 해소됐나**: Renderer3D::Draw와 동일한 4단계 구조로 2D/3D 메시 파이프라인을 통일 — A-1의 근거("GPU mesh는 100% 미사용")가 사라졌다. 2D 메시의 GPU VB/IB/InputLayout은 이제 모든 프레임 실제 드로우에 사용된다.
- **부수 효과**: 메시 배칭 상실 → 오브젝트당 1콜 (드로우콜 증가는 인스턴싱 C-3으로 추후 극복 — 계획 수용).

### 해소 상세 — C-2 (2D DrawMesh CPU 정점 변환 → GPU 변환)

- **어떻게 수정했나**
  - `Renderer2D` 내장 셰이더(`s_szSpriteShader`)에 `ConstantBufferObject(b1) world_` + `ConstantBufferMaterial(b2) baseColor_` 추가.
  - VS: `output.position_ = mul(mul(float4(pos,1), world_), viewProjection_)` — GPU에서 월드 변환.
  - PS: `texture × input.color_ × baseColor_` — 틴트를 b2로 이관 (기존 CPU 틴트 곱 제거).
  - `DrawMesh`: `_world.TransformPoint` 루프와 `meshScratch_` 제거, 월드 행렬 1개만 b1로 업로드.
  - 배치 경로(사각형/원/스프라이트/DeclareStatic)는 CPU 변환 유지 — `Flush`가 b1=단위행렬, b2=흰색을 장착해 기존 셰이더 동작과 수학적으로 동일 보존.
- **왜 해소됐나**: 유니티/언리얼 표준 방식 — 정점은 로컬 공간 불변, 월드 정보는 상수버퍼로 전달. CPU 부하가 "정점 수 × 오브젝트 수"에서 "행렬 1개 업로드"로 축소. 2D/3D 메시가 동일 파이프라인으로 통일.
- **남은 것**: 비메시 2D(배치 경로)의 CPU 변환은 UI/정적 콘텐츠 위치로 의도적 유지 (uGUI/Slate와 동일). 텍스처 아틀라스(C-4)는 별도 항목으로 잔여.

### 해소 상세 — B-5 (Transform setter 즉시 재귀 dirty 전파)

- **어떻게 수정했나**
  - setter(`SetLocalPosition/Scale/Rotation*`)와 `SetParent`가 `worldDirty_ = true` + 자식 서브트리 전체 재귀 전파(`PropagateTransformDirtyRecursive`)를 하던 것을, **변경 stamp 방식**으로 교체.
  - `Transform.cpp`에 파일 정적 전역 시계 `g_transformStamp` 추가. 노드마다 `dirtyStamp_`(내 변경 시각) / `computedStamp_`(마지막 계산 시각) 보관.
  - `SetDirty()`: `dirtyStamp_ = ++g_transformStamp;` — 자기만 갱신, 전파 없음. (setter O(1))
  - `GetWorldMatrix()`: 부모 체인을 올라가며 최신 stamp를 찾아 `computedStamp_`보다 새면 재계산. (조회 O(깊이))
  - `GameObject::PropagateTransformDirty / PropagateTransformDirtyRecursive` 삭제, `worldDirty_` 멤버 삭제.
- **왜 해소됐나**: "setter 호출당 O(서브트리) 재귀"가 "setter O(1)"으로 바뀌었다. 변경된 노드의 자손만 (조회 시점에) 재계산된다. **정확성**: 부모가 먼저 재계산해도 stamp는 유지되므로, 자식이 나중에 조회해도 "부모가 이후 바뀌었음"을 감지한다 (즉시 전파와 동일 결과).
- **부수 효과**: `pOwner_` 멤버가 미사용이 되어 함께 제거. 생성 시 stamp를 부여해 최초 조회에 반드시 계산되도록 보장.
- **남은 것**: A-9(`GetWorldPosition`의 const_cast)는 별도 항목으로 잔여 — lazy와 무관.

### 해소 상세 — B-6 (Camera::ViewProjection 매 호출 재계산)

- **어떻게 수정했나**
  - `Camera.h`: `mutable mat4 vp_` 캐시 + `mutable bool vpDirty_` 플래그. `ViewProjection()`은 dirty일 때만 `View() * Projection()` 재계산. `InvalidateViewProjection()` 공개.
  - `Camera2D::Rebuild2D()` 끝에 `InvalidateViewProjection()` 호출 — 모든 2D 파라미터 변경(SetOrthographic2D/SetPosition2D/SetZoom)이 Rebuild2D로 수렴.
  - `Camera3D::Rebuild3D()` 끝에 동일 호출 — SetLookAt/Orbit/Dolly/Pan/Move* 전부 Rebuild3D 경유. `SetPerspective`는 projection_을 직접 설정하지만 Rebuild3D를 호출하므로 함께 커버.
- **왜 해소됐나**: 뷰/투영이 바뀌지 않으면 합성 곱셈이 1회만 수행된다. BeginScene당 1회 호출이라 실질 이득은 적지만, 다중 카메라/분할 화면에서 호출이 늘어도 캐시가 흡수한다.
- **남은 것**: 없음.

### 해소 상세 — B-7 (ResourceMgr::RemovePathEntry 선형 탐색)

- **어떻게 수정했나**
  - `ResourceBase`에 `String path_` 멤버 + `GetPath()/SetPath()` 추가. (모든 리소스는 ResourceBase 파생 — 기존 `static_cast<ResourceBase*>` 패턴과 일치)
  - `Add(IResource*, StringView _path)`가 등록 시 리소스에 경로를 보관(`SetPath`).
  - `RemovePathEntry`: `pathIndex_` 전체 ForEach 선형 탐색 제거 → `Find(_key)`로 리소스를 얻고 `GetPath()`로 바로 `pathIndex_.Remove(path)`. (Remove()가 리소스 삭제 **전에** 호출하므로 Find 가능 — `ResourceMgr.cpp:197`)
- **왜 해소됐나**: 경로는 더 이상 "외부 맵의 별칭"이 아니라 **리소스 자신의 속성**이다. 역방향 인덱스가 불필요해져 탐색이 O(리소스 수) → O(1). `pathIndex_`는 중복 로드 방지용 정방향 검색(FindKeyByPath)으로만 사용.
- **남은 것**: 없음.

### 해소 상세 — B-1 (상태 캐시 불일치, P0) + A-5/A-6 (중복 상태 설정 흡수)

- **어떻게 수정했나**
  - **1단계 — GraphicContext에 Raw 오버로드 4종 추가** (핸들 버전과 동일한 캐시 필드 공유):
    `SetSamplerRaw(ShaderStage, slot, ID3D11SamplerState*)`, `SetRasterizerStateRaw(ID3D11RasterizerState*)`, `SetBlendStateRaw(ID3D11BlendState*)`, `SetDepthStencilStateRaw(ID3D11DepthStencilState*)`.
  - **2단계 — GraphicDevice 직접 OMSet 4곳을 캐시 경유로 교체** (시그니처 유지 — 호출부 무변경):
    `SetDepthTest` → `context_.SetDepthStencilStateRaw(states_.GetDepthState(...))`, `SetBlendMode` → `context_.SetBlendStateRaw(states_.GetBlendState(...))` (`SetAlphaBlending`은 SetBlendMode 경유 — 자동 커버), `SetSampler` → `context_.SetSamplerRaw(ssPixel, ...)`, `ApplyRasterizerState` → `context_.SetRasterizerStateRaw(states_.GetRasterizerState(...))`.
  - **3단계 — 프레임 경계 캐시 무효화**: `BeginFrame(Window*)`와 구버전 `BeginFrame(color)` 시작부에 `context_.InvalidateCache()` 1회.
- **왜 해소됐나**: "캐시를 우회하는 직접 OMSet 경로"가 **존재 자체로 사라졌다**. `Material::Bind`(핸들 오버로드)와 `Renderer2D/3D` Flush(디바이스 API → Raw 오버로드)가 **같은 캐시 필드를 읽고 쓰므로** "기억(캐시)과 실제(D3D) 어긋남"이 구조적으로 불가능해졌다. 프레임 경계 무효화는 외부 코드(튜토리얼 등)가 컨텍스트를 직접 건드려도 1프레임 안에서만 영향이 머물게 하는 방어막.
- **부수 효과**: A-5/A-6(상태 중복 설정)이 **자동 해소** — Flush마다의 재설정이 캐시 스킵으로 1회만 실제 호출된다.
- **위험 (수용)**: 튜토리얼 23의 `skippedCallCount_` 집계 변화 — 매 프레임 첫 바인딩이 실제 호출로 집계 (정답 쪽으로 변화).
- **남은 것**: 없음 (B-3은 별도 항목으로 이 문서에서 해소 처리됨).

### 해소 상세 — B-3 (Material 상태 객체 비공유) + C-5 (재질 전환 재바인드 흡수)

- **어떻게 수정했나**
  - `Material.h`: `RasterizerState rasterizer_/BlendState blend_/DepthStencilState depth_/SamplerState sampler_` 멤버 4종 제거 → **설정 키 멤버 8개**로 교체
    (`blendMode_/depthMode_/cullMode_/fillMode_/frontFace_/filter_/addrU_/addrV_` — 기본값은 기존 PipelineState 핸들 기본값과 동일). `PipelineState.h` include 제거, Getter 4종 제거(외부 사용처 없음 확인).
  - `Material.cpp`:
    - `Initialize`: 상태 객체 생성 4개 제거 — `pDevice_` 저장 + `constantBuffer_.Create`만.
    - setter 4종: 키만 갱신(O(1), 객체 생성 없음), `pDevice_` assert 유지(Initialize 필수 계약 보존), 반환 true.
    - `Bind`: `pDevice_->States()`(RenderStates 풀)에서 조회 → `SetBlendStateRaw/SetDepthStencilStateRaw/SetRasterizerStateRaw/SetSamplerRaw`로 바인딩 (B-1의 Raw 오버로드 활용).
- **왜 해소됐나**: 같은 설정의 재질 N개가 각자 D3D 객체를 만들던 것을 풀의 객체 1개를 공유하도록 바꿨다. 풀은 조합별 1개만 생성하는 지연 생성 캐시이므로 **같은 설정 = 항상 같은 포인터** → GraphicContext의 포인터 비교 캐시가 히트 → 재질 전환에도 상태 재바인드가 사라진다 (C-5 자동 해소). 상태 객체 수명이 디바이스 수명으로 승격되어 수명 정책도 단순해졌다.
- **부수 효과**: C-5 해소. Material이 더 이상 D3D 객체를 만들지 않으므로 Initialize의 실패 경로도 줄었다.
- **위험 (수용)**: 없음 — setter/Initialize 시그니처 유지로 튜토리얼 20 등 호출부 무변경 (빌드 검증 완료).
- **남은 것**: 없음.

### 해소 상세 — A-9 (Transform::GetWorldPosition의 const_cast)

- **어떻게 수정했나**
  - `Transform.h`: `GetWorldPosition()/GetWorldPosition2D()`의 `const` 제거 — "캐시를 갱신하는 조회는 non-const다"가 정직한 계약이라는 주석 추가.
  - `Transform.cpp`: `const_cast<Transform*>(this)` 경유 호출 2곳 제거, 그냥 `GetWorldMatrix()` 호출로 단순화 (본문 로직 무변경).
- **왜 해소됐나**: `GetWorldPosition`은 실제로 lazy 캐시(`world_`)를 갱신한다. const는 "상태를 바꾸지 않는다"는 약속인데 이 메서드에겐 애초에 틀린 약속이었고, 꼼수(const_cast)나 우회 장치(mutable) 대신 **약속 자체를 진실과 일치**시키는 것이 가장 단순하다. 안전 근거(재검증): ① 두 메서드의 사용처 0개 ② sgf/sgfr 전체에 const Transform/const GameObject 수신부 0개 ③ `GameObject::GetTransform()`이 const 메서드이면서 non-const `Transform*`를 반환하는 기존 관례(`GameObject.h:91`) — 미래에 const Transform 요구가 발생할 가능성도 매우 낮아 YAGNI로 판단.
- **위험**: 없음 — 사용처 0개. const 반환을 기대하던 외부 코드가 있다면 컴파일 에러로 즉시 검출 (현재 없음, 빌드 검증 완료).
- **남은 것**: 없음.
