# 함수 구분자 설명주석 통일 (jc/sgf/sgfr)

## 목표

1. `coding-conventions_cpp.md`의 "함수 시각적 구분자" 절에 설명 주석 스타일을 보강한다.
2. `jc`/`sgf`/`sgfr` `.cpp` 파일의 구분자를 전수 변환한다.
3. 나머지 컨벤션(네이밍/Allman/virtual/탭 등)을 검사하고 보고한다.
4. `jc`/`sgf`/`sgfr` 빌드로 검증한다.

## 확정된 규칙 (사용자 확인済)

- 설명 있음: 상단 구분자 + `// : 설명` + 하단 구분자 + 빈 줄 없이 바로 함수.
- 설명 없음: 단일 구분자 1줄 + 빈 줄 없이 바로 함수.
- 설명줄은 `// : ` 리터럴(콜론+공백) 강제. 기존 `// 설명`은 콜론 추가.
- 구분자 길이는 기존 규칙 유지 (`90 - 들여쓰기×4`). 예시의 13개는 약식 표기.
- 적용 범위: `.cpp`만. `.h`/`.inl`은 제외.
- 하단 구분자 누락분: sgf 196곳, sgfr 78곳, jc 4곳 (.cpp 기준 추정치).
- 일괄 수정 승인済 (AGENTS.md 5파일 초과 확인 절차 완료).

## 절차

1. 컨벤션 문서 수정.
2. Python 스크립트로 `.cpp` 전수 변환 (dry-run → 적용 → diff 확인).
   - 단일 구분자+설명 → 하단 구분자 삽입 + 콜론 정규화.
   - 샌드위치済 → 콜론 정규화 + 하단 빈 줄 제거.
   - 섹션 헤더(설명 뒤 빈 줄 + 구분자)도 샌드위치로 통일.
   - `#` 전처리문 바로 앞 설명은 하단 구분자 삽입 제외, 콜론만 정규화.
   - 원본 인코딩(BOM 유무)/개행(CRLF/LF) 보존.
3. 전체 컨벤션 검사 스크립트 실행 후 결과 보고.
4. `jc.bat` / `sgf.bat` / `sgfr.bat` (`-C Debug -P x64`) 빌드.

## 검증

- `git diff --stat`으로 변경 범위 확인.
- 변환 스크립트 재실행 시 잔여 위반 0건.
- 3개 프로젝트 빌드 통과.
