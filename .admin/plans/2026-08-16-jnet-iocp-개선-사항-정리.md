## 1. 개요

`jnet` 라이브러리 전체 분석 결과, **확실한 버그 6건**, **동시성/안정성 위험 10건**, **성능 개선 6건**, **기능 누락 7건**, **구조/리팩토링 8건**, **테스트 부재 2건** 을 발견했다.
우선순위는 [중요도 ★★★(치명) / ★★(중요) / ★(개선)] 로 표기한다.

## 2. 버그 (확실한 결함)

### 2-1. `StreamBuffer::Read` readPos 오염 — ★★ (재검증: 사용처 없음 → 잠복 버그)
- 위치: `Buffer/StreamBuffer.h:62`
- `readPos_ += sizeof(sizeof(T));` → `sizeof(size_t)` = 8 (x64) 이 더해진다.
- 재검증 결과: **현재 코드베이스 어디에도 `StreamBuffer::Read` 호출처가 없어 즉시 영향은 없음.** 하지만 잠복 버그이므로 수정 필요.
- 수정: `readPos_ += sizeof(T);`

### 2-2. `StreamBuffer::GetWriteableSource` 잘못된 오프셋 — ★★ (재검증: 사용처 없음 → 잠복 버그)
- 위치: `Buffer/StreamBuffer.h:205-208`
- `buffer_ + readPos_` 반환 → `writePos_` 여야 한다. (현재 호출처 없음 — 잠복)

### 2-3. `RecvedPacket::Clone` 헤더 미복사 + 페이로드 위치 오류 — ★★★ (확정)
- 위치: `Packet/Packet.cpp:35-41`
- `CopyUnsafe(pCopy, pRead, payloadLen_)` : (1) 패킷 헤더를 복사하지 않고, (2) 페이로드를 할당 시작부(헤더 영역)에 복사하며, (3) 끝부분은 미초기화 상태로 남는다.
- 수정: `CopyUnsafe(pCopy, this, PACKET_HEADER_SIZE + payloadLen_)`

### 2-4. `SocketOption::SetBroadcastEnabled` 잘못된 옵션 — ★★ (확정)
- 위치: `Socket.cpp:534-538`
- `SO_SNDBUF`에 BOOL을 설정 → **`SO_BROADCAST`** 여야 한다. (UDP 브로드캐스트 불가)

### 2-5. `PacketParser` 잘못된 패킷 수신 시 재동기화 불가 — ★★ (재검증: 문구 수정)
- 위치: `Packet/PacketParser.cpp:59-86`
- 매직넘버/타입/길이 불일치 시 `ResetPosition()`(전체 버퍼 폐기) + break. 이후 수신은 처음부터 다시 파싱하므로, **상대가 계속 오염 데이터를 보내면 세션이 끊기지 않고 매 수신마다 오류가 반복되며 정상 패킷도 함께 유실**된다.
- 재검증: 단일 호출 내 "무한 루프"는 아니므로 기존 "무한 재파싱" 표현을 수정. 핵심 문제는 **Disconnect(또는 명시적 스킵 정책)가 없다는 것**.
- 수정: 오류 카운트 누적 후 세션 Disconnect 또는 수신 버퍼 스킵 정책 도입.

### 2-6. `TcpServer::Start` 실패 경로 세션 누수 — ★★ (확정)
- 위치: `Host/TcpServer.cpp:252-268`
- `AcceptAsync()` 실패한 세션은 `pSessionContainer_->Add()` 전이라 컨테이너에 없고 `delete` 되지 않는다. (생성 후 실패 시 즉시 정리 필요)

## 3. 동시성/안정성 위험

### 3-1. 세션 재사용 vs `TcpServer::Stop` UAF Race — ★★★ (재검증: 핵심 시나리오 재작성)
- 위치: `Host/TcpServer.cpp:45-69` (SessionDisconnected 재사용), `Host/TcpServer.cpp:280-311` (Stop)
- **실제 race 시나리오**: 워커 스레드가 `SessionDisconnected`에서 `state_ != eListening` 체크(55행)를 **통과한 직후**, 유저 스레드가 `Stop()` → `DisconnectAll()` + `Clear()`로 세션을 `delete` → 워커가 `_pSession->Initialize()`(62행)를 호출 → **UAF**.
- 재검증: `Stop()`은 `lock_`을 잡지만 워커의 재사용 경로는 락을 안 잡으므로, 체크와 재사용 사이의 창이 보호되지 않음. `TcpServer.cpp:55` 주석("맞겠지?")이 우려하던 지점.
- 또한 이전 연결의 stale Send 오버랩 완료는 `IOCPOverlappedSend::Process`가 실패/0바이트 시 조기 return 하므로 교차 데이터 위험은 낮음 (UAF가 본질).
- 개선: 세션 재사용 시 서버의 `lock_`(또는 전용 재사용 락)으로 보호, 세대(버전) 카운터 도입, 또는 재사용 대신 새 세션 생성.

### 3-2. `Session::Send` / `SendPending` / `pendingData_` 스레드 안전성 없음 — ★★★ (확정)
- 위치: `Host/Session.cpp:119-230`
- `pendingData_`, `sendBuffer_` 접근에 락이 없음 (sendBufferLock_은 EnqueueCmd에서만 사용). 다중 스레드 Send 시 레이스.

### 3-3. `Host::State` enum 값 충돌 — ★★ (확정)
- 위치: `Host/Host.h:49-60`
- `eAcceptWait==eConnectWait==2`, `eListening==eAccepted==eConnected==3`, `eDisconnected==eStopped==4` — 상태 판별 모호.
- 참고: `ForEachConnected`(SessionContainer.cpp:142)는 `== eConnected` 체크인데 서버 세션은 `eAccepted(3)`이라 우연히 동작. 값 분리 필요.

### 3-4. `SessionContainer` 내부 동기화 없음 — ★★ (재검증: 문구 수정)
- 위치: `Host/SessionContainer.cpp` 전반
- 재검증: 워커 스레드는 컨테이너 메서드를 직접 호출하지 않음. 다만 (1) 유저 스레드 간 동시 `Get/ForEach` 접근, (2) `TcpServer::Stop`의 `Clear()`가 세션을 `delete`하는 동안 유저가 `GetSessionContainer()->Get(...)`으로 접근하면 **UAF**. 내부 락(또는 shared_ptr 보유) 필요.

### 3-5. `DisconnectAll`의 `WaitForZeroPending` 블로킹 → 리스너 콜백에서 데드락 — ★★ (확정)
- 위치: `Host/SessionContainer.cpp:71-98`, `Host/Session.cpp:460-494`
- 재검증: 데드락 경로는 **워커 스레드에서 호출되는 리스너 콜백**(`OnDisconnected` 등)에서 유저가 `Stop()`을 호출하는 경우. 워커가 `WaitForZeroPending`으로 블로킹되면 남은 완료를 처리할 워커가 없어 영원히 대기. `Sleep(10)` 폴링도 지양 → 이벤트 기반 대기로 변경.

### 3-6. `IOCP::Destroy` pending 검증 없음 — ★★ (확정)
- 위치: `IOCP/IOCP.cpp:48-63`
- pending 오버랩이 남은 채 핸들을 닫으면 완료 이벤트 유실/미해제 + 워커가 닫힌 핸들로 busy 루프 진입 가능. (`IOCPWorker.cpp:69-73` 주석의 Accept 오버랩 해제 문제와 연계)

### 3-7. `GetQueuedCompletionStatusEx` 실패 경로 무시 — ★★ (확정)
- 위치: `IOCP/IOCPWorker.cpp:90-95`
- 실패 시 `GetLastError()` 확인 없이 `continue`. 핸들 닫힘 시 워커가 무한 busy 루프에 빠질 수 있음.

### 3-8. `IOCPOverlappedRecvFrom::Process` 수신 실패 무시 — ★★ (확정)
- 위치: `IOCPOverlapped/IOCPOverlappedRecvFrom.cpp:39-42`
- `RecvFromAsync()` 실패 결과를 빈 if 블록으로 무시 → **UDP 수신이 조용히 중단**된다. (TCP Recv는 실패 시 Disconnect 처리함)

### 3-9. `TcpClient::Connect` 동기(select) 경로의 문제 — ★ (재검증: 내용 수정)
- 위치: `Host/TcpClient.cpp:68-167`
- 재검증 결과: "완료 이벤트 섞임"은 실제로 발생하지 않음(동기 connect는 오버랩 미사용). 실제 문제는 (1) **select 기반이라 호출 스레드가 블로킹** — 워커 스레드에서 호출 시 위험, (2) 타임아웃/오류 경로가 `state_ = eDisconnected` 세팅 후 `Initialize()`가 `eInitailized`로 덮는 **비일관적 상태 전이**, (3) 소켓 재생성이 무거움.
- 개선: `ConnectAsync`(ConnectEx) 단일 경로로 통일.

### 3-10. `IOCP::WaitForZeroPending` 폴링 — ★ (확정)
- 위치: `IOCP/IOCP.cpp:101-125`
- `Pulser` + `Sleep` 폴링 → 완료 시 Signal하는 이벤트/카운터 방식으로 개선.

## 4. 성능 개선

### 4-1. 오버랩 재사용/풀링 — ★★ (확정)
- 위치: `IOCPOverlapped/IOCPOverlapped.h:14-17`, `IOCPOverlappedRecvFrom.cpp:39`
- `USE_OVERLAPPED_STATIC_POOL`이 벤치마크(BM_PacketPooling) 결과 **4% 성능 저하**(전역 풀 락 병목)로 주석 처리됨.
- 개선 방향: 세션별(또는 스레드별 TLS) 오버랩 캐시, 재사용 시 `Process` 내 `this` 재등록 전 `AddRef()` + 완료 시 `Release()`로 수명 관리. (주의: `IOCPWorker.cpp:119`의 `JC_REF_COUNT_GUARD`와 충돌 — 재등록 시 refcount 조정 필요)

### 4-2. 전역 pending count 원자 연산 경합 — ★★ (확정)

### 4-4. `Session::SendPending` / 커맨드 버퍼 플러시 — ★ (확정)

### 4-6. `StreamBuffer::PopReads` memmove 비용 — ★ (확정)

## 5. 기능 누락

### 5-1. 0바이트 수신(Page-Lock 방지) 미구현 — ★★ (확정)
- 위치: `Host/Session.cpp:448-449` (TODO 주석), `IOCPOverlappedRecv.cpp:31`
- WSARecv 미대기 시간이 길면 수신 윈도우가 0이 되어 상대 송신이 막힘.
- 주의: 현재 `IOCPOverlappedRecv::Process`는 `_bytesTransferred == 0`을 **무조건 Disconnect로 처리**하므로, 0바이트 수신 구현 시 "0바이트 = graceful close" 판별과 "0바이트 = 프로브 완료" 판별을 분리해야 함.

### 5-2. 수신 버퍼 고정 크기 문제 — ★★ (재검증: 메커니즘 정밀화)
- 위치: `Host/Session.cpp:36,361-380`
- `recvBuffer_`가 가득 차면 `GetRemainBuffer()`이 길이 0 WSABUF를 반환 → 재검증 결과, 0길이 `WSARecv`는 **즉시 0바이트 완료**되어 `IOCPOverlappedRecv::Process`의 `_bytesTransferred == 0` 분기로 **세션이 끊김** (또는 `WSAENOBUFS` 실패). 패킷 최대 크기(payloadLen_은 _u16 → 최대 65535)가 수신 버퍼 6000을 초과하는 경우 발생 가능.
- 개선: 버퍼 확장 정책 또는 분할 수신.

### 5-3. IPv6 미지원 — ★★ (확정)
- 위치: `Socket.h:192-209`(Socketv6 stub), `IPEndPoint.h:62-69`, `IPAddress.h:124-136`
- 소켓/엔드포인트/주소 전체가 IPv4 전용. 필요 시 전면 확장.

### 5-4. `IOCPOverlappedDisconnect` 미구현 — ★ (확정)

### 5-5. `InitializeJNet` 옵션 파싱 미구현 — ★ (확정)

- `argc/argv` 파라미터를 무시. 서버/클라 공용 설정(버퍼 크기, 워커 수, Nagle 등)을 argv/설정 파일로 주입 가능하게 확장.

### 5-6. `MsgPacket` 미구현 — ★ (확정)
