# sgf 테스트 벤치 추가 계획

## 1. 목표
- `jc_gtest/jc_gbench`와 동일한 방식으로 `sgf_gtest/sgf_gbench` 프로젝트를 신설한다.
- 테스트와 벤치마크는 임시로 핵심 코드만 가볍게 추가한다.
- GPU 없이 실행 가능한 CPU 영역만 대상으로 한다.

## 2. 사전 분석 결과
- `jc_gtest`: `gtest 1.8.1.5` NuGet 참조, PCH `Core.h`에 `TEST_*` on/off 매크로, `PCH/Core.cpp`에 `main` 포함. `Projects/jc_gtest/Project/jc_gtest.vcxproj:197`, `Projects/jc_gtest/Sources/jc_gtest/PCH/Core.h:42-60`, `Projects/jc_gtest/Sources/jc_gtest/PCH/Core.cpp:43-54`
- `jc_gbench`: `ThirdParty/GoogleBenchmark` include/lib 참조, `BENCHMARK_STATIC_DEFINE`, PreBuild에서 `benchmark.lib` 존재 검사. `Projects/jc_gbench/Project/jc_gbench.vcxproj:113-114,141,158-165`
- `sgf`: 정적 라이브러리, PCH `sgf/PCH/Core.h`가 d3d11/jc 포함. `Transform` 생성자는 `nullptr` 허용. `Projects/sgf/Sources/sgf/Scene/Transform.cpp:23-29`
- `PrimitiveBuilder`와 `FillResult`는 GPU 무접촉 순수 함수. `Projects/sgf/Sources/sgf/Graphics/PrimitiveBuilder.h:12-15`
- `GraphicsEnums.h`의 `ToD3D11`은 디바이스 없이 호출 가능. `Projects/sgf/Sources/sgf/Graphics/GraphicsEnums.h:160-230`

## 3. 설계
- `jc_gtest` 구조를 그대로 복사한다. PCH `Core.h` + `Core.cpp(main)` + 영역별 테스트 3개.
- `jc_gbench` 구조를 그대로 복사한다. PCH `Core.h` + `Core.cpp(main)` + 벤치 2개.
- 링크는 `jc.lib + sgf.lib`를 사용한다. `sgf.props`의 `tinyxml2.lib`도 포함한다.
- `Directory.Build.props`에 `sgf_gtest/sgf_gbench`를 `base.props + jc.props + sgf.props` 조건에 추가한다.
- 솔루션은 `Harmony_Test.sln`과 `Harmony_Engine.sln`에 2개 프로젝트를 추가한다.
- 빌드 스크립트는 `Scripts/BuildProject/sgf_gtest.bat`, `Scripts/BuildProject/sgf_gbench.bat`를 신설한다.
- 주석 규칙: 핵심 헤더(`PCH/Core.h`)에만 주석을 남기고 나머지 파일은 주석 없이 작성한다.

## 5. 테스트 내용
- `GraphicsEnumsTest`: `ToD3D11` 매핑 6종 확인.
- `TransformTest`: 초기 행렬 항등, 위치/스케일/회전 설정 후 월드 행렬 반영 확인.
- `PrimitiveBuilderTest`: `BuildRect` 정점 4 인덱스 6, `BuildCircle` 세그먼트 수에 따른 정점/인덱스 개수 확인.

## 6. 벤치 내용
- `TransformBench`: `GetWorldMatrix` 반복 호출.
- `PrimitiveBuilderBench`: `BuildCircle` 반복 호출.

## 7. 검증
- `Scripts/BuildProject/sgf_gtest.bat -C Debug -P x64` 빌드.
- `Scripts/BuildProject/sgf_gbench.bat -C Debug -P x64` 빌드.
- gtest 실행 파일은 빌드 산출물 존재까지만 확인하고 직접 실행은 생략한다.
