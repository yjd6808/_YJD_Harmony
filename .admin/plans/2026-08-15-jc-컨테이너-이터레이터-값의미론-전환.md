# Plan: jc 컨테이너 인터페이스 계층 제거 + 이터레이터 값 의미론 전환

## 날짜
2026-08-15

## 작업 배경

jc의 컨테이너(Projects/jc/Sources/jc/Container)는 Java 스타일의 가상 인터페이스 계층 위에 구축되어 있음:

```
Vector      : ArrayCollection : Collection : Iterable          ← 인터페이스 계층 2겹
LinkedList  : ListCollection  : Collection : Iterable
HashMap     : MapCollection   : Collection : Iterable
HashSet     : SetCollection   : Collection : Iterable
TreeMap     : MapCollection   : Collection : Iterable
TreeSet     : SetCollection   : Collection : Iterable
CollectionStream, Properties  : Collection (직접)
```

**문제점**
1. **인터페이스 계층**: `Iterable::Begin()/End()`가 가상 함수로 `SharedPtr<Iterator>`(Enumerator) 반환 → 이터레이터 1개당 힙 할당 2회 (MakeShared + 제어블록), vtable 경유 순회
2. **const 시맨틱 전무**: `T& Current()/Next()/Previous()`만 존재 — const 컬렉션 순회 불가
3. **owner_/watcher 과잉**: `Collection::owner_`(CVoidOwner) + 이터레이터의 union `CVoidWatcher` + dynamic_cast 타입 소거 — 힙 제어블록 할당, IsValid() 사망 감지용
4. **쓸모없는 런타임 타입 식별**: `ContainerType`/`CollectionType` getter — 실제 사용처는 ArrayQueue.h 내부 최적화 분기 2곳뿐 (grep 확인)

**사용 규모 (grep 전수 조사 결과):**
- `it->HasNext()/Current()/Next()/Previous()`: **151곳** / `.Begin()/.End()/.Keys()/.Values()`: **152곳**
- `Extension()` (CollectionExtension): **7곳** (jnet/WorkerGroup, jdb/ConnectionPool, sgcl/Image, sgcl/CommandSynchronizer, 테스트 4곳)
- `Collection<T>` 직접 참조: **WaitHandle.h(WaitAny), Random.h(Pick/RandomPicker)** 2모듈
- `GetContainerType/GetCollectionType` 외부 분기: **ArrayQueue.h:122, 405** 단 2곳

## 목표

1. **인터페이스 계층 제거**: `Collection`/`Iterable` 및 그 파생 인터페이스(`MapCollection`/`SetCollection`/`CollectionType`/`ContainerType`/`CollectionExtension`/`Iterator` 베이스) 삭제 → 각 컨테이너가 단일 개체처럼 동작 (구현 공유 베이스 `ArrayCollection`/`ListCollection`는 잔존하되 **가상 함수 전부 비가상화**)
2. **힙 할당 제거**: 이터레이터 값 의미론 전환 → 순회당 힙 할당 0회
3. **const 시맨틱 지원**: `const_iterator` 추가 (const 컬렉션 순회 + `const T&` 반환)
4. **owner_/watcher 제거**: `Collection::owner_`·`GetOwner()`·`CVoidWatcher`·union·dynamic_cast 전부 삭제 → 컬렉션 생성 시 힙 할당 0건. `IsValid()` API 폐기, std 의미론(소멸 후 댕글링 = 호출부 책임) 채택
5. **가상함수 100% 제거**: 컨테이너 계층(`Container/` 폴더)에서 `virtual` 키워드 0건 달성 — 인터페이스 계층 가상(삭제) + 잔존 베이스(ArrayCollection/ListCollection)의 가상 멤버(전수 약 36개) 비가상화 + LinkedList의 override 위임 제거
6. 가상 순회가 필요했던 보조 알고리즘(PushBackAll/InsertAll/WaitAny/Pick)은 템플릿화로 대체

## 설계 방향 (확정안)

### 1. 타깃 아키텍처

```
Vector/ArrayStack/ArrayQueue  : ArrayCollection<T, A>   (구현 공유, 비가상)
LinkedList/ListStack/ListQueue: ListCollection<T, A>    (구현 공유, 비가상)
HashMap, HashSet              : 독립 (내부 HashTable 사용)
TreeMap, TreeSet              : 독립 (내부 TreeTable 사용)
CollectionStream, Properties, DataMap, StaticVector     : 독립 (기존/전환)
```

**ArrayQueue는 독립 클래스로 전환** (구현 공유 베이스에서 제외):
- ArrayQueue는 원형 버퍼(circular buffer)라 `IsFull/IsValidIndex/IsValidRange/Expand/CopyFrom/Clear/DestroyAtRange` 등을 ArrayCollection 상속 + override로 재정의 중 — 실제 공유 로직이 거의 없음
- 상속을 끊고 자체 구현(버퍼 관리)으로 전환해야 ArrayCollection의 비가상화가 가능해짐
- 대가는 버퍼 관리 코드 중복(ArrayQueue 전용, ~200줄) — 이미 대부분 자체 구현된 상태라 실제 중복은 적음

**잔존 베이스의 가상함수 전부 비가상화 (전수 목록):**
- `ArrayCollection` (≈20개): `Clear/Valid/IsFull/CopyFrom×3/ExpandIfNeeded/Expand/Shrink/ShrinkToFit/IsValidIndex×2/IsValidRange×2/ExpandAuto/DestroyAtRange/dtor(=0 추상)`
- `ListCollection` (16개): `Clear/CopyFrom/Valid/PushBack×2/PushBackAll/Remove/PushFront×2/PushFrontAll/PopFront×2/PopBack×2/Front/Back/dtor`
- `LinkedList`의 override 12개: 전부 `TListCollection::xxx()` 위임이므로 **override 삭제, 베이스 구현만 사용**
- `ListStack`(Push/Pop/Top) · `ListQueue`(Enqueue/Dequeue) 자체 virtual: 비가상화
- 모든 컨테이너/이터레이터의 `override` 키워드 일괄 삭제, 소멸자 비가상화

### 2. 이터레이터 재설계

- `Iterator.h`(가상 인터페이스) 삭제. 계열 이터레이터 베이스만 잔존:
  - `ArrayCollectionIterator<T, A, Const>` — `ArrayCollection<T,A>* pCollection_` 직접 보관 (watcher/dynamic_cast 제거)
  - `ListCollectionIterator<T, A, Const>` — `ListCollection<T,A>* pCollection_` 보관
- 맵/셋 이터레이터(`HashMapIterator`, `TreeMapIterator`, `HashSetIterator`, `TreeSetIterator`)는 **독립 클래스**로 전환 — `TCollection*` 멤버를 각자 직접 보관 (HashTable/TreeTable 노드 순회 로직은 그대로)
- `template <bool Const>` 파라미터로 `iterator`/`const_iterator` 쌍 제공 (`TRef = const T& or T&`)

```cpp
template <typename T, typename TAllocator, bool Const = false>
class ListCollectionIterator   // 예시: 계열 베이스
{
    using TRef = std::conditional_t<Const, const T&, T&>;
    TRef Current() const;
    TRef Next();          // 위치 이동은 비 const 멤버
    TRef Previous();
    bool HasNext() const; bool HasPrevious() const;
    bool IsEnd() const;   bool IsBegin() const;
protected:
    ListCollection<T, TAllocator>* pCollection_ = nullptr;
};
```

- `Enumerator`/`ConstEnumerator` 별칭(Iterable.h) **삭제** → 사용처는 `auto`/구체 타입
- sizeof ≈ 16B (포인터 + 파생 상태), 스택 배치, 힙 할당 0

### 3. const 시맨틱

- 각 컨테이너에 `Begin() const → const_iterator`, `Begin() → iterator` 오버로드
- 조회 멤버는 const 반환, 이동 멤버만 비 const
- range-for(`SIterator` 어댑터)는 `m_it->` → `m_it.` 수정, `begin() const` 오버로드 추가

### Phase 1 — 계열 베이스 루트화 + 비가상화 (ArrayCollection/ListCollection)

- **`ArrayCollection.h`** (Collection 상속 제거 + 비가상화):
  - public: `virtual Clear(bool _removeHeap = false)`·`virtual Valid() const`·`virtual IsFull() const` → **비가상** (이름/시그니처 불변)
  - protected: `CopyFrom×3`·`ExpandIfNeeded`·`Expand`·`Shrink`·`ShrinkToFit`·`IsValidIndex×2`·`IsValidRange×2`·`ExpandAuto`·`DestroyAtRange` → **비가상**, `GetCollectionType` 삭제
  - `~ArrayCollection() noexcept override = 0` → `~ArrayCollection() noexcept` (하단 out-of-line 정의 유지 — 파생 소멸자가 명시적 호출)
  - `using TCollection`(private 별칭) 삭제, `owner_`/`GetOwner()` 제거, friend(계열 이터레이터)는 값 이터레이터용 friend로 교체, `IsEmpty/Size`는 기존 정의 그대로(비가상)
- **`ListCollection.h`** (동일 처리):
  - public `virtual Clear()` → 비가상 / protected `CopyFrom(&&)`·`Valid()`·`PushBack×2`·`PushBackAll`·`PushFront×2`·`PushFrontAll`·`PopFront×2`·`PopBack×2`·`Front`·`Back`·`Remove(TListCollectionIterator&)` → **비가상**, `GetCollectionType` 삭제, 추상 소멸자(`= 0`) → 일반
  - `ForEach`/`ForEachDelete`/`IsEmpty`/`Size` 유지 (이름 불변), `pHead_/pTail_/size_` 멤버 유지
- **`LinkedList.h`**: 위임 override 10개(`PushBack×2`/`PushBackAll`/`PushFront×2`/`PushFrontAll`/`Back`/`Front`/`PopBack`/`PopFront`) + `~LinkedList`의 `override` 키워드 삭제 → 베이스 구현만 사용. 자체 구현(`PopBack(T*)`/`PopFront(T*)`/`Remove×2`/`Exist`/`RemoveIf`/`EmplaceBack`/`EmplaceFront`)은 유지

## 위험 요소

1. **API 파괴 변경**: `Enumerator` 타입 삭제 + `->` → `.` 전환으로 전 프로젝트 컴파일 에러 → 컴파일러 에러 목록이 곧 작업 목록이므로 통제 가능, 단 작업량 큼(~380곳 + Extension 7곳)

3. **SIterator(range-for) 호환**: `begin()/end()` const 오버로드 누락 시 const 컬렉션 range-for 빌드 실패 — Phase 2에서 즉시 검증
4. **사망 감지 상실 (의도된 변경)**: 컨테이너 소멸 후 이터레이터 사용은 UB로 전환 — Phase 9의 장기 보관 패턴 조사로 안전 확인, 코딩 관례 문서화
5. **맵/셋 이터레이터 독립화**: MapCollectionIterator/SetCollectionIterator 제거 시 HashMap/TreeMap 이터레이터의 공통 로직 중복 발생 (패턴 반복이지만 로직 자체는 간단 — successor/bucket 순회)
6. **ArrayQueue 복사 최적화 분기**: 런타임 타입 분기 → 컴파일 타임 분기 전환 시 의미 동일성 확인 (동일 계열 복사 시 버퍼 재사용 최적화)
7. **ArrayQueue 독립화 코드 중복**: 상속 제거 시 원형 버퍼 관리(Expand/CopyFrom/Clear/DestroyAtRange 등)가 ArrayQueue 자체 구현으로 귀속 — 이미 대부분 자체 정의되어 있으나, ArrayCollection에만 있고 상속으로 쓰던 유틸(IsValidRange 등)의 이관 누락 주의 (Phase 2에서 반드시 검증)
8. **추상 소멸자 전환**: `ArrayCollection`/`ListCollection`의 `virtual ~...() = 0` + 정의가 있던 구조 → 일반 소멸자 전환 시 가상 해제 경로에 의존한 코드(없음으로 확인) 외에 파생 클래스 소멸자(`~Vector() override` 등)의 `override` 제거 누락 주의
