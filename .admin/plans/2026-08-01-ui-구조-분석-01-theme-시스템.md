# SGCL UI 전체 구조 분석 - 01. Theme 시스템

> 작성일: 2026-08-01
> 위치: `Projects/sgcl/Classes/sgcl/Game/UI/Theme/`

## 1. 목적

런타임에 스타일(색/기하/글로스)을 해석하여 **픽셀 텍스처를 생성(Bake)** 하고,
이를 Scale9/Fixed 스프라이트로 컨트롤에 바인딩하는 시스템.
레거시 SGA 이미지 없이도 통일된 "메탈 골드" 스타일의 UI를 그릴 수 있게 한다.

## 4. 스타일 해석 (UIStyleResolver)

`UIStyleResolver::Resolve(control, state, theme, local)` → `UIResolvedStyle` (UIStyleResolver.cpp:4-14)
```
1. ApplyStateModifiers(theme, state)   // 토큰 → 해석값
2. ApplySparseOverride(result, local)  // UIStyleOverride 로 부분 오버라이드
3. ValidateAndClamp(result)            // 음수/1.0 초과 클램프
```

- `ApplySurfaceToken` (UIStyleResolver.cpp:108-139): state별 surface top/bottom 선택
- `ApplyMetalToken` (UIStyleResolver.cpp:141-152): metal 6색 복사
- `ApplyGlossToken` (UIStyleResolver.cpp:154-179): Pressed 시 glossAlpha=0, Hover 시 *1.32
- `ApplySparseOverride` (UIStyleResolver.cpp:60-92): `UIStyleOverride.mask` 기반 부분 적용

### 4-1. UIResolvedStyle (UIStyleOverride.h:6-35)
해석 결과 = surface(4) + metal(6) + glossTint/glossAlpha + geometry(5) + semantic(4).
`ComputeHash()` (UIStyleOverride.cpp:9-49)로 `styleHash` 산출
→ 색상은 RGBA 바이트 4개를 64비트에 패킹, float는 비트 패턴 그대로 `HashCombine`(0x9E3779B97F4A7C15).

### 4-2. UIStyleOverride / UIStyleToken (UIStyleOverride.h:37-148)
- `UIStyleToken` = 오버라이드 가능한 모든 스타일 필드 (Count=39개 정도)
- `UIStyleOverrideMask` = 128비트 마스크(lo/hi uint64)
- `Set(token, color/float)`, `Has(token)`, `Clear(token)`

## 5. Theme 매니저 (UIThemeManager)

### 5-1. 싱글턴 & 라이프사이클
- `UIThemeManager::Get()` (UIThemeManager.cpp:6-13): 전역 포인터 `g_pThemeManager`
- `Initialize(params)` (UIThemeManager.cpp:15-30): 활성 테마 = EngineDefaults, revision=1, bake 콜백 등록. **호출부: SteinsGateApp.cpp:151 (cacheRoot="")**
- `Update(dt)` (UIThemeManager.cpp:41-49): `bakeService_.Update` → `ProcessCompleted` → `deferredRelease_.Update` → `SwapTextureSet` (현재 게임루프에서 호출 지점 미확인 — 스튜디오/비동기 bake 사용 시 필요)
- `Shutdown()` (UIThemeManager.cpp:32-39)

### 5-2. 리비전 (UIThemeRevision, UIThemeTypes.h:168-175)
`sourceRevision / mappedRevision / textureRevision` 3단계.
- `IncrementSourceRevision()` (UIThemeManager.cpp:51-55)
- `CommitDraft()` (UIThemeManager.cpp:172-186): mappedRevision++
- `SwapTextureSet()` (UIThemeManager.cpp:200-212): textureRevision++

### 5-3. Resolve 진입점
- `Resolve(control, state, local)` (UIThemeManager.cpp:57-63) → `resolver_.Resolve(activeTheme_)`
- `ResolveWithEditOverrides(control, state)` (UIThemeManager.cpp:65-72): 편집 세션 활성 시 draft+overrides로 해석

### 5-4. BakeDefaultTextureSet (UIThemeManager.cpp:79-160)
앱 시작 시 1회 동기 실행 (SteinsGateApp.cpp:152).
1. 16개 시맨틱을 순회 (UIThemeManager.cpp:92-108)
2. 시맨틱별 컨트롤 타입 매핑 (UIThemeManager.cpp:112-131): Button→Button, CheckMark→CheckBox, ToggleKnob→ToggleButton, ProgressCap→ProgressBar, ScrollBarTrack→ScrollBar ...
3. `resolver_.Resolve(elemType, Normal, activeTheme_)` → variant 생성
4. `bakeService_.BuildTextureSet(request)` → `activeTextureSet_` 교체, textureRevision++

### 5-5. 편집 세션 (UIThemeEditSession, UIThemeManager.h:17-22)
- `BeginEdit()` (UIThemeManager.cpp:162-170): draft=activeTheme 복사
- `CommitDraft(draft)` / `CommitDraft(draft, overrides)` (172-186)
- `CancelPreview()` (188-191)
- 사용처: `UIThemeStudio` (인게임 편집기)

## 9. 시각 파이프라인 요약

```
[테마 토큰]  UIRuntimeTheme
   ↓ UIStyleResolver::Resolve (state 반영)
[해석 스타일] UIResolvedStyle
   ↓ ComputeHash → styleHash
[자산 키]    UIAssetKey {semantic, styleHash, recipeHash}
   ↓ UITextureBakeService::BuildTextureSet (Baker가 픽셀 생성)
[텍스처]     UITextureEntry (Texture2D + sliceInsets + contentPadding)
   ↓ UIThemeTextureBinding::Refresh (컨트롤마다)
[바인딩]     Scale9Sprite / Sprite  ← 컨트롤의 화면 표현
```
