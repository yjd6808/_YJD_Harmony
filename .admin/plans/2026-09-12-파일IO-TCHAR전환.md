# 파일 I/O 경로 TCHAR 전환 계획 (2026-09-12, D-4)

- 인계 §4-2 두 번째 항목. Phase 3 `_char` 오버로드(`FileOpen`/`FileDelete`/`FileRename`)가
  이미 있으므로 호출부만 전환한다. narrow 오버로드는 MBCS 경로 경계로 유지한다 (제1규칙 2항).

## 1. 분석 결과 (실측)

- 완료됨: `Exist`/`Size`/`Delete` String 오버로드 (직접 `_char` 호출), `FileStream` 전부 `_T()` 모드,
  `FileSource`/`FileDest`/`FileLogger`/`Directory` String 경로 직접 전달.
- 미완료 2곳 (`File.cpp`):
  1. `Move(String)`: `ToAnsi` 왕복 후 narrow `Move` 호출 — 비ASCII 경로 손실.
     → `CRuntime::FileRename(_srcPath.Source(), _dstPath.Source())` 직접 호출.
  2. `Copy(String)`: `ToUtf8` 왕복 후 narrow `Copy` 호출 — 같은 문제.
     → `_T("rb")`/`_T("wb")` 직접 오픈 본문으로 교체.
- 유지 (점검 결과): `WriteAllText`/`WriteAllBytes`/`ReadAllText` narrow 경로 API — 내용(content)은
  바이트이므로 narrow가 맞고, String 경로 오버로드 자체가 없어 신설은 범위 밖.
  `Directory`/`Path` narrow 오버로드는 `FromUtf8`/`FromAnsi` 위임 경계로 유지.
