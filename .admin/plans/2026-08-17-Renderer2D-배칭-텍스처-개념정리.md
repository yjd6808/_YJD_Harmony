## 1. 렌더 경로 2개 — 메시 경로 vs 배치 경로

sgf의 2D 렌더링에는 **서로 다른 설계 철학을 가진 경로 2개**가 있다.

| | 메시 경로 (DrawMesh) | 배치 경로 (DeclareStatic/RenderStatic 등) |
|---|---|---|
| 데이터 | Mesh + Material | Fill (사각형/원/스프라이트/9-패치/폴리곤) |
| 변환 | **GPU** — b1(월드 행렬) 상수버퍼 | **CPU** — 위치/회전이 정점에 bake |
| 드로우콜 | 오브젝트당 1콜 | 같은 텍스처 연속분 = 1콜 (배칭) |
| 정점 데이터 | 고정 (로컬 좌표, 평생 안 변함) | 오브젝트마다 다른 최종 위치를 포함 |
| 업로드 | 생성 시 1회 | **매 프레임 복사 + 업로드** (C-1의 문제) |

```cpp
// 메시 경로: 정점 = 로컬 고정, 위치는 전부 b1이 담당
object.world_ = _world;                 // 오브젝트 위치는 여기서
objectCb_.Update(pDevice_, object);     // → 움직여도 정점은 안 변함!

// 배치 경로: 정점에 "최종 위치"가 이미 구워져(baake) 들어감
vertices[i].position_ = vec3(locals[i].x * c - locals[i].y * s + _center.x, ...);
//                      ← 오브젝트 위치/회전이 정점 안에 있음. GPU는 b1=단위행렬로 찍기만 함
```

**결론**: "월드 매트릭스로 업데이트되니 정점은 4개면 되지 않나?"라는 질문은 **메시 경로**에만 성립한다. 배치 경로는 다르다.

## 2. 월드 매트릭스는 왜 배치 경로에 안 쓰나

**배칭 때문이다.** 상수버퍼(b1)는 **드로우콜당 1개**다.

```
메시 경로:   콜마다 b1 교체 → 오브젝트당 1콜 (드로우콜 비쌈, 정점은 영구)
배치 경로:   정점에 위치를 bake → 같은 텍스처 전부 1콜 (배칭, CPU가 정점 갱신)
```

같은 텍스처의 오브젝트 100개를 **한 콜로** 그리려면 b1은 단 하나만 쓸 수 있으므로(단위행렬 고정) **각 오브젝트의 다른 위치를 정점 자체에 담아야** 한다. 오브젝트마다 b1을 바꾸면 그 순간 콜이 100개로 갈라진다.

> 비유: 메시 경로는 "못 위치만 바꾸는 액자", 배치 경로는 "그림 100장을 한 장의 큰 벽지에 붙여 한 번에 벽에 붙이는 방식".

## 3. 텍스처 개념 — 정점은 뼈대, 텍스처는 살

- **정점(Vertex)**: 도형의 구조 — "여기부터 여기까지 사각형". 위치/UV/색만 가진다.
- **텍스처(Texture)**: 정점이 감싼 영역에 채울 **픽셀 내용** — 벽돌 사진, 나무 무늬 등.
- **UV**: 정점에서 텍스처의 어느 부분을 쓸지 연결하는 좌표 (0~1).

```hlsl
// 셰이더 (DefaultShaders.h)
return texture0_.Sample(sampler0_, input.uv_) * input.color_ * baseColor_;
//                ↑ 텍스처 색       ↑ 틴트 곱셈
```

텍스처가 있으면 색 = `텍스처 색 × 틴트`, 텍스처가 없으면(흰색 1x1) 색 = `틴트 그대로`.

---

## 4. 흰색 1x1 텍스처 트릭

**"단색 도형 = 텍스처 없음"이 아니다.** 이 엔진에서 단색은 **흰색 1x1 텍스처 × 틴트(색상 곱셈)**로 그린다.

```cpp
void Renderer2D::DrawRect(const vec2& _center, const vec2& _size, const color& _color, _f32 _radian)
{
    // 단색 사각형도 흰색 기본 텍스처를 쓴다 (ResourceMgr::GetDefaultTexture)
    DrawSprite(g_cResourceMgr.GetDefaultTexture(), _center, _size, _color, _radian);
}
```

**이게 좋은 이유**:
1. **셰이더 하나로 통일** — 텍스처가 없을/있을 때를 위한 별도 셰이더가 필요 없음
2. **배칭 유지** — 모든 단색 도형이 "같은 흰색 텍스처"를 공유하므로 단색끼리 1콜 배칭
3. **비용 0** — 흰색 1x1 픽셀은 메모리도, 로드도, 샘플링도 무시 가능

`GetDefaultTexture()`는 **조회(Find)일 뿐 생성/변경이 아니다** (ResourceMgr.cpp:292-295). B-1 바인딩 캐시 덕분에 매번 바인드도 안 한다.

## 5. 배칭 규칙 — 텍스처 전환 = Flush

배치 경로의 분리 조건은 **텍스처 포인터가 바뀌는 순간**이다.

```cpp
// Renderer2D.cpp — PushTriangles
if (pCurrentTexture_ != nullptr && pCurrentTexture_ != _pTexture)
    Flush();                    // 텍스처가 바뀌면 이전 배치를 발사
```

```
예약 순서: [벽돌][벽돌][벽돌][단색][단색][벽돌]
드로우:     └──1콜──┘  └─1콜─┘ └1콜┘  = 3콜 (전환 2번)
```

- 같은 텍스처끼리 연속이면 그대로 쌓이다가 **텍스처가 바뀌는 시점에만** 이전 배치를 Flush(드로우콜 1회)한다.
- "단색"도 흰색 1x1 텍스처이므로 벽돌 텍스처와는 **서로 다른 텍스처** → 배치 분리.
- 벽돌 100개 + 단색 100개를 각각 연속 예약하면 2콜, 번갈아 예약하면 최악 100콜. → **같은 텍스처끼리 모아서 예약하는 것이 배칭의 핵심** (예약 순서 = 드로우 순서).

## 6. pCurrentTexture_ vs pBatchTexture

둘 다 "묶음의 텍스처 라벨" 역할이지만 **대상이 다르다**.

| 변수 | 의미 | 사용처 |
|---|---|---|
| `pCurrentTexture_` (멤버) | **vertices_ 배치**가 어느 텍스처로 쌓이는지 — 배치 분리 판정 | PushTriangles / Flush (배치 경로 전용 상태) |
| `pBatchTexture` (C-1 수정안의 로컬) | **스태틱 GPU 세그먼트 묶음**이 어느 텍스처인지 | FlushStatic이 자체 DrawIndexed할 때의 묶음 판정 |

**왜 재사용하면 안 되나** — FlushStatic은 `vertices_`에 아무것도 쌓지 않고 스스로 그리는 별도 경로다. 여기서 `pCurrentTexture_`를 덮어쓰면 **배치 경로의 판정 상태가 오염**된다:

```
RenderScene 순서: FlushStatic → FlushDynamic
FlushStatic이 pCurrentTexture_를 "스태틱 마지막 텍스처"로 바꿔치기
→ 이후 FlushDynamic의 첫 PushTriangles가 "pCurrentTexture_ != 새 텍스처"로
  오판단 → 불필요한 Flush() 발생
```

→ 스태틱이 바인딩한 텍스처는 `vertices_` 배치와 무관하므로 로컬 변수로 분리한다.

## 7. C-1: 스태틱 GPU 버퍼화 — 가변 dirtyFlag_ 설계 (확정)

### 문제
지금의 배치 경로는 **매 프레임** 같은 스태틱 지오메트리를 `vertices_`에 복사하고 GPU에 업로드한다. 스태틱은 "가변이 없는 한 변하지 않는" 데이터인데 매 프레임 다시 보낸다.

### 설계 (사용자 확정 — "언제든 치우고 놓기" + dirtyFlag_)
- GPU 버퍼는 **DYNAMIC 유지** — `Update`로 내용 갱신, 크기 부족 시 2배 성장 재생성
- `DeclareStatic`은 **언제든 호출 가능** — 누적 배열에 추가 + `staticGpuDirty_ = true` (가변 시점 1회 업데이트)
- **`RemoveStatic` 신규** — 슬롯을 **실제로 제거**하고 남은 슬롯만 누적 배열 재구축 (비활성 플래그 아님! 메모리 회수)
- `FlushStatic`은 **dirty일 때만 업로드**, 이후 프레임은 바인딩 + 세그먼트 DrawIndexed만

### 핵심 코드 (수도 코드)

```cpp
// Renderer2D.h — StaticSlot (GPU 세그먼트 범위 + 자기 id 보관)
struct StaticSlot
{
    _u64 id_ = 0;           // staticId — 슬롯이 자기 id를 보관 (중간 제거에도 id 안정)
    FillResult geometry_;   // 채움 결과 (선언 시 1회 — 이후 변경은 재선언)
    RenderLayer layer_;     // 렌더 버킷 (선언 시 고정)
    _u32 vertexOffset_ = 0; // 누적 배열에서 정점 시작 위치
    _u32 vertexCount_ = 0;  // 정점 개수
    _u32 indexOffset_ = 0;  // 누적 배열에서 인덱스 시작 위치
    _u32 indexCount_ = 0;   // 인덱스 개수
};

// (private 멤버 추가)
jc::Vector<VertexPTC> staticVertices_;   // 스태틱 누적 정점 (가변)
jc::Vector<_u32> staticIndices_;         // 스태틱 누적 인덱스
VertexBuffer staticVertexBuffer_;        // DYNAMIC — 가변 대응
IndexBuffer  staticIndexBuffer_;
bool staticGpuCreated_ = false;          // 최초 FlushStatic에서 생성
bool staticGpuDirty_ = false;            // 누적 배열 변경 → 다음 FlushStatic에서 업로드
```

```cpp
// FindStatic: id_ 비교 선형 검색 (기존 id-1=인덱스 매핑은 중간 제거 시 깨지므로)
Renderer2D::StaticSlot* Renderer2D::FindStatic(_u64 _staticId)
{
    if (_staticId == 0) return nullptr;
    for (_s32 i = 0; i < staticCache_.Size(); ++i)
        if (staticCache_[i].id_ == _staticId) return &staticCache_[i];
    return nullptr;   // 제거된 슬롯의 id → nullptr (예약 시 스킵)
}
```

```cpp
// DeclareStatic: 언제든 호출 가능 — 누적 배열에 복사 + dirty
_u64 Renderer2D::DeclareStatic(const RenderParams& _params)
{
    StaticSlot slot;
    slot.layer_ = _params.layer_;
    BuildFill(_params.fill_, _params, slot.geometry_);

    const _u32 baseVertex = (_u32)staticVertices_.Size();
    const _u32 baseIndex  = (_u32)staticIndices_.Size();
    for (_s32 i = 0; i < slot.geometry_.vertices_.Size(); ++i)
        staticVertices_.PushBack(slot.geometry_.vertices_[i]);
    for (_s32 i = 0; i < slot.geometry_.indices_.Size(); ++i)
        staticIndices_.PushBack(baseVertex + (_u32)slot.geometry_.indices_[i]);
    slot.vertexOffset_ = baseVertex;
    slot.vertexCount_  = (_u32)slot.geometry_.vertices_.Size();
    slot.indexOffset_  = baseIndex;
    slot.indexCount_   = (_u32)slot.geometry_.indices_.Size();

    _u64 id = staticIdProvider_.Acquire();
    slot.id_ = id;
    staticCache_.PushBack(jc::Move(slot));
    staticGpuDirty_ = true;   // 가변 시점 1회 업데이트
    return id;
}
```

```cpp
// RemoveStatic (신규): "가구 치우기" — 슬롯 실제 제거 + 재구축
void Renderer2D::RemoveStatic(_u64 _staticId)
{
    _s32 index = -1;
    for (_s32 i = 0; i < staticCache_.Size(); ++i)
        if (staticCache_[i].id_ == _staticId) { index = i; break; }
    if (index < 0) return;

    staticCache_.RemoveAt(index);   // 슬롯 진짜 제거 (메모리 회수)
    RebuildStaticBuffer();          // 남은 슬롯만 재누적 + 오프셋 재계산 + dirty
}
```

```cpp
// RebuildStaticBuffer (신규): 남은 슬롯만 누적 배열에 다시 쌓는다
void Renderer2D::RebuildStaticBuffer()
{
    staticVertices_.Clear();
    staticIndices_.Clear();
    for (_s32 i = 0; i < staticCache_.Size(); ++i)
    {
        StaticSlot& slot = staticCache_[i];
        const _u32 baseVertex = (_u32)staticVertices_.Size();
        const _u32 baseIndex  = (_u32)staticIndices_.Size();
        for (_s32 v = 0; v < slot.geometry_.vertices_.Size(); ++v)
            staticVertices_.PushBack(slot.geometry_.vertices_[v]);
        for (_s32 k = 0; k < slot.geometry_.indices_.Size(); ++k)
            staticIndices_.PushBack(baseVertex + (_u32)slot.geometry_.indices_[k]);
        slot.vertexOffset_ = baseVertex;
        slot.vertexCount_  = (_u32)slot.geometry_.vertices_.Size();
        slot.indexOffset_  = baseIndex;
        slot.indexCount_   = (_u32)slot.geometry_.indices_.Size();
    }
    staticGpuDirty_ = true;
}
```

```cpp
// FlushStatic: dirty일 때만 업로드, 이후 바인딩 + 세그먼트 DrawIndexed
void Renderer2D::FlushStatic()
{
    if (staticItems_.Empty() || staticVertices_.Empty()) { staticItems_.Clear(); return; }

    // 가변 대응: 변경이 있었을 때만 GPU 버퍼를 (재)업로드한다
    if (staticGpuDirty_)
    {
        if (!staticGpuCreated_ || staticVertexBuffer_.Count() < staticVertices_.Size())
        {
            _u32 capacity = staticVertexBuffer_.Count();
            if (capacity < staticVertices_.Size()) capacity = (_u32)staticVertices_.Size() * 2;
            if (!staticVertexBuffer_.Create(pDevice_, staticVertices_.Source(),
                sizeof(VertexPTC), capacity, true)) { staticItems_.Clear(); return; }
            if (!staticIndexBuffer_.Create(pDevice_, staticIndices_.Source(),
                staticIndices_.Size(), true)) { staticItems_.Clear(); return; }
            staticGpuCreated_ = true;
        }
        else
        {
            // 크기 충분 — 내용만 갱신 (VertexBuffer::Update는 오프셋 API가 없어 전체 업로드)
            staticVertexBuffer_.Update(pDevice_, staticVertices_.Source(), (_u32)staticVertices_.Size());
            staticIndexBuffer_.Update(pDevice_,  staticIndices_.Source(), (_u32)staticIndices_.Size());
        }
        staticGpuDirty_ = false;
    }

    // ... ApplyFrameStates, b1=단위행렬, b2=흰색, 버퍼 바인딩 ...

    // 배칭: 같은 텍스처 + 누적 배열에서 연속인 세그먼트를 한 묶음으로
    Texture* pBatchTexture = nullptr;   // ← pCurrentTexture_ 대신 로컬 (섹션 6)
    _u32 batchStart = 0, batchCount = 0, batchIndexEnd = 0;

    auto FlushBatch = [&]() {
        if (batchCount == 0) return;
        pBatchTexture->Bind(pDevice_, 0);
        ++drawCallCount_;
        context.DrawIndexed(batchCount, batchStart, 0);
        batchStart = batchCount = batchIndexEnd = 0;
        pBatchTexture = nullptr;
    };

    for (RenderLayer pass : kFlushOrder)
    {
        for (DrawItem& item : staticItems_)
        {
            if (item.layer_ != pass) continue;
            StaticSlot* pSlot = FindStatic(item.key_);
            if (pSlot == nullptr) continue;   // 제거된 슬롯의 예약 → 스킵

            if (pBatchTexture != nullptr &&
                (pBatchTexture != item.pTexture_ || batchIndexEnd != pSlot->indexOffset_))
                FlushBatch();
            if (batchCount == 0) { batchStart = pSlot->indexOffset_; pBatchTexture = item.pTexture_; }
            batchCount += pSlot->indexCount_;
            batchIndexEnd = pSlot->indexOffset_ + pSlot->indexCount_;
        }
        FlushBatch();   // 버킷 경계 — 버킷 간 절대 섞이지 않음
    }
    staticItems_.Clear();
}
```

```cpp
// Finalize: 선언 세트(슬롯 + 누적 배열 + 플래그)를 함께 정리
void Renderer2D::Finalize()
{
    staticCache_.Clear();
    staticVertices_.Clear();   // 누적 배열도 함께 — 재초기화 시 이전 씬 정점이
    staticIndices_.Clear();    //     남으면 GPU 버퍼가 이전 것까지 포함해 생성되는 버그
    staticGpuCreated_ = false;
    staticGpuDirty_  = false;
    BatchRenderer::Finalize();
}
```

### 왜 이렇게 수정하나
스태틱은 "가변이 없는 한 변하지 않는" 데이터다. **변경 시점(dirty)에만 업로드**하면 "대부분의 프레임 = 바인딩 + DrawIndexed만"이 된다. 동시에 **가변 구조**(언제든 추가/제거)를 지원한다.

### 위험 (검증 포인트)
- **id 매핑 변경**: 슬롯이 자기 `id_`를 보관하고 `FindStatic`이 선형 검색 (O(슬롯 수) — 수십~수백 개 규모에서 무시 가능)
- **RemoveStatic 비용**: 슬롯 제거 + 재구축 + (다음 프레임) GPU 업로드 — O(스태틱 전체). "가변 시점 1회" 설계와 부합, 가구 치우기는 드문 이벤트
- **크기 부족 재생성**: 가변 추가 반복 시 재생성 반복 가능 → 2배 성장으로 상각. `Update`는 전체 업로드(오프셋 API 없음)
- **같은 프레임 내 제거 후 예약**: `FindStatic`이 nullptr → 스킵 (모든 경로 안전)
- **예약 순서가 선언 순서와 다르면**: 버퍼 연속 조건이 깨져 배칭 분리 (드로우콜 증가 — `GetDrawCallCount`로 검증)

> 비유: 벽에 걸린 액자를 매초 새로 그려 다시 걸지 않는다. **그림이 바뀐 날에만**(dirtyFlag) 다시 걸고, 액자를 내리면(RemoveStatic) **목록에서 지우고 남은 액자를 빽빽하게 다시 정리**(재구축).

## 8. C-3: 인스턴싱

### 사용자 제안 ("정점 정보가 왜 이렇게 많이 필요해?")
1x1 사각형이면 정점은 -0.5~0.5 4개로 끝이다. **사각형마다 정점 4개를 반복 저장하지 말고, 사각형 파라미터만 쌓아두고 GPU 콜 시 상수버퍼로 전달**하면 된다 — 즉 인스턴싱이다.

### 수도 코드
```cpp
// 정점 버퍼: 사각형 1개분 4정점만 (영구 — 진짜 4개로 끝!)
VertexPTC quad[4] = { (-0.5,-0.5), (0.5,-0.5), (0.5,0.5), (-0.5,0.5) };

// 인스턴스 버퍼: "가구 수"만큼 파라미터 (가변 — dirty 업로드 대상)
struct QuadInstance { mat4 world_; vec2 uvMin_, uvMax_; color color_; };
QuadInstance instances[N];   // 위치 변경 = 이 데이터만 수정 (정점 재구축 불필요!)

// 한 번의 콜로 N개:
DrawIndexedInstanced(6, instanceCount, 0, 0, 0);
```

### 한계
인스턴싱은 **"같은 정점 구조"를 가진 그룹**에만 적용된다. 배치 경로에는 원(segment마다 정점 수 다름), 9-패치, 폴리곤, 게이지 같은 도형이 섞여 있어서 **도형 종류마다 정점 구조가 다르다** → 인스턴싱은 "사각형/스프라이트 계열"만 대상.

### 잔여 문서 C-3 근거 (인용)
> "Draw가 오브젝트마다 Material::Bind + Mesh::Bind + DrawIndexed — 인스턴싱 도입 시 2D/3D 모두 드로우콜 복원 가능. 동일 (meshKey, materialKey) 그룹을 DrawIndexedInstanced로. 셰이더 b1을 인스턴스별 월드 배열로 확장. 2D는 텍스처/정점 포맷이 단순해(VertexPTC) 먼저 적용 가능. 위험: 인스턴스 배열 크기/셰이더 변경. → 콘텐츠 확장 시점에 재평가"

## 9. C-1과 C-3은 다른 축

| | C-1 | C-3 |
|---|---|---|
| 대상 경로 | **배치 경로** (Renderer2D FlushStatic) | **메시 경로** (DrawMesh) |
| 문제 | 업로드량 — 매 프레임 같은 데이터 재업로드 | 콜 수 — 오브젝트마다 1콜 |
| 해결 | 변경 시에만 업로드 (dirty) | 한 콜에 N개 (인스턴싱) |

**중요**: C-3이 아무리 잘 도입돼도 **배치 경로의 매 프레임 vertices_ 복사는 남는다**. 두 경로는 완전히 별개의 시스템이고, C-1은 독립적으로 적용할 가치가 확실하다.

## 10. C-4: 텍스처 아틀라스

### 개념
여러 그림 파일을 로드할 때 **한 장의 큰 텍스처에 나란히 붙여 넣고**, 각 그림의 **이름 → UV 사각형**을 기록하는 테이블. 그림을 그릴 때는 "아틀라스 1장 + UV 영역"으로 그린다.

```
그림 파일 3장               아틀라스 (텍스처 1장)
[벽돌.png]  [나무.png]  →   ┌─────────┬─────────┬─────────┐
[흙.png]                    │  벽돌   │   나무  │   흙    │
                            └─────────┴─────────┴─────────┘
                            "brick"  "wood"   "dirt"   ← 이름 → UV 사각형
```

### 왜 이 엔진에 자연스러운가 (확인된 사실)
- `DrawSprite`는 **이미** `_uvMin/_uvMax` 인자를 가진다 (Renderer2D.cpp:351-352, 376)
- `Fill::Texture`는 **이미** `(Texture*, rect uv_)` 시그니처다 (Fill.h:60-62, 96)
- 배칭 분리 조건은 텍스처 포인터 비교뿐 — **모든 그림이 같은 Texture 객체**면 절대 분리되지 않음
- → **렌더러/배칭 코드는 0줄 수정**, 로드 레이어(아틀라스 클래스)만 추가하면 됨

### 수도 코드

```cpp
// === 1. 신규: TextureAtlas 클래스 ===
class TextureAtlas
{
public:
    bool AddRegion(GraphicDevice* _pDevice, const char* _name, const char* _pFilePath);
    bool Build(GraphicDevice* _pDevice);          // 등록 끝나면 한 번만 GPU 업로드
    bool GetUV(const char* _name, rect& _outUV) const;  // 이름 → UV 사각형
    Texture* GetTexture() { return &atlas_; }     // Renderer2D에 넘길 텍스처 1장

private:
    Texture atlas_;                       // GPU 텍스처 1장
    jc::Map<String, rect> regions_;       // "brick" → rect(0,0,0.5,1) 등
    jc::Vector<Image> canvas_;            // CPU 합치기용
    _u32 appendX_ = 0;                    // 다음 그림 붙일 x 좌표
};

// === 2. 로드 — "한 장으로 합치기" ===
bool TextureAtlas::AddRegion(GraphicDevice* _pDevice, const char* _name, const char* _pFilePath)
{
    Image img = LoadImage(_pFilePath);            // 1. 그림 1장 읽기

    // 2. 캔버스 행에 오른쪽으로 이어 붙이기 (간단 버전 — 2D bin packing으로 최적화 가능)
    const _f32 w = atlas_.Width(), h = atlas_.Height();
    rect uv;
    uv.min = vec2((_f32)appendX_ / w, 0.0f);      // UV = 0~1 좌표
    uv.max = vec2((_f32)(appendX_ + img.Width()) / w, (_f32)img.Height() / h);
    appendX_ += img.Width();

    canvas_.Blit(img, uv);                        // 3. CPU 이미지에 복사
    regions_[_name] = uv;                         // 4. 이름 → UV 등록
    return true;
}

// === 3. 그리기 — 기존 API 그대로, UV만 채워주면 됨 ===
void Game::OnRender(Renderer2D& r)
{
    // 수정 전: 텍스처 3장 → 배치 3번 분리 → 3콜
    r.DrawSprite(brickTex, pos, size, tint);
    r.DrawSprite(woodTex,  pos, size, tint);
    r.DrawSprite(dirtTex,  pos, size, tint);

    // 수정 후: 아틀라스 1장 + UV만 다름 → 1콜 배칭
    rect uv;
    atlas.GetUV("brick", uv);
    r.DrawSprite(atlas.GetTexture(), pos, size, tint, 0.0f, uv.min, uv.max);
    atlas.GetUV("wood", uv);
    r.DrawSprite(atlas.GetTexture(), pos, size, tint, 0.0f, uv.min, uv.max);
    atlas.GetUV("dirt", uv);
    r.DrawSprite(atlas.GetTexture(), pos, size, tint, 0.0f, uv.min, uv.max);
}

// === 4. Fill 경로 — Fill::Texture에 이미 uv_ 인자가 있음 ===
Fill fill = Fill::Texture(atlas.GetTexture(), rect(uv));   // 이미 가능한 시그니처
```

### 주의 사항
1. **경계 이음새**: Linear 필터로 UV 경계를 샘플링하면 옆 그림이 비칠 수 있음 → UV를 반 픽셀 안쪽으로 보정(inset) 필요
2. **단색도 아틀라스에 흰색 영역을 넣으면** 단색 + 스프라이트가 한 배치로 통합 가능
3. 용량: 그림을 계속 붙이면 텍스처가 커짐 → 시트 분할 또는 packing 최적화 필요
