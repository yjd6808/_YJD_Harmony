### Phase 4에서 알아낸 것 (중요 — 신규)

1. **멤버 함수와 struct 템플릿의 이름 숨김 함정**: `HashMap::Bucket()` 멤버 함수가 클래스 스코프에서 namespace의 `struct Bucket` 템플릿을 가림 → 중첩 struct 안의 `using TBucket = Bucket<TKey,TValue,TAllocator>`가 C2061('Bucket' syntax error) + 연쇄(C2027 undefined type, C2061 'TBucket', `_pCurrentBucket` undeclared). **해결: `::jc::Bucket<...>` 네임스페이스 한정으로 숨김 회피**. HashMapIterator.h에서는 에러 없었던 이유 — HashMap 클래스 스코프 밖이므로
2. **클래스 스코프 이름 조회는 선언 위치와 무관** (전체 클래스 스코프) — 그래서 중첩 struct `Iterator`의 반환 타입 사용은 OK였지만, **클래스 템플릿 `jc::Iterator`와의 충돌**은 회피 불가 → 멤버 함수 반환 타입에 중첩 타입 이름을 쓰는 건 파싱 시점 문제로 C2955 가능. **해결: `auto Keys()/Values()`, `auto Begin()/End()` 후행 추론** (함수 본문은 인스턴스화 시점 해석이라 완전 타입 사용 가능). Keys/Values 반환 타입이 완전 정의 전이면 C2027 (auto는 본문에서만 추론되므로 안전)
3. **HashTable.h에 HashTable 템플릿 2개 존재**: `HashTable<TKey, TAllocator>`(HashSet용, 20행~, `TBucket* Bucket(int) const` 302행) / `HashTable<TKey, TValue, TAllocator>`(HashMap용, 556행~, 922행). `pHeadBucket_/pTailBucket_`는 protected — friend 선언으로 HashMap/HashMapIterator/Properties/CPropertiesIterator가 접근. `Bucket`의 `size_/GetAt(int)/pNext_/pPrevious_`는 public (이터레이터 접근)
4. **C2903 함정(이전부터)**: CDefaultAllocator 전방 선언만 있는 헤더들 — 완전 정의는 `jc/Allocator/DefaultAllocator.h` 유일, AllocateInitStatic 사용 헤더는 반드시 include
