# 01. 선형대수 — 벡터와 행렬로 게임 세계의 좌표를 조종한다

> 관련 코드: `Projects/sgfr/Sources/sgfr/Tutorial/01_LinearAlgebra/` (`01_LinearAlgebra_Main.cpp`, `01_LinearAlgebra_Function.cpp`)
> 실행: sgfr 실행 후 콘솔 메뉴에서 **1번** 선택

## 1. 이 장에서 배우는 것

게임 속 캐릭터가 "어디에 있고, 어느 방향을 보고, 얼마나 크게 보이는가"를 정하는 모든 판단은 수학, 그중에서도 **벡터와 행렬**이라는 도구로 이루어집니다. 이 장은 윈도우도, 그래픽도 없는 순수 콘솔 튜토리얼로, 앞으로 32개 튜토리얼 전체에서 매일 쓰게 될 벡터 연산(길이·정규화·내적·외적)과 행렬 변환(이동·회전·크기·SRT 합성)을 직접 손으로 계산해가며 익힙니다.

## 2. 실행하면 보이는 것

윈도우는 하나도 뜨지 않고, 콘솔 화면에만 숫자들이 줄줄이 출력됩니다. 아래와 같은 순서로 결과가 나옵니다.

- **1. 벡터 기초**: `a = (3, 4)`의 길이가 5인 것, `a + b`, `a - b`, `a * 2`, 정규화된 `(0.6, 0.8)` 출력
- **2. 내적**: `right.Dot(right) = 1`, `right.Dot(up) = 0`, `right.Dot(-right) = -1`, `right.Dot(diag) = 0.707` 같은 값들
- **3. 외적**: `X cross Y = (0, 0, 1)` 그리고 2D 외적 `right.Cross(up)`의 양수/음수 판정
- **4. 행렬 기초**: 단위 행렬, 이동/크기/회전 행렬의 4×4 격자 출력, 그리고 `(1,0,0)`을 Z축 90도 회전하면 `(0,1,0)`이 됨
- **5. 변환 순서**: "회전 후 이동" `(10, 1, 0)` vs "이동 후 회전" `(0, 11, 0)` — 똑같은 두 행렬을 곱하는 순서만 바꿨는데 결과가 완전히 달라집니다.

## 3. 핵심 개념 — 비유로 먼저 이해하기

### 3-1. 벡터 = 화살표

벡터는 **크기(길이)와 방향**을 가진 화살표입니다. "집에서 학교까지 북쪽으로 500m"라는 안내는 화살표 하나로 표현할 수 있습니다. 게임에서는 캐릭터의 위치, 속도, 바라보는 방향, 빛이 오는 방향 등이 전부 벡터입니다. 화살표는 이어붙이면 더해지고(걷는 방향 + 바람 방향), 뒤집으면 빼지고, 늘리면 길이만 변합니다.

### 3-2. 내적 = 방향이 얼마나 같은가

손전등을 든 사람이 "적이 내 앞에 있는가, 뒤에 있는가?"를 판단하는 방법이 바로 내적입니다. 내적은 두 화살표가 **얼마나 같은 방향을 보고 있는지**를 숫자 하나로 알려주며, 값이 +1이면 정확히 같은 방향, 0이면 수직, -1이면 정반대입니다. 부호만 봐도 "앞/뒤"를 알 수 있어서 조명 계산과 시야 판정의 핵심입니다.

### 3-3. 외적 = 수직인 화살표 만들기

벽을 칠할 때 벽에 수직으로 세우는 줄자처럼, 외적은 두 화살표에 **동시에 수직인 새 화살표**를 만들어냅니다. 3D에서는 평면의 법선(면이 바라보는 방향)을 구할 때, 2D에서는 "이 물체가 내 왼쪽에 있나 오른쪽에 있나"를 판정할 때 쓰입니다.

### 3-4. 행렬 = 좌표 변환 기계

행렬은 **하나의 기계**라고 생각하면 쉽습니다. 점 하나를 넣으면 이동/회전/크기 중 원하는 변환을 거친 새 점이 나옵니다. 기계를 여러 대 이어 붙이면(행렬 곱셈) 점이 한 번에 여러 변환을 통과합니다. 다만 기계의 **배치 순서가 결과를 바꿉니다** — "돌리고 나서 옮기기"와 "옮기고 나서 돌리기"는 전혀 다른 결과입니다. 화장실에서 몸을 돌린 뒤 물을 켜는 것과, 물을 켠 뒤 돌리는 것의 차이와 같습니다.

## 4. 초보자 용어 사전

| 용어 | 뜻(쉬운 말) | 비유 |
|---|---|---|
| 벡터 (Vector) | 크기와 방향을 가진 값 | 화살표 |
| 정규화 (Normalize) | 길이를 1로 만들기 (방향은 그대로) | "이 방향으로 1m만" 보정 |
| 내적 (Dot) | 두 방향의 일치 정도 | 방향을 보는 손전등 각도 |
| 외적 (Cross) | 두 벡터에 수직인 벡터 | 벽에 수직인 줄자 |
| 행렬 (Matrix) | 점을 변환하는 4×4 숫자 격자 | 좌표 변환 기계 |
| 단위 행렬 (Identity) | 아무것도 안 하는 행렬 | 곱해도 그대로인 1 |
| SRT | 크기→회전→이동 순서의 합성 | 옷 입는 순서 |
| row-major | 행 우선 저장 방식, v' = v·M 규약 | 왼쪽부터 읽는 문장 |
| TransformPoint | 행렬로 점을 변환 | 기계에 점 투입 |
| 동차 좌표 (w) | 2D/3D 점을 4차원으로 표현해 이동까지 행렬로 처리 | 통장에 1원을 항상 넣어둠 |

## 5. 코드 워크스루

`01_LinearAlgebra_Main.cpp`의 `LinearAlgebra_Main()` 함수 하나로 전체가 진행되며, 윈도우·디바이스 없이 순수 계산만 합니다.

### 5-1. 벡터 기초 (코드 36~49행)

```cpp
const vec2 a(3.0f, 4.0f);
const vec2 b(1.0f, 0.0f);
PrintVec2("a + b", a + b);
jc::Console::Write("a.Length()            = %.3f (기대값: 5)\n", a.Length());
PrintVec2("a.Normalized()", a.Normalized());
```

- `a + b`는 성분끼리 더합니다 — 화살표 이어붙이기.
- `a.Length()`는 피타고라스 정리로 `sqrt(3²+4²) = 5`.
- `a.Normalized()`는 길이 5로 나눠 `(0.6, 0.8)` — 방향은 그대로인 길이 1짜리 화살표.

### 5-2. 내적 (코드 63~70행)

```cpp
jc::Console::Write("right.Dot(right)  = %.3f (같은 방향: +1)\n", right.Dot(right));
jc::Console::Write("right.Dot(up)     = %.3f (수직: 0)\n", right.Dot(up));
jc::Console::Write("right.Dot(-right) = %.3f (반대: -1)\n", right.Dot(-right));
```

내적 공식은 `a.Dot(b) = |a||b|cosθ` 입니다. 부호만으로 앞/뒤/수직을 판정할 수 있다는 것이 핵심이며, 나중에 14번 조명 튜토리얼의 람버트 라이트에 그대로 쓰입니다. (11번 카메라는 뷰 행렬 계산과 줌, 이동만 다룹니다.)

### 5-3. 외적 (코드 81~85행)

```cpp
const vec3 xAxis = vec3::Right();
const vec3 yAxis = vec3::Up();
PrintVec3("X cross Y", xAxis.Cross(yAxis));   // (0, 0, 1) = Z축
jc::Console::Write("right cross up (2D) = %.3f (양수: up은 right의 반시계 방향)\n", right.Cross(up));
```

3D 외적 `Cross`는 두 벡터에 모두 수직인 벡터를 반환합니다. 왼손 좌표계인 DX에서 X×Y = Z가 됩니다. 2D 외적은 스칼라로 반환되며, 부호로 b가 a의 왼쪽(양수)/오른쪽(음수)인지 판정합니다.

### 5-4. 행렬 기초 (코드 92~99행)

```cpp
PrintMat4("Translation(10, 20, 0)", mat4::Translation(10.0f, 20.0f, 0.0f));
PrintVec3("(1,0,0)을 Z축 90도 회전", mat4::RotationZ(jc_math_deg2rad(90.0f)).TransformPoint(p));
```

`PrintMat4`는 4행을 한 줄씩 `| ... |` 격자로 출력합니다. 행렬의 **4번째 행 `m[3][0..2]`에 이동 성분**이 들어가 있는지 직접 눈으로 확인하는 것이 이 부분의 목적입니다. `TransformPoint`는 점을 행렬에 태워 변환한 결과를 돌려줍니다.

### 5-5. 변환 순서 (코드 110~119행)

```cpp
PrintVec3("회전 -> 이동 (R*T)", (r * t).TransformPoint(p));	// (10, 1, 0) 부근
PrintVec3("이동 -> 회전 (T*R)", (t * r).TransformPoint(p));	// (0, 11, 0) 부근
```

행벡터 규약에서는 **왼쪽에 있는 행렬이 먼저 적용**됩니다. `R * T`는 "먼저 돌고, 그 다음 옮기라"는 뜻이라 점이 `(10, 1, 0)`으로 이동하고, `T * R`은 "먼저 옮기고 돌려라"라서 원점 주위를 크게 공전한 `(0, 11, 0)`이 됩니다. 같은 행렬 두 개를 순서만 바꿔 곱했는데 결과가 전혀 다릅니다.

마지막의 `mat4::SRT2D(vec2::One(), jc_math_deg2rad(90.0f), vec2(10.0f, 0.0f))`는 내부적으로 `Scale * RotationZ * Translation`을 한 번에 합성하는 헬퍼로, 10번 월드 변환 튜토리얼에서 태양의 월드 행렬을 만드는 바로 그 함수입니다.

## 6. GPU와 DX11, 하드웨어 깊이 보기

이 튜토리얼은 순수 CPU 계산이지만, 그 계산이 GPU에서 **어떤 하드웨어 유닛으로 실행되는지**를 미리 아는 것은 이후 튜토리얼을 이해하는 지름길입니다.

### 6-1. 벡터/행렬 연산은 GPU의 "ALU 파이프라인"에서 실행된다

게임의 행렬 연산은 CPU가 아니라 GPU의 셰이더 유닛(Shader Unit)에서 실행됩니다. 현대 GPU는 수천 개의 셰이더 코어(예: NVIDIA Turing의 CUDA 코어, AMD의 스트림 프로세서)를 가지며, 각 코어는 내부에 32비트 부동소수점(FP32) 연산을 하는 **ALU(Arithmetic Logic Unit)**와 FMA(Fused Multiply-Add) 유닛을 갖추고 있습니다. 행렬 곱셈 한 번은 수십 회의 "곱하기+더하기"로 분해되며, 이 모든 것은 FMA 한 사이클로 처리됩니다. 4×4 행렬 변환(`TransformPoint`)은 정점마다 16번의 곱셈·덧셈이 필요한데, GPU는 이를 SIMD(단일 명령 다중 데이터) 방식으로 여러 정점에 동시에 적용합니다.

### 6-2. DX11에서 행렬을 표현하는 방식: row-major 규약의 의미

Direct3D 11은 HLSL에서 기본적으로 **행 우선(row-major) 저장 + 행벡터 곱셈(v·M)** 규약을 사용합니다. 이것이 이 튜토리얼의 "왼쪽 행렬이 먼저 적용" 규칙이 하드웨어와 맞물리는 이유입니다. CPU 쪽 C++ 구조체 `mat4`는 `float m[4][4]`로 저장되며, `TransformPoint`는 다음을 계산합니다:

```
result.x = p.x*m[0][0] + p.y*m[1][0] + p.z*m[2][0] + m[3][0]
result.y = p.x*m[0][1] + p.y*m[1][1] + p.z*m[2][1] + m[3][1]
result.z = p.x*m[0][2] + p.y*m[1][2] + p.z*m[2][2] + m[3][2]
```

이때 `m[3][0..2]`가 이동 성분인데, 이는 행렬을 메모리에 연속적으로 저장했을 때 **4번째 행이 마지막 12바이트에 위치**한다는 의미입니다. GPU로 데이터를 보낼 때 이 메모리 배치가 HLSL 셰이더의 `float4x4`와 1:1로 대응해야 합니다(이 규약 때문에 06번 튜토리얼에서 상수 버퍼의 16바이트 정렬을 강조합니다).

### 6-3. 동차 좌표(w)와 하드웨어의 고정기능: 왜 4×4 행렬인가

3D 점은 벡터 3개(x,y,z)로 표현할 수 있는데 왜 4×4 행렬을 쓸까요? 그 이유는 **이동(Translation)을 행렬 곱셈으로 표현**하기 위해서입니다. 3×3 행렬로는 회전·크기만 가능하고, 이동은 별도의 덧셈이 필요합니다. 동차 좌표계는 점에 w=1을 추가해 4차원 벡터 (x,y,z,1)로 만드는데, 이러면 이동까지도 행렬 곱셈 하나로 통일됩니다. HLSL 셰이더에서 `float4(position, 1.0f)`라고 적는 것(05번 튜토리얼의 `VSMain` 내부)이 바로 이 동차 좌표 사용입니다.

하드웨어 측면에서 흥미로운 점은, 모던 GPU가 더 이상 고정기능 변환 유닛(Fixed-Function T&L)을 따로 두지 않는다는 것입니다. D3D9 시절에는 "변환·조명 엔진"이 GPU에 하드웨어로 박혀 있었지만, D3D10/11부터는 모든 변환이 프로그래머블 셰이더(Vertex Shader)의 ALU에서 처리됩니다. 즉 이 장에서 배운 행렬 곱셈은 미래의 셰이더 코드에서 그대로 하드웨어 ALU의 FMA로 실행됩니다.

### 6-4. 내적/외적의 SIMD 구현과 정밀도

GPU의 벡터 ALU는 4성분(float4) 연산을 한 번에 처리하도록 설계되어, `dot`(내적)는 곱셈 4회+덧셈 트리로, `cross`(외적)는 6회 곱셈과 3회 뺄셈으로 매우 빠르게 실행됩니다. 주의할 점은 FP32 정밀도입니다. 아주 큰 좌표(수만 유닛 떨어진 곳)에서 길이를 구하면 부동소수점 오차가 생길 수 있는데, 이 때문에 게임 엔진은 캐릭터 주변 기준으로 좌표를 다시 계산(리베이스)하는 기법을 씁니다. 이 튜토리얼의 `Length()`가 `sqrt(x²+y²)`을 그대로 쓰는 반면, 실전에서는 수치 안정성을 위해 오차가 적은 기법을 쓰기도 합니다.

### 6-5. sin/cos과 삼각함수 하드웨어

`RotationZ(jc_math_deg2rad(90.0f))`처럼 회전 행렬에는 sin/cos이 들어갑니다. GPU 셰이더 유닛은 SFU(Special Function Unit)라는 전용 유닛으로 sin, cos, exp, log, sqrt를 하드웨어 가속합니다. CPU에서의 `std::sin`보다 훨씬 빠른 근사 계산을 제공하며, 그래서 06번 튜토리얼부터는 애니메이션에서 매 프레임 sin을 마음껏 사용할 수 있는 것입니다.

### 6-6. 행렬 곱셈의 비용: FMA 카운트와 셰이더 최적화의 기초

4×4 행렬 곱셈은 64회의 곱셈과 48회의 덧셈, 즉 112회의 스칼라 연산이 필요합니다. GPU의 FMA 명령은 곱셈과 덧셈을 한 사이클에 묶어 처리하므로, 실질 비용은 대략 64회의 FMA입니다. 정점 변환 `v·M`은 이보다 가벼워서 4개의 내적(각각 FMA 4회)으로 계산됩니다. 이 숫자들을 알면 왜 "셰이더에서 매 프레임 행렬을 다시 만들지 않고" 상수 버퍼로 한 번만 보내는지 이해할 수 있습니다 — 수백만 정점이 각각 64회의 FMA를 한다고 상상해 보십시오. 06번의 상수 버퍼와 10번의 월드 변환이 이 비용 관점에서 자연스럽게 이어집니다.

## 7. 핵심 규칙 요약

- [ ] 벡터는 크기+방향. 길이는 피타고라스, 정규화는 길이 1로 만들기.
- [ ] 내적 `a·b = |a||b|cosθ` — 양수면 같은 방향(앞), 음수면 반대(뒤), 0이면 수직.
- [ ] 3D 외적 = 두 벡터에 수직인 벡터(법선), 왼손 좌표계에서 X×Y = Z.
- [ ] 2D 외적의 부호 = 왼쪽(양수)/오른쪽(음수) 판정.
- [ ] **행벡터 규약 v' = v·M → 왼쪽 행렬이 먼저 적용.** SRT는 `M = S * R * T`.
- [ ] 이동 성분은 행렬의 4번째 행 `m[3][0..2]`에 저장.
- [ ] 회전 후 이동(R·T) vs 이동 후 회전(T·R)은 결과가 다름 — 순서는 의미 있다.
- [ ] 각도는 항상 라디안(`jc_math_deg2rad`)으로 변환해 사용.
- [ ] `SRT2D`는 Scale×RotationZ×Translation 합성 헬퍼 (10번 월드 변환에서 사용).
