# 24. 셰이딩 모델 — 빛 반사의 수식 근사 (램버트/퐁/블린-퐁)

> 관련 코드: `Projects/sgfr/Sources/sgfr/24_ShadingModel/` (`24_ShadingModel_Main.cpp`, `24_ShadingModel_Function.cpp`)
> 엔진 코드: `Projects/sgf/Sources/sgf/Graphics/Shader.h/.cpp`, `Buffers.h` (ConstantBuffer), `Vertex.h` (VertexPNT)
> 실행: sgfr 실행 후 콘솔 메뉴에서 **24번** 선택
> 선행 학습: 14번(라이팅 — 람버트 확산광), 13번(3D 큐브), 22번(렌더 루프)

## 1. 이 장에서 배우는 것

**셰이딩(Shading)** = 빛이 표면에서 어떻게 반사되는지를 수식으로 흉내 내는 작업임을 배우고, 세 가지 모델 — **램버트**(확산만), **퐁**(반사 벡터 R·V), **블린-퐁**(하프 벡터 N·H) — 의 차이를 직접 비교합니다. 정반사광에 카메라 위치(시선 벡터)가 필요한 이유를 이해하고, 부수적으로 UV 구(Sphere) 지오메트리를 `jc::Vector`로 직접 생성해 그리는 방법도 익힙니다.

## 2. 실행하면 보이는 것

주황색 UV 구가 천천히 자전하고, **빛이 구 주위를 돌면서** 명암 경계가 움직입니다. 창 제목에 현재 모드와 날카로움이 표시됩니다.

| 키 | 동작 |
|---|---|
| `1` / `2` / `3` | 램버트(확산만) / 퐁(R·V) / 블린-퐁(N·H) |
| `↑` / `↓` | 날카로움(SpecPower) 2~256 증감 (2배/절반) |
| `ESC` | 종료 |

관찰 포인트:

1. **1번(램버트)은 반짝임이 전혀 없습니다.** 무광택 표면(분필, 천)처럼 보입니다.
2. **2번(퐁)**과 **3번(블린-퐁)**은 하이라이트가 생기고, 모양이 미묘하게 다릅니다. 퐁은 반사 벡터 기반이라 하이라이트가 주변보다 넓게 퍼지는 경향이 있고, 블린-퐁은 더 둥글고 자연스럽습니다.
3. `↑`를 누르면 SpecPower가 커져 **작고 선명한** 하이라이트(매끈한 표면 느낌), `↓`는 크고 흐릿한 하이라이트(거친 표면 느낌)가 됩니다.

## 3. 핵심 개념 — 비유로 먼저 이해하기

### 3-1. 셰이딩 = "물체가 빛을 받는 모습을 계산하는 요리"

빛이 표면에 닿으면 세 갈래로 갈라집니다.

- **주변광(Ambient)**: 어디서 왔는지 모를 은은한 빛. 방 안의 간접광처럼 모든 면을 조금씩 밝힙니다 (여기서는 상수 0.15).
- **확산광(Diffuse)**: 표면이 빛을 **정면으로 마주볼수록** 밝게 반사하는 성분. 각도가 벌어질수록 어두워집니다 (램버트 법칙: `max(0, N·(-L))`).
- **정반사광(Specular)**: 거울처럼 특정 방향으로만 반사하는 **하이라이트**. 빛이 반사되는 방향(또는 하프 벡터)이 눈에 닿아야 보입니다. 그래서 **카메라 위치가 필요합니다.**

### 3-2. 세 모델 = "하이라이트 계산 공식의 세 버전"

| 모델 | 하이라이트 조건 | 수식 | 특성 |
|---|---|---|---|
| 램버트 | 없음 | 확산광만 | 무광택 (분필) |
| 퐁 | 반사 벡터 R과 시선 V의 일치도 | `pow(saturate(dot(R, V)), n)` | 전통적, reflect 계산 |
| 블린-퐁 | 하프 벡터 H와 법선 N의 일치도 | `pow(saturate(dot(N, H)), n)` | 퐁보다 싸고 자연스러움 → 현대 표준 |

비유: 당구공의 반사를 봅시다. **퐁**은 "빛이 공에 맞고 튕겨 나가는 방향(R)을 계산해, 그 방향을 정확히 바라보는 관찰자에게만 반짝임을 보여주는" 방식입니다. **블린-퐁**은 "관찰자와 빛의 **중간 방향(H)**이 공 표면의 수직선(N)과 얼마나 일치하는지"로 반짝임을 계산합니다. 중간 방향을 구하는 것이 반사 벡터를 구하는 것보다 계산이 싸고(reflect 수식에 비해) 결과도 부드러워서 현대 엔진의 표준이 되었습니다.

### 3-3. UV 구 = "지구본을 만드는 방법"

구는 위도(ring)와 경도(segment)로 나뉜 격자입니다. 각 격자점의 위치는 구면 좌표 `(sinφ·cosθ, cosφ, sinφ·sinθ)`로 구하는데, 이 값은 **반지름 1짜리 단위 방향 벡터**이므로 그 자체가 법선입니다. 그래서 `position = normal × radius`로 위치를 구하고 UV는 `(seg/segments, ring/rings)`로 매깁니다. 경도 마지막 열(`seg == segments`)은 첫 열과 위치가 같지만 UV가 다르므로 **이음자리를 위해 복제**해서 만듭니다.

## 4. 초보자 용어 사전

| 용어 | 뜻(쉬운 말) | 비유 |
|---|---|---|
| 셰이딩(Shading) | 빛 반사를 수식으로 근사해 색 계산 | 채색 방법 계산 |
| 주변광(Ambient) | 방향 없는 기본 밝기 | 방의 간접 조명 |
| 확산광(Diffuse) | 빛을 마주보는 정도에 비례하는 밝기 | 종이에 비친 빛 |
| 정반사광(Specular) | 방향성 있는 반짝임 | 거울/유리의 반사 |
| 램버트 법칙 | `max(0, N·(-L))`: 표면이 빛과 수직일수록 밝음 | 얼굴을 정면으로 마주할수록 잘 보임 |
| 반사 벡터 R | `reflect(L, N)`: 빛이 표면에 튕긴 방향 | 당구공 반사각 |
| 하프 벡터 H | `normalize(-L + V)`: 빛과 시선의 중간 방향 | 두 사람 사이의 정중앙 |
| SpecPower | 하이라이트 날카로움 (클수록 작고 선명) | 반짝임의 집중도 |
| 법선(Normal) | 표면이 향하는 방향 (길이 1) | 표면의 화살표 |
| UV 구 | 위도/경도 격자로 만든 구 | 지구본 격자 |

## 5. 코드 워크스루

`ShadingModel_Main()`의 흐름을 따라갑니다.

### 5-1. UV 구 지오메트리 생성

```cpp
jc::Vector<VertexPNT> vertices;
jc::Vector<_u32> indices;
GenerateSphere(vertices, indices, 1.0f, 32, 32);   // 반지름 1, 위도 32 x 경도 32

VertexBuffer vb;  IndexBuffer ib;
vb.Create(&device, vertices.Source(), sizeof(VertexPNT), vertices.Size());
ib.Create(&device, indices.Source(), indices.Size());
```

`GenerateSphere`(24_ShadingModel_Function.cpp)는 ring 0~32, seg 0~32를 순회하며 `(rings+1) × (segments+1)` = 1089개 정점을 만들고, 격자 한 칸마다 인덱스 6개(삼각형 2개)로 `_rings × _segments × 6` = 6144개 인덱스를 만듭니다. 정점당 `position_`, `normal_`, `uv_`가 있는 `VertexPNT`입니다.

```cpp
// 인덱스 생성: 격자 한 칸을 삼각형 2개로 분할 (밖에서 볼 때 시계 방향)
const _u32 i0 = ring * columns + seg;      // 왼위
const _u32 i1 = i0 + 1;                    // 오른위
const _u32 i2 = i0 + columns;              // 왼아래
const _u32 i3 = i2 + 1;                    // 오른아래
// (i0, i1, i2) 와 (i2, i1, i3) 푸시
```

### 5-2. 상수 버퍼 2종: b0 변환, b1 셰이딩

```cpp
struct CbTransform
{
	mat4 world_;    // 모델 -> 월드 (법선 변환에 필요)
	mat4 wvp_;      // 합성 변환
};

struct CbShading
{
	vec3 lightDir_;   // 빛이 나아가는 방향
	_s32 mode_;       // 0=램버트, 1=퐁, 2=블린-퐁
	vec3 cameraPos_;  // 월드 공간 카메라 위치
	_f32 specPower_;  // 하이라이트 날카로움
	color baseColor_; // 물체 기본색 (주황)
};
```

`CbShading`은 `vec3+int`(16바이트) + `vec3+float`(16바이트) + `color`(16바이트) = **48바이트**로 정확히 16바이트의 배수입니다. `_s32 mode_`와 `_f32 specPower_`가 각각 vec3 뒤의 네 번째 슬롯을 채우는 "vec3 + 스칼라 한 칸" 패킹입니다.

### 5-3. 렌더 루프: 빛과 상수 갱신

```cpp
const mat4 world = mat4::RotationY(elapsed * 0.3f);   // 구 자전
const _f32 lightAngle = elapsed * 0.7f;
const vec3 lightDir = vec3(cosf(lightAngle), -0.6f, sinf(lightAngle)).Normalized();

CbTransform cbT;
cbT.world_ = world;
cbT.wvp_ = world * view * proj;
cbTransform.UpdateAndBind(&device, cbT, 0);   // b0

CbShading cbS;
cbS.lightDir_ = lightDir;
cbS.mode_ = mode;
cbS.cameraPos_ = cameraPos;                   // (0, 0.8, -3)
cbS.specPower_ = specPower;                   // 기본 32
cbS.baseColor_ = color(0.9f, 0.45f, 0.2f, 1.0f);   // 주황 도자기
cbShading.UpdateAndBind(&device, cbS, 1);     // b1

vb.Bind(&device);  ib.Bind(&device);  shader.Bind(&device);
device.Context()->IASetPrimitiveTopology(D3D11_PRIMITIVE_TOPOLOGY_TRIANGLELIST);
device.Context()->DrawIndexed(indices.Size(), 0, 0);
```

빛 방향은 `lightAngle`이 커지면서 구 주위를 한 바퀴 돕니다. 카메라 위치는 상수버퍼에 넣어 **픽셀마다 시선 벡터를 계산**할 수 있게 합니다. 키 처리에서 `↑/↓`는 `Clamp(specPower * 2.0f, 2.0f, 256.0f)`처럼 배율로 조절합니다.

### 5-4. 셰이더: 세 모델의 분기

24_ShadingModel_Function.cpp의 `ShadingShaderSource()` 핵심입니다.

```hlsl
float4 PSMain(VSOutput _input) : SV_TARGET
{
	float3 N = normalize(_input.normal);            // 보간된 법선 재정규화
	float3 L = normalize(gLightDir);
	float3 V = normalize(gCameraPos - _input.worldPos);  // 픽셀 -> 카메라 시선

	float ambient = 0.15f;
	float diffuse = saturate(dot(N, -L));           // 램버트

	float specular = 0.0f;
	if (gMode == 1)                                 // [퐁]
	{
		float3 R = reflect(L, N);
		specular = pow(saturate(dot(R, V)), gSpecPower);
	}
	else if (gMode == 2)                            // [블린-퐁]
	{
		float3 H = normalize(-L + V);
		specular = pow(saturate(dot(N, H)), gSpecPower);
	}

	if (diffuse <= 0.0f)                            // 등진 면: 정반사 0
	{
		specular = 0.0f;
	}

	float3 color = (ambient + diffuse) * gBaseColor.rgb + specular * float3(1,1,1);
	return float4(color, gBaseColor.a);
}
```

VS는 `output.normal = mul(float4(_input.normal, 0.0f), gWorld).xyz`(법선은 방향이라 w=0), `output.worldPos = mul(float4(_input.position, 1.0f), gWorld).xyz`(위치는 w=1)로 월드 공간 값을 픽셀 셰이더에 넘깁니다.

## 6. GPU와 DX11, 하드웨어 깊이 보기

### 6-1. 셰이더의 수식이 GPU에서 실행되는 모습

픽셀 셰이더는 **GPU의 셰이더 유닛(SM, Streaming Multiprocessor)**에서 SIMD 워프(보통 32 스레드) 단위로 실행됩니다. 이 셰이더의 각 픽셀은 다음을 수행합니다:

| 수식 | GPU 명령 수준 | 특징 |
|---|---|---|
| `normalize(x)` | RCP(역수) 1 + SQRT 1 + 곱셈 3 | 상수 레지스터의 RCP 근사 유닛 사용 |
| `dot(N, -L)` | FMA 3 | 누적곱 1명령(DP3)으로 처리 |
| `reflect(L, N)` | FMA 3~4 | `L - 2·N·(N·L)` 전개 |
| `pow(x, n)` | LOG2 + MUL + EXP2 (2~3 명령) | 거듭제곱은 로그 영역에서 계산 |
| `saturate` | 무료(클램프 유닛) | 별도 명령 비용 없음 |

즉 퐁 모드의 픽셀은 대략 15~20개 ALU 명령, 블린-퐁은 `reflect`가 `-L+V`와 `normalize(H)`로 대체되어 몇 명령 저렴합니다. 워프는 이 명령들을 **병렬로** 실행하므로, 800×600 화면의 수십만 픽셀이 수천 개 워프로 나뉘어 동시에 계산됩니다. 각 스레드는 스칼라 레지스터 파일(명령당 여러 레지스터)을 쓰고, 상수는 b0/b1 상수버퍼에서 캐시된 상수 레지스터로 접근합니다.

### 6-3. 보간과 재정규화 — 픽셀당 시선 벡터의 필요성

VS는 정점 3개의 법선과 월드 위치만 계산합니다. 삼각형 내부 픽셀은 **래스터라이저의 보간기**가 3개 정점 값을 거리 비율로 보간해 넘겨줍니다. 그런데 보간된 법선은 길이가 1이 아니므로(구면에서는 특히 왜곡), 픽셀 셰이더는 `normalize`로 **재정규화**해야 합니다. 이 보간 → 재정규화 패턴은 평면이 많은 큐브에서는 문제가 없지만 구처럼 곡면이면 명백해지는데, 이 튜토리얼의 UV 구가 정확히 그 학습 사례입니다. `V = normalize(gCameraPos - worldPos)`는 **픽셀마다** 계산되므로, 카메라 위치를 상수버퍼(b1)로 넘기지 않으면 정반사광을 계산할 방법이 없습니다 — "정반사광에는 카메라 위치가 필요하다"는 말의 하드웨어적 의미입니다.

### 6-4. 셰이더 분기와 워프의 코스트

`if (gMode == 1) ... else if (gMode == 2)`는 **동적 분기**입니다. 워프 안의 모든 스레드가 같은 gMode를 보므로 워프 내 발산은 없고(모두 같은 경로), GPU는 분기 예측 없이 한 경로만 실행합니다. 다만 gMode가 변하지 않는데도 매 픽셀 분기 비용이 있으므로, 실전 엔진은 이처럼 모드가 다른 셰이더를 **컴파일 타임 상수(매크로/변형)**로 분리해 전혀 다른 프로그램으로 만들어 버립니다 — "셰이더 변형(shader variant)" 기법입니다. 여기서는 학습을 위해 하나의 셰이더에 세 모델을 넣었습니다. 분기 결과 `diffuse <= 0`에서 specular를 0으로 밀어내는 것은 수학적 오류(빛을 등진 면에 하이라이트)를 막는 안전장치입니다.

### 6-5. 상수버퍼의 레지스터 패킹 — vec3 + 스칼라 한 칸

`CbShading`의 HLSL 선언은 `float3 gLightDir; int gMode; float3 gCameraPos; float gSpecPower; float4 gBaseColor;`입니다. HLSL cbuffer는 16바이트 단위로 패킹되므로 `float3+int`가 한 칸(16B), `float3+float`가 한 칸(16B), `float4`가 한 칸(16B) — 총 3칸 = 48바이트입니다. GPU 상수 레지스터 뱅크도 이 16바이트 워드 단위로 관리하므로, C++ 구조체가 이 배치를 똑같이 따라야 합니다. 만약 C++ 쪽에서 `vec3 lightDir_; int mode_;`가 아닌 다른 순서로 선언했다면 값이 어긋났을 것입니다. 이것이 "상수버퍼는 HLSL과 C++이 공유하는 계약"이라는 12번 학습의 실전 예제입니다.

### 6-6. 구 지오메트리와 버스

1089개 정점(각 32바이트 = 위치12+법선12+UV8)은 약 35KB, 인덱스 6144개는 약 24KB로, D3D11 버퍼 생성 시 PCIe(또는 통합 GPU 공유 메모리)로 한 번 업로드됩니다. 이후는 GPU 메모리에 상주하며 재전송되지 않습니다. 버텍스 셰이더는 정점마다 이 데이터를 스트림에서 읽어 월드/뷰/투영 변환을 수행하고, 삼각형 셋업 유닛이 32×32 격자의 삼각형 2048개를 조립해 픽셀 셰이더로 보냅니다. 이음자리(경도 마지막 열 복제) 덕분에 UV가 0→1로 텍스처를 가로지르는 지점에서도 보간이 어긋나지 않습니다.

### 6-7. 법선 변환의 w 구분 — 방향과 위치의 수학

VS에서 `mul(float4(normal, 0), gWorld)`와 `mul(float4(position, 1), gWorld)`의 차이는 행렬의 **이동(translation) 성분을 적용할지**를 결정합니다. w=0이면 행렬의 마지막 열이 0으로 곱해져 이동이 사라지고 **회전/스케일만** 적용됩니다(방향 벡터는 위치를 갖지 않으므로 옮기면 안 됨). w=1이면 이동까지 적용되어 월드 공간 좌표가 나옵니다. GPU는 이 w를 하드웨어 곱셈 유닛이 그대로 처리하므로 특별한 분기 없이 단일 명령으로 두 유형을 모두 지원합니다. 균등 스케일만 쓰는 이 장에서는 회전 행렬의 3×3 부분으로 법선이 충분히 정확히 변환되지만, 비균등 스케일이 있는 씬이라면 법선을 역전치(transpose-inverse) 행렬로 변환해야 합니다 — 디폴트 3D 셰이더가 `(float3x3)gWorld`를 쓰는 것도 같은 가정(균등 스케일) 때문입니다.

## 7. 핵심 규칙 요약

- [ ] 셰이딩 = 주변광 + 확산광 + 정반사광의 합으로 빛 반사를 근사.
- [ ] 램버트: `saturate(dot(N, -L))` — 정반사 없음 (무광택).
- [ ] 퐁: `pow(saturate(dot(R, V)), n)` — `R = reflect(L, N)`.
- [ ] 블린-퐁: `pow(saturate(dot(N, H)), n)` — `H = normalize(-L + V)`. reflect가 빠져 **저렴하고 자연스러워 현대 표준**.
- [ ] 정반사광에는 **카메라 위치(시선 벡터)**가 필요하다. → 픽셀마다 `V = normalize(gCameraPos - worldPos)`.
- [ ] 법선은 w=0(방향), 위치는 w=1로 변환. 보간된 법선은 **재정규화** 필수.
- [ ] 확산광 ≤ 0이면 정반사도 0 (등진 면의 하이라이트 오류 방지).
- [ ] 상수버퍼 16바이트 정렬: `CbShading` = vec3+int(16) + vec3+float(16) + color(16) = 48바이트.
- [ ] UV 구: 단위 구면 좌표 = 법선. 경도 마지막 열은 이음자리 UV를 위해 복제.
- [ ] SpecPower: 클수록 작고 선명한 하이라이트 (2~256).
