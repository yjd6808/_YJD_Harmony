# 26. 포스트 프로세싱 — 화면 전체를 사진 보정하듯 가공하기

> 관련 코드: `Projects/sgfr/Sources/sgfr/26_PostProcess/26_PostProcess_Main.cpp`, `26_PostProcess_Function.cpp`
> 실행: sgfr 실행 후 콘솔 메뉴에서 26번 선택 (창이 뜨면 ESC로 종료)
> 선행 학습: `25_렌더_타깃.md`

## 1. 이 장에서 배우는 것

장면을 먼저 렌더 타깃에 다 그린 뒤, **화면 전체 사각형(Fullscreen Quad)**으로 그 결과를 픽셀 단위로 가공하는 2단계 구조를 배웁니다. 그레이/세피아/반전/비네트/물결 5가지 효과의 수식을 실제 HLSL로 구현하면서, **"후보정 비용은 장면이 아니라 화면 픽셀 수에만 비례한다"**는 핵심 성질을 체험합니다.

## 2. 실행하면 보이는 것

회전하는 큐브 장면이 **노란 세로 경계선으로 좌/우로 분할**되어 보입니다.

- **왼쪽(원본, Before)**: 아무 효과 없는 장면
- **오른쪽(효과, After)**: 선택한 효과가 적용된 장면
- `0`~`5` 키로 효과를 바꾸고, `←`/`→` 방향키로 경계를 실시간으로 이동시킬 수 있습니다.
- 창 제목에 현재 효과 이름과 경계 위치가 표시됩니다. 예: `왼쪽: 원본 | 오른쪽: 세피아 (경계 50%)`

사진 앱의 필터 미리보기와 똑같은 구조로, 같은 장면의 보정 전/후를 한 화면에서 직접 비교하는 것이 목적입니다.

콘솔 설명 중 핵심 문장:

```
 핵심: 장면이 아무리 복잡해도 후보정 비용은 화면 픽셀 수에만 비례한다!
```

## 3. 핵심 개념 — 비유로 먼저 이해하기

### 3-1. "사진 찍고, 필터 입히기" 2단계

포스트 프로세싱은 두 단계입니다.

1. **촬영 단계**: 장면을 카메라(렌더 타깃)로 "사진"을 찍습니다. 이때는 어떤 필터도 없습니다.
2. **보정 단계**: 그 사진(텍스처)을 화면 전체에 내걸고, 각 픽셀에 필터 공식을 적용해 출력합니다.

음식 비유: 먼저 **요리를 완성하고(패스 1)**, 그 사진을 찍어서 **사진 앱에서 인스타 필터를 입힌다(패스 2)**. 요리를 다시 만들 필요가 전혀 없습니다. 그래서 장면이 아무리 복잡해도 필터 비용은 "사진 픽셀 수"만큼만 듭니다.

### 3-2. 풀스크린 쿼드 — 화면을 정확히 덮는 사각형

보정 단계에서 그리는 사각형은 NDC 좌표로 꼭지점이 정확히 `(-1,-1)`~`(+1,+1)`입니다. 이 사각형은 화면을 완전히 덮기 때문에 GPU가 **픽셀마다 셰이더를 정확히 한 번** 실행합니다. 화면 픽셀 수 = 셰이더 실행 횟수입니다. UV(0~1)가 그대로 텍스처 좌표가 되어, 각 픽셀은 "내 화면 위치에 해당하는 장면 색"을 샘플링합니다.

### 3-3. 효과는 "픽셀 색을 고치는 수식"이다

효과란 결국 `출력색 = f(입력색, 위치, 시간)`이라는 **색 변환 함수**일 뿐입니다.

- 그레이: 색을 밝기 하나로 압축
- 세피아: 밝기 위에 갈색 입히기
- 반전: `1 - 색`
- 비네트: **위치**가 멀수록 어둡게 (여기서 처음으로 위치가 쓰임!)
- 물결: **UV 자체를 흔들어서** 다른 곳의 색을 가져옴

### 3-4. 노란 경계선 — Before/After 비교용

픽셀의 UV.x가 `gSplit`과 거의 같으면(차이 < 0.002) 노란색을, 왼쪽이면 원본을, 오른쪽이면 효과를 출력합니다. "물리적인 두 화면"이 아니라 **하나의 셰이더가 조건문으로 나눠** 그리는 것입니다.

## 4. 초보자 용어 사전

| 용어 | 뜻(쉬운 말) | 비유 |
|---|---|---|
| 포스트 프로세싱 (Post Processing) | 장면을 그린 뒤 화면 전체에 적용하는 후처리 효과 | 사진 필터 |
| 풀스크린 쿼드 (Fullscreen Quad) | 화면을 꽉 덮는 사각형. 픽셀마다 셰이더 1회 실행 보장 | 사진 앱의 필터 미리보기 화면 |
| UV 좌표 | 텍스처 위치 (0~1). (0,0)=왼쪽 위 | 지도 좌표 |
| 그레이스케일 (Grayscale) | 색 정보를 버리고 밝기만 남기는 것 | 흑백 사진 |
| 세피아 (Sepia) | 그레이에 갈색 톤을 입혀 옛날 사진 느낌 | 빈티지 필터 |
| 비네트 (Vignette) | 화면 가장자리를 어둡게 하는 효과 | 사진 주변 감광 |
| IsKeyPressed | "막 눌린 순간" 한 번만 true (1회성 동작용) | 문을 열 때 벨 누르기 |
| IsKeyDown | "누르고 있는 동안" 계속 true (연속 동작용) | 문을 밀며 이동하기 |

### 5-3. 상수 버퍼 두 종

```cpp
struct CbPost
{
	_s32 mode_;		// 0=원본, 1=그레이, 2=세피아, 3=반전, 4=비네트, 5=물결
	_f32 time_;		// 물결 애니메이션용 누적 시간
	_f32 split_;	// Before/After 경계 (UV x, 0~1)
	_f32 padding_;	// 16바이트 정렬용 여백
};
```

HLSL의 cbuffer는 **16바이트 정렬 규칙**이 있어서 `int + float*3 = 16바이트`가 되도록 `padding_`으로 맞춥니다. `ConstantBuffer<CbPost>`는 구조체 크기가 16의 배수여야 컴파일됩니다 (`static_assert`).

### 5-4. 입력 — 숫자 키와 경계 슬라이더

```cpp
for (int k = 0; k <= 5; ++k)
{
	// '0'~'5' 숫자 키: 문자 코드와 가상 키 코드가 같다.
	if (input.IsKeyPressed('0' + k)) { effectMode = k; ... }
}

// 경계 슬라이더: 누르고 있는 동안 부드럽게 이동 (IsKeyDown)
if (input.IsKeyDown(VK_LEFT))  { split = Clamp(split - 0.4f * dt, 0.02f, 0.98f); ... }
if (input.IsKeyDown(VK_RIGHT)) { split = Clamp(split + 0.4f * dt, 0.02f, 0.98f); ... }
```

- 효과 전환은 **순간 반응**(`IsKeyPressed`)이 맞고,
- 경계 이동은 **연속 반응**(`IsKeyDown` + `dt * 속도`)이 맞습니다. 이 "용도에 따른 선택"이 28번 입력 튜토리얼의 예습이 됩니다.

### 5-7. 픽셀 셰이더 — 5가지 효과 수식

```hlsl
float4 PSMain(VSOutput _input) : SV_TARGET
{
	float2 uv = _input.uv;

	// [경계선] Before/After를 나누는 노란 세로선
	if (abs(uv.x - gSplit) < 0.002f) { return float4(1.0f, 0.85f, 0.2f, 1.0f); }

	// [Before] 경계 왼쪽: 원본 그대로
	if (uv.x < gSplit) { return gScene.Sample(gSampler, uv); }

	// [5. 물결] 샘플링 위치(UV) 자체를 사인파로 흔들어 버린다.
	if (gMode == 5)
	{
		uv.x += sin(uv.y * 30.0f + gTime * 4.0f) * 0.01f;
		uv.y += cos(uv.x * 30.0f + gTime * 4.0f) * 0.01f;
	}

	float4 color = gScene.Sample(gSampler, uv);

	if (gMode == 1)
	{
		// [1. 그레이스케일] 눈은 초록에 가장 민감 -> 가중치 평균(표준 계수)
		float gray = dot(color.rgb, float3(0.299f, 0.587f, 0.114f));
		color.rgb = float3(gray, gray, gray);
	}
	else if (gMode == 2) { ... }	// 세피아: gray * (1.07, 0.87, 0.65)
	else if (gMode == 3) { color.rgb = 1.0f - color.rgb; }	// 반전
	else if (gMode == 4)
	{
		// [4. 비네트] 화면 중심에서 멀수록 어둡게
		float dist = length(_input.uv - float2(0.5f, 0.5f));
		float vignette = saturate(1.0f - dist * 1.4f);
		color.rgb *= vignette * vignette;
	}
	return color;
}
```

- **물결**은 샘플링 *위치*를 바꾸는 점이 흥미롭습니다. UV를 흔들면 "다른 픽셀의 색"을 가져오므로 화면이 출렁이는 것처럼 보입니다. 이건 왜곡(디스토션)의 가장 단순한 형태입니다.
- **그레이스케일 가중치 0.299/0.587/0.114**는 인간 눈이 색마다 밝기 감도가 다른 것(초록에 가장 민감)을 반영한 표준 계수입니다. 단순 평균 `(R+G+B)/3`을 쓰면 똑같은 밝기여도 파란 영역이 너무 어둡게 보입니다.

## 6. GPU와 DX11, 하드웨어 깊이 보기

### 6-1. 풀스크린 쿼드가 하드웨어에서 "정확히 픽셀 1회" 보장하는 이유

풀스크린 쿼드는 화면 전체를 두 개의 삼각형으로 덮습니다. GPU의 **래스터라이저(고정기능 유닛)**는 삼각형 안에 속하는 모든 픽셀 중심(샘플 위치)에 대해 픽셀 셰이더 실행을 발행합니다. 쿼드가 화면을 빠짐없이 덮으므로 실행 횟수 = 화면 픽셀 수가 됩니다.

다만 실제 GPU는 **2x2 쿼드(quad) 단위로 픽셀 셰이더를 묶어 실행**합니다. 텍스처의 2x2 테이블에 있는 4개 픽셀의 UV가 나란히 실행되어야 파생값(derivatives)을 구할 수 있고, 샘플러가 mipmap 레벨을 정할 수 있기 때문입니다. 그래서 정확히는 "화면 픽셀 수 + 모서리 여분"만큼 실행됩니다. 이 장의 셰이더는 `Sample`을 쓰므로 이 하드웨어 파생값 기능에 의존한다고 볼 수 있습니다.

### 6-2. 후보정 비용 = 화면 픽셀 수 (ALU 관점)

효과 계산은 대부분 부동소수점 산술(ALU)입니다.

- 그레이: 내적 1회 (3 MAC) + 이동 3회
- 비네트: 제곱근(`length`) 1회, `saturate`, 곱셈 2회
- 물결: `sin/cos` 2회 — 이것은 **트랜스센덴털(초월함수) 유닛** 또는 다항식 근사(MAD 시퀀스)로 처리됩니다. 일부 GPU는 sin/cos을 특수 유닛으로, 정수부가 높은 경우에는 여러 클록이 걸립니다.

GPU는 32개~128개 이상의 ALU 코어를 묶어 SIMT(단일 명령 다중 스레드) 방식으로 픽셀을 일괄 처리하므로, 800x600=48만 픽셀은 현대 GPU 기준으로 "무시할 만한" 부하입니다. 물결을 켜도 프레임이 거의 떨어지지 않는 이유입니다.

### 6-3. 샘플링 비용 — 텍스처 캐시와 메모리 버스

후보정의 진짜 비용은 ALU보다 **메모리 대역폭**입니다.

1. 픽셀마다 `gScene.Sample()`은 VRAM의 텍스처 데이터를 읽어야 합니다.
2. GPU는 텍스처 캐시(다단계: L0/L1/L2)를 두어, 화면상으로 서로 가까운 픽셀들은 같은 텍셀 주변을 읽으므로 캐시 히트율이 매우 높습니다.
3. 캐시 미스만 실제 DRAM(VRAM)으로 내려갑니다. VRAM 대역폭이 수백 GB/s인 것을 감안하면, 48만 픽셀 x 4바이트 = 약 2MB를 읽는 것은 1/60초 안에 거뜬합니다.
4. Linear 필터는 **2x2 텍셀 보간**이라 캐시 트래픽이 약간 더 늘지만, 캐시가 이웃 텍셀을 함께 담으므로 실제 DRAM 트래픽 증가는 미미합니다.

`amClamp`(주소 모드)를 쓰는 이유는 UV가 0~1을 벗어날 때 텍스처가 반복(wrap)되면 화면 가장자리에서 잘못된 색이 물결쳐 보이기 때문입니다.

### 6-4. ROP의 역할 — 최종 출력

픽셀 셰이더가 계산한 색은 OM(Output Merger) → **ROP(Raster Operations Unit)**로 흘러갑니다. ROP는 블렌드, 깊이 테스트, 쓰기 허용(마스크)을 실제 메모리에 수행합니다. 풀스크린 쿼드 그리기에서는:

- 깊이 테스트가 꺼져 있고(2D이므로) 블렌드는 기본(불투명)이므로 ROP는 단순 색 쓰기만 수행합니다.
- 각 ROP 파티션(메모리 채널)은 화면의 한 구역을 담당하므로, 48만 픽셀 쓰기가 여러 메모리 채널에 분산되어 병렬로 완료됩니다.

### 6-5. 이 장의 파이프라인 정리 (하드웨어 여행)

```
패스1: IA(큐브 정점) → VS(WVP) → 래스터라이저 → 깊이 테스트 → PS(정점색) → ROP → sceneTarget(VRAM)
패스2: IA(쿼드 정점) → VS(NDC 통과, 무변환) → 래스터라이저 → PS(t0 샘플링+수식) → ROP → 백버퍼 → Present
```

VS가 변환 행렬 없이 NDC를 통과시키는 이유는 이미 NDC 좌표가 쿼드의 꼭지점이기 때문입니다. 뷰포트 변환 유닛만 NDC를 백버퍼 픽셀 좌표로 펼칩니다.

|---|---|---|
| `sceneTarget.Create(창 크기)` | `CreateTexture2D` + RTV/DSV/SRV | VRAM 2장(색+깊이) |
| `sceneTarget.BindAsTexture` | `PSSetShaderResources` | 텍스처 캐시 → 샘플러 |
| `cbPost.UpdateAndBind` | `Map(WRITE_DISCARD)` + `VSSet/PSSetConstantBuffers` | 상수 버퍼 (constant cache) |
| `device.SetSampler` | `PSSetSamplers` | 필터 유닛 설정 |
| `DrawIndexed(6)` | `DrawIndexed` | 래스터라이저 → 파이프라인 실행 |

## 7. 핵심 규칙 요약

- 포스트 프로세싱 = **장면 렌더 타깃 → 풀스크린 쿼드 후보정** 2패스 구조.
- 후보정 비용은 **화면 픽셀 수에만 비례**한다. 장면 복잡도와 무관!
- 풀스크린 쿼드 VS는 NDC를 **그대로 통과**시킨다 (변환 행렬 없음).
- 그레이스케일: `0.299R + 0.587G + 0.114B` (눈의 초록 민감도 반영).
- 물결 효과 = **UV 자체를 사인파로 왜곡** (위치 기반 효과의 시작).
- 비네트 = 중심에서 거리 비례 감쇠, `saturate(1 - dist*1.4)` 후 제곱.
- 효과 전환엔 `IsKeyPressed`, 연속 이동엔 `IsKeyDown` + `dt` 스케일.
- HLSL cbuffer는 16바이트 정렬 — 구조체에 `padding_`으로 맞춘다.
