# 04. 디바이스와 스왑체인 — 화면을 부드럽게 지우고 보여주기

> 관련 코드: `Projects/sgfr/Sources/sgfr/04_DeviceAndSwapChain/` (`04_DeviceAndSwapChain_Main.cpp`, `04_DeviceAndSwapChain_Function.cpp`)
> 관련 엔진: `Projects/sgf/Sources/sgf/Graphics/GraphicDevice.h`, `SwapChain.h`, `Core/FrameTimer.h`
> 실행: sgfr 실행 후 콘솔 메뉴에서 **4번** 선택
> 선행 학습: 02. 윈도우와 메시지 루프, 03. 디바이스와 컨텍스트

## 1. 이 장에서 배우는 것

창에 이제 본격적인 그래픽 장치를 연결합니다. `GraphicDevice::Initialize(HWND, w, h)`가 내부적으로 수행하는 전체 초기화 절차(D3D11CreateDeviceAndSwapChain → RTV → 깊이 버퍼/DSV → 상태 객체 → 뷰포트)를 파악하고, **스왑체인(더블 버퍼링)**이 왜 화면을 깜박임 없이 보여주는지, 왜 매 프레임 **화면을 지워야(Clear)** 하는지, 그리고 **BeginFrame/EndFrame 프레임 루프**의 완성형을 배웁니다. 실행 결과로 화면 배경색이 무지개처럼 부드럽게 순환합니다.

## 2. 실행하면 보이는 것

800×600 창이 뜨고, 배경색이 파동처럼 **무지개 색으로 부드럽게 순환**합니다. 시간이 지남에 따라 빨강→초록→파랑이 자연스럽게 섞이면서 변합니다. 이는 "지우는 색(Clear color)"이 매 프레임 조금씩 바뀌기 때문이며, 아직 아무것도 그리지 않아 "화면 지우기 그 자체"가 주제인 튜토리얼입니다. ESC 또는 창 닫기로 종료합니다.

## 3. 핵심 개념 — 비유로 먼저 이해하기

### 3-1. 스왑체인 = 무대 뒤의 무대

연극 무대에서 관객에게 보이는 **프론트 무대(프론트버퍼)**와, 다음 장면을 준비하는 **백스테이지(백버퍼)**가 분리되어 있다고 상상해 봅시다. 배우들이 백스테이지에서 미리 준비를 마치면, 무대 전체를 순식간에 통째로 바꿉니다. 만약 관객이 보는 무대에서 바로 그림을 바꾸면, 바꾸는 과정이 그대로 노출되어 깜박임이 보일 것입니다.

D3D11도 같습니다. `IDXGISwapChain`은 **백버퍼**와 **프론트버퍼** 두 장의 그림을 관리하고, 렌더링이 끝나면 `Present()`로 둘을 통째로 맞바꿉니다. 이렇게 하면 관객(모니터)은 완성된 그림만 보고, 그리는 중간 과정은 결코 볼 수 없습니다. 이것이 **더블 버퍼링**이며, 깜박임과 화면 찢어짐(tearing)이 사라지는 원리입니다. sgf의 `EndFrame(true)`가 바로 이 Present 호출입니다.

### 3-2. 매 프레임 화면을 지우는 이유 = 칠판 지우기

교실 칠판에 매일 새로운 그림을 그리려면 전날 그린 그림을 먼저 지워야 합니다. GPU 백버퍼도 마찬가지입니다 — **지난 프레임에 그린 그림이 백버퍼에 그대로 남아 있습니다.** 지우지 않고 그리면 이전 그림 위에 새 그림이 겹쳐 그려집니다. 게다가 화면의 일부만 그리는 게임은 지우지 않으면 이전 프레임 잔상이 영원히 남게 됩니다. 그래서 매 프레임 시작 시 `ClearRenderTargetView`로 단색을 채워 밀어내는 것이고, sgf의 `BeginFrame(color)`이 이 일을 합니다.

### 3-3. DeltaTime = 프레임 독립 애니메이션

빠른 컴퓨터는 초당 300프레임, 느린 컴퓨터는 30프레임일 수 있습니다. 만약 애니메이션이 "프레임마다 0.01 증가"한다면 빠른 컴퓨터에서 10배 빠르게 도는 버그가 생깁니다. 올바른 방법은 "지난 프레임에서 **몇 초**가 지났는지(DeltaTime)를 재서 곱해주는" 것입니다. 위치 += 속도 × DeltaTime 패턴이 바로 그것이고, `FrameTimer::Tick()` + `DeltaTime()`이 이 장에서 소개됩니다.

## 4. 초보자 용어 사전

| 용어 | 뜻(쉬운 말) | 비유 |
|---|---|---|
| 스왑체인 (SwapChain) | 백버퍼와 프론트버퍼를 교체하는 장치 | 무대 전환 장치 |
| 백버퍼 (Back Buffer) | 지금 그리고 있는 숨겨진 그림 | 백스테이지 |
| 프론트버퍼 (Front Buffer) | 화면에 보이는 그림 | 프론트 무대 |
| Present | 두 버퍼를 통째로 맞바꾸는 순간 | 무대 통째 전환 |
| 더블 버퍼링 | 버퍼 2장으로 깜박임 제거 | 무대+대기실 구조 |
| Clear | 매 프레임 시작에 화면을 단색으로 밀기 | 칠판 지우기 |
| RTV (RenderTargetView) | "여기에 그려라" 표시 (그리기 대상 뷰) | 화가가 바라보는 캔버스 |
| DSV (DepthStencilView) | 깊이(앞뒤) 판정용 버퍼의 뷰 | 거리 측정 자 |
| VSync (수직동기) | 모니터 주사율에 맞춰 화면 갱신 대기 | 관객 타이밍 맞추기 |
| DeltaTime | 지난 프레임에서 흐른 시간(초) | 스톱워치 초계 |
| 뷰포트 (Viewport) | NDC를 픽셀로 매핑할 화면 영역 | 캔버스에서 그릴 구역 |

## 5. 코드 워크스루

`04_DeviceAndSwapChain_Main.cpp`의 `DeviceAndSwapChain_Main()`을 따라갑니다.

### 5-1. 윈도우 생성 (코드 37~45행)

02번과 동일한 `Window::Create(L"04. 디바이스와 스왑체인 (ESC로 종료)", 800, 600)`와 `ConnectInput`입니다. 이제부터 HWND가 그래픽 초기화의 입력으로 쓰입니다.

### 5-2. 디바이스+스왑체인 초기화 (코드 54~60행)

```cpp
GraphicDevice device;
if (!device.Initialize(window.Handle(), window.Width(), window.Height()))
{
	printf("그래픽 디바이스 초기화 실패!\n");
	window.Destroy();
	return;
}
```

`Initialize(HWND, w, h)` 내부(`GraphicDevice.cpp`의 `CreateDeviceAndSwapChain`)에서 일어나는 일:

1. `D3D11CreateDeviceAndSwapChain` — **Device + Context + SwapChain**을 한 번에 생성 (DXGI 팩토리로 백버퍼 2장+포맷 협상)
2. 백버퍼에 대한 **RenderTargetView(RTV)** 생성 — "이 그림에 그려라" 표시
3. **깊이 버퍼와 DepthStencilView(DSV)** 생성 — 3D에서 앞/뒤 판정용 (13번 큐브에서 본격 사용)
4. 블렌드/깊이/래스터라이저/샘플러 **상태 객체** 생성
5. **뷰포트** 설정 — NDC 좌표(-1~+1)를 800×600 픽셀 좌표로 매핑하는 영역

이 5단계가 "GPU에 그림 그릴 준비 전체"입니다.

### 5-3. 타이머 (코드 65~68행)

```cpp
FrameTimer timer;
timer.Reset();
_f32 elapsed = 0.0f;	// 누적 시간(초)
```

`FrameTimer::Reset()`은 고해상도 카운터(QueryPerformanceCounter) 기반 타이머를 초기화합니다.

### 5-4. 렌더 루프 (코드 71~91행) — 이제부터의 표준 골격

```cpp
while (window.PumpMessage())
{
	if (input.IsKeyPressed(VK_ESCAPE)) break;
	input.NextFrame();

	timer.Tick();
	elapsed += timer.DeltaTime();

	device.BeginFrame(RainbowColor(elapsed));	// 지우기 + 그리기 대상 묶기
	device.EndFrame(true);						// Present + VSync
}
```

- `timer.Tick()` — 직전 호출로부터 경과 시간 계산, `DeltaTime()`이 초 단위로 반환
- `elapsed += timer.DeltaTime()` — 프레임마다 누적 → 이 값이 무지개 색 계산의 입력
- `BeginFrame(color)` — 백버퍼를 지정 색으로 지우고 RTV/DSV를 묶고 뷰포트 설정
- `EndFrame(true)` — 백버퍼를 프론트버퍼로 교체(Present), `true` = 수직동기화(VSync). 모니터 주사율(보통 60Hz)에 맞춰 대기하므로 화면 찢어짐이 없습니다.

### 5-5. 무지개 색 함수 (Function.cpp)

```cpp
color RainbowColor(_f32 _timeSec)
{
	const _f32 r = std::sin(_timeSec) * 0.5f + 0.5f;
	const _f32 g = std::sin(_timeSec + jc_math_deg2rad(120.0f)) * 0.5f + 0.5f;
	const _f32 b = std::sin(_timeSec + jc_math_deg2rad(240.0f)) * 0.5f + 0.5f;
	return color(r, g, b, 1.0f);
}
```

sin은 -1~+1을 부드럽게 오가므로 `* 0.5 + 0.5`로 0~1 범위로 만듭니다. R/G/B에 각각 0°/120°/240° **위상 차**를 주면 색상이 무지개처럼 도는 효과가 나옵니다.

### 5-6. 정리 (코드 94~95행)

`device.Finalize()` → `window.Destroy()` 순서로 해제합니다.

## 6. GPU와 DX11, 하드웨어 깊이 보기

### 6-1. D3D11CreateDeviceAndSwapChain의 하드웨어 협상 과정

이 함수는 한 번의 호출로 여러 계층의 초기화를 수행합니다. 먼저 DXGI(DirectX Graphics Infrastructure) 팩토리가 GPU 어댑터를 선택하고, **백버퍼 포맷(보통 DXGI_FORMAT_R8G8B8A8_UNORM)**을 협상합니다. 스왑체인 생성 시 지정하는 버퍼 수(보통 2~3장), 화면 주사율 관련 Flip 모드 설정 등이 모두 이 단계에서 GPU 디스플레이 하드웨어와의 계약으로 체결됩니다. 백버퍼 메모리는 GPU VRAM에 할당되며, 창 크기 800×600 = 480,000픽셀 × 4바이트 ≈ 1.83MB가 버퍼 2장에 약 3.7MB 사용됩니다.

### 6-2. Clear의 하드웨어 경로: 고정기능 유닛의 일괄 채우기

`ClearRenderTargetView`는 셰이더를 전혀 실행하지 않고 GPU의 **고정기능(Fixed-Function) 유닛**만 사용해 백버퍼 메모리를 일괄로 채웁니다. GPU 메모리 대역폭이 넓기 때문에 풀HD(1920×1080) 기준 약 8MB를 매 프레임 0.1ms 내외로 지울 수 있습니다. 흥미로운 점은 D3D11에서 Clear는 **즉시 실행 명령**으로, 커맨드 큐에 쌓이지 않고 다른 드로우와의 순서 보장을 위해 내부적으로 동기화 마커로 취급된다는 것입니다. 04번 튜토리얼이 "지우는 것"을 주제로 삼는 이유는, 이 명령이 프레임 루프의 첫 단계로 모든 렌더링의 전제 조건이기 때문입니다.

### 6-3. Present와 VSync: GPU 파이프라인과 모니터의 만남

`EndFrame(true)`의 Present는 두 가지 일을 합니다. 첫째, 커맨드 큐에 쌓인 모든 드로우를 GPU가 실행 완료하게 기다린 뒤(렌더 완료), 백버퍼와 프론트버퍼의 메모리 매핑을 교체합니다. 둘째, **수직동기화**로 모니터가 주사선을 처음부터 다시 그리는 순간(VBlank)에 맞춰 교체가 일어나도록 합니다. 만약 VSync 없이 아무 때나 교체하면, 모니터가 화면을 그리는 중간에 버퍼가 바뀌어 화면이 위아래로 찢어진 것처럼 보이는 **tearing**이 발생합니다. VSync를 켜면 GPU는 모니터의 주사 타이밍을 기다리므로 CPU가 자연스럽게 60fps(주사율에 맞춤)로 유지됩니다. 이것이 02번에서 본 `Sleep(1)`이 실전에서 사라지는 이유입니다 — 잠자기는 VSync 대기가 대신합니다.

### 6-4. 깊이 버퍼와 DSV: 백버퍼와 쌍을 이루는 두 번째 표면

Initialize 내부의 3번째 단계인 깊이 버퍼는 백버퍼와 크기가 같은 별도의 GPU 메모리 표면입니다(24비트 깊이 + 8비트 스텐실 포맷이 일반적). 이 튜토리얼은 2D만 다뤄 깊이 판정을 쓰지 않지만, 하드웨어적으로 OM(Output Merger) 단계는 매 픽셀마다 깊이 비교 연산을 고정기능으로 수행할 준비가 되어 있습니다. 13번 3D 큐브 튜토리얼에서 이 버퍼가 켜지는 순간을 만나게 됩니다. 깊이 버퍼도 프레임마다 Clear해야 하는데, `BeginFrame`이 RTV와 DSV를 **동시에** 지정 색과 깊이 1.0으로 지우는 이유입니다.

### 6-5. 뷰포트: NDC(-1~+1)를 픽셀(0~799, 0~599)로 매핑하는 고정기능 변환

파이프라인에서 래스터라이저는 클립 공간 좌표를 뷰포트 변환으로 픽셀 좌표로 바꿉니다. 공식은 대략 `pixelX = (ndcX * 0.5 + 0.5) * width` 입니다. 이 변환은 고정기능 유닛이 수행하며, 나중에 25번 렌더 타깃에서 "백버퍼가 아닌 다른 표면"으로 뷰포트를 바꾸는 응용으로 이어집니다. Initialize에서 뷰포트를 창 크기로 채워두는 것은 "백버퍼 전체를 캔버스로 쓰겠다"는 선언입니다.

### 6-6. 프레임 루프의 CPU-GPU 파이프라이닝

매 프레임 `BeginFrame → (그리기) → EndFrame`의 구조는 CPU와 GPU가 **파이프라이닝(동시 작업)**을 하게 합니다. CPU는 프레임 N+1의 명령을 준비하고, GPU는 프레임 N의 렌더링을 실행합니다. VSync가 있으면 이 파이프라인의 깊이는 "모니터 1프레임"으로 고정되어, CPU가 너무 앞서가지 못하게 막아줍니다. 이 장의 무지개 애니메이션이 프레임 수와 무관하게 일정한 속도로 도는 것은 `elapsed += DeltaTime` 누적 덕분입니다 — 300fps 컴퓨터든 60fps 컴퓨터든 같은 속도로 순환합니다.

### 6-7. 트리플 버퍼링과 스왑 체인 모드: 더블 버퍼링의 확장

이 장의 더블 버퍼링은 가장 기본 형태입니다. 실전 게임은 백버퍼를 3장 쓰는 **트리플 버퍼링**을 사용하기도 하는데, GPU가 이전 프레임을 그리는 동안 CPU가 다음 프레임을 준비하고, 대기 중인 버퍼가 하나 더 있어 화면 교체를 기다리지 않아도 됩니다. D3D11의 스왑 체인 생성 시 지정하는 버퍼 개수와, Present가 버퍼를 회전시키는 방식(Flip 모드)은 DXGI 계층의 설정이며, VSync를 꺼야만 하는 경쟁 게임(FPS)에서는 삼중 버퍼 + VSync 오프 조합이 표준이 되었습니다. 이 장의 `EndFrame(true)`는 이 트레이드오프의 가장 단순한 한 점일 뿐이라는 점을 기억하면, 이후 31번 파이프라인 여행에서 성능 튜닝 이야기를 들을 때 쉽게 이해할 수 있습니다.

## 7. 핵심 규칙 요약

- [ ] 스왑체인 = 백버퍼+프론트버퍼, `EndFrame(true)` = Present + VSync.
- [ ] 더블 버퍼링 덕분에 깜박임/tearing이 사라진다.
- [ ] 지난 프레임 그림이 백버퍼에 남으므로 매 프레임 Clear 필수 (`BeginFrame(color)`).
- [ ] Initialize 내부 5단계: D3D11CreateDeviceAndSwapChain → RTV → 깊이/DSV → 상태 객체 → 뷰포트.
- [ ] 애니메이션은 `elapsed += timer.DeltaTime()` 누적으로 프레임 독립적이어야 한다.
- [ ] `sin * 0.5 + 0.5` = 0~1 범위 색상 값, 위상 120° 차이 = 무지개 순환.
- [ ] VSync는 모니터 타이밍에 맞춰 대기 → CPU 프레임율이 주사율로 고정.
- [ ] 정리 순서: `device.Finalize()` → `window.Destroy()`.
