# 22. 스프라이트 애니메이션 — 시트 UV와 트위닝으로 생명 불어넣기

> 튜토리얼: `Projects/sgfr/Sources/sgfr/22_SpriteAnimation/`
> 선행 학습: `15_샘플러와_필터링.md`(UV/Point 샘플러), `16_블렌드_스테이트.md`(알파 블렌드)

---

## 1. 왜 필요한가요?

Cocos2d-x로 게임을 만들어본 사람이라면 `Animate`, `EaseOut` 같은 걸 써보셨을 겁니다.
그 기능들이 내부에서 어떻게 돌아가는지, 이 마지막 장에서 밑바닥부터 직접 만듭니다.
핵심은 단 두 가지입니다:

1. **스프라이트 시트 애니메이션**: 여러 프레임 그림을 한 장에 모아두고 UV로 오려서 보기
2. **트위닝(이징)**: 위치/크기 같은 값을 시간에 따라 "어떤 곡선으로" 변화시킬지

> **비유**: 스프라이트 시트는 영화 필름과 같습니다. 필름 한 벌(텍스처 한 장)에 장면들이 격자로 박혀 있고,
> 영사기(UV 오프셋)가 한 칸씩 옮겨 보여주면 그림이 움직이는 것처럼 보입니다.

---

## 2. 개념 설명

### 2-1. 시트에서 프레임 꺼내기 — UV 오프셋 계산

4×4 = 16프레임 시트라면 한 프레임의 UV 폭은 1/4 = 0.25입니다.
n번째 프레임(0부터 시작)의 UV 사각형은:

```cpp
int col = n % 4;              // 열: 0,1,2,3,0,1,2,3,…
int row = n / 4;              // 행: 0,0,0,0,1,1,1,1,…
float u0 = col * 0.25f;       // 왼쪽 위 UV
float v0 = row * 0.25f;
float u1 = u0 + 0.25f;        // 오른쪽 아래 UV
float v1 = v0 + 0.25f;
```

그리고 현재 프레임 번호는 시간으로 계산합니다:

```cpp
int frame = (int)(elapsed * animFps) % 16;   // 초당 animFps장씩 순환
```

프레임마다 UV가 바뀌므로 정점 버퍼를 매 프레임 갱신합니다. 그래서 `VertexBuffer::Create`의 `bDynamic = true`옵션과 `Update`가 여기서 활약합니다.

### 2-2. 이징(Easing) — 움직임의 성격

점 A에서 B로 이동할 때, 같은 1초라도 "어떤 속도 곡선으로" 가느냐에 따라 느낌이 완전히 달라집니다.
수학적으로는 진행도 t(0~1)를 보정된 진행도 t'(0~1)로 바꾸는 함수일 뿐입니다.

| 이징 | 수식 | 느낌 |
|---|---|---|
| Linear | `t' = t` | 기계적, 무미 |
| Smoothstep | `t' = t²(3-2t)` | 시작과 끝이 부드러움 — 카메라 이동 등 만능 |
| EaseOutBounce | 7.5625 계수의 구간별 포물선 | 도착해서 통통 튀 — UI 팝업, 떨어지는 아이템 |

보정된 t'를 `Lerp(시작값, 끝값, t')`에 넣으면 끝입니다. 모든 트위닝 라이브러리(Cocos2d-x의 EaseXxx 포함)가 이 구조입니다.

### 2-3. 핑퐁(Ping-Pong) 순환

캐릭터가 좌↔우를 왕복하려면 t를 0→1→0→1…로 접어야 합니다:

```cpp
float cycle = fmodf(elapsed * speed, 2.0f);      // 0 ~ 2 순환
float t = (cycle < 1.0f) ? cycle : 2.0f - cycle; // 0→1→0 접기
```

### 2-4. 15·16장 지식의 총동원

- 도트 감성의 픽셀아트 스프라이트 → **Point 샘플러** (뻑지면 안 됨!) + **Clamp**
- 캐릭터 주변의 투명 영역 → **Alpha 블렌드**

마지막 장답게 지금까지 배운 것이 모두 합첨됩니다.

## 3. 코드 따라가기 — 22번 튜토리얼

### 3-1. 시트를 코드로 생성

외부 그림 파일 없이 256×256 RGBA 배열에 4×4 = 16프레임을 직접 그려 `Texture::CreateFromMemory`로 올립니다.
각 프레임에는 프레임 번호에 따라 회전·크기가 변하는 도형이 그려져 있어, 재생하면 빙글빙글 도는 애니메이션으로 보입니다.
(11번 PNG 장에서 배운 대로, 실전에서는 아틀라스 PNG를 로드해서 쓰면 됩니다)

### 3-2. 화면 구성

애니메이션 스프라이트가 핑퐁으로 좌↔우를 왕복합니다. `posX = Lerp(-0.6, 0.6, 이징(t))`

### 3-3. 조작법

```
[1] Linear  [2] Smoothstep  [3] EaseOutBounce
[↑/↓] 애니메이션 FPS ±4 (4 ~ 60)
```

1/2/3을 바꿔가며 같은 왕복 움직임의 "성격"이 바뀌는 걸 느껴보세요. 특히 3번 바운스의 통통 튀는 느낌을요.
↓로 FPS를 4까지 내리면 애니메이션이 뚝뚝 끊기지만 이동은 부드러운 것도 관찰하세요 — "프레임 애니메이션 FPS"와 "게임 렌더링 FPS"는 별개의 개념입니다.

## 4. 직접 해보기

1. 이징 함수를 하나 추가해보세요: EaseInQuad `t' = t²` (천천히 출발해서 가속). `ApplyEasing`에 case만 늘리면 됩니다.
2. 샘플러를 Linear로 바꿔보세요. 프레임 경계의 이웃 프레임 색이 번지는 "비밀이 샐" 현상을 볼 수 있습니다. 실무에서는 프레임 사이에 여백(padding)을 두어 해결합니다.
3. 핑퐁 대신 한 방향 순환(`fmodf(t, 1.0f)`)으로 바꿔 벨트 컸베이어처럼 만들어보세요.
4. 애니메이션 순서를 역재생해보세요: `frame = 15 - frame`.

## 5. 정리 — 그리고 22장 전체를 돌아보며

- 스프라이트 애니메이션 = 시트 텍스처 + 시간에 따른 UV 오프셋
- 트위닝 = 진행도 t를 곡선 함수로 보정해 Lerp에 넣는 것
- 픽셀아트는 Point 샘플러, 투명 스프라이트는 Alpha 블렌드 — 앞 장 지식의 실전 응용

이것으로 22개 챕터가 끝났습니다. 돌아보면:

- **01~09**: 수학 → 윈도우 → 디바이스 → 파이프라인 → 셰이더 → 버퍼 → 변환 → 카메라 → 3D (기초 골격)
- **10~14**: 빛 → 텍스처 → 입력 → 씬 그래프 (살붙이기)
- **15~22**: 샘플러 → 블렌드 → 래스터라이저 → 셰이딩 → 렌더 타깃 → 포스트 프로세싱 → 그림자 → 애니메이션 (심화 렌더링)

이제 `23_sgcl_통합_가이드.md`로 넘어가 이 엔진을 실제 게임 클라이언트(sgcl)에 붙이는 방법을 보세요. 수고하셨습니다!

## 부록: Before/After 비교 뷰 (2레인 구조)

이 튜토리얼은 같은 캐릭터를 두 줄로 동시에 달리게 해 이징(Easing)의 효과를 직접 비교할 수 있도록 되어 있습니다.

| 구분 | 위치 | 내용 |
|---|---|---|
| **Before** | 지단 (y = +0.4) | 항상 선형 이동 = 등속 기준선 |
| **After** | 아랫줄 (y = -0.4) | 선택한 이징(부드럽게/바운스) 적용 |

### 어떻게 구현했나요?

- 프레임 번호, 핑퇰 진행도 등 애니메이션 계산은 한 번만 하고, 이징 함수만 달리 적용해 두 줄을 그립니다.
- 하나의 동적 정점 버퍼를 프레임당 두 번 Update → Draw 합니다. WRITE_DISCARD 방식은 이전 내용을 보호하며 새 공간을 주므로 안전합니다. (DX11 동적 버퍼의 중요한 성질!)
- 두 캐릭터는 같은 스프라이트 시트/같은 프레임을 공유하므로 걸음 동작은 완전히 동기화됩니다. 다른 것은 오직 "x 위치를 계산하는 속도 곡선"뿐입니다.

### 관찰 포인트

- **1번(선형)**: 두 줄이 완전히 나란히 달립니다. 기준선 확인용.
- **2번(부드럽게)**: 아랫줄이 출발점에서 뒤처지다가 중간에서 앞지르고 도착 직전에 다시 따라잡힙니다. "같은 시간에 같은 거리"이지만 속도 분배가 다른 것입니다.
- **3번(바운스)**: 아랫줄이 도착 지점에서 공처럼 통통 튀니다. 지단과 비교하면 오버슧 구간이 명확히 보입니다.
- 이징은 렌더링 기술이 아니라 "시간 → 진행도 변환 함수"입니다. UI 연출, 카메라 이동, 스킬 이펙트 등 게임 전반에서 쓰이는 핵심 개념입니다.
