## 1. 카메라는 사실 움직이지 않는다?!

게임에서 "카메라가 오른쪽으로 이동한다"는 것은 사실…
**세상 전체가 왼쪽으로 이동하는 것**과 완전히 같습니다.

> 비유: 기차에 타고 있으면 내가 앞으로 가는 건지 풍경이 뒤로 가는 건지 구분할 수 없죠.
> GPU 입장에서 카메라는 항상 원점에 고정되어 있고, 세상을 반대로 움직입니다.

그래서 **뷰 행렬 = 카메라 움직임의 역변환**입니다.

- 카메라가 (3, 0)에 있다 → 세상 전체를 (-3, 0)만큼 이동
- 카메라가 2배 줌 인 → 세상 전체를 2배 확대

```cpp
// 2D 카메라의 뷰 행렬 (순서 주의: 이동의 역 → 줌)
Mat4 view = Mat4::Translation(-camX, -camY, 0.0f) * Mat4::Scale(zoom, zoom, 1.0f);
```

## 2. 투영 행렬 — "화면 비율" 문제 해결

NDC는 항상 -1~+1이므로, 800×600 처럼 가로가 긴 화면에서는 정사각형이 옆으로 넌적하게 늘어나 보입니다.
이걸 바로잡는 것이 **직교 투영(Orthographic)** 행렬입니다.

```cpp
// "가로 8단위 × 세로 6단위의 세상을 화면에 꽉 채워라"
Mat4 proj = Mat4::Orthographic2D(8.0f, 6.0f); // 가로세로 비율 8:6 = 창 비율 → 왜곡 없음
```

이제 3단 변신이 완성됩니다:

```cpp
Mat4 worldViewProj = world * view * proj; // 로컬 → 월드 → 카메라 → NDC
// VS에서: output.position = mul(float4(정점, 1), gWorldViewProj);
```

> CPU에서 행렬 3개를 미리 곱해 하나로 보내는 이유: VS는 정점마다 실행되므로, 정점 1만 개면 행렬 곱셈 두 번씩 총 2만 번을 아끼는 셀입니다.

## 3. 카메라 조작 구현 패턴

8번 튜토리얼은 WASD로 카메라를 움직이고 마우스 휠로 줌합니다.

```cpp
// 매 프레임 (dt = DeltaTime, 프레임 간 경과 시간)
if (input.IsKeyDown('W')) camY += moveSpeed * dt;  // 위로
if (input.IsKeyDown('S')) camY -= moveSpeed * dt;
if (input.IsKeyDown('A')) camX -= moveSpeed * dt;
if (input.IsKeyDown('D')) camX += moveSpeed * dt;

if (input.WheelDelta() != 0)
	zoom = sgf::Clamp(zoom + input.WheelDelta() / 120.0f * 0.1f, 0.2f, 5.0f);
```

### 왜 `* dt`를 곱하나요? (프레임 독립 이동)

`camX += 0.1f`처럼 고정값을 더하면 FPS 120 컴퓨터에서는 FPS 60보다 2배 빨리 움직입니다.
`속도(초당 이동량) × dt(이번 프레임의 실제 경과 초)`를 더하면 어떤 컴퓨터에서도 초당 이동량이 같아집니다. **게임 프로그래밍의 철칙입니다.**

## 4. 3D 카메라 맛보기: LookAtLH

2D는 이동+줌이면 끝이지만, 3D 카메라는 "어디서 어디를 보느냐"로 정의합니다.

```cpp
Mat4 view = Mat4::LookAtLH(
	Vec3(0.0f, 1.0f, -3.0f),  // eye: 카메라 위치
	Vec3(0.0f, 0.0f, 0.0f),   // target: 바라보는 지점
	Vec3::Up());              // up: 카메라의 위쪽 (보통 +Y)
```

내부적으로는 카메라의 앞/오른쪽/위 방향 벡터 3개를 구해(외적 활용! 01번 복습) 역변환 행렬을 만듭니다. LH는 Left-Handed(왼손 좌표계, +Z가 화면 안쪽)라는 뜻으로 DirectX 전통입니다. 자세한 활용은 09번에서.

## 5. 튜토리얼(8번)에서 직접 확인할 것

1. 여러 물체가 흘어진 세상을 WASD로 돌아다닐 수 있습니다.
2. 마우스 휠로 줌 인/아웃이 됩니다.
3. 물체들은 가만히 있고 카메라만 움직이지만, 화면상으로는 세상이 움직이는 것처럼 보입니다. (뷰 행렬의 본질 체험)
4. 실험 제안: 뷰 행렬의 곱셈 순서(이동×줌 ↔ 줌×이동)를 바꿔보세요. 줌할 때 화면 중심이 어딜 기준으로 커지는지 달라집니다.

## 6. 정리

| 개념 | 한 줄 요약 |
|---|---|
| 뷰 행렬 | 카메라 움직임의 역변환 (세상을 반대로 이동) |
| 직교 투영 | 원근감 없이 화면 비율만 맞춤 (2D용) |
| WVP | `world * view * proj` — 로컬→NDC 직행 버스 |
| 프레임 독립 | 이동량에 반드시 `* dt` |
| LookAtLH | "어디서 어디를 본다"로 3D 뷰 행렬 생성 |
