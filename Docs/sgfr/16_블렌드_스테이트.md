# 16. 블렌드 스테이트 — 반투명은 어떻게 만들어질까?

> 튜토리얼: `Projects/sgfr/Sources/sgfr/16_BlendState/`
> 엔진 코드: `Projects/sgf/Sources/sgf/Graphics/GraphicDevice.h/.cpp` (`SetBlendMode`)

---

## 1. 왜 필요한가요?

지금까지 그린 모든 물체는 **불투명**이었습니다. 나중에 그린 것이 먼저 그린 것을 완전히 덮어버렸죠.
하지만 게임에는 반투명이 넘쳐납니다. 유리창, 연기, 불방울 이펙트, 반투명 UI 창, 그림자…

"새로 칠할 색"과 "이미 화면에 있는 색"을 **섞는 규칙**이 바로 블렌딩(Blending)이고,
그 규칙을 담는 DX11 객체가 **블렌드 스테이트(Blend State)**입니다.
블렌딩은 파이프라인 마지막 단계인 **OM(Output Merger)**에서 일어납니다. (04번에서 본 그 OM!)

> **비유**: 화면은 도화지, 새 그림은 셀로판지입니다. 불투명 종이를 올리면 아래가 안 보이고(Opaque),
> 반투명 셀로판지면 아래가 비치고(Alpha), 빛 필름을 겹치면 점점 밝아지고(Additive), 어두운 필름을 겹치면 점점 어두워집니다(Multiply).

---

## 2. 개념 설명

### 2-1. 블렌딩 공식 — 단 하나의 식이 전부다

```
최종색 = (새색 × SrcBlend)  (+/-)  (화면색 × DestBlend)
```

- **Src(소스)** = 지금 픽셀 셰이더가 뱉은 새 색
- **Dest(대상)** = 이미 백버퍼에 있는 색
- SrcBlend/DestBlend 자리에 무엇을 넣느냐가 모드 차이의 전부입니다.

| 모드 | SrcBlend | DestBlend | 식 | 용도 |
|---|---|---|---|---|
| **Opaque** | — | — | 새색 (블렌딩 OFF) | 일반 불투명 물체 |
| **Alpha** | SrcAlpha | InvSrcAlpha | 새색×a + 화면색×(1-a) | 반투명 UI, 스프라이트 |
| **Additive** | SrcAlpha | One | 새색×a + 화면색 | 빛, 불꽃, 마법 이펙트 |
| **Multiply** | Zero | SrcColor | 화면색×새색 | 그늘, 스테인드글라스 |

알파(a)는 색의 4번째 성분으로 "불투명도"입니다. a=1이면 완전 불투명, a=0이면 완전 투명.

예를 들어 빨간색(1,0,0)을 알파 0.5로 파란 화면(0,0,1) 위에 Alpha 블렌딩하면:
`(1,0,0)×0.5 + (0,0,1)×0.5 = (0.5, 0, 0.5)` — 보라색이 됩니다. 직접 계산해 보면 당연하죠?

### 2-2. Additive는 왜 "빛"에 쓰일까

Additive는 화면색을 지우지 않고 더하기만 합니다. 손전등 두 개를 같은 곳에 비추면 더 밝아지듯,
겹칠수록 흰색에 가까워집니다. 그래서 폭발·레이저·반짝임 같은 발광 이펙트에 쓰입니다.
반대로 Multiply는 곱셈이므로 결과가 항상 원래보다 어두워집니다(1보다 작은 수끼리 곱하면 작아지니까). 그래서 그늘·얼룩에 쓰입니다.

### 2-3. 그리는 순서가 중요하다

블렌딩 공식을 보면 "화면색"이 식에 들어있습니다. 즉 **먼저 그린 것이 나중 결과에 영향**을 줍니다.
반투명 물체는 반드시 불투명 물체를 전부 그린 뒤, 멀리 있는 것부터 그려야 올바른 결과가 나옵니다.
상용 엔진이 "불투명 패스 → 반투명 패스(깊이 정렬)"로 나누는 이유가 바로 이것입니다.

### 2-4. DX11에서의 실체: `ID3D11BlendState`

```cpp
D3D11_BLEND_DESC desc = {};
auto& rt = desc.RenderTarget[0];
rt.BlendEnable    = TRUE;
rt.SrcBlend       = D3D11_BLEND_SRC_ALPHA;     // 새색에 곱할 값
rt.DestBlend      = D3D11_BLEND_INV_SRC_ALPHA; // 화면색에 곱할 값
rt.BlendOp        = D3D11_BLEND_OP_ADD;        // 더하기
rt.RenderTargetWriteMask = D3D11_COLOR_WRITE_ENABLE_ALL;
device->CreateBlendState(&desc, &pState);
context->OMSetBlendState(pState, nullptr, 0xffffffff);
```

## 3. 엔진은 어떻게 감쌀나 — `GraphicDevice::SetBlendMode`

```cpp
device.SetBlendMode(BlendMode::Alpha);    // 반투명
device.SetBlendMode(BlendMode::Additive); // 빛
device.SetBlendMode(BlendMode::Opaque);   // 다시 불투명 (기본값)
```

샘플러와 똑같이 모드별로 한 번만 만들어 캨시합니다. `GraphicDevice.cpp`의 `SetBlendMode` 주석에 4가지 모드의 Src/Dest 설정이 표로 정리되어 있습니다.

## 4. 코드 따라가기 — 16번 튜토리얼

### 4-1. 부드러운 원 텍스처 (`FillSoftCirclePixels`)

중심은 알파 1, 가장자리로 갈수록 알파가 0으로 부드럽게 줄어드는 128×128 흰색 원을 코드로 만듭니다.
흰색인 이유: 정점 색을 곱해서(R/G/B) 원하는 색으로 물들이기 위해서입니다. (흰색 × 빨강 = 빨강)

### 4-2. 세 개의 원이 빙븙 도는 장면 (`16_BlendState_Main.cpp`)

빨강/초록/파랑 원 3개가 서로 겹치며 공전합니다. 겹치는 부분을 보면:

- **[1] Opaque**: 사각형 텍스처 경계가 그대로 보임 (알파 무시, 나중 것이 덮음)
- **[2] Alpha**: 자연스럽게 포개짐 — 겹침 부분이 섞인 색
- **[3] Additive**: 겹칠수록 밝아져 중앙이 흰색에 가까워짐 (R+G+B = 흰색!)
- **[4] Multiply**: 겹칠수록 어두워짐

같은 장면·같은 텍스처에서 블렌드 스테이트 하나만 바꿨는데 결과가 완전히 달라집니다.

## 6. 정리

- 블렌딩 = 새색과 화면색을 섞는 규칙, OM 단계에서 수행
- 공식: `새색×SrcBlend + 화면색×DestBlend` — 계수만 바꾸면 Alpha/Additive/Multiply가 전부 한 식에서 나옴
- 반투명은 그리는 순서가 중요 (불투명 먼저, 반투명은 먼 것부터)
- sgf에서는 `SetBlendMode` 한 줄로 전환

다음 장(17번)에서는 삼각형을 "어떻게 채울지/어느 면을 버릴지"를 정하는 래스터라이저 스테이트를 배웁니다.

## 부록: Before/After 비교 뷰

이 튜토리얼은 같은 원 3개 묶음을 좌/우에 나란히 그려 블렌드 모드의 효과를 직접 비교할 수 있도록 되어 있습니다.

| 구분 | 위치 | 내용 |
|---|---|---|
| **Before** | 왼쪽 그룹 | 항상 Opaque (섞임 없음, 나중에 그린 것이 덮어쓰기) |
| **After** | 오른쪽 그룹 | 키로 선택한 블렌드 모드 (Alpha/Additive/Multiply) |

### 어떻게 구현했나요?

- 서로 겹치며 도는 반투명 원 3개를 그리는 로직을 람다 함수로 묶고, 그룹 중심과 블렌드 모드만 바꿔 두 번 호출합니다.
- 그리기 직전에 `SetBlendMode`만 바꾸므로 "블렌드 스테이트는 파이프라인 상태다"라는 것을 그대로 보여줍니다.
- 가운데 흰 세로선은 Opaque로 그린 구분선입니다.

### 관찰 포인트

- **Opaque(왼쪽)**: 겹친 부분이 섞이지 않고 나중에 그린 원이 앞의 원을 지워버립니다. 투명 영역도 검게 덮입니다.
- **Alpha**: 유리처럼 자연스럽게 섞입니다. UI/캐릭터 스프라이트의 기본값.
- **Additive**: 겹칠수록 밝아집니다. 불퇹/레이저/글로우 이펙트용.
- **Multiply**: 겹칠수록 어둡습니다. 그림자/스테인 효과용.
- 같은 장면이 블렌드 모드 하나로 완전히 다른 느낌이 되는 것을 양쪽을 번갈아 보며 확인하세요.
