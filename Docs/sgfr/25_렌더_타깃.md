# 25. 렌더 타깃 — 화면이 아닌 텍스처에 그리기, 미니맵의 시작

> 관련 코드: `Projects/sgfr/Sources/sgfr/25_RenderTarget/25_RenderTarget_Main.cpp`, `25_RenderTarget_Function.cpp`
> 실행: sgfr 실행 후 콘솔 메뉴에서 25번 선택 (창이 뜨면 ESC로 종료)
> 선행 학습: `04_디바이스와_스왑체인.md`, `13_3D_큐브.md`

## 1. 이 장에서 배우는 것

지금까지는 항상 "화면(백버퍼)"에만 그림을 그렸습니다. 이번 장에서는 **내가 직접 만든 텍스처에 그림을 그리고, 그 결과를 다시 텍스처로 읽어 화면에 붙이는 멀티 패스 구조**를 배웁니다. 이것은 미니맵·백미러·포스트 프로세싱·그림자 매핑 등 현대 엔진의 모든 고급 기법이 서는 토대입니다.

## 2. 실행하면 보이는 것

800x600 창이 열리고 두 개의 물체가 보입니다.

- **가운데 큐브**: 경사진 시점(카메라)에서 본 회전 큐브. 이전 장들처럼 백버퍼에 직접 그려집니다.
- **오른쪽 위 초록 사각형**: "미니맵"입니다. 같은 큐브를 **하늘 바로 위에서 내려다본** 모습이 작은 사각형 안에 그려집니다. 배경이 초록색인 것은 "이건 렌더 타깃에 그린 결과다"라는 걸 눈에 띄게 하기 위한 장치입니다.

핵심 관찰 포인트는 **둘은 완전히 같은 큐브 지오메트리인데, 카메라만 달라 보이는 모습이 다르다**는 것입니다.

콘솔에도 다음과 같은 설명이 출력됩니다.

```
[렌더 타깃(Render Target)이란?]
 지금까지는 항상 '백버퍼(화면)'에만 그렸습니다.
 렌더 타깃을 쓰면 '내가 만든 텍스처'에 그릴 수 있습니다.
 그려진 결과는 그냥 텍스처이므로 다시 샘플링해서 화면에 붙일 수 있죠!
```

## 3. 핵심 개념 — 비유로 먼저 이해하기

### 3-1. 종이 대신 "필름"에 그리기

지금까지는 그림을 항상 **화이트보드(백버퍼)**에 그렸습니다. 렌더 타깃을 쓰면 **투명 필름(텍스처)**에 그림을 그릴 수 있습니다. 필름에 그려진 그림은 언제든 다른 그림 위에 덮어서 보여줄 수 있지요.

비유하자면: 지도를 그릴 때 본 지도 한 장만 쓰지 않고, **작은 인쇄판(렌더 타깃)을 따로 만들어 축소 지도를 찍어서**, 본 지도의 오른쪽 위 구석에 풀로 붙여 놓은 것입니다.

### 3-2. 같은 텍스처, 두 개의 관점(뷰)

그려진 필름을 다시 사용하려면 "이 텍스처를 **출력용**으로 볼 것인지, **입력용**으로 볼 것인지" 관점을 정해야 합니다. 정리하면:

| 관점 | D3D11 이름 | 뜻 |
|---|---|---|
| 여기에 그려라 | RTV (RenderTargetView) | 렌더 타깃으로 묶는 관점 |
| 여기서 읽어라 | SRV (ShaderResourceView) | 셰이더가 샘플링하는 관점 |

중요한 규칙은 **같은 텍스처를 그리는 동안에는 동시에 읽을 수 없다**는 것입니다. 다 그리고 나서 관점을 바꿔야 하지요.

### 3-3. 패스(Pass) — 한 프레임을 여러 번 나누어 그리기

한 프레임은 반드시 한 번 그려야 하는 게 아닙니다. 이 튜토리얼은 한 프레임을 **3번의 패스**로 나눕니다.

1. 패스 1: 미니맵용으로 렌더 타깃에 큐브 그리기
2. 패스 2: 백버퍼에 장면 큐브 그리기
3. 패스 3: 렌더 타깃의 결과를 사각형으로 백버퍼에 붙이기

요리로 비유하면, 재료를 먼저 **데쳐서(패스 1)** 두고, 나중에 본 요리에 **곁들여서(패스 3)** 내는 이중 조리 과정입니다.

### 3-4. 바로 위에서 보는 카메라는 +Y를 쓸 수 없다

카메라를 `(0, 5, 0)` — 큐브의 바로 위에 두고 아래를 내려다봅니다. 이때 "위쪽 방향"으로 +Y(위)를 지정하면 모순이 생깁니다. 카메라가 위를 바라보는데 위 방향이 또 위라면 방향을 정할 수 없기 때문입니다. 그래서 이 튜토리얼은 카메라의 위 방향으로 **+Z(정면 방향)**를 사용합니다. (`vec3::Forward()`)

## 4. 초보자 용어 사전

| 용어 | 뜻(쉬운 말) | 비유 |
|---|---|---|
| 백버퍼 (Backbuffer) | 화면에 보이는 그릇. Present되면 모니터로 나간다 | 화이트보드 |
| 렌더 타깃 (Render Target) | 백버퍼 대신 그릴 수 있는 "내가 만든 텍스처" | 투명 필름 |
| RTV (RenderTargetView) | 텍스처를 "여기에 그려라"로 보는 관점 | 필름을 인쇄기에 끼우기 |
| SRV (ShaderResourceView) | 텍스처를 "여기서 읽어라"로 보는 관점 | 필름을 프로젝터에 끼우기 |
| DSV (DepthStencilView) | 텍스처를 "깊이 버퍼"로 보는 관점 | 필름을 자에 붙여 두께 재기 |
| 멀티 패스 (Multi-pass) | 한 프레임을 여러 번 나누어 그리는 것 | 데치고 나서 다시 볶기 |
| 샘플링 (Sampling) | 텍스처의 UV 위치에 있는 색을 읽는 것 | 지도에서 좌표 보고 색 읽기 |
| aspect ratio (종횡비) | 가로/세로 비율. 800:600은 1.333 | TV 화면의 길쭉한 정도 |
| NDC | 화면을 -1~+1로 정규화한 좌표계 | 화면을 크기와 무관한 정규 판 위에 표현 |

## 5. 코드 워크스루

### 5-1. 준비: 렌더 타깃 생성

`RenderTarget_Main()` 함수의 초반부는 윈도우/디바이스/입력을 만들고, 미니맵용 렌더 타깃을 256x256으로 생성합니다.

```cpp
RenderTarget miniMapTarget;
if (!miniMapTarget.Create(&device, 256, 256))
```

`RenderTarget::Create`는 **색상 텍스처 + 전용 깊이 버퍼(DSV)를 함께** 만듭니다. 크기는 백버퍼와 달라도 됩니다. (27번 그림자 매핑에서는 깊이 전용 버전 `CreateDepthOnly`가 등장합니다.)

### 5-2. 큐브 지오메트리와 NDC 사각형

장면용 큐브는 공용 헬퍼 `FillColorCube(cubeVertices, cubeIndices)`로 정점 8개 + 인덱스 36개를 채웁니다. 미니맵 출력용 사각형은 `FillScreenQuad`로 채웁니다.

```cpp
FillScreenQuad(quadVertices, vec2(0.62f, 0.55f), vec2(0.25f, 0.25f * window.AspectRatio()));
```

`FillScreenQuad`는 **NDC 좌표 기준** 정점 4개(UV 0~1, 흰색)를 만듭니다. 중심 `(0.62, 0.55)`는 "오른쪽 위"에 해당하고, 반폭은 0.25인데 y 쪽에 `window.AspectRatio()`(800/600 = 1.333)를 곱해서 **화면 비율을 보정**합니다. 이것을 생략하면 화면이 4:3이기 때문에 사각형이 세로로 길쭉하게 보입니다. NDC는 항상 -1~+1이지만 실제 픽셀로 늘어날 때 비율이 반영되기 때문입니다.

### 5-3. 셰이더 2종과 카메라 2개

- `ColorTransformShaderSource()`: WVP 행렬 변환 + 정점 색 그리기 (큐브용, `VertexPC`)
- `TextureShaderSource()`: NDC 그대로 통과 + 텍스처 샘플링 (사각형용, `VertexPTC`)

둘 다 `Shader::CompileFromString`으로 컴파일하고, `ConstantBuffer<CbTransform>`(64바이트, wvp_ 행렬 하나)도 하나만 만듭니다. 카메라는 두 개입니다.

```cpp
const mat4 sceneView = mat4::LookAtLH(vec3(0.0f, 1.5f, -4.0f), vec3::Zero(), vec3::Up());
// 바로 위에서 볼 때는 Up 벡터로 +Y를 쓸 수 없으므로 +Z를 사용한다.
const mat4 topView = mat4::LookAtLH(vec3(0.0f, 5.0f, 0.0f), vec3::Zero(), vec3::Forward());
const mat4 topProj = mat4::PerspectiveFovLH(jc_math_pi_div4, 1.0f, 0.1f, 100.0f);
```

`topProj`의 aspect가 `1.0f`인 이유는 렌더 타깃이 정사각형(256x256)이기 때문입니다.

### 5-4. 렌더 루프 — 세 개의 패스

매 프레임의 흐름을 코드로 따라가 봅시다.

```cpp
// ---- 패스 1: 렌더 타깃에 미니맵 시점으로 그리기 ----
device.BeginFrame(color(0.08f, 0.08f, 0.12f, 1.0f));	// 백버퍼도 미리 클리어

device.SetRenderTarget(&miniMapTarget);					// 이제 그리기는 텍스처로!
miniMapTarget.Clear(&device, color(0.1f, 0.25f, 0.15f, 1.0f));	// 초록 배경

CbTransform cb;
cb.wvp_ = world * topView * topProj;
cbTransform.UpdateAndBind(&device, cb, 0);

cubeVb.Bind(&device); cubeIb.Bind(&device); cubeShader.Bind(&device);
device.Context()->IASetPrimitiveTopology(D3D11_PRIMITIVE_TOPOLOGY_TRIANGLELIST);
device.Context()->DrawIndexed(36, 0, 0);
```

- `device.SetRenderTarget(&miniMapTarget)`가 이후의 모든 그리기 대상을 렌더 타깃으로 바꿉니다.
- `miniMapTarget.Clear`는 색을 초록으로, 깊이를 1.0(가장 먼 곳)으로 되돌립니다. **그리기 전에 반드시 지워야** 합니다.
- WVP 행렬을 `world * topView * topProj`로 바꿔 `ConstantBuffer::UpdateAndBind`로 b0 슬롯에 장착합니다. 같은 큐브 버퍼 그대로, 행렬만 바뀌면 됩니다.

```cpp
// ---- 패스 2: 백버퍼에 장면 그리기 ----
device.SetRenderTarget(nullptr);						// 다시 화면으로 복귀!

cb.wvp_ = world * sceneView * sceneProj;
cbTransform.UpdateAndBind(&device, cb, 0);
... DrawIndexed(36, 0, 0);
```

**`SetRenderTarget(nullptr)`은 "백버퍼로 복귀"를 의미합니다.** 이게 이 장의 가장 중요한 API입니다.

```cpp
// ---- 패스 3: 렌더 타깃 결과를 미니맵 사각형에 출력 ----
device.SetSampler(GraphicDevice::SamplerFilter::fmLinear, GraphicDevice::SamplerAddress::amClamp, 0);
miniMapTarget.BindAsTexture(&device, 0);				// 그려진 결과를 텍스처로 장착

quadVb.Bind(&device); quadIb.Bind(&device); quadShader.Bind(&device);
device.Context()->DrawIndexed(6, 0, 0);
```

패스 3에서는 미니맵 사각형이 NDC 좌표 그대로 그려지므로 **변환 행렬이 전혀 필요 없습니다.** `BindAsTexture(&device, 0)`가 렌더 타깃의 결과를 셰이더의 t0 슬롯(SRV)으로 바꿔 장착하고, `TextureShaderSource`가 UV 위치를 샘플링해 출력합니다. 미니맵을 축소하므로 축소 필터로 `fmLinear`(부드러운 보간)를 사용합니다.

마지막으로 `device.EndFrame(true)`로 백버퍼를 화면에 표시하면 한 프레임이 끝납니다.

### 5-5. 정리

`miniMapTarget.Destroy(); device.Finalize(); window.Destroy();` 순서로 모든 것을 해제합니다.

## 6. GPU와 DX11, 하드웨어 깊이 보기

### 6-1. 렌더 타깃이 실제로 만드는 것들

`RenderTarget::Create(&device, 256, 256)`이 D3D11 수준에서 하는 일은 크게 3가지입니다.

1. **텍스처 리소스**: `ID3D11Texture2D`를 만듭니다. 256x256, 포맷은 `DXGI_FORMAT_R8G8B8A8_UNORM`(색 텍스처) — 색상용 하나, 깊이용(`D32_FLOAT`) 하나가 **VRAM에 실제 메모리를 차지**합니다. 256x256x4바이트 = 256KB, 깊이는 256KB로 총 512KB입니다.
2. **뷰(Views)**: 같은 리소스를 해석하는 창구들 — RTV(`ID3D11RenderTargetView`), DSV(`ID3D11DepthStencilView`), SRV(`ID3D11ShaderResourceView`). 뷰는 리소스의 메모리를 복사하지 않고 "해석 방법"만 정의합니다. OpenGL의 FBO(프레임 버퍼 오브젝트)가 이 개념을 통째로 하나로 묶은 것과 비교하면, D3D11은 뷰를 분리해서 만드는 것을 명시적으로 보여줍니다.
3. **상태 연결**: `SetRenderTarget`을 부르면 디바이스 컨텍스트의 **OM(Output Merger) 단계**에 RTV/DSV 배열이 설정됩니다. GPU 하드웨어에서 OM은 픽셀 셰이더 이후의 **ROP(Raster Operations Unit)**로 직접 연결되는데, ROP는 색 쓰기, 깊이 테스트, 블렌드를 실제 메모리에 수행하는 "펜" 역할의 유닛입니다. "RTV를 바꾼다"는 것은 곧 "ROP가 색을 쓸 주소지를 바꾼다"는 뜻입니다.

### 6-2. 같은 텍스처, 두 관점 — 하드웨어에서의 의미

패스 1에서 그릴 때 GPU는 렌더 타깃 텍스처를 **쓰기 대상**으로 사용합니다. 패스 3에서 읽을 때는 **SRV로 바인딩**되어 텍스처 캐시/필터 유닛을 거쳐 셰이더 유닛에 색을 공급합니다.

D3D11은 **리소스가 동시에 RTV와 SRV로 바인딩되는 것을 금지**합니다 (SRV 위에 쓰기 금지 = 성능상의 "WRITE-READ 헤저드" 방지). sgf 엔진의 `GraphicDevice::SetRenderTarget`은 백버퍼 복귀 시 SRV 언바인딩도 자동 처리하므로, 이 내부 규칙을 사용자가 신경 쓸 필요가 없게 만든 설계입니다. 하드웨어적으로는 이렇게 해야 GPU 메모리 계층에서 쓰기와 읽기가 충돌(RAW hazard)해 정확성이 무너지는 사태를 막을 수 있습니다.

### 6-3. 미니맵 렌더링이 하드웨어에서 도는 과정

패스 1의 큐브 그리기가 256x256 타깃에서 실행되면:

1. **VS**: 8개 정점(36개 인덱스 참조)이 셰이더 유닛(SM)의 스트림 프로세서들에서 `world * topView * topProj`로 변환됩니다. 행렬 연산은 벡터 ALU 파이프에서 4벌(4-way SIMD)로 처리됩니다.
2. **래스터라이저**: 삼각형을 픽셀로 쪼갭니다. 256x256 해상도라 픽셀 수가 작아 매우 가볍습니다. 이때 **뷰포트**는 렌더 타깃 크기(256x256)로 자동 설정됩니다 — 뷰포트 변환 유닛이 NDC를 텍스처 픽셀 좌표로 펼치는 단계입니다.
3. **깊이 버퍼**: 큐브는 자체 DSV로 깊이 테스트를 통과해야 그려집니다. ROP의 깊이 비교 유닛(Depth Compressor)이 새 픽셀의 z와 기존 깊이를 비교합니다. 깊이 버퍼는 텍스처이므로 **Z 압축(Z-compression)/계층적 Z(Hierarchical-Z)** 같은 기법으로 초기 거부(Early-Z)가 이뤄질 수 있습니다 — 큐브가 거의 화면을 덮는 경우 절반 이상의 픽셀이 값싸게 폐기됩니다.
4. **PS**: 픽셀 셰이더는 정점 색만 통과시키므로 ALU 부담이 거의 없습니다. 이 튜토리얼의 셰이더가 단순한 이유는 미니맵 자체를 배우기 위함입니다.

패스 3의 사각형(6 인덱스)은 800x600 백버퍼에 그려지면서 렌더 타깃 텍스처를 **축소 샘플링**합니다. 이때 텍스처 캐시(2차원 캐시 라인)가 작은 타깃 영역을 효율적으로 유지하고, Linear 필터가 4개 텍셀(2x2)을 보간하는 부동소수점 ALU 작업을 수행합니다. 축소된 미니맵을 그리면 캐시 활용률이 매우 높아져서 사실상 "캐시 친화적"인 저비용 드로우 콜이 됩니다.

### 6-4. 멀티 패스의 성능 의미

한 프레임에 드로우 콜이 3개(패스1 큐브, 패스2 큐브, 패스3 쿼드)로 늘었지만, 각각의 부담이 작아 전체 프레임 비용은 크게 늘지 않습니다. 렌더 타깃 전환은 GPU 파이프라인을 **플러시(flush)하는 지점**이 될 수 있으므로 패스를 최소화하는 것이 실무의 관례입니다. 다만 미니맵처럼 해상도가 낮은 타깃으로의 전환은 비용이 매우 작아 "공짜에 가깝게" 미니맵을 얻을 수 있다는 것이 이 장의 실용적 교훈입니다.

### 6-5. Direct3D 11 API 대응표

| sgf API | D3D11 API | 하드웨어 |
|---|---|---|
| `RenderTarget::Create` | `CreateTexture2D` + `CreateRenderTargetView` + `CreateDepthStencilView` + `CreateShaderResourceView` | VRAM 할당 + 뷰 생성 |
| `device.SetRenderTarget` | `OMSetRenderTargets` | ROP 쓰기 주소 지정 |
| `miniMapTarget.Clear` | `ClearRenderTargetView` + `ClearDepthStencilView` | 메모리 채우기 (채우기 비율 최적화) |
| `BindAsTexture` | `PSSetShaderResources` | 텍스처 캐시 → 샘플러 유닛 |
| `device.SetSampler` | `PSSetSamplers` | 필터/주소 하드웨어 설정 |
| `device.EndFrame` | `Present` | 스왑체인 → 디스플레이 컨트롤러 |

## 7. 핵심 규칙 요약

- `SetRenderTarget(nullptr)`은 **백버퍼 복귀**다. (`25_RenderTarget_Main.cpp` 패스 2)
- 렌더 타깃은 **색 RTV + 깊이 DSV가 함께** 생성된다. 깊이 전용은 27번에서 `CreateDepthOnly`로.
- 같은 텍스처를 그리면서 읽을 수 없다 — 그릴 때(RTV)와 읽을 때(SRV)는 분리된 패스여야 한다.
- 바로 위에서 내려다보는 카메라는 위 방향으로 `+Y`를 못 쓰므로 `vec3::Forward()`(+Z)를 쓴다.
- 정사각형 타깃에는 **aspect = 1.0** 투영을 쓴다.
- NDC 사각형은 변환 행렬 없이 그대로 그려진다 (`TextureShaderSource`가 NDC 통과).
- `FillScreenQuad`의 y 반폭에 `window.AspectRatio()`를 곱해 정사각형을 유지한다.
- 미니맵 축소에는 Linear(보간) 샘플러가 깔끔하다.
