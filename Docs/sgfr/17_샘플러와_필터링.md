# 17. 샘플러와 필터링 — GPU는 텍스처를 어떻게 "읽을까"?

> 관련 코드: `Projects/sgfr/Sources/sgfr/Tutorial/17_SamplerFiltering/` (`17_SamplerFiltering_Main.cpp`, `17_SamplerFiltering_Function.cpp`)
> 엔진 코드: `Projects/sgf/Sources/sgf/Graphics/GraphicDevice.h/.cpp` (`SetSampler`), `RenderStates.h/.cpp` (`GetSamplerState`)
> 실행: sgfr 실행 후 콘솔 메뉴에서 **17번** 선택
> 선행 학습: 15번(PNG 텍스처), 16번(SVG 텍스처)

## 1. 이 장에서 배우는 것

화면 픽셀 하나를 칠할 때 "텍스처의 어느 색을 가져올지"를 정하는 규칙인 **샘플링(Sampling)**과, 그 규칙을 담은 **샘플러(Sampler State)**를 배웁니다. 필터(Point/Linear)와 주소 모드(Wrap/Clamp/Mirror)를 실시간으로 바꿔가며 화면 차이를 눈으로 확인하고, 엔진의 `GraphicDevice::SetSampler`가 이를 어떻게 지원하는지 익힙니다.

## 2. 실행하면 보이는 것

화면이 **노란 세로 경계선**으로 좌/우로 나뉩니다.

- **왼쪽(Before)**: 기준 상태 고정 = **Point 필터 + Wrap 주소 모드**
- **오른쪽(After)**: 키로 선택한 필터/주소 모드

화면 대부분을 덮는 커다란 사각형에 32×32 픽셀짜리 체커보드 텍스처가 붙어 있는데, UV가 0~3으로 확장되어 있어 텍스처가 좌우로 3번 반복됩니다. 키를 누를 때마다 창 제목이 "왼쪽: Point+Wrap(기준) | 오른쪽: Linear + Wrap"처럼 갱신되고, 오른쪽 화면만 바뀝니다.

| 키 | 동작 |
|---|---|
| `1` / `2` | 오른쪽 필터: Point(최근접) / Linear(선형보간) |
| `3` / `4` / `5` | 오른쪽 주소 모드: Wrap(반복) / Clamp(고정) / Mirror(거울) |
| `ESC` | 종료 |

체커보드의 1픽셀 빨간 테두리는 **Clamp 모드를 고르면 줄줄이 늘어나는 것**을 보여주기 위해 일부러 넣은 장치입니다. 텍스처가 32×32로 작기 때문에 확대 시 Point는 모자이크로 각지고, Linear는 부드럽게 번집니다.

## 3. 핵심 개념 — 비유로 먼저 이해하기

### 3-1. 샘플링 = "우체국에서 그림 색을 물어보는 손님"

모눈종이(텍스처)에 32개의 점(텍셀)이 색깔별로 그려져 있습니다. 화면 픽셀(400개) 하나하나는 "그래서 저 위치 색이 뭐예요?"라고 물어보는 손님입니다. 그런데 물어보는 위치가 모눈 칸 **사이**인 경우가 대부분입니다. 여기서 규칙이 필요해집니다.

- **Point 필터**: 제일 가까운 칸의 색을 그대로 대답. 손님마다 옆 칸 색을 보여주니 도트 느낌이 납니다.
- **Linear 필터**: 주변 4칸의 색을 거리 비율로 섞어 대답. 부드럽지만 원래 그림은 흐려집니다.

이 "대답하는 규칙 묶음"(필터 + 범위 밖 처리 + 밉맵 설정)을 담은 객체가 **샘플러**입니다. 샘플러는 셰이더 코드 `Texture.Sample(샘플러, UV)`에서 UV 다음 인자로 등장합니다. 어떤 샘플러를 넣는지는 셰이더가 정하지 않고, **C++ 쪽이 정점 파이프라인에 미리 꽂아둔 상태**가 정합니다.

### 3-2. 주소 모드 = "종이 밖으로 손이 나가면?"

UV가 0~1을 벗어나면 어쩌지? 물어보는 위치가 모눈종이 밖일 때의 규칙이 주소 모드입니다.

- **Wrap**: 종이를 이어 붙여 계속 반복 (바닥 타일링).
- **Clamp**: 가장자리 색을 잡아당겨 늘임 (빨간 테두리가 줄줄 늘어남).
- **Mirror**: 거울처럼 뒤집어 반복 (Wrap보다 이음새가 덜 보임).

### 3-3. 상태(State) = "규칙을 담은 카드"

GPU에 규칙을 넘길 때마다 규칙을 설명하는 대신, "카드"를 미리 만들어 두고 그 카드를 꽂는 방식을 씁니다. 이 카드가 상태 객체입니다. 같은 카드를 다시 꽂는 것은 반복해도 아주 저렴합니다. 그래서 이 튜토리얼은 매 프레임 `SetSampler`를 호출하며 실시간으로 규칙을 바꿔도 부담이 없습니다.

## 4. 초보자 용어 사전

| 용어 | 뜻(쉬운 말) | 비유 |
|---|---|---|
| 텍셀(Texel) | 텍스처 이미지의 점 하나 | 모눈종이의 칸 하나 |
| 픽셀(Pixel) | 화면의 점 하나 | 전광판의 전구 하나 |
| 샘플링(Sampling) | UV 위치에서 텍스처 색을 꺼내는 행위 | 그림판에서 색을 찍어 오기 |
| 샘플러(Sampler) | 색을 꺼내는 규칙 묶음(필터+주소모드 등) | 색을 섞는 방법이 적힌 카드 |
| 필터(Filter) | 확대/축소 시 색을 지어내는 방법 | 없는 색을 섞어 만드는 요리법 |
| 주소 모드(Address Mode) | UV가 0~1 밖으로 나갔을 때의 처리 | 종이 밖을 볼 때의 규칙 |
| UV 좌표 | 텍스처 위의 위치 (0~1) | 지도의 가로/세로 좌표 |
| SV_POSITION | 픽셀 셰이더에서 읽는 화면 좌표 | 전구의 주소(몇 번째 줄 몇 번째) |
| 보간(Interpolation) | 정점 값으로 사이 값을 매끄럽게 계산 | 두 점 사이를 잇는 줄 |
| 상태 객체(State Object) | GPU에 꽂는 설정값 묶음 | 미리 만든 규칙 카드 |

## 5. 코드 워크스루

`SamplerFiltering_Main()`의 흐름을 따라가 봅시다.

### 5-1. 준비: 텍스처와 UV 0~3 사각형

```cpp
_u8 pixels[32 * 32 * 4];
FillCheckerPixels(pixels, 32, 32, 4);            // 32x32 체커 + 빨간 테두리

Texture texture;
texture.CreateFromMemory(&device, pixels, 32, 32);

VertexPTC vertices[4];
_u32 indices[6];
FillUvQuad(vertices, indices, 3.0f);             // UV 0~3인 NDC 사각형
```

`FillCheckerPixels`(17_SamplerFiltering_Function.cpp)는 가장자리 1픽셀을 빨강(220,60,60)으로, 나머지는 `(칸x+칸y)%2`가 짝수면 밝은 칸(240,240,240), 홀수면 파란 칸(40,70,160)으로 채웁니다. `FillUvQuad`는 NDC 좌표 `±0.85`의 사각형에 UV를 `0.0 ~ 3.0`으로 넣습니다. UV가 3.0이므로 텍스처가 3번 반복됩니다.

### 5-2. 샘플러 상태와 경계 상수 버퍼

```cpp
struct CbSplit
{
	_f32 splitPixelX_;   // 화면 좌/우 경계의 픽셀 x좌표
	_f32 padding_[3];    // 16바이트 정렬용 여백
};
```

`CbSplit`은 HLSL의 `cbuffer CbSplit : register(b0)`와 1:1로 일치해야 합니다. `_f32` 하나는 4바이트인데, HLSL cbuffer는 **16바이트 단위로 정렬**되므로 여백 3개를 붙여 정확히 16바이트로 맞춥니다. 셰이더는 `TextureQuadShaderSource()`로 컴파일하며, `VertexPTC::LayoutDescs()`로 입력 레이아웃을 만듭니다.

### 5-3. 셰이더: 좌/우 분할의 비밀

17_SamplerFiltering_Function.cpp의 핵심 부분입니다.

```hlsl
Texture2D gTexture : register(t0);
SamplerState gSamplerBefore : register(s0);   // [Before] Point + Wrap 고정
SamplerState gSamplerAfter  : register(s1);   // [After]  현재 선택한 규칙

float4 PSMain(VSOutput _input) : SV_TARGET
{
	if (abs(_input.position.x - gSplitPixelX) < 1.5f)   // 경계선 1.5px는 노란색
		return float4(1.0f, 0.85f, 0.2f, 1.0f);

	if (_input.position.x < gSplitPixelX)
		return gTexture.Sample(gSamplerBefore, _input.uv) * _input.color;  // 왼쪽: 기준 규칙
	return gTexture.Sample(gSamplerAfter, _input.uv) * _input.color;       // 오른쪽: 선택 규칙
}
```

`SV_POSITION`은 픽셀 셰이더에서 **현재 픽셀의 화면 좌표(픽셀 단위)**로 읽힙니다. 이를 `gSplitPixelX`(화면 절반 = 400px)와 비교해, 한 번의 `DrawIndexed(6)` 호출로 좌우에 서로 다른 규칙을 적용합니다. VS는 이미 NDC 좌표이므로 행렬 계산 없이 그대로 통과시킵니다.

### 5-4. 렌더 루프

```cpp
device.BeginFrame(color(0x14, 0x14, 0x1A, 0xFF));

// s0: 기준 샘플러 (Point + Wrap 고정) / s1: 현재 선택한 샘플러
device.SetSampler(GraphicDevice::SamplerFilter::fmPoint,
                  GraphicDevice::SamplerAddress::amWrap, 0);
device.SetSampler(filter, address, 1);

CbSplit cbS;
cbS.splitPixelX_ = window.Width() * 0.5f;
cbS.padding_[0] = cbS.padding_[1] = cbS.padding_[2] = 0.0f;
cbSplit.UpdateAndBind(&device, cbS, 0);      // b0 갱신 + 바인딩

texture.Bind(&device, 0);                    // t0 슬롯
vb.Bind(&device);  ib.Bind(&device);  shader.Bind(&device);
device.Context()->IASetPrimitiveTopology(D3D11_PRIMITIVE_TOPOLOGY_TRIANGLELIST);
device.Context()->DrawIndexed(6, 0, 0);      // 삼각형 2개 = 사각형 1장
device.EndFrame(true);
```

- `device.SetSampler(필터, 주소, 슬롯)`은 내부적으로 `RenderStates::GetSamplerState()`가 상태 객체를 캐싱하므로 매 프레임 호출해도 새 객체를 만들지 않습니다. `states_.GetSamplerState(filter, address)` → `PSSetSamplers(slot, 1, ...)`로 PS 단계 s0/s1 슬롯에 꽂습니다.
- 키 입력은 문자 키 `'1'`~`'5'`를 사용합니다. 문자 키의 가상 키 코드 값이 문자 그대로와 같기 때문에 `input.IsKeyPressed('1')`로 바로 비교할 수 있습니다.
- `UpdateTitle` 람다가 `swprintf_s`로 현재 모드 이름을 조합해 `window.SetTitle(szTitle)`로 창 제목을 갱신합니다. 이름표 배열 `s_szFilterNames`, `s_szAddressNames`의 인덱스가 enum 순서와 일치한다는 점을 이용합니다.
- 종료 시 `device.Finalize(); window.Destroy();`로 정리합니다.

## 6. GPU와 DX11, 하드웨어 깊이 보기

### 6-1. D3D11의 샘플러 상태 객체

이 튜토리얼의 `SetSampler`는 최종적으로 `D3D11_SAMPLER_DESC` 구조체를 채워 `ID3D11Device::CreateSamplerState()`로 만든 `ID3D11SamplerState` 객체를 `PSSetSamplers()`로 바인딩합니다 (RenderStates.cpp:240). 이 desc의 핵심 필드는:

| D3D11_SAMPLER_DESC 필드 | 이 엔진 매핑 | 의미 |
|---|---|---|
| `Filter` | `ToD3D11(FilterMode)` | MIN/MAG/MIP 필터 조합 (예: `D3D11_FILTER_MIN_MAG_MIP_POINT`, `_LINEAR`) |
| `AddressU/V/W` | `ToD3D11(AddressMode)` | `D3D11_TEXTURE_ADDRESS_WRAP/CLAMP/MIRROR/BORDER` |
| `MaxAnisotropy` | 16 (Anisotropic일 때), 그 외 1 | 비등방성 필터의 샘플 개수 |
| `MinLOD/MaxLOD` | 0 ~ FLOAT_MAX | 밉맵 선택 범위 |
| `BorderColor` | 불투명 검정 | Border 모드용 테두리 색 |

여기서 `Filter`가 MIN/MAG/MIP **세 축의 조합**이라는 점이 중요합니다. `D3D11_FILTER_MIN_MAG_MIP_POINT`는 축소(MIN)·확대(MAG)·밉맵(MIP) 모두 최근접을 쓴다는 뜻입니다. 이 튜토리얼은 UV 0~3 확대 상황이라 MAG(확대) 필터만 눈에 보이는 것이고, 텍스처가 화면보다 작아지면 MIN(축소) 필터가, 멀리서 밉맵 사이가 되면 MIP 필터가 개입합니다.

### 6-2. 하드웨어: 텍스처 유닛(TMU)과 샘플러 하드웨어

현대 GPU(예: NVIDIA 암페어, AMD RDNA)에서 픽셀 셰이더의 `Sample` 명령은 셰이더 ALU가 직접 계산하지 않습니다. GPU 안에는 **텍스처 유닛(Texture Mapping Unit, TMU)**이라 불리는 전용 하드웨어가 따로 있고, 셰이더의 워프(warp, 한 번에 실행되는 32개 스레드 묶음)가 텍스처 요청을 TMU로 보내면 TMU가 병렬로 처리합니다. 이때 샘플러 desc가 이미 GPU에 업로드되어 있어서 TMU는 필터/주소 모드를 참조합니다.

샘플링이 수행되는 과정:

1. **텍셀 주소 계산**: UV 좌표를 텍스처 크기(예: 32×32)로 곱해 텍셀 공간 좌표를 구합니다. UV는 0~1로 정규화되어 있으므로 GPU는 고정소수점(fixed-point) 곱셈기로 주소를 만듭니다.
2. **주소 모드 적용**: 범위 밖(UV>1 또는 <0)인지 판정해 주소를 보정합니다. 하드웨어 구현은 놀랍게 단순합니다:
   - **Wrap**: 정수부를 버리는 fractional 연산 (예: 3.7 → 0.7)
   - **Clamp**: `saturate`처럼 0~1로 고정
   - **Mirror**: 정수부의 최하위 비트로 뒤집기(XOR) + fractional
3. **필터 적용**:
   - Point: 하나의 텍셀을 읽어 그대로 반환
   - Linear(이중 선형 보간): 주변 4개 텍셀을 읽고 거리 가중치로 섞음 — 텍스처 캐시 대역폭이 4배로 필요
4. **결과 반환**: 필터링된 색이 다시 셰이더 ALU로 전달됩니다.

이 때문에 샘플링은 "셰이더 ALU 연산 + 메모리 읽기"가 결합된 작업이며, **텍스처 캐시(L1/L2)** 히트율이 성능을 좌우합니다. Linear 필터는 텍셀 4개를 읽으므로 캐시와 대역폭 사용량이 Point의 4배입니다. 같은 텍스처를 화면의 이웃 픽셀들이 함께 읽으므로 캐시 지역성이 좋아 실제로는 큰 부담이 되지 않지만, 이것이 "큰 텍스처를 잔뜩 샘플링하면 GPU 메모리 대역폭이 병목이 된다"는 원칙의 시작입니다.

### 6-3. 픽셀 좌표 vs 텍셀 좌표의 반올림 규칙

D3D11의 텍스처 좌표계는 "텍셀 중심" 규칙을 씁니다. 텍셀 (u,v)의 중심은 `(u + 0.5) / width`입니다. 32×32 텍스처에서 UV 0은 "첫 텍셀의 왼쪽 가장자리"가 아니라 "첫 텍셀 중심에서 0.5칸 왼쪽"이므로, Point 필터가 UV 0.0을 읽으면 첫 텍셀이 아니라 **하프-텍셀 시프트**된 결과가 나옵니다. 이 튜토리얼의 체커 테두리가 Clamp 모드에서 줄줄 늘어나는 것도 같은 좌표 규칙의 결과입니다. 이 0.5 시프트는 UV를 정확히 텍셀에 맞추는 모든 2D 게임에서 반드시 기억해야 하는 규칙입니다.

### 6-4. 슬롯/레지스터: 셰이더와 하드웨어의 계약

HLSL의 `register(t0)`는 텍스처 슬롯, `register(s0)`은 샘플러 슬롯입니다. 셰이더 컴파일 후 바이트코드는 "t0 텍스처 + s0 샘플러로 샘플링하라"는 명령만 담고 있습니다. 실제 어떤 텍스처/샘플러가 꽂히는지는 **드로우 시점에 CPU가 설정한 슬롯 내용**이 결정합니다. 이것이 "규칙은 C++ 상태가 정한다"의 하드웨어적 의미입니다. GPU 관점에서는 `PSSetSamplers(0,1,샘플러)`와 `PSSetShaderResources(0,1,SRV)` 호출이 명령 버퍼에 기록되고, 드로우 명령이 실행될 때 PS 스테이지의 샘플러 레지스터가 이 값을 사용합니다. s0와 s1이 이 튜토리얼에서 각각 다른 샘플러를 받고, 셰이더가 `gSamplerBefore`/`gSamplerAfter`로 참조하는 것이 바로 이 메커니즘입니다.

### 6-5. 상태 객체가 저렴한 이유

`CreateSamplerState`는 드라이버가 상태를 검증해 GPU가 읽을 수 있는 형태로 변환하고 하드웨어 desc를 만들어 반환합니다. 한 번 만든 뒤 바인딩은 명령 버퍼에 desc 포인터(핸들) 하나를 기록하는 정도라 매우 십니다. 그래서 엔진의 `RenderStates`는 **플라이웨이트 캐시**(enum 조합 → 상태 객체)로 미리 만들어 두고, 같은 조합은 다시 만들지 않습니다. 이 튜토리얼이 매 프레임 `SetSampler`를 두 번씩 부르는 이유이자, 다음 장들에서 드로우 사이에 상태를 바꿔 끼우는 것이 성능상 문제없는 이유입니다.

### 6-6. 한 걸음 더 — 밉 선택 원리와 필터링 비용

- **밉 레벨 자동 선택의 원리**: 하드웨어는 옆 픽셀과의 UV 차이(미분값, `ddx`/`ddy`)로 '픽셀 하나에 텍셀 몇 개가 지나가는지'를 재서 레벨을 고릅니다. 이웃 픽셀이 필요해서 PS는 항상 2×2 쿼드로 실행되고, 삼각형 경계의 남는 픽셀은 결과가 버려지는 **헬퍼 레인**이 됩니다 — 얇고 긴 삼각형이 많을수록 낭비가 커집니다.
- **비용 감각**: 바이리니어 ≈ 무료(TMU 전용 회로), 트라이리니어 ≈ 2배, 비등방 = 배율만큼. 밉맵은 화질과 캐시 적중률 모두에 이득이라 끌 이유가 없습니다.

## 7. 핵심 규칙 요약

- [ ] 샘플링 = 셰이더가 `Texture.Sample(샘플러, UV)`로 색을 꺼내는 행위. **어떤 샘플러인지는 C++ 상태가 정한다.**
- [ ] 필터: Point=최근접 1텍셀(각짐), Linear=주변 4텍셀 보간(부드러움). 확대(MAG)일 때 차이가 잘 보인다.
- [ ] 주소 모드: Wrap=반복, Clamp=가장자리 늘임, Mirror=거울 반복. UV가 0~1을 벗어날 때 적용.
- [ ] UV 0~N 사각형 + 체커 텍스처 = 주소 모드 차이를 한 화면에서 보는 표준 실험 방법.
- [ ] `SV_POSITION`은 픽셀 셰이더에서 **픽셀 단위 화면 좌표**. 좌/우 분할 드로우 기법의 핵심.
- [ ] 상수 버퍼 구조체는 **16바이트 배수** (예: `CbSplit` = `_f32` + `_f32 padding_[3]`).
- [ ] 상태 객체는 캐싱되므로 매 프레임 `SetSampler` 호출은 저렴하다.
- [ ] 문자 키 `'1'`~`'5'`는 가상 키 코드 값과 같아 `IsKeyPressed('1')`로 바로 쓴다.
