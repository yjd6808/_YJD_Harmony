## 1. 이제 행렬을 실전으로!

04~06번에서는 정점에 NDC 좌표를 직접 적었습니다. 불편하죠.
이제부터는 정점을 **물체 기준 좌표(로컬 좌표)**로 만들고, 행렬을 곱해 원하는 위치로 보냅니다.

### 좌표계의 3단 변신 (이 시리즈의 핵심 그림)

```
로컬 좌표 ──(월드 행렬)─→ 월드 좌표 ──(뷰 행렬)─→ 카메라 좌표 ──(투영 행렬)─→ NDC
(물체 기준)              (세상 기준)             (카메라 기준)              (화면)
```

- **로컬**: 물체 자신이 중심. "내 코는 내 얼굴 가운데에 있다"
- **월드**: 세상의 중심 기준. "나는 지구 위 서울에 있다"
- **카메라(뷰)**: 카메라가 중심. "내 앞 3m에 있다" → 08번
- **NDC**: 화면 기준 -1~+1 → 04번에서 배움

이번 튜토리얼은 첫 번째 화살표인 **월드 행렬**을 다룹니다.

## 2. SRT 공식 — 크기, 회전, 이동의 올바른 순서

```cpp
Mat4 world = Mat4::Scale(2.0f, 2.0f, 1.0f)      // 1) 먼저 2배로 키우고
           * Mat4::RotationZ(angle)              // 2) 제자리에서 회전하고
           * Mat4::Translation(0.5f, 0.0f, 0.0f);// 3) 오른쪽으로 이동
```

sgf는 행 벡터 규약(`v' = v * M`)이므로 **왼쪽 행렬부터 적용**됩니다.

왜 S → R → T 순서일까요? 순서를 바꿔보면 압니다.

- **T → R**: 먼저 이동해버리면 회전이 원점 기준이 라 물체가 원점 주위를 큽도는 '공전'이 됨
- **R → S**: 회전 후 축 단위 확대를 하면 물체가 비스듬히 찌그러짐

그래서 "제자리에서 크기 바꾸고 → 제자리에서 돌리고 → 마지막에 갖다 놓기"가 정답입니다.

### 셰이더에서 사용하기

월드 행렬을 상수 버퍼(05번에서 배움!)로 보내고, VS에서 곱합니다.

```hlsl
cbuffer CbTransform : register(b0)
{
	row_major float4x4 gWorld; // sgf 규약: 항상 row_major
};

VSOutput VSMain(VSInput _input)
{
	VSOutput output;
	output.position = mul(float4(_input.position, 1.0f), gWorld); // 행 벡터 × 행렬
	output.color = _input.color;
	return output;
}
```

## 3. 계층 구조 — 태양-지구-달

이번 튜토리얼의 하이라이트입니다. 달은 지구를 도고, 지구는 태양을 돕니다.
이걸 일일이 계산하려면 머리가 아프지만, **행렬 곱셈 하나**로 해결됩니다.

```cpp
// 태양: 원점에서 자전만
Mat4 sunWorld = Mat4::RotationZ(sunSpin);

// 지구: (1) 자전하고 (2) 태양에서 멀리 떨어져 (3) 태양 주위를 공전
Mat4 earthWorld = Mat4::RotationZ(earthSpin)          // 자전
                * Mat4::Translation(0.6f, 0.0f, 0.0f) // 태양으로부터 거리
                * Mat4::RotationZ(earthOrbit);        // 공전 (원점=태양 기준 회전)

// 달: 지구 기준으로 같은 공식을 만들고, 마지막에 지구의 월드 행렬을 곱한다!
Mat4 moonWorld = Mat4::Scale(0.4f)                     // 달은 작게
               * Mat4::Translation(0.25f, 0.0f, 0.0f) // 지구로부터 거리
               * Mat4::RotationZ(moonOrbit)            // 지구 주위 공전
               * earthWorld;                           // ← 부모(지구) 변환 상속!
```

마지막 줄이 핵심입니다.

> **자식의 월드 행렬 = 자식의 로컬 변환 × 부모의 월드 행렬**

이 한 줄이 바로 **씬 그래프(Scene Graph)**의 수학적 정체입니다.
Cocos2d-x의 `addChild`, sgf의 `Node::AddChild`(14번)가 내부에서 하는 일이 정확히 이것입니다. 부모가 움직이면 자식이 따라 움직이는 이유 = 부모 행렬이 곱해져 있으니까!

## 4. 튜토리얼(7번)에서 직접 확인할 것

1. 태양(큰 사각형)이 제자리에서 돌고, 지구가 그 주위를 돌고, 달이 지구 주위를 돕니다.
2. 각 천체는 사실 모두 **같은 정점 버퍼**(사각형 하나)를 사용합니다. 월드 행렬만 바꿔 3번 그리는 것입니다. (인스턴싱의 기초 개념)
3. 실험 제안: `earthWorld`의 곱셈 순서를 바꿔보세요. 공전이 망가지는 모습으로 순서의 중요성을 체감할 수 있습니다.
4. 실험 제안: 달에 손자(달의 달)를 추가해보세요. `로컬 × moonWorld`만 곱하면 됩니다.

## 5. 정리

| 개념 | 한 줄 요약 |
|---|---|
| 로컬 → 월드 | 물체 기준 좌표를 세상 기준으로 |
| SRT | Scale × Rotation × Translation 순서 |
| 공전 | 이동 후 회전 (`T × R`) |
| 계층 구조 | 자식 월드 = 자식 로컬 × 부모 월드 |
| 씬 그래프 | 계층 변환을 자동화한 구조 (14번) |
