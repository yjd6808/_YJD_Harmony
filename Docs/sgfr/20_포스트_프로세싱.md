# 20. 포스트 프로세싱 — 다 그린 화면을 통째로 후보정하기

> 튜토리얼: `Projects/sgfr/Sources/sgfr/20_PostProcess/`
> 선행 학습: `19_렌더_타깃.md` (반드시 먼저!)

---

## 1. 왜 필요한가요?

사진 앱의 "필터"를 생각해 보세요. 사진을 다 찍은 뒤에 세피아 톤을 입히거나, 흑백으로 만들거나, 가장자리를 어둡게 하죠.
게임도 똑같은 일을 합니다. 장면을 다 그린 뒤 **화면 전체를 한 장의 그림으로 보고 후보정**하는 것 — 이게 포스트 프로세싱(Post Processing)입니다.

실제 게임의 블룸, 모션 블러, 피격 시 화면 붉어짐, 독 맞았을 때 화면 보라색, 회상 신 흑백 처리가 전부 이 기법입니다.

---

## 2. 개념 설명

### 2-1. 전체 구조 — 단 2패스

```
패스 1: [3D 장면] ─그리기→ppp [렌더 타깃 텍스처]   (19번에서 배운 그것)
패스 2: [화면 꽉 채우는 사각형] + [후보정 셰이더] ─그리기→ [백버퍼]
```

패스 2의 사각형을 **풀스크린 쿴드(Fullscreen Quad)**라고 부릅니다.
NDC 좌표 ±1로 직접 정점을 적으므로 행렬 변환이 아예 필요 없습니다. VS는 정점을 그대로 통과시키기만 합니다.

### 2-2. 후보정 셰이더의 입력은 "화면 = 텍스처"

픽셀 셰이더 입장에서 보면, 방금 그려진 장면은 그냥 텍스처 한 장입니다.
즉 **포스트 프로세싱 = "텍스처 색을 읽어서 수식으로 가공하는 픽셀 셰이더 놀이"**입니다. 수식만 알면 무엇이든 만들 수 있습니다.

### 2-3. 이번 튜토리얼의 6가지 효과 수식

| 모드 | 수식 | 원리 |
|---|---|---|
| 0 원본 | `color` | 그대로 통과 |
| 1 그레이 | `dot(rgb, (0.299, 0.587, 0.114))` | 눈은 초록에 제일 민감 — 가중치 평균으로 밝기 추출 |
| 2 세피아 | `gray × (1.07, 0.87, 0.65)` | 흑백에 누런 빛을 곱해 옛날 사진 느낌 |
| 3 반전 | `1 - rgb` | 색상 뒤집기 (필름 네가티브) |
| 4 비네트 | `saturate(1 - 중심거리×1.4)²` 곱하기 | 가장자리로 갈수록 어둡게 — 시선 집중 효과 |
| 5 물결 | UV에 `sin/cos` 흔들기 더한 후 샘플 | 읽는 위치 자체를 일렁이게 — 시간을 받아 움직임 |

중요한 패턴 두 가지:
- 1~4는 **색을 읽은 뒤** 가공 (색 공간 조작)
- 5는 **읽기 전에 UV를** 가공 (좌표 공간 조작) — 굴절, 열흔림, 충격파 효과가 전부 이 계열입니다

### 2-4. 샘플러는 왜 Clamp인가

물결 모드에서 UV가 0~1을 살짝 벗어날 수 있습니다. Wrap이면 화면 반대편 가장자리 색이 샐니다.
15번에서 배운 대로, 화면 계열 텍스처는 항상 **Clamp**입니다.

## 3. 코드 따라가기 — 20번 튜토리얼

### 3-1. 두 벌의 셰이더

- `SceneCubeShaderSource()`: 회전 큐브를 그리는 평범한 셰이더 (09번과 같은 구조)
- `PostProcessShaderSource()`: 풀스크린 쿴드용. `CbPost(b0)`에 모드 번호와 시간이 들어있고, PS에서 switch처럼 모드별 수식 적용

### 3-2. 메인 루프의 흐름

```cpp
// 패스 1: 장면 → 타깃
device.SetRenderTarget(&sceneTarget);
sceneTarget.Clear(&device, 어두운보라);
// 큐브 그리기 (회전 행렬 + DrawIndexed)

// 패스 2: 타깃 → 화면
device.SetRenderTarget(nullptr);
cbPost.UpdateAndBind(&device, postData, 0);      // 모드/시간 전달
device.SetSampler(SamplerFilter::Linear, SamplerAddress::Clamp);
sceneTarget.BindAsTexture(&device, 0);           // 장면 = 텍스처
// 풀스크린 쿴드 그리기 (정점 4개, 인덱스 6개짜리)
```

조작: **0~5 숫자 키**로 효과 전환. 윈도우 제목에 현재 효과 이름이 표시됩니다.

## 4. 직접 해보기

1. 그레이 계수를 `(0.333, 0.333, 0.333)` 단순 평균으로 바꿔보세요. 미묘하게 느낌이 다릅니다. 왜 눈에는 0.587이 더 자연스러울까요?
2. 비네트의 1.4를 2.5로 바꿔 터널처럼 좁아지는 시야를 만들어보세요.
3. 물결의 진폭 0.01을 0.05로 키우면 술 취한 화면이 됩니다.
4. 새 효과를 직접 추가해보세요: 모드 6으로 "색을 4단계로 뚝뚝 끊기" `floor(color × 4) / 4` (포스터라이즈 효과). 셰이더 문자열만 고치면 됩니다!

## 5. 정리

- 포스트 프로세싱 = 장면을 타깃에 그리고 → 풀스크린 쿴드로 후보정해 화면에 출력
- 효과는 픽셀 셰이더 수식일 뿐: 색 가공(그레이/세피아/반전/비네트) vs UV 가공(물결)
- 화면 계열 텍스처는 Clamp 샘플러
- 상용 엔진의 블룸/모션블러/톤매핑도 전부 이 구조의 확장판

다음 장(21번)은 렌더 타깃 기법의 꽃, **그림자 매핑**입니다. 이제 모든 재료가 준비됐습니다.

## 부록: Before/After 비교 뷰 (이동형 경계 슬라이더)

이 튜토리얼은 사진 앱의 "필터 미리보기"처럼 효과 적용 전/후를 한 화면에서 비교할 수 있도록 되어 있습니다.

| 구분 | 위치 | 내용 |
|---|---|---|
| **Before** | 노란 경계선 왼쪽 | 원본 장면 그대로 |
| **After** | 노란 경계선 오른쪽 | 선택한 효과(그레이/세피아/반전/비네트/물결) 적용 |

다른 튜토리얼과 달리 경계가 고정이 아니라 **왼쪽/오른쪽 방향키로 경계를 직접 좀일 수 있습니다** (2% ~ 98%).

### 어떻게 구현했나요?

- 상수 버퍼 `CbPost`에 `split_`(0~1) 값을 추가했습니다. (16바이트 정렬 유지)
- 화면 전체 사각형의 픽셀 셰이더가 `uv.x < gSplit`이면 효과 없이 원본을 그대로 샘플링해 반환하고, 오른쪽만 효과 분기를 탑니다.
- 물결 효과처럼 UV 자체를 흔드는 효과도 경계 오른쪽에서만 적용됩니다.

### 관찰 포인트

- 경계를 천천히 움직이며 같은 픽셀이 원본 ↔ 효과 사이를 넘나드는 순간을 관찰하세요. 효과가 정확히 무엇을 바꾸는지 픽셀 단위로 확인됩니다.
- 장면(회전 큐브)은 하나인데 경계 양쪽의 느낌이 완전히 다릅니다. 포스트 프로세싱이 장면과 무관한 "화면 픽셀 후보정"이라는 증거입니다.
- 0번(원본)을 선택하면 경계 양쪽이 완전히 같아집니다.
