변환 순서 — 공간에서 공간으로

카메라 공간의 정점은 아래 순서로 공간을 갈아탑니다. 화살표 하나가 변환 한 번입니다.

STEP ①

near 평면에 투영

정점과 투영점은 카메라에서 나가는 같은 광선 위에 있으므로 닮음입니다. 여기에는 FOV가 필요 없습니다.

yn / n = y1 / z1
yn = n·y1 / z1
xn = n·x1 / z1
STEP ②

화면 경계로 정규화

near 평면의 위쪽 끝 높이 hn과 오른쪽 끝 너비 wn으로 나누면 [−1, 1]이 됩니다. tan은 여기서 등장합니다.

hn = n·tan(θv/2)
wn = a·hn
yNDC = yn / hn
STEP ③

n 소거 → 행렬화

n이 약분되고 z1으로 나누는 일만 남습니다. 이 나눗셈을 w에 맡기고, 깊이는 0~1로 맞춥니다.

yNDC = y1 / (z1·tan(θv/2))
wclip = z1
zNDC = A + B / z1
실제 GPU에서의 순서

위 ①→③은 “이해용” 순서입니다. 실제로는 Mproj를 곱해 클립 공간(w = z1)을 만들고, 클리핑한 뒤 ÷w 한 번으로 투영과 정규화가 동시에 끝납니다. near 평면에 투영하는 중간 단계는 행렬 안에서 따로 계산되지 않습니다.

Chapter 02

near·far와 렌더링 범위

카메라는 어디까지 그리고, 왜 가까운 물체가 크게 보이는가.

2-1. FarZ는 “깊이 범위의 끝”

far는 원거리 클리핑 평면입니다. near보다 가까운 부분과 far보다 먼 부분은 잘립니다. 기준은 카메라에서의 직선거리가 아니라 전방 깊이 z1입니다.

n ≤ z1 ≤ f
  • f = 1000이면 “전방 깊이 1000까지”이지, 반지름 1000인 구 안이 아닙니다.
  • 이 범위 안이라도 FOV 밖에 있거나 다른 물체에 가려지면 보이지 않습니다.
  • far 평면에 걸친 물체는 원칙적으로 안쪽 부분만 표시됩니다. 엔진의 거리 콜링이 물체 전체를 먼저 제외할 수도 있습니다.

2-2. 왜 가까우면 크게 보이나

near와 far 모두 화면의 경계는 NDC ±1로 갑니다. 하지만 그 경계까지의 실제 크기가 다릅니다. far 쪽은 더 큰 영역을 같은 [−1, 1]에 압축해 넣습니다.

같은 깊이 z1에 있는 두 정점의 높이 차가 Δy라면 (Ch 5의 결과를 미리 쓰면):

ΔyNDC = Δyz1·tan(θv/2)

화면에서 차지하는 크기는 깊이 z1에 반비례합니다. 같은 길이는 near에서 far보다 f / n배 크게 보입니다.

Chapter 03

near 평면에 투영 — 닮은 삼각형

정점 (y1, z1)이 near 평면 Z = n에서 어디 (yn, n)에 떨어지는지 구합니다.

3-1. 같은 광선 위의 두 점

카메라 원점에서 정점으로 직선을 긋고, 그 직선이 near 평면과 만나는 점이 투영점입니다. 평면에 수직으로 내리는 정사가 아니라, 카메라를 향하는 직선을 따라 투영합니다.

카메라            near 평면 (Z=n)            정점 (Z=z₁)
  O ─────────────────┼────────────────────────── (y₁, z₁)
                 (yₙ, n)  ← 투영점

카메라 각을 공유하고 둘 다 직각인 삼각형이므로 닮음입니다.

ynn = y1z1 ⇒ yn = nz1·y1 (3-1)
xn = nz1·x1 (3-2)
여기엔 tan이 없다

이 식은 정점을 평면에 옮기는 일만 합니다. FOV와 무관합니다. yn은 아직 정규화 전의 실제 높이라서 1보다 클 수도 있습니다.

3-2. 예시

n = 2, 정점 (y1, z1) = (3, 4)이면:

yn = 24 × 3 = 1.5

이 1.5가 화면에서 어디인지는 화면 맨 위가 near 평면에서 얼마인지 알아야 정해집니다. 그게 다음 챕터의 hn입니다.

Chapter 04

화면 경계 hn, hf 구하기 — tan(θv/2)가 나오는 곳

화면 맨 위 경계가 각 평면에서 실제로 얼마의 높이인지 FOV로 구합니다.

4-1. 경계는 각도 θv/2의 광선 위에 있다

전방 축과 시야 위쪽 경계 사이 각은 θv/2입니다. 탄젠트 = 높이 ÷ 전방 거리이므로:

tan(θv2) = hnn = hff (4-1)
hn = n·tan(θv/2), hf = f·tan(θv/2), hfhn = fn

near의 위쪽 경계와 far의 위쪽 경계는 같은 광선 위에 있습니다. 그래서 두 비율이 같고, 둘 다 NDC y = 1에 대응합니다.

θv = 90°, n = 2, f = 10Near (Z = 2)Far (Z = 10)
NDC y = 1에 대응하는 실제 높이hn = 2hf = 10
카메라 공간 높이 범위−2 ~ 2−10 ~ 10
높이 ÷ 거리 = tan 45°2 / 2 = 110 / 10 = 1
NDC 높이 범위−1 ~ 1−1 ~ 1
1 / n = tan(θv/2)는 틀린 식

NDC의 1은 정규화된 값입니다. 분자에는 각 평면에서 경계까지의 실제 높이가 들어가야 합니다. 1/n = 1/f는 n ≠ f이면 성립하지 않습니다. 1/n = tan(θv/2)는 우연히 hn = 1인 경우에만 맞습니다.

4-2. 임의의 점은 각도가 다르다

화면 안의 임의의 투영점 yn은 자기만의 각도 α를 가집니다.

ynn = tan α (점마다 다름) vs hnn = tan(θv/2) (고정)

투영점이 화면 맨 위까지 올라가면 yn = hn, α = θv/2가 됩니다. tan(θv/2)는 경계 하나에만 쓰는 값입니다.

Chapter 05

NDC 정규화 — 왜 n이 사라지는가

투영된 높이를 화면 반높이로 나눠 [−1, 1]로 만들고, 식을 정점 좌표만으로 다시 씁니다.

5-1. 정규화 = 투영 높이 ÷ 화면 반높이

yNDC = ynhn = ynn·tan(θv/2) (5-1)
n = 2, θv = 90° (hn = 2)ynyn / n = tan αyNDC = yn / hn

중심000

[−1, 1] 안에 있어야 하는 것은 yNDC이지 yn이 아닙니다.

5-2. (3-1)을 대입하면 n이 약분된다

yNDC = (n / z1)·y1n·tan(θv/2) = y1z1·tan(θv/2) (5-2)

최종 식에는 near 거리 n이 없고, 정점의 깊이 z1만 남습니다.

5-3. 상은 어디에 맺히나 — “화면”은 특정 Z에 고정되어 있지 않다

화면 역할을 하는 가상 평면을 near 대신 임의의 깊이 s에 놓아도 같습니다. 투영 높이도, 화면 반높이도 같이 s에 비례하기 때문입니다.

yNDC = (s / z1)·y1s·tan(θv/2) = y1z1·tan(θv/2)
  • 화면 평면만 옮긴다(s = n, s = f, 임의의 값) → X·Y NDC는 같습니다.
  • 물체를 옮긴다(z1이 바뀜) → NDC가 달라져 크기가 바뀝니다.

near 평면은 “화면이 놓인 위치”가 아니라 가까운 쪽을 잘라내는 경계입니다. 다만 이해할 때는 near 평면을 화면으로 생각해도 결과가 같습니다.

결론 — 상이 맺히는 “정확한 Z”는 없다

원근 투영에는 실제 카메라의 필름이나 센서 같은 고정된 상 평면이 없습니다. “화면에 맺힌다”는 말은 정점이 어느 광선 방향에 있는지를 2D 좌표로 바꾼다는 뜻입니다. 투영 평면을 near에 두든, far에 두든, 깊이 1에 두든 결과 NDC는 똑같습니다. 그래서 “화면이 정확히 어느 z에 있느냐”는 정답이 없는 질문이고, 정할 필요도 없습니다.

헷갈리기 쉬운 것 — zNDC = 0, 1은 화면 평면이 아니다

zNDC = 0은 near 평면, zNDC = 1은 far 평면에 대응합니다. 하지만 이건 깊이 버퍼에 저장할 깊이 값의 범위일 뿐, “상이 z = 0에 맺힌다”거나 “화면이 z = 1에 있다”는 뜻이 아닙니다.

  • xNDC, yNDC → 화면의 어디에 찍히나 (방향). 투영 평면 위치 s와 무관합니다.
  • zNDC → 얼마나 먼가 (가림 판정용). 화면 위치 정보가 아닙니다.

즉 NDC 공간의 z축은 “화면 안쪽 깊이 눈금”이고, 화면 자체는 x·y 두 축뿐입니다. 화면은 특정 z 평면이 아니라 x·y 정사각형 [−1, 1]²입니다.

Chapter 06

수평 FOV와 화면 비율 a

가로 방향은 수평 FOV를 쓰고, 수평 FOV는 화면 비율로 수직 FOV에서 구합니다.

6-1. 가로도 같은 원리

wnn = tan(θh2), xNDC = xnwn

화면 비율이 a이면 wn = a·hn이므로:

tan(θh/2) = a·tan(θv/2) (6-1)

각도가 아니라 탄젠트 값이 a배입니다. θh = a·θv가 아닙니다.

예) θv = 45°, 16:9
tan(θh/2) = (16/9)·tan 22.5° ≈ 0.736
θh = 2·arctan(0.736) ≈ 72.7°

(5-2)와 같은 방식으로 n을 약분하면:

xNDC = x1z1·tan(θh/2) = x1z1·a·tan(θv/2) (6-2)

6-2. a를 빼면 어떻게 되나

a 없이 xn을 hn으로 나누면 수평 FOV도 θv로 취급하는 것과 같습니다. 카메라는 45° × 45° 정사각형 시야만 보고, 그걸 16:9 화면에 꽉 채우게 됩니다.

θv = 45°, 16:9a 사용a 미사용
실제로 보이는 수평 범위≈ 72.7°45° (양옆이 잘림)
화면에 그려지는 모습정상 비율가로로 약 1.78배 늘어남
원의 모양원가로로 긴 타원
왜 최종 화면은 정상 비율인가

NDC는 가로·세로 모두 [−1, 1]인 정사각형 공간입니다. 투영할 때 가로를 a로 나눠 압축하고, 뷰포트 변환에서 화면 너비에 맞춰 다시 늘리므로 두 과정이 상쇄됩니다. 화면이 정사각형(a = 1)이면 a를 빼도 결과가 같습니다.

Chapter 07

클립 공간과 wclip = z1

행렬은 나눗셈을 못 합니다. 그래서 분자만 계산하고, 분모 z1은 wclip 자리에 맡겨 둡니다.

7-1. 기호

  • 정점(행 벡터): [x1 y1 z1 1] — 카메라 공간
  • M: 4×4 투영 행렬, mij는 i행 j열 칸
  • 클립 좌표: [xclip yclip zclip wclip] = [x1 y1 z1 1] · M
  • sy = 1tan(θv/2), sx = sya

7-2. 행렬은 “곱하고 더하기”만 한다

행 벡터 기준으로 클립 좌표의 j번째 성분은 M의 j열과 곱해진 값입니다.

(j번째 성분) = x1·m1j + y1·m2j + z1·m3j + 1·m4j

즉 x1, y1, z1의 일차식만 만들 수 있습니다. y1 / z1처럼 변수로 나누는 식은 만들 수 없습니다.

7-3. wclip은 정점의 깊이 z1 그 자체

M의 4열을 [0, 0, 1, 0]으로 두면

wclip = x1·0 + y1·0 + z1·1 + 1·0 = z1

행렬은 깊이 z1을 w 자리에 복사해 둘 뿐입니다. 나눗셈은 그다음 GPU가 합니다.

7-4. 네 성분을 모두 같은 wclip으로 나눈다

성분클립 (행렬 결과)NDC (÷ wclip)
xxclip = sx·x1xNDC = sx·x1 / z1
yyclip = sy·y1yNDC = y1 / (z1·tan(θv/2))
zzclip = A·z1 + BzNDC = A + B / z1
wwclip = z11

7-5. near 평면 식과 완전히 같다

yNDC = yclipwclip = sy·y1z1 = y1z1·tan(θv/2) = ynhn = n·y1 / z1n·tan(θv/2)
순서만 다르다

행렬 경로: sy·y1을 먼저 만들고 나중에 ÷ z1
near 평면 경로: 먼저 ÷ z1(투영)하고 나중에 ÷ hn(정규화)
wclip = z1은 x, y, z가 함께 쓰는 공통 분모입니다.

7-6. 숫자로 보기

θv = 90°, a = 16/9, n = 2, f = 10, 정점 (3, 3, 4)

클립 = [1.6875, 3, 2.5, 4] → wclip = z1 = 4
NDC = [1.6875/4, 3/4, 2.5/4] = (0.421875, 0.75, 0.625)
검산: yn = 2·3/4 = 1.5, hn = 2·tan 45° = 2 → 1.5 / 2 = 0.75 ✓
Chapter 08

깊이 — 왜 zNDC = A + B / z1인가

이 모양은 우리가 고른 게 아닙니다. 행렬과 ÷ w 때문에 이 모양밖에 나올 수 없습니다.

8-1. 1단계 — 행렬이 만드는 zclip

zclip은 M의 3열과 곱해집니다.

zclip = x1·m13 + y1·m23 + z1·m33 + 1·m43

깊이가 화면 위치 x1, y1에 따라 달라지면 안 되므로 m13 = m23 = 0. 남은 두 칸을 A = m33, B = m43이라 부르면

zclip = A·z1 + B

8-2. 2단계 — z만 빼고 나눌 수는 없다

x, y는 원근 때문에 z1로 나눠야 해서 wclip = z1로 정했습니다(7장). 정점 하나에 w는 딱 하나이고, GPU는 x, y, z를 전부 그 w로 나눕니다.

8-3. 3단계 — 합치면

zNDC = zclipwclip = A·z1 + Bz1 = A + Bz1
이 모양은 강제된다

행렬이라서 → 분자는 A·z1 + B
x, y 때문에 정한 w = z1 → 분모는 z1
우리가 고를 수 있는 건 숫자 A, B 두 개뿐입니다.

8-4. A, B 구하기 — near → 0, far → 1

A + B / n = 0 ⇒ B = −A·n
A + B / f = 1 ⇒ A − A·n / f = 1 ⇒ A(f − n) = f
A = ff − n, B = −n·ff − n

미지수 2개, 조건 2개라서 n < f이기만 하면 범위가 아무리 커도 항상 0 ~ 1에 맞출 수 있습니다.

8-5. 왜 z1을 직선으로 0 ~ 1에 못 넣나

원하는 값이 (z1 − n)/(f − n)이라면, 나눗셈 뒤에 이 값이 나오려면 나누기 전에

zclip = z1 − nf − n·z1

이어야 합니다. 이건 z1² 항이라 행렬로 만들 수 없습니다. 그래서 깊이는 1/z1 꼴(비선형)이 됩니다. 대신 A + B/z1은 화면 공간에서 선형이라 삼각형 안에서 픽셀별로 직선 보간하기 좋습니다.

8-6. 비선형이라 생기는 일

n = 2, f = 10z1 = 2z1 = 4z1 = 6z1 = 10
zNDC00.6250.8331

앞쪽 구간이 깊이 값 대부분을 씁니다. 먼 쪽은 정밀도가 떨어져 Z-fighting이 생기기 쉽고, 주원인은 n을 너무 작게 잡는 것입니다.

[x1 y1 z1 1]·M = [sx·x1 sy·y1 f·z1 − n·ff − n z1]

w = z1로 나누면 7-4 표의 NDC 식이 그대로 나옵니다.

위치값역할
1행 1열sx = 1 / (a·tan(θv/2))가로를 화면 반너비 기준으로 정규화

열벡터(M·v) 기준이면 이 행렬을 전치해서 씁니다.

Chapter 10

클립 공간 → NDC → 화면 픽셀

행렬 곱 이후 GPU가 하는 세 단계: 클리핑, 원근 나눗셈, 뷰포트 변환.

10-1. 클리핑 — 나누기 전에 한다

NDC 범위 조건에 w를 곱하면 클립 공간에서 바로 검사할 수 있습니다.

−w ≤ xclip ≤ w
−w ≤ yclip ≤ w
  0 ≤ zclip ≤ w 깊이 0~1 기준

나누기 전에 검사하는 이유는 카메라 뒤쪽(w ≤ 0) 정점 때문입니다. 먼저 나누면 부호가 뒤집히거나 0으로 나누게 됩니다. 경계에 걸친 삼각형은 클립 공간에서 잘라 새 정점을 만듭니다.

10-2. 원근 나눗셈 — 클립 → NDC

(xNDC, yNDC, zNDC) = (xclipw, yclipw, zclipw)

이 한 번의 나눗셈으로 “near 평면 투영(÷ z1)”과 “화면 경계 정규화”가 동시에 끝납니다. 결과는 x, y ∈ [−1, 1], z ∈ [0, 1]인 상자입니다.

10-3. 뷰포트 변환 — NDC → 픽셀

화면 크기를 W × H 픽셀이라 하면, 픽셀 Y는 아래로 증가하므로 세로를 뒤집습니다.

px = xNDC + 12·W
py = 1 − yNDC2·H
depth = zNDC 깊이 버퍼

여기서 가로를 W로, 세로를 H로 늘리면서 Ch 6의 a로 나눈 압축이 상쇄됩니다.

Chapter 11

숫자로 끝까지 따라가기

정점 하나를 행렬부터 픽셀까지 넣어 보고, near 평면 방식과 결과가 같은지 확인합니다.

11-1. 설정

θv = 90° (tan 45° = 1), 화면 1920 × 1080 (a = 16/9), n = 2, f = 10
sy = 1, sx = 9/16 = 0.5625, A = 1.25, B = −2.5
정점 (x1, y1, z1) = (3, 3, 4)

11-2. 행렬 경로

  1. 클립 공간: [3·0.5625, 3·1, 1.25·4 − 2.5, 4] = [1.6875, 3, 2.5, 4]
  2. 클리핑: |1.6875| ≤ 4, |3| ≤ 4, 0 ≤ 2.5 ≤ 4 → 통과
  3. NDC: (1.6875/4, 3/4, 2.5/4) = (0.4219, 0.75, 0.625)
  4. 픽셀: px = (1.4219/2)·1920 = 1365, py = (0.25/2)·1080 = 135

11-3. near 평면 경로로 검산

hn = 2·tan 45° = 2, wn = a·hn ≈ 3.556
yn = 2·3/4 = 1.5 → yNDC = 1.5 / 2 = 0.75 ✓
xn = 2·3/4 = 1.5 → xNDC = 1.5 / 3.556 ≈ 0.4219 ✓
