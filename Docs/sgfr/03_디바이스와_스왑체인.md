# 03. 디바이스와 스왑체인 — GPU와 대화 시작, 화면 지우기

> 관련 코드: `Projects/sgf/Sources/sgf/Graphics/GraphicDevice.h/.cpp`, `Projects/sgfr/Sources/sgfr/03_DeviceAndSwapChain/`
> 실행: sgfr 메뉴에서 **3번**

## 1. 이번 장의 목표

윈도우(종이)는 준비됐으니, 이제 **붓(GPU)**을 손에 쥐어야 합니다.
이번 튜토리얼에서는 삼각형도 그리지 않습니다. 딱 하나, **화면을 원하는 색으로 지우는 것**만 합니다.
그런데 이 "화면 지우기" 안에 DX11 초기화의 핵심이 전부 들어 있습니다.

---

## 2. 등장인물 4명

### 2-1. Device (ID3D11Device) — 공장장

GPU 자원을 **만드는** 담당자입니다. 버퍼 생성, 텍스처 생성, 셰이더 생성… "만들기"는 전부 Device의 일입니다.

### 2-2. DeviceContext (ID3D11DeviceContext) — 현장 감독

만들어진 자원을 **사용해서 명령하는** 담당자입니다. "이 버퍼 묶어", "이 셰이더 써", "그려!(Draw)" 같은 명령은 전부 Context로 내립니다.

> 외우기 쉬운 구분법: **Create는 Device, Set/Draw는 Context.**

### 2-3. SwapChain (IDXGISwapChain) — 그림 교체 장치

화면에 그림을 보여주는 방법이 생각보다 정교합니다. 만약 모니터에 보이는 그림을 직접 수정하면, 그리는 중간 과정(지우고 → 하나씩 그리고)이 그대로 노출돼 화면이 깜박거립니다.

그래서 **종이를 두 장** 줍니다.

- **프론트 버퍼**: 지금 모니터에 보이는 그림
- **백버퍼**: 뒤에서 몰래 그리는 중인 다음 그림

다 그리면 `Present()` 호출 한 번으로 두 장을 교체합니다. 이것이 **더블 버퍼링**이고, 교체 장치가 스왑체인입니다. ("Swap" = 교체, "Chain" = 버퍼들의 줄)

### 2-4. RenderTargetView (RTV) — "여기에 그려도 됩니다" 허가증

DX11은 안전을 위해 자원을 직접 쓰지 않고 **View(뷰)**라는 허가증을 통해 사용합니다.
백버퍼를 "그리기 대상"으로 쓰려면 백버퍼의 RTV를 만들어 Context에 꽂아야 합니다.

> 같은 원리로 09번에서는 깊이 버퍼의 DSV(DepthStencilView), 11번에서는 텍스처의 SRV(ShaderResourceView)가 나옵니다. 전부 "용도별 허가증"입니다.

---

## 3. sgf GraphicDevice가 초기화되는 순서

`GraphicDevice::Initialize(HWND, width, height)`가 하는 일을 순서대로 보면:

1. **Device + Context + SwapChain 동시 생성** (`D3D11CreateDeviceAndSwapChain`)
   - 윈도우 핸들, 해상도, 버퍼 포맷(RGBA 8비트씩) 등을 기재한 설계서(DESC 구조체)를 넘깁니다.
2. **백버퍼를 꺼내 RTV 생성**
3. **깊이 버퍼(Depth Buffer) + DSV 생성** — 3D(09번)를 위해 미리 준비
4. **뷰포트(Viewport) 설정** — "윈도우의 이 영역에 그려라"는 사각형 지정 (전체 화면)
5. **샘플러/블렌드/깊이 상태 같은 공통 상태 준비** — 뒤 튜토리얼을 위한 기본값 (샘플러는 s0 슬롯에 자동 바인딩)

이 모든 과정이 주석과 함께 `GraphicDevice.cpp`에 적혀 있습니다. 꼭 한 번 정독하세요.

## 4. 매 프레임의 리듬: BeginFrame → (그리기) → EndFrame

```cpp
device.BeginFrame(Color(0.2f, 0.4f, 0.8f, 1.0f)); // 1) 백버퍼를 지정 색으로 통째로 칠하기
                                                   //    + 깊이 버퍼도 초기화
// 2) (다음 튜토리얼부터) 여기서 Draw 호출들이 들어감
device.EndFrame(true);                             // 3) Present로 프론트/백 교체. true = VSync 켜기
```

### VSync(수직 동기화)란?

모니터는 보통 1초에 60번 화면을 갱신합니다. VSync를 켜면(`EndFrame(true)`) 모니터 갱신 타이밍에 맞춰 교체하므로 화면 찢짐(티어링)이 없고 FPS가 60에 고정됩니다. 끄면 최대한 빠르게 그리지만 찢짐이 생길 수 있습니다.

---

## 5. 튜토리얼(3번)에서 직접 확인할 것

1. 화면이 시간에 따라 무지개 색으로 부드럽게 변합니다. (매 프레임 다른 색으로 Clear)
2. 콘솔에 초당 프레임 수(FPS)가 출력됩니다.
3. 코드에서 `EndFrame(false)`로 바꿔보면 FPS가 치솟는 것을 볼 수 있습니다. (VSync 실험)

화면에 아무것도 안 그렸는데 색이 바뀝니다. 이게 되면 GPU와의 대화가 성공한 것입니다!

## 6. 자주 헷갈리는 것들 (Q&A)

**Q. 왜 매 프레임 화면을 지워야 하나요? 지난 프레임 그림 위에 이어 그리면 안 되나요?**
- 움직이는 물체는 이전 위치의 잔상이 그대로 남습니다. 매 프레임 깨끗한 종이에 처음부터 다시 그리는 게 기본입니다.

**Q. 백버퍼는 몇 장이 좋나요?**
- sgf는 2장(더블 버퍼링)입니다. 3장(트리플)은 더 부드럽지만 지연이 늘 수 있습니다. 학습에는 2장이면 충분합니다.

**Q. ComPtr은 무엇인가요?**
- DX11 객체는 COM 객체라 수동으로 `Release()`를 호출해 반납해야 합니다. 깜빡하면 메모리 누수! sgf는 `SgfComPtr<T>`(= `Microsoft::WRL::ComPtr`)로 감싸 소멸 시 자동 반납되도록 했습니다. (C++의 스마트 포인터와 같은 아이디어)

## 7. 정리

| 개념 | 한 줄 요약 | sgf 코드 |
|---|---|---|
| Device | 자원 공장장 (Create 담당) | `device.Device()` |
| Context | 현장 감독 (Set/Draw 담당) | `device.Context()` |
| SwapChain | 프론트/백 버퍼 교체 장치 | `EndFrame` 내부 Present |
| RTV | "여기 그려도 됨" 허가증 | `BeginFrame` 내부 |
| 더블 버퍼링 | 뒤에서 그리고 한 번에 교체 | `BeginFrame`/`EndFrame` |
| VSync | 모니터 박자에 맞춰 교체 | `EndFrame(true)` |
