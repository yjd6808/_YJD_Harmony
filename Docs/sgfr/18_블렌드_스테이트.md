# 18. 블렌드 스테이트 — 새 색과 기존 색을 섞는 규칙

> 관련 코드: `Projects/sgfr/Sources/sgfr/18_BlendState/` (`18_BlendState_Main.cpp`, `18_BlendState_Function.cpp`)
> 엔진 코드: `Projects/sgf/Sources/sgf/Graphics/GraphicDevice.cpp` (`SetBlendMode`), `RenderStates.cpp` (`GetBlendState`)
> 실행: sgfr 실행 후 콘솔 메뉴에서 **18번** 선택
> 선행 학습: 17번(샘플러와 필터링 — 상태 객체 개념)

## 1. 이 장에서 배우는 것

픽셀 셰이더가 계산한 **새 색**과 백버퍼에 **이미 그려진 색**을 섞는 규칙인 **블렌딩(Blending)**을 배웁니다. 불투명/알파/가산/곱셈 네 가지 모드의 공식과 용도를 직접 비교하며, 블렌드 스테이트가 드로우 단위로만 바뀐다는 사실과 매 프레임 CPU에서 갱신하는 **동적 정점 버퍼**도 익힙니다.

## 2. 실행하면 보이는 것

화면이 **흰 세로선**으로 좌/우로 나뉘고, 양쪽 모두 **빨강/초록/파랑 원 3개**가 120° 간격으로 원형 궤도를 그리며 회전합니다.

- **왼쪽(Before)**: 블렌딩 미적용(Opaque) 고정 — 알파가 무시되어 원들이 각자의 **사각형**으로 통째로 보입니다.
- **오른쪽(After)**: 키로 선택한 모드 적용 — 원끼리 겹치는 부분의 색 합성이 달라집니다.

| 키 | 모드 | 공식 | 관찰 포인트 |
|---|---|---|---|
| `1` | Opaque | 덮어쓰기 | 알파 무시, 사각형 그대로 |
| `2` | Alpha | 새색×알파 + 기존색×(1-알파) | 반투명 겹침 |
| `3` | Additive | 새색×알파 + 기존색 | 겹칠수록 **흰색**으로 (빛의 삼원색) |
| `4` | Multiply | 새색 × 기존색 | 겹칠수록 **검게** (물감처럼) |

배경이 중간 밝기 회색인 이유는, 가산(밝아짐)과 곱셈(어두워짐)의 방향이 모두 뚜렷하게 보이도록 하기 위해서입니다. ESC로 종료합니다.

## 3. 핵심 개념 — 비유로 먼저 이해하기

### 3-1. 블렌딩 = "물감 통에 새 물감을 어떻게 넣을까?"

뒷면(백버퍼)에 이미 물감(기존색)이 발려 있습니다. 여기에 새 물감(새색)을 올리는데, 섞는 방식이 모드별로 다릅니다.

- **Opaque**: 통째로 부어 기존 물감을 완전히 덮습니다.
- **Alpha**: 새 물감의 알파(투명도)만큼만 넣고, 나머지는 기존 물감이 비쳐 보이게 합니다. 안개를 낀 유리처럼.
- **Additive**: 새 물감을 **추가로** 붓습니다. 무대 조명처럼 밝기만 올라갑니다.
- **Multiply**: 새 물감과 기존 물감을 섞어 **곱**합니다. 색필터를 겹치듯 어두워집니다.

이 "섞는 방법"은 픽셀마다 정할 수 없고, **드로우 호출 사이에 상태로 정합니다.** 한 드로우 안의 모든 픽셀은 같은 블렌드 공식을 씁니다.

### 3-2. 왜 블렌드는 드로우 단위인가?

17번에서 배운 샘플러와 같은 맥락입니다. 블렌드는 "출력 병합(OM) 단계"라는 고정 기능 하드웨어의 설정값입니다. 하드웨어 설정은 파이프라인 전체에 적용되므로, 그림 중간에 "이 픽셀만 다르게 섞어"라고 지시할 수 없습니다. 그래서 튜토리얼은 **왼쪽 묶음 → 오른쪽 묶음** 사이에 `SetBlendMode`를 끼워 넣어 비교합니다.

### 3-3. 동적 정점 버퍼 = "매번 자리를 바꾸는 좌석표"

원 3개가 매 프레임 움직이므로 정점 위치가 계속 바뀝니다. 일반 정점 버퍼(DEFAULT usage)는 한 번 넣으면 바꿀 수 없는 "인쇄된 좌석표"라면, **동적 버퍼(DYNAMIC usage)**는 "수정 가능한 전자 좌석표"입니다. `Create(..., true)`로 만들고 매 프레임 `vb.Update()`로 갱신합니다.

## 4. 초보자 용어 사전

| 용어 | 뜻(쉬운 말) | 비유 |
|---|---|---|
| 블렌딩(Blending) | 새 색과 기존 색을 섞는 규칙 | 물감 섞기 |
| OM(Output Merger) 단계 | 파이프라인 끝에서 색을 합치는 단계 | 그림 조립 마지막 공정 |
| SrcBlend / DestBlend | 새 색에 곱할 계수 / 기존 색에 곱할 계수 | 새 물감 양 / 기존 물감 유지 양 |
| 알파(Alpha) | 투명도 (0=완전 투명, 1=완전 불투명) | 안개의 짙기 |
| 가산 블렌드 | 새색×(알파) + 기존색 | 조명 겹치기 |
| 곱셈 블렌드 | 새색 × 기존색 | 색필터 겹치기 |
| 동적 정점 버퍼 | CPU가 매 프레임 내용을 갱신할 수 있는 버퍼 | 수정 가능한 좌석표 |
| Map / Unmap | GPU 메모리를 CPU가 잠시 접근하는 절차 | 통장에 입출금 기록하는 창구 |
| 백버퍼 | 화면에 표시되기 전 그림을 그리는 숨은 화면 | 무대 뒤의 캔버스 |

## 5. 코드 워크스루

`BlendState_Main()`의 흐름을 따라갑니다.

### 5-1. 준비: 부드러운 원 텍스처 + 동적 버퍼

```cpp
static _u8 s_Pixels[128 * 128 * 4];
FillSoftCirclePixels(s_Pixels, 128);           // 흰색 + 알파가 부드럽게 0으로

Texture texture;
texture.CreateFromMemory(&device, s_Pixels, 128, 128);

VertexPTC vertices[4] = {};
_u32 indices[6] = { 0, 1, 2, 2, 1, 3 };
VertexBuffer vb;
vb.Create(&device, vertices, sizeof(VertexPTC), 4, true);   // bDynamic = true!
ib.Create(&device, indices, 6);
```

`FillSoftCirclePixels`(18_BlendState_Function.cpp)는 중심에서 거리를 정규화해 안쪽 70%는 알파 1.0, 그 밖은 `1 - (dist - 0.7)/0.3`으로 선형 감쇠하는 흰 원을 만듭니다. 색은 텍스처가 아니라 **정점 색**으로 입히므로 원 텍스처 하나를 세 원 모두 재활용합니다.

`VertexBuffer::Create(..., true)`는 `D3D11_USAGE_DYNAMIC` + `CPU_ACCESS_WRITE`로 버퍼를 만들어 매 프레임 `Update`가 가능하게 합니다. 내부적으로 `Map(D3D11_MAP_WRITE_DISCARD)`로 "이전 내용은 버릴 테니 새 메모리 달라"고 요청해 GPU가 아직 읽는 중이어도 기다리지 않습니다.

### 5-2. 셰이더: 곱셈 블렌드를 위한 트릭

```hlsl
float4 PSMain(VSOutput _input) : SV_TARGET
{
	float4 tex = gTexture.Sample(gSampler, _input.uv) * _input.color;

	// 알파가 0일수록 색을 흰색(x1 = 변화 없음)으로 섞어서 내보낸다.
	return float4(lerp(float3(1.0f, 1.0f, 1.0f), tex.rgb, tex.a), tex.a);
}
```

곱셈 모드는 알파를 보지 않고 "기존색 × 새색"만 계산합니다. 만약 원 밖(알파 0) 픽셀이 검은색(0,0,0)을 내보내면 곱셈 결과가 0이 되어 **검은 사각형**이 남습니다. 그래서 알파 0일수록 색을 흰색(1,1,1)으로 끌어올려 "곱해도 변화 없음"으로 만듭니다. 이것은 곱셈 블렌드와 함께 쓸 때 흔한 실수(검은 사각형 잔상)를 피하는 전형적인 기법입니다.

### 5-3. 렌더 루프: 묶음 단위 드로우

```cpp
auto DrawCircleGroup = [&](const vec2& _groupCenter, GraphicDevice::BlendMode _mode)
{
	device.SetBlendMode(_mode);
	for (int c = 0; c < 3; ++c)
	{
		const _f32 angle = elapsed * 0.8f + jc_math_pi2 * c / 3.0f;   // 120도 간격
		const vec2 center(_groupCenter.x + cosf(angle) * 0.15f, _groupCenter.y + sinf(angle) * 0.15f);

		FillQuadVertices(vertices, center, 0.28f, circleColors[c]);
		vb.Update(&device, vertices, 4);     // 동적 버퍼 갱신
		vb.Bind(&device);  ib.Bind(&device);
		device.Context()->DrawIndexed(6, 0, 0);
	}
};

DrawCircleGroup(vec2(-0.5f, 0.0f), GraphicDevice::BlendMode::bmNone);  // 왼쪽 기준
DrawCircleGroup(vec2(+0.5f, 0.0f), blendMode);                          // 오른쪽 선택 모드
```

- 각 원은 반지름 0.15짜리 궤도를 돌며, `elapsed * 0.8f + jc_math_pi2 * c / 3.0f`로 서로 120° 차이를 유지합니다.
- 텍스처/셰이더/토폴로지 바인딩은 루프 밖에서 한 번만 수행하고, 매 원마다 `SetBlendMode` → `vb.Update` → `DrawIndexed(6)`만 반복합니다. 상태 교체가 싸다는 17번 학습의 연장입니다.
- 기본 모드는 `bmAlpha`에서 시작합니다.

### 5-4. 경계선: UV 한 점 고정의 재사용

```cpp
device.SetBlendMode(GraphicDevice::BlendMode::bmNone);
const vec2 uvCenter(0.5f, 0.5f);
vertices[0] = { vec3(-0.004f, +1.0f, 0.0f), uvCenter, lineColor };
...
vb.Update(&device, vertices, 4);
device.Context()->DrawIndexed(6, 0, 0);
```

흰 세로 분할선은 **같은 원 텍스처**를 재사용합니다. UV를 원 중앙 `(0.5, 0.5)` 한 점에 고정하면 원의 가장 불투명한 흰 픽셀만 샘플링되어 선처럼 보입니다. `-0.004 ~ +0.004` NDC 폭의 얇은 사각형이 흰 세로선이 됩니다.

## 6. GPU와 DX11, 하드웨어 깊이 보기

### 6-1. D3D11의 블렌드 상태 객체

`SetBlendMode`는 `RenderStates::GetBlendState(BlendMode)`를 호출해 `D3D11_BLEND_DESC`로 상태 객체를 만들고, `ID3D11DeviceContext::OMSetBlendState()`로 적용합니다 (GraphicDevice.cpp:336). 이 엔진이 만드는 네 모드의 desc는 (RenderStates.cpp:95):

| 모드 | BlendEnable | SrcBlend | DestBlend | 결과 공식 |
|---|---|---|---|---|
| bmNone | FALSE | ONE | ZERO | 새색 × 1 + 기존색 × 0 = 덮어쓰기 |
| bmAlpha | TRUE | SRC_ALPHA | INV_SRC_ALPHA | 새색×A + 기존색×(1-A) |
| bmAdd | TRUE | SRC_ALPHA | ONE | 새색×A + 기존색 |
| bmMultiply | TRUE | ZERO | SRC_COLOR | 0 + 기존색×새색 = 곱 |

`D3D11_BLEND_DESC`는 **렌더 타깃별(RenderTarget[0..7])**로 계수를 줄 수 있고, `BlendOp`(기본 ADD)를 바꾸면 빼기/최솟값/최댓값 블렌드도 가능합니다. `OMSetBlendState`의 두 번째 인자로 샘플 블렌드 팩터(Blend Factor)를, 세 번째로 렌더 타깃 쓰기 마스크(예: 색만, 알파만)를 넘길 수 있는데, 이 엔진은 팩터에 `nullptr`, 마스크에 `0xFFFFFFFF`(전부)를 씁니다.

### 6-2. 하드웨어: ROP(출력 병합 유닛)의 고정 기능 블렌딩

블렌딩은 셰이더가 아니라 **ROP(Render Output Unit)**, 또는 D3D11 용어로 OM(Output Merger) 고정 기능 하드웨어가 수행합니다. 픽셀 셰이더가 `SV_TARGET`로 내보낸 색은 파이프라인 끝에서 ROP로 흘러 들어가고, ROP는 다음 작업을 순서대로 수행합니다.

1. **깊이/스텐실 테스트**: 그 픽셀이 앞에 있는지 판정 (13번 큐브 장에서 배운 내용)
2. **블렌드 계산**: 새 색 × SrcBlend + 기존 색 × DestBlend
3. **컬러버퍼 쓰기**: 계산된 색을 백버퍼(또는 렌더 타깃)의 해당 주소에 기록

여기서 2번이 블렌드 상태 desc가 선택한 연산입니다. ROP의 블렌드 유닛은 병렬로 구성되어 있어 화면 픽셀당 하나씩 동시에 계산하며, 이 과정은 "그래픽 메모리에서 기존 색을 **읽고**(read), 새 값을 **쓴다**(write)"는 **읽기-수정-쓰기(Read-Modify-Write)** 패턴입니다. 그래서 블렌딩을 켜면 끈 상태보다 컬러버퍼 대역폭이 늘어납니다. 이것이 **반투명 물체가 많은 씬이 느려지는 근본 이유**입니다.

GPU 제조사들은 이 비용을 줄이기 위해 **컬러 압축(color compression)**을 씁니다. "기존 색이 그대로"인 영역(예: Opaque로 전부 덮는 영역)은 압축을 유지하며 쓰기 대역폭을 절약합니다. 블렌드가 활성화되면 압축 상태의 해제(decompress)가 필요해져 특정 패턴에서 추가 비용이 생기기도 합니다. 또한 MSAA(멀티샘플링)가 켜져 있으면 ROP는 각 샘플 위치에 대해 별도 블렌드 후 resolve(병합)를 수행하므로 블렌드 비용이 샘플 수에 비례합니다.

### 6-3. 블렌드와 깊이 테스트의 순서 — "반투명은 뒤에서 앞으로"

이 튜토리얼의 오른쪽 묶음에서 세 원은 겹치는 순서에 따라 색이 결정됩니다. 하드웨어는 픽셀 하나에 대해 **드로우가 호출된 순서대로** 블렌드를 누적합니다. 깊이 테스트를 통과한 픽셀만 블렌드에 도달하므로, 반투명 물체를 그릴 때는 순서가 중요합니다.

- 불투명 물체: 먼저 다 그리고,
- 반투명 물체: **가장 먼 것부터 가까운 것 순으로**(뒤→앞) 그려야 멀리 있는 것 위에 가까운 것이 자연스럽게 섞입니다.

이 튜토리얼의 왼쪽 묶음은 알파를 무시하므로 그리는 순서가 화면에 영향을 주지 않는다는 사실이, 블렌딩이 "순서 의존적(순서가 결과를 결정)"임을 반대로 증명해줍니다. 20번 머티리얼에서 배울 `DepthMode::dmReadOnly`(깊이 테스트는 하되 기록 안 함)도 반투명 처리의 또 다른 도구입니다.

### 6-4. 동적 버퍼의 하드웨어 경로

`vb.Update()`의 `Map(D3D11_MAP_WRITE_DISCARD)`는 GPU에게 "이전 데이터를 읽지 않을 테니 새 주소를 달라"고 알려주는 것입니다. 드라이버는 버퍼의 **다른 물리 메모리 조각**을 매핑해 CPU가 갱신하는 동안 GPU가 이전 조각을 안전하게 읽을 수 있게 합니다(파이프라인 스톨 방지). 이후 `Unmap`과 함께 드라이버가 새 데이터를 GPU 메모리로 전송(또는 공유 메모리라면 그대로 참조)하고, 다음 드로우부터 새 내용을 읽습니다. 매 프레임 `Update`는 이 경로를 타므로 상수 버퍼 갱신과 같은 패턴입니다. GPU 메모리와 CPU 메모리를 연결하는 것이 **PCIe 버스**(이산 GPU 기준)와 **공유 메모리**(통합 GPU 기준)라는 점도 기억해 두면 좋습니다.

### 6-5. 한 걸음 더 — 대역폭, 순서 보장, 타일 GPU

- **같은 픽셀은 순서 보장**: 수천 픽셀이 병렬로 처리되지만, 같은 픽셀 좌표에 겹친 드로우는 ROP가 **제출 순서대로** 처리함을 보장합니다(다른 픽셀끼리는 자유 병렬). 반투명이 많으면 이 지점이 직렬화 병목이 될 수 있습니다.
- **타일 기반 GPU(모바일)**: 화면을 타일로 나눠 칩 내부 고속 메모리에서 블렌딩을 끝내고, 타일 완성 시 한 번만 VRAM에 씁니다. 블렌딩은 상대적으로 싸지만 렌더 타깃 교체는 타일을 통째로 비우고 채워야 해 매우 비쌉니다.

## 7. 핵심 규칙 요약

- [ ] 블렌딩 공식: **최종색 = 새색 × SrcBlend + 기존색 × DestBlend**
- [ ] 네 모드: Opaque(덮어쓰기) / Alpha(SRC_ALPHA, INV_SRC_ALPHA) / Add(SRC_ALPHA, ONE) / Multiply(ZERO, SRC_COLOR)
- [ ] 블렌드 스테이트는 **드로우 단위로만** 바꿀 수 있다. 픽셀 단위로는 불가능.
- [ ] 블렌딩은 ROP(OM) 고정 기능 하드웨어가 수행하는 **읽기-수정-쓰기**라 대역폭을 소모한다.
- [ ] 반투명 물체는 **뒤→앞 순서**로 그린다. (순서 의존적)
- [ ] 곱셈 블렌드 + 알파 텍스처는 검은 사각형 잔상 방지를 위해 `lerp(white, tex.rgb, tex.a)` 같은 보정이 필요하다.
- [ ] `VertexBuffer::Create(..., true)` = 동적 버퍼. 매 프레임 `Update()`로 갱신. `Map(DISCARD)`는 기다리지 않는다.
- [ ] 상태를 바꿨으면 드로우 뒤 기본값(bmNone)으로 복원해 다음 튜토리얼을 보호한다.

## 8. 직접 해보기 — 실험으로 확인하기


1. 반투명 사각형 두 개를 겹쳐 그리고, 그리는 순서를 바꿔 결과가 달라지는 것을 확인하세요.
2. 가산 블렌딩으로 원 스프라이트를 20개 겹쳐 하얗게 타는 것을 만들어보세요.
3. 반투명 물체에 깊이 쓰기를 켜서, 뒤의 반투명 물체가 사라지는 버그를 재현하세요.
4. 전체화면 크기 반투명 사각형을 30장 겹쳐 그리고 FPS를 확인하세요 (오버드로 체감).
