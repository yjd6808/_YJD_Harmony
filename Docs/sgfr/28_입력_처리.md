# 28. 입력 처리 — 폴링 vs 이벤트, 마우스로 화면에 그리기

> 관련 코드: `Projects/sgfr/Sources/sgfr/28_Input/28_Input_Main.cpp`, `28_Input_Function.cpp`
> 실행: sgfr 실행 후 콘솔 메뉴에서 28번 선택 (창이 뜨면 ESC로 종료)
> 선행 학습: `02_윈도우와_메시지_루프.md`, `26_포스트_프로세싱.md`(입력 API 첫 등장)

## 1. 이 장에서 배우는 것

입력을 읽는 두 가지 방식 — **폴링(매 프레임 상태 묻기)**과 **이벤트(발생 순간 1회 콜백)** — 을 비교하며, 마우스 픽셀 좌표를 NDC로 바꾸는 공식과 매 프레임 갱신되는 **동적 정점 버퍼**를 배웁니다.

## 2. 실행하면 보이는 것

- 마우스 커서를 따라다니는 사각형이 그려집니다.
- **왼쪽 버튼 유지 = 빨강**, **오른쪽 버튼 유지 = 파랑**, 아니면 흰색. (폴링으로 매 프레임 색 결정)
- **마우스 휠**을 굴리면 사각형 크기가 변합니다. (이벤트)
- **아무 키나 누르면** 콘솔에 가상 키 코드가 출력됩니다. (이벤트, 누르는 순간 1번만!)
- 마우스 버튼을 누르면 콘솔에 `[이벤트] 마우스 왼쪽 버튼 눌림 @ (x, y)` 같은 메시지가 출력됩니다.

콘솔 설명의 핵심:

```
 1. 폴링(Polling): 매 프레임 '지금 눌린 상태인가?'를 직접 묻는다.
    - 이동처럼 매 프레임 연속적으로 반응할 때 적합
 2. 이벤트(Event): '눌리는 순간' 등록해둔 함수가 호출된다.
    - 버튼 클릭, 메뉴 열기처럼 '발생 순간' 1번만 반응할 때 적합
 Cocos2d-x의 EventListener가 2번 방식, 유니티의 Input.GetKey가 1번 방식이다.
```

## 3. 핵심 개념 — 비유로 먼저 이해하기

### 3-1. 폴링 = 매일 밤 문을 확인하는 경비원

폴링은 매 프레임(매 순간) "지금 키가 눌려 있나요?"를 **스스로 물어보는** 방식입니다. 경비원이 60초마다 문을 열어보며 "누가 왔나?"를 확인하는 것과 같습니다. 이동처럼 "누르고 있는 동안 계속" 반응해야 하는 동작에 어울립니다.

### 3-2. 이벤트 = 초인종을 누르면 알려주는 방식

이벤트는 OS가 키 입력을 받는 **그 순간** 등록해둔 콜백 함수를 불러주는 방식입니다. 초인종을 누르면 문을 열어보지 않아도 벨이 울려서 "지금 왔다"를 알려주는 것과 같습니다. 누르는 순간 1번만 반응하면 되는 동작(점프, 클릭, 메뉴 열기)에 어울립니다.

**중요**: 꾹 눌러도 이벤트는 **1번만** 발생합니다. "누르는 중"의 연속 반응은 폴링의 몫입니다.

### 3-3. 픽셀 좌표 vs NDC — 좌표계가 서로 다르다

마우스 좌표는 **픽셀 단위, 원점이 왼쪽 위, y는 아래로 증가**합니다. NDC는 **원점이 화면 중앙, y는 위로 증가, -1~+1**입니다. 서로 원점도 방향도 다르므로 공식으로 맞춰줘야 합니다.

```
x: 0 ~ width   → 0 ~ 2 →  -1 ~ +1
y: 0 ~ height  → 0 ~ 2 →  +1 ~ -1  (방향이 반대라 부호 뒤집음)
```

마우스로 그린 물체가 정확히 커서 아래 오게 하려면 이 변환이 필수입니다.

### 3-4. 동적 정점 버퍼 = 매 프레임 내용을 갈아끼우는 버퍼

지금까지의 정점 버퍼는 한 번 만들면 고정이었습니다. 이번에는 **매 프레임 위치/색이 바뀌는** 사각형이므로, CPU가 매 프레임 버퍼 내용을 갈아끼울 수 있는 **DYNAMIC 버퍼**로 생성합니다 (`bDynamic = true` + `vb.Update(...)`).

## 4. 초보자 용어 사전

| 용어 | 뜻(쉬운 말) | 비유 |
|---|---|---|
| 폴링 (Polling) | 매 프레임 상태를 직접 물어보는 방식 | 정기 순찰 경비원 |
| 이벤트 (Event) | 발생 순간에 콜백을 불러주는 방식 | 초인종 |
| 콜백 (Callback) | 사건 발생 시 불려지는 등록된 함수 | 벨이 울리면 일하는 종소리 |
| jc::Event::Register/Unregister | 콜백 등록/해제 (id로 구분) | 초인종에 이름표 달기/떼기 |
| 가상 키 코드 (VK Code) | 키보드 키를 숫자로 표현한 코드 (VK_ESCAPE=0x1B) | 키의 주민등록번호 |
| 픽셀 좌표 | 화면 왼쪽 위 원점, y 아래 증가 | 모눈종이 좌표 |
| NDC | 화면 중앙 원점, y 위 증가, -1~+1 | 정규화된 판 위 좌표 |
| DYNAMIC 버퍼 | CPU가 매 프레임 갱신할 수 있는 버퍼 | 매일 내용이 바뀌는 화이트보드 |
| 델타 (delta, 휠) | 휠이 굴러간 "틱 단위" (이미 120으로 나눠짐) | 사다리 한 칸씩 |

## 5. 코드 워크스루

### 5-1. 이벤트 3종 등록 — 람다로 순간 반응

```cpp
_f32 halfSize = 0.08f;		// 사각형 반폭 (NDC 단위)

// 휠 이벤트: 굴리는 순간마다 크기를 바꾼다.
// (onMouseWheel의 delta는 이미 120으로 나눈 "틱 단위"이므로 또 나누면 안 된다)
input.onMouseWheel.Register(1, [&halfSize](int _delta)
{
	halfSize = Clamp(halfSize + _f32(_delta) * 0.02f, 0.02f, 0.4f);
	printf("[이벤트] 휠 delta=%d -> 반폭 %.2f\n", _delta, halfSize);
});

input.onKeyPressed.Register(1, [](int _vkCode)
{
	printf("[이벤트] 키 눌림: VK 코드 0x%02X\n", _vkCode);
});

input.onMousePressed.Register(1, [](MouseButton _button, int _x, int _y)
{
	const char* szName = (_button == MouseButton::Left) ? "왼쪽"
		: (_button == MouseButton::Right) ? "오른쪽" : "가운데";
	printf("[이벤트] 마우스 %s 버튼 눌림 @ (%d, %d)\n", szName, _x, _y);
});
```

- `jc::Event::Register(id, 람다)`에서 `id`는 이벤트 구분자입니다. `Unregister(id)`로 해제할 때 같은 id를 사용합니다.
- 람다 캡처 `[&halfSize]`로 바깥 변수를 수정할 수 있습니다.
- 휠 `delta`는 **이미 120으로 나눈 틱 단위**입니다. 다시 나누면 안 됩니다 (0.02씩 증감).

### 5-3. 렌더 루프 — 폴링과 이벤트의 만남

```cpp
// === 폴링 방식 ===
// 매 프레임 마우스 위치와 버튼 상태를 직접 읽는다.
const vec2 center = PixelToNdc(input.MouseX(), input.MouseY(), window.Width(), window.Height());

// 버튼 상태에 따른 색상 (누르고 있는 동안 계속 유지 = 폴링의 특징)
color tintColor = color(0.9f, 0.9f, 0.9f, 1.0f);
if (input.IsMouseDown(MouseButton::Left))       { tintColor = color(0.95f, 0.3f, 0.3f, 1.0f); }
else if (input.IsMouseDown(MouseButton::Right)) { tintColor = color(0.3f, 0.5f, 0.95f, 1.0f); }

input.NextFrame();	// 이번 프레임 입력 확정 (Pressed/Released 계산용)

// 마우스 중심의 사각형 정점 4개 계산 (화면 비율 보정)
const _f32 aspect = window.AspectRatio();
vertices[0] = { vec3(center.x - halfSize, center.y + halfSize * aspect, 0.0f), tintColor };
vertices[1] = { vec3(center.x + halfSize, center.y + halfSize * aspect, 0.0f), tintColor };
vertices[2] = { vec3(center.x - halfSize, center.y - halfSize * aspect, 0.0f), tintColor };
vertices[3] = { vec3(center.x + halfSize, center.y - halfSize * aspect, 0.0f), tintColor };
vb.Update(&device, vertices, 4);
```

- `input.NextFrame()`은 매 프레임 끝에 "현재 상태 → 이전 상태"로 복사해줍니다. `IsKeyPressed`(막 눌림)가 정확하려면 **프레임당 정확히 1번** 호출해야 합니다.
- y 반폭에 `aspect`를 곱하는 이유: NDC는 화면 비율과 무관한 -1~+1 판이므로, 그대로 그리면 800x600 화면에서 세로로 길쭉해집니다. aspect를 곱해 정사각형으로 보정합니다 (25번 `FillScreenQuad`와 같은 원리).

그리기 자체는 이전 장들과 동일합니다 — 버퍼/셰이더 바인딩 후 `DrawIndexed(6, 0, 0)`.

### 5-4. 픽셀 → NDC 변환 함수

```cpp
vec2 PixelToNdc(int _pixelX, int _pixelY, int _screenWidth, int _screenHeight)
{
	// x: 0~width 를 0~2로 늘리고 1을 빼면 -1~+1
	const _f32 ndcX = (_pixelX / (_f32)_screenWidth) * 2.0f - 1.0f;

	// y: 방향이 반대라서 부호를 뒤집는다
	const _f32 ndcY = 1.0f - (_pixelY / (_f32)_screenHeight) * 2.0f;

	return vec2(ndcX, ndcY);
}
```

### 5-5. 정리 — 등록한 이벤트는 꼭 해제

```cpp
input.onMouseWheel.Unregister(1);
input.onKeyPressed.Unregister(1);
input.onMousePressed.Unregister(1);
```

이벤트에 람다(바깥 변수 참조)를 캡처로 남겨둔 채 입력 매니저가 먼저 소멸하면 **달링 참조(dangling reference)** 위험이 있습니다. "등록했으면 해제한다"는 습관을 코드가 직접 가르쳐줍니다.

### 5-6. 셰이더

`InputDemoShaderSource()`는 NDC 통과 + 정점 색 그리기입니다 (05번의 첫 삼각형과 같은 구조). 마우스 위치는 이미 NDC로 변환되었으므로 변환 행렬이 필요 없습니다.

## 6. GPU와 DX11, 하드웨어 깊이 보기

### 6-1. 입력이 GPU에 닿기 전까지의 여정 (CPU + OS)

이 장은 GPU가 아니라 **CPU/OS 경로**가 중심입니다. 입력 데이터는 아래 순서로 흘러갑니다.

1. **하드웨어**: 키보드의 키 스위치가 눌리면 키보드 컨트롤러가 **스캔 코드(scan code)**를 만들어 USB로 전송합니다. 마우스는 움직임을 델타(Δx, Δy)로, 휠은 틱 단위로 보냅니다.
2. **OS**: Windows 커널의 입력 스택이 이를 가상 키 코드(VK)와 메시지(`WM_KEYDOWN`, `WM_MOUSEMOVE`, `WM_MOUSEWHEEL`)로 변환해 **메시지 큐**에 넣습니다.
3. **애플리케이션**: `window.PumpMessage()`가 큐에서 메시지를 꺼내 `Window`의 WndProc → `InputManager::HandleMessage(msg, wParam, lParam)`로 전달합니다.
4. **InputManager**: 키 상태 배열 `bKeyDown_[256]`을 갱신하고, 이벤트 등록이 있으면 `onKeyPressed` 등을 즉시 호출합니다.

즉, **폴링은 "최신 상태 배열을 읽는 것", 이벤트는 "메시지가 도착한 그 순간 콜백을 호출하는 것"** — 둘 다 같은 메시지 흐름에서 나오지만 시점이 다릅니다.

### 6-2. IsKeyPressed가 "한 프레임만 true"인 원리

`InputManager`는 두 개의 상태 배열을 유지합니다.

- `bKeyDown_[256]`: 이번 프레임 상태
- `bPrevKeyDown_[256]`: 이전 프레임 상태

`IsKeyPressed(vk)`는 `bKeyDown_[vk] && !bPrevKeyDown_[vk]` — "지금 눌렸고, 직전엔 안 눌렸다"로 계산됩니다. `NextFrame()`이 프레임 경계에서 현재 상태를 이전 상태로 복사하므로, 60FPS면 키를 누른 순간의 단 한 프레임만 true입니다. 키를 1/240초만 눌렀다가 떼면 이벤트는 1번, 폴링의 IsKeyPressed는 프레임 타이밍에 따라 **0번**일 수도 있습니다 — 그래서 "순간을 놓치면 안 되는" 용도에는 이벤트가 더 안전할 수 있습니다.

### 6-3. 동적 정점 버퍼가 GPU에서 처리되는 방식

`vb.Update(&device, vertices, 4)`의 내부는 D3D11의 `Map(D3D11_MAP_WRITE_DISCARD)`입니다.

- **WRITE_DISCARD**는 "이전 내용은 버리겠다"를 GPU에 알리면서 **새 메모리 공간**을 줍니다. GPU가 이전 내용을 아직 그리는 중이어도 CPU는 기다리지 않고 새 공간에 쓰기 때문에 **파이프라인 스톨이 없습니다.**
- CPU가 쓴 데이터는 결국 **PCIe 버스**를 통해 GPU의 VRAM(정점 버퍼 전용 메모리 영역)에 올라갑니다. DYNAMIC 버퍼는 고정(static) 버퍼보다 접근이 약간 느릴 수 있지만, 매 프레임 갱신이 필요한 데이터에는 필수입니다.
- 이후 `DrawIndexed(6, 0, 0)`는 IA(Input Assembler)가 그 버퍼를 읽어 정점을 만들어 파이프라인에 흘려보냅니다. 이때 CPU가 쓰기 직전의 데이터를 GPU가 읽으면 안 되므로, D3D11 런타임이 쓰기/읽기 동기화를 내부적으로 관리합니다 — WRITE_DISCARD가 이 동기화 비용을 최소화하는 핵심입니다.

한 버퍼를 프레임당 여러 번 Update→Draw해도 되는 이유도 같은 원리입니다(30번 스프라이트 애니메이션에서 자세히 활용됩니다).

### 6-4. 마우스/키보드 하드웨어에서 Windows 메시지까지

- **키보드**: 각 키 스위치는 눌리면 전기적 접점이 닫힙니다. 키보드의 마이크로컨트롤러가 스캔 행렬을 읽어 **스캔 코드**를 만들고, USB HID 프로토콜로 1ms마다 전송합니다. Windows는 이를 가상 키 코드로 변환해 `WM_KEYDOWN` 메시지를 만듭니다. "Repeat"는 키를 누르고 있는 동안 OS가 주기적으로 다시 보내지만, `InputManager`는 상태 배열 기준으로 처리하므로 폴링 관점에서는 "누름 유지"일 뿐입니다.
- **마우스**: 센서(광학/레이저)가 움직임을 픽셀 수(Dot/Inch)로 감지해 델타로 보냅니다. Windows는 커서 위치를 누적 갱신하고 `WM_MOUSEMOVE`로 전달합니다. 휠은 "클릭"마다 한 틱(120의 배수)이므로, `WM_MOUSEWHEEL`의 델타가 120씩 오는 이유가 여기에 있습니다 — sgf가 미리 120으로 나누어 **틱 단위**로 전달하는 것입니다.
- **창 메시지 큐**: 모든 입력은 결국 `GetMessage/PeekMessage`가 긁어가는 **메시지 큐**를 거칩니다. 게임 루프가 `PumpMessage()`로 큐를 비워야 하며, 큐가 차면 새 입력이 지연됩니다. 즉 **폴링의 응답성은 메시지 펌프의 빠름에 달려** 있습니다.

### 6-5. 사각형 그리기의 하드웨어 비용

사각형 하나 = 정점 4개 + 인덱스 6개 + `DrawIndexed(6)`. IA → VS(NDC 통과) → 래스터라이저 → PS(정점 색 그대로) → ROP(불투명 색 쓰기)의 짧은 여행입니다. 픽셀 수가 아주 작아 전체 프레임 예산 중 극히 일부만 사용하므로, 매 프레임 버퍼를 갱신해도 성능 문제가 전혀 없습니다.

### 6-6. 이 장의 성능 교훈

- 폴링 호출(`IsKeyDown`, `MouseX()`)은 단순 배열 읽기 + 캐시 접근이라 **수십만 번 호출해도 무시 가능**합니다. 루프 안에서 마구 호출해도 되는 이유입니다.
- 이벤트는 콜백 함수 호출 비용이 있으며, 콜백이 무거운 일(파일 읽기 등)을 하면 메인 스레드가 막힙니다. "이벤트는 가볍게, 상태 읽기는 폴링으로"가 실무 패턴입니다.

## 7. 핵심 규칙 요약

- **폴링** = 매 프레임 상태 묻기 → 연속 반응(이동, 버튼 유지 색상). `IsKeyDown`, `IsMouseDown`, `MouseX/MouseY`.
- **이벤트** = 발생 순간 1회 콜백 → 1회성 동작(클릭, 키 입력 로그). 꾹 눌러도 1번만!
- `input.NextFrame()`은 프레임당 정확히 1번. `IsKeyPressed`의 정확성을 보장한다.
- 휠 `delta`는 이미 **120으로 나눈 틱 단위** — 또 나누지 말 것.
- 픽셀→NDC: `x' = (x/w)*2-1`, `y' = 1-(y/h)*2` (y 부호 뒤집기).
- NDC 사각형은 y 반폭에 `aspect`를 곱해 정사각형 보정.
- 동적 버퍼: `Create(..., true)` + `Update()` — 매 프레임 갱신용.
- 이벤트 등록 후에는 반드시 `Unregister`로 해제 (달링 참조 방지).
