# 19. 래스터라이저 스테이트 — 삼각형을 채울까, 선만 그릴까?

> 관련 코드: `Projects/sgfr/Sources/sgfr/Tutorial/19_RasterizerState/` (`19_RasterizerState_Main.cpp`, `19_RasterizerState_Function.cpp`)
> 공용 코드: `Projects/sgfr/Sources/sgfr/Common/TutorialCommon.h/.cpp` (`FillColorCube`, `ColorTransformShaderSource`)
> 엔진 코드: `Projects/sgf/Sources/sgf/Graphics/GraphicDevice.cpp` (`SetWireframe`, `SetCullMode`), `RenderStates.cpp` (`GetRasterizerState`)
> 실행: sgfr 실행 후 콘솔 메뉴에서 **19번** 선택
> 선행 학습: 13번(3D 큐브), 17번(상태 객체 개념), 18번(드로우 단위 상태)

## 1. 이 장에서 배우는 것

삼각형이 화면 픽셀로 바뀌는 **래스터라이저(Rasterizer)** 단계의 두 가지 옵션을 배웁니다. 첫째는 채우기 모드(Solid/Wireframe)로 메쉬 구조를 선으로 보며 디버깅하는 법, 둘째는 **컬링(Culling)**으로 안 보이는 면을 미리 버려 그리기 비용을 절반으로 줄이는 원리입니다. 그리고 정점의 감기 순서(시계/반시계)가 앞면/뒷면을 결정한다는 사실을 직접 눈으로 확인합니다.

## 2. 실행하면 보이는 것

**같은 큐브 2개**가 나란히 회전합니다. 왼쪽 큐브(Before)는 Solid + Back 컬링으로 고정되고, 오른쪽 큐브(After)만 키 입력에 반응합니다.

| 키 | 동작 |
|---|---|
| `W` | 오른쪽 큐브 와이어프레임 토글 |
| `1` / `2` / `3` | 컬링: None(양면) / Back(뒷면 제거, 기본) / Front(앞면 제거) |
| `ESC` | 종료 |

관찰 포인트는 세 가지입니다.

1. **Front 컬링**을 고르면 오른쪽 큐브의 **"속"이 보입니다.** 뒷면만 남기 때문입니다.
2. **와이어프레임 + None 컬링**이면 모든 삼각형의 모서리가 겹쳐 보여 큐브가 삼각형 12개로 이루어졌음을 한눈에 알 수 있습니다.
3. 왼쪽 큐브는 어떤 키를 눌러도 변하지 않습니다(기준).

## 3. 핵심 개념 — 비유로 먼저 이해하기

### 3-1. 래스터라이저 = "종이에 그림을 채색하는 화공"

파이프라인에서 삼각형은 정점 3개의 좌표로만 존재합니다. 이 삼각형을 실제 화면의 픽셀들로 바꾸는 공정이 **래스터라이제이션(Rasterization)**입니다. 여기에 두 가지 옵션이 있습니다.

- **채우기 모드**: 면 안을 꽉 채울지(Solid), 모서리 선만 그릴지(Wireframe). 건축 설계도를 보듯 뼈대를 보고 싶을 때 Wireframe이 필수입니다.
- **컬링**: 물체 뒤에 숨겨져 보이지 않을 면을 **그리기 전에 버릴지**, 어떤 면을 버릴지 정합니다.

### 3-2. 컬링 = "옆면이 안 보이는 종이 집"

종이로 만든 집을 생각해 봅시다. 앞에서 보면 뒷벽이 보이지 않습니다. 뒷벽까지 그리는 것은 낭비입니다. GPU는 삼각형이 "몇 바퀴 방향으로 감겼는지"를 보고 앞면/뒷면을 판정합니다. 화면에 투영된 삼각형의 정점 순서가 **시계 방향이면 앞면**, 반시계 방향이면 뒷면으로 보는 것이 이 엔진(D3D 기본)의 규칙입니다.

- **Back 컬링**(기본): 뒷면을 버린다 → 닫힌 물체의 그리기 비용이 **절반**이 된다.
- **Front 컬링**: 앞면을 버린다 → 큐브가 뒤집혀 속이 보인다.
- **None**: 양면 모두 그린다 → 종이처럼 얇은 물체(풀잎, 종이)에 필요하지만 2배 비용.

이렇게 "어느 쪽을 버릴지"는 삼각형마다 다르지 않고 **상태로 정해져 있습니다.** 드로우 호출 사이에 바꿀 수 있는 드로우 단위 상태입니다.

### 3-3. 회전 후 이동: 행벡터 규약

`rotation * Translation(x,0,0)`은 행벡터 규약에서 "왼쪽부터 먼저 적용"됨을 의미합니다. 즉, 먼저 제자리에서 회전하고, **그다음** 오른쪽으로 옮깁니다. 순서를 바꾸면 "먼저 옮기고 회전"이 되어 공전하듯 움직입니다. 10번(월드 변환)에서 배운 결합 순서의 실전 적용입니다.

## 4. 초보자 용어 사전

| 용어 | 뜻(쉬운 말) | 비유 |
|---|---|---|
| 래스터라이제이션 | 삼각형을 화면 픽셀로 바꾸는 단계 | 그림을 픽셀로 채색 |
| 채우기 모드(Fill Mode) | 면을 채울지(Solid) 선만 그릴지(Wireframe) | 색칠 vs 스케치 |
| 컬링(Culling) | 안 보이는 면을 그리기 전에 버리는 일 | 뒤에 숨은 물건 안 사기 |
| 감기 순서(Winding) | 삼각형 정점이 감기는 방향 (시계/반시계) | 종이접기 방향 |
| 앞면/뒷면 | 감기 순서로 판정된 면 | 표지 vs 뒷표지 |
| 와이어프레임 | 모서리 선만 그리는 모드 | 설계도의 뼈대 |
| 클립(Clip) | 화면 밖 삼각형을 잘라내는 단계 | 캔버스 밖 부분 오려내기 |
| NDC | 화면 정규화 좌표 (-1~1) | 지도의 축척 좌표 |

## 5. 코드 워크스루

`RasterizerState_Main()`의 흐름을 따라갑니다.

### 5-1. 준비: 공용 큐브와 셰이더

```cpp
VertexPC vertices[8];
_u32 indices[36];
FillColorCube(vertices, indices);   // TutorialCommon: 면마다 색이 다른 큐브

Shader shader;
ConstantBuffer<CbTransform> cbTransform;
shader.CompileFromString(&device, ColorTransformShaderSource(),
                         pLayoutDescs, layoutCount);
```

이 튜토리얼은 큐브 지오메트리와 셰이더를 `Common/TutorialCommon`에서 재사용합니다. `FillColorCube`는 정점 8개(반 변 0.5)와 인덱스 36개(면당 삼각형 2개)를 만들고, 모든 면이 바깥에서 볼 때 **시계 방향**이 되도록 인덱스를 지정합니다(주석: "바깥에서 볼 때 시계 방향 감기 = 앞면 (D3D 기본)"). `ColorTransformShaderSource`는 `cbuffer CbTransform : register(b0)`의 `gWvp`로 변환하는 단순 셰이더입니다.

### 5-2. 카메라: 두 큐브가 보이게 후퇴

```cpp
const mat4 view = mat4::LookAtLH(vec3(0.0f, 1.5f, -4.5f), vec3::Zero(), vec3::Up());
const mat4 proj = mat4::PerspectiveFovLH(jc_math_pi_div4, window.AspectRatio(), 0.1f, 100.0f);
```

큐브 두 개(-1.1, +1.1)가 모두 보이도록 카메라를 z=-4.5로 후퇴시키고 위로 1.5 올려 약간 내려다봅니다. `jc_math_pi_div4` = 45° 시야각입니다.

### 5-3. 렌더 루프: 드로우 사이에 상태 끼우기

```cpp
const mat4 rotation = mat4::RotationY(elapsed * 0.8f) * mat4::RotationX(elapsed * 0.4f);

auto DrawCube = [&](_f32 _offsetX, bool _bWire, GraphicDevice::CullMode _cull)
{
	device.SetWireframe(_bWire);
	device.SetCullMode(_cull);

	CbTransform cb;
	cb.wvp_ = rotation * mat4::Translation(_offsetX, 0.0f, 0.0f) * view * proj; // 회전 후 이동
	cbTransform.UpdateAndBind(&device, cb, 0);
	device.Context()->DrawIndexed(36, 0, 0);
};

DrawCube(-1.1f, false, GraphicDevice::CullMode::cmBack);   // [Before] 기본 고정
DrawCube(+1.1f, bWireframe, cullMode);                     // [After]  선택 상태
```

- `cb.wvp_ = rotation * mat4::Translation(...) * view * proj` — 행벡터 규약으로 왼쪽부터 적용: 회전 → 이동 → 뷰 → 투영.
- `SetWireframe`/`SetCullMode`는 GraphicDevice 내부에서 플래그를 기억하고, 둘 중 하나라도 바뀌면 `ApplyRasterizerState()`가 현재 조합에 맞는 상태 객체를 `RSSetState`로 꽂습니다. 같은 값을 다시 설정하면 아무 일도 하지 않습니다(GraphicDevice.cpp:358~382).
- 상태 교체는 두 드로우 사이에만 들어갑니다 — 드로우 단위 상태라는 18번 학습의 재확인.

### 5-4. 정리

```cpp
device.SetWireframe(false);
device.SetCullMode(GraphicDevice::CullMode::cmBack);   // 기본 상태 복원
device.Finalize();
window.Destroy();
```

## 6. GPU와 DX11, 하드웨어 깊이 보기

### 6-1. D3D11의 래스터라이저 상태 객체

`D3D11_RASTERIZER_DESC`는 (RenderStates.cpp:201):

| 필드 | 이 엔진 값 | 의미 |
|---|---|---|
| `FillMode` | `D3D11_FILL_SOLID` / `D3D11_FILL_WIREFRAME` | 면 채우기 vs 선만 |
| `CullMode` | `D3D11_CULL_NONE` / `_BACK` / `_FRONT` | 버릴 면 |
| `FrontCounterClockwise` | FALSE(시계 방향 = 앞면) | 앞면 판정 기준 |
| `DepthClipEnable` | TRUE | 깊이가 0~1을 벗어난 픽셀 클립 |

이 desc로 만든 상태 객체가 `ID3D11DeviceContext::RSSetState()`로 래스터라이저 스테이지에 꽂힙니다. 나머지 필드(DepthBias, ScissorEnable, MultisampleEnable, AntialiasedLineEnable 등)는 이 엔진이 0/FALSE로 두었지만, 그림자 맵(27번)의 depth bias나 선 앤티앨리어싱 같은 곳에서 의미를 가집니다.

### 6-2. 하드웨어: 래스터라이저는 전용 고정 기능 블록

래스터라이제이션은 GPU마다 전용으로 설계된 고정 기능 유닛(셰이더 유닛이 아님)이 수행합니다. D3D11 파이프라인의 **RS(Rasterizer Stage)**는 스트림 아웃/클리핑 후 단계로, 다음을 순서대로 처리합니다.

1. **클리핑(Clip)**: 화면(클립 공간) 밖으로 나간 삼각형 부분을 잘라냅니다. 절두체 안쪽 조각만 남깁니다.
2. **원근 나눗셈**: 클립 좌표를 w로 나눠 NDC(-1~1)로 변환합니다.
3. **뷰포트 변환**: NDC를 픽셀 좌표로 확대/이동합니다.
4. **컬링 판정**: 삼각형의 **부호 있는 면적(signed area)**을 계산합니다. 화면 좌표에서 두 변의 외적 `(v1-v0)×(v2-v0)`의 z 성분 부호가 시계/반시계를 결정하고, 이 부호가 CullMode가 버리는 쪽과 일치하면 그 삼각형은 즉시 폐기됩니다.
5. **픽셀 생성(Scan conversion)**: 남은 삼각형 내부를 지나는 픽셀들을 찾고, 각 픽셀에 대해 3개 정점 값(UV, 색, 법선 등)을 **보간**해 픽셀 셰이더로 보냅니다.

여기서 4번이 이 튜토리얼의 핵심입니다. 컬링은 **삼각형 단위의 미리 버리기**라서 매우 저렴합니다. 외적 한 번과 부호 비교로 끝나며, 버려진 삼각형은 이후 픽셀 생성과 픽셀 셰이더 실행을 전혀 거치지 않습니다. 닫힌 물체(큐브 등)는 뒷면 삼각형이 화면의 절반 정도를 차지하므로 Back 컬링만으로 **픽셀 셰이더 부하와 메모리 대역폭을 대략 절반으로** 줄이는 것입니다. 이 절감은 셰이더가 복잡해질수록(14번 라이팅, 24번 셰이딩 모델) 비례해 커집니다.

### 6-3. 와이어프레임의 하드웨어 동작

`D3D11_FILL_WIREFRAME`은 픽셀 생성 단계에서 "삼각형 내부" 대신 "삼각형의 모서리 근처 픽셀"만 생성하게 합니다. GPU는 보간기를 삼각형 가장자리에서만 통과시키므로 면 중앙 픽셀은 만들어지지 않습니다. 컬링은 채우기 모드와 무관하게 **먼저** 적용되므로, 와이어프레임 상태에서도 뒷면 삼각형의 선은 그려지지 않습니다(이 튜토리얼에서 와이어프레임 + Front 컬링을 조합하면 뒷면의 선만 보이는 것을 관찰할 수 있습니다). 또한 와이어프레임은 래스터라이저 상태이므로 MSAA나 앤티앨리어싱 선과 달리 부드러워지지 않습니다 — 모서리가 계단처럼 보이는 것이 정상입니다.

### 6-4. 감기 순서와 행벡터의 결합

"화면에서 시계 방향 = 앞면"이라는 판정은 **투영 후** 화면 좌표를 기준으로 합니다. 같은 큐브도 회전하면 일부 면은 반시계로 보이기 때문에, 정점 인덱스가 "항상" 시계 방향이어도 회전 중에는 앞면/뒷면이 바뀌는 것처럼 보이지 않습니다 — 큐브의 각 면은 물리적으로 닫혀 있으므로 어느 각도에서 보든 보이는 면은 "앞면"이 되도록 회전이 정확히 뒤집어 주기 때문입니다. 이것이 컬링이 "뒤집힌 지오메트리에서 반대 동작"으로 보이는 이유이며, 인덱스 순서를 잘못 지정하면 물체가 통째로 사라지거나 안쪽만 보이는 흔한 버그의 원인이 됩니다. 이 튜토리얼의 Front 컬링 모드는 그런 버그 상태를 의도적으로 연출해 학습시킵니다.

### 6-5. 상태 캐싱과 성능

`SetWireframe`/`SetCullMode`는 GraphicDevice가 현재 조합을 기억하다가 **실제로 바뀔 때만** `ApplyRasterizerState()`를 호출합니다. 이는 23번 스테이트 캐시의 원형입니다. GPU 관점에서 RSSetState는 명령 버퍼에 상태 핸들을 기록하는 것으로, 드로우 사이에 여러 번 꽂아도 파이프라인 재시작(stall)이 거의 없습니다. 다만 상태가 바뀌면 드라이버가 **파이프라인 상태 검증(validation)**을 다시 하므로, 100개 물체를 그리며 매번 상태를 갈아끼우는 것은 CPU 비용이 누적됩니다. 그래서 23번은 "같은 값을 다시 바인딩하지 말라"는 결론으로 나아갑니다.

## 7. 핵심 규칙 요약

- [ ] 래스터라이저 = 삼각형 → 픽셀 변환의 고정 기능 단계. 옵션은 드로우 단위 상태.
- [ ] 채우기 모드: Solid(면 채우기) / Wireframe(모서리 선만). Wireframe은 메쉬 구조 디버깅 필수.
- [ ] 컬링 판정 = **화면에 투영된 정점 순서**. 이 엔진은 시계 방향 = 앞면.
- [ ] Back 컬링은 닫힌 물체의 그리기 비용을 약 절반으로 줄인다. (픽셀 셰이더 부하 절감)
- [ ] Front 컬링 = 속이 보이는 효과. None = 양면 (얇은 물체용, 2배 비용).
- [ ] 행벡터 규약: `rotation * Translation(x,0,0)`은 "회전 후 이동". 순서를 바꾸면 공전이 된다.
- [ ] 인덱스 지정 순서가 앞면을 결정한다 — 반대로 지정하면 물체가 사라지거나 안쪽만 보인다.
- [ ] 상태는 드로우 사이에 끼워 바꾼다. 끝나면 기본값(SetWireframe(false), SetCullMode(cmBack)) 복원.
