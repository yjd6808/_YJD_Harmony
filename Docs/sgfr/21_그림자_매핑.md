# 21. 그림자 매핑 — 빛의 눈으로 본 깊이로 그림자를 만들다

> 튜토리얼: `Projects/sgfr/Sources/sgfr/21_ShadowMapping/`
> 선행 학습: `09_3D_큐브.md`(깊이 버퍼), `19_렌더_타깃.md`(CreateDepthOnly) — 둘 다 필수!

---

## 1. 왜 필요한가요?

그림자는 입체감의 핵심입니다. 그림자가 없으면 물체가 떠 있는지 바닥에 붙어 있는지조차 구분이 안 됩니다.

그런데 생각해보면 이상합니다. 픽셀 셰이더는 지금 그리는 픽셀 하나밖에 모릅니다.
"나와 빛 사이에 다른 물체가 있는지"를 어떻게 알 수 있을까요?

해답이 바로 **그림자 매핑(Shadow Mapping)**이고, 발상이 아주 우아합니다:

> **"빛의 입장에서 보이지 않는 곳이 그림자다."**
>
> 태양 위치에 카메라를 놓고 사진을 찍으면, 그 사진에 찍힌 곳은 햇빛을 받는 곳,
> 안 찍힌 곳(뭔가에 가려진 곳)은 그림자진 곳입니다.

---

## 2. 개념 설명 — 2패스 알고리즘

### 2-1. 패스 1: 빛의 눈으로 깊이만 기록하기 (그림자 맵 생성)

빛 위치에 가상 카메라를 놓고 장면을 그립니다. 단, 색은 필요 없고 **깊이만** 기록합니다.
그래서 19번에서 만든 `RenderTarget::CreateDepthOnly(1024, 1024)`를 씁니다.

결과물인 **그림자 맵(Shadow Map)**은 이렇게 읽힙니다:
"빛이 이 방향으로 내다보았을 때, 각 방향별로 가장 먼저 만난 물체까지의 거리가 적힌 표"

이번 튜토리얼은 태양광 같은 방향성 빛(directional light)이므로 원근감 없는 **직교 투영**(`OrthographicOffCenterLH(-4,4,-4,4,0.1,20)`)을 씁니다. 태양 광선은 평행하니까요.

### 2-2. 패스 2: 카메라 시점으로 그리면서 "빛에게 물어보기"

평소처럼 카메라 시점으로 그리되, 픽셀마다 다음 질문을 합니다:

1. 이 픽셀의 월드 위치를 **빛의 뷰×투영 행렬**로 변환 → 그림자 맵의 어느 칸에 해당하는지 + 빛에서의 깊이가 얼마인지 계산
2. 그 칸에 **저장된 깊이**를 읽음
3. 비교: `내 깊이 > 저장된 깊이` 이면 → 나보다 빛에 가까운 뭔가가 있다 → **그림자!** (밝기를 0.35배로)

### 2-3. NDC → 텍스처 UV 변환

빛 기준 투영 결과는 NDC 좌표(x,y: -1~+1)인데, 텍스처 UV는 0~1이고 **y축이 반대**입니다(NDC는 위가 +, UV는 아래가 +).

```hlsl
float2 shadowUv;
shadowUv.x = ndc.x *  0.5f + 0.5f;
shadowUv.y = ndc.y * -0.5f + 0.5f;   // y 뒤집기 주의!
```

이 y 부호를 빼먹으면 그림자가 상하 반전된 위치에 생깁니다. 실수 1순위입니다.

### 2-4. 그림자 여드름(Shadow Acne)과 바이어스

그림자 맵은 해상도가 유한하므로(1024×1024), 같은 면 위의 이웃 픽셀들이 그림자 맵의 같은 칸을 공유합니다.
그러면 미세한 깊이 오차 때문에 "자기 자신의 그림자에 가려졌다"는 오판이 줄무늬처럼 발생합니다. 이게 **그림자 여드름**입니다.

해결책은 비교할 때 약간의 여유(**바이어스**)를 두는 것:

```hlsl
if (내깊이 - gShadowBias > 저장된깊이) → 그림자
```

단, 바이어스가 너무 크면 그림자가 물체에서 분리되어 둥둥 떠보입니다. 이건 **피터 팬닝(Peter Panning)**이라고 부릅니다.
(피터팬이 그림자를 잃어버리는 동화에서 온 이름) — 이 튜토리얼에서 ↑↓ 키로 직접 체험할 수 있습니다!

### 2-5. 그림자 맵 샘플러는 반드시 Point + Clamp

- **Point**: 깊이값은 "거리"입니다. 이웃 칸끼리 보간하면 있지도 않은 중간 깊이가 나와 판정이 엉망이 됩니다.
- **Clamp**: 그림자 맵 범위 밖이 Wrap으로 반대편 깊이를 읽으면 엉뚱한 그림자가 복사됩니다.

15번에서 배운 샘플러 지식이 여기서 실전으로 쓰입니다.

## 3. 코드 따라가기 — 21번 튜토리얼

### 3-1. 장면 구성

넓은 바닥 판 + 공중에 떠 있는 회전 큐브. 큐브 그림자가 바닥에 떨어집니다.

### 3-2. 상수 버퍼 세 개

- `CbDepth(b0, 64B)`: 패스 1용. 빛 기준 WVP 하나만
- `CbScene(b0, 192B)`: 패스 2용. 월드/카메라 WVP/**빛의 ViewProj**(픽셀을 그림자 맵 좌표로 보내는 열쇠)
- `CbLight(b1, 32B)`: 빛 방향, 바이어스, 기본 색

### 3-3. 프레임 흐름

```cpp
// 패스 1: 빛 시점 → 그림자 맵 (깊이 전용)
device.SetRenderTarget(&shadowMap);
shadowMap.Clear(&device, …);                 // 깊이를 1.0으로 초기화
depthShader.Bind(…);                          // PS가 사실상 빈 셰이더
// 바닥 + 큐브 그리기 (빛 기준 WVP)

// 패스 2: 카메라 시점 → 화면
device.SetRenderTarget(nullptr);
device.SetSampler(SamplerFilter::Point, SamplerAddress::Clamp);
shadowMap.BindAsTexture(&device, 0);          // 그림자 맵을 t0으로
sceneShader.Bind(…);
// 바닥 + 큐브 그리기 (카메라 WVP + 빛 ViewProj 동시 전달)
```

### 3-4. 조작법

```
[←/→] 빛의 방위각 회전 (누르고 있는 동안 연속 회전)
[↑/↓] 바이어스 ±0.001 (0 ~ 0.01)
```

빛을 돌리면 그림자가 반대 방향으로 돌고, 바이어스를 0으로 내리면 여드름이, 최대로 올리면 피터 팬닝이 보입니다.

## 4. 직접 해보기

1. 바이어스를 0으로 내려 바닥의 줄무늬 무늬(여드름)을 관찰하세요. 왜 바닥에 주로 생길까요? (힌트: 빛과 면의 각도)
2. 그림자 맵 해상도를 1024 → 256으로 줄여보세요. 그림자 가장자리가 계단처럼 급니다. 상용 게임은 이걸 PCF(주변 여러 칸 평균)로 부드럽게 만듭니다.
3. 직교 투영 범위를 ±4 → ±10으로 키워보세요. 같은 1024픽셀이 더 넓은 영역을 담당하게 되어 그림자 품질이 떨어집니다. — "투영 범위는 딱 필요한 만큼"이 그림자 품질의 핵심입니다.
4. 그림자 밝기 0.35를 0으로 바꿔 완전한 검은 그림자를 만들어보세요. 왜 부자연스러울까요? (힌트: 18번의 주변광)

## 5. 정리

- 그림자 매핑 = "빛의 눈에 안 보이면 그림자" — 2패스 알고리즘
- 패스 1: 빛 시점에서 깊이만 기록(그림자 맵). 방향성 빛은 직교 투영
- 패스 2: 픽셀의 빛-기준 깊이와 그림자 맵의 깊이를 비교
- NDC→UV 변환에서 y 부호 반전 주의
- 바이어스는 여드름과 피터 팬닝 사이의 줄타기
- 그림자 맵 샘플러는 Point + Clamp

## 부록: Before/After 비교 뷰

이 튜토리얼은 화면을 세로로 반으로 잘라 그림자의 유무를 한 화면에서 비교할 수 있도록 되어 있습니다.

| 구분 | 위치 | 내용 |
|---|---|---|
| **Before** | 노란 경계선 왼쪽 | 그림자 판정 없음 = 라이팅만 있는 세상 |
| **After** | 노란 경계선 오른쪽 | 그림자 매핑 적용 = 큐브 그림자가 바닥에 드리워짐 |

### 어떻게 구현했나요?

- 상수 버퍼 `CbLight`에 `splitPixelX_`(경계 픽셀 x좌표)를 추가했습니다. (48바이트 = 16의 배수 유지)
- 그림자 맵 생성(패스 1)은 동일하게 수행하되, 픽셀 셰이더(패스 2)가 `SV_Position.x`가 경계보다 왼쪽이면 그림자 판정 블록을 통째로 건너뜁니다. (shadow = 1.0 고정)
- 즉 두 번 그리는 게 아니라, 같은 드로우 안에서 픽셀 단위로 분기합니다.

### 관찰 포인트

- 왼쪽만 보면 큐브가 공중에 떠 있는지 바닥에 붙어 있는지 구분하기 어렵습니다. 오른쪽은 그림자 하나 덕분에 높이감이 바로 느껴집니다. 그림자가 "공간감을 만드는 장치"라는 것을 체감하는 것이 이 뷰의 목적입니다.
- 왼쪽/오른쪽 방향키로 빛을 돌리면 오른쪽 그림자만 반대 방향으로 이동합니다.
- 아래 방향키로 바이어스를 0까지 내리면 오른쪽 표면에만 줄무늬(그림자 여드름)이 생깁니다. 왼쪽은 그림자 판정이 없으므로 항상 깨끗합니다 — 여드름이 "그림자 판정 과정에서 생기는 오차"임을 보여주는 증거입니다.
