# 19. 렌더 타깃 — 화면이 아닌 곳에 그리기

> 튜토리얼: `Projects/sgfr/Sources/sgfr/19_RenderTarget/`
> 엔진 코드: `Projects/sgf/Sources/sgf/Graphics/RenderTarget.h/.cpp`, `GraphicDevice::SetRenderTarget`

---

## 1. 왜 필요한가요?

지금까지 우리는 항상 **백버퍼**(화면으로 나갈 버퍼)에만 그렸습니다.
그런데 상용 게임의 수많은 기능은 "화면이 아닌 곳에 먼저 그려두고, 그 결과를 텍스처처럼 쓰는" 방식으로 구현됩니다.

- **미니맵**: 위에서 내려다본 장면을 작은 텍스처에 그려 화면 구석에 붙임
- **거울/물 반사**: 반사된 시점의 장면을 텍스처에 그려 거울 면에 붙임
- **포스트 프로세싱(20번)**: 장면 전체를 텍스처에 그린 뒤 후보정해서 화면에 출력
- **그림자 맵(21번)**: 빛의 시점에서 깊이만 텍스처에 그려 그림자 판정에 사용

이 "화면이 아닌 그리기 대상"이 바로 **렌더 타깃(Render Target)**입니다.

> **비유**: 방송국 스튜디오의 "별도 카메라"를 생각하세요. 메인 카메라(백버퍼) 외에 별도 카메라로 다른 각도를 찍어둔 뒤,
> 그 영상을 메인 화면 구석의 작은 창(PIP)으로 띄우는 것과 완전히 같은 구조입니다.

---

## 2. 개념 설명

### 2-1. 백버퍼도 사실 렌더 타깃이다

03번에서 스왑체인의 백버퍼로 RTV(Render Target View)를 만들어 `OMSetRenderTargets`로 묶었던 것, 기억나시나요?
우리가 직접 만드는 렌더 타깃도 똑같습니다. 다만 백버퍼 대신 **일반 텍스처**를 대상으로 쓸 뿐입니다.

핵심은 텍스처 하나에 **다른 종류의 뷰(View) 두 개**를 만드는 것:

| 뷰 | 역할 | 언제 사용 |
|---|---|---|
| **RTV** (RenderTargetView) | "이 텍스처에 그려라" | 1패스: 그리기 대상으로 바인딩 |
| **SRV** (ShaderResourceView) | "이 텍스처를 읽어라" | 2패스: 셀이더 입력(t0)으로 바인딩 |

텍스처 생성 시 `BindFlags`에 `D3D11_BIND_RENDER_TARGET | D3D11_BIND_SHADER_RESOURCE`를 둘 다 주면 됩니다.

### 2-2. 절대 규칙: 같은 텍스처를 동시에 읽고 쓸 수 없다

GPU는 한 텍스처가 RTV(쓰기)와 SRV(읽기)로 동시에 묶이는 걸 금지합니다.
그래서 sgf의 `SetRenderTarget`은 타깃을 바꾸기 전에 **PS의 SRV 슬롯을 먼저 해제**합니다. 이걸 빼먹으면 디버그 로그에 경고가 쏟아지고 그림이 깨집니다.

### 2-3. 깊이 버퍼도 타깃마다 별도

3D 장면을 렌더 타깃에 그리려면 그 타깃 전용 깊이 버퍼도 필요합니다(크기도 타깃과 같아야 함).
sgf의 `RenderTarget::Create`는 색 텍스처 + 깊이 버퍼를 세트로 만들어 줍니다.
별도로 `CreateDepthOnly`는 색 없이 깊이만 기록하는 타깃을 만듭니다 — 21번 그림자 맵이 이걸 씁니다.

### 2-4. 뷰포트도 함께 바꿔야 한다

800×600 화면에 그리다가 256×256 타깃에 그릴 때는 뷰포트(그리는 영역)도 256×256으로 바꿔야 합니다.
sgf의 `SetRenderTarget`이 타깃 크기에 맞춰 뷰포트까지 자동으로 바꿔줍니다. (이걸 깜빡하면 그림이 잘리거나 늘어납니다)

---

## 3. 엔진 API

```cpp
RenderTarget rt;
rt.Create(&device, 256, 256);        // 색 + 깊이 세트

// 1패스: 타깃에 그리기
device.SetRenderTarget(&rt);         // 뷰포트도 256×256으로 자동 전환
rt.Clear(&device, color(0,0,0,1));   // 타깃 전용 Clear
// … 평소처럼 DrawIndexed …

// 2패스: 다시 화면(백버퍼)에 그리기
device.SetRenderTarget(nullptr);     // nullptr = 백버퍼 복귀
rt.BindAsTexture(&device, 0);        // 방금 그린 결과를 t0 텍스처로!
// … 작은 사각형에 그려서 PIP 완성 …

rt.Destroy();                        // 종료 전 정리
```

한 프레임에 세 번 그립니다:

같은 장면 데이터(정점/인덱스/셰이더)를 두 카메라로 두 번 그리는 것뿐입니다. 코드로 보면 생각보다 단순합니다.

## 6. 정리

- 렌더 타깃 = 화면 대신 그릴 수 있는 텍스처. RTV로 쓰고 SRV로 읽는다
- 같은 텍스처를 동시에 읽고 쓸 수 없다 — 타깃 전환 시 SRV 해제 필수
- 타깃마다 깊이 버퍼와 뷰포트도 따로
- 미니맵·거울·포스트 프로세싱·그림자 맵이 전부 이 기법 위에 있다

다음 장(20번)에서는 화면 전체를 렌더 타깃에 그리고 후보정하는 포스트 프로세싱을 배웁니다.
