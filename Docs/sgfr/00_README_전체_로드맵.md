# 00. 전체 로드맵 — sgf 엔진과 DX11 학습 여행의 지도

> 작성자: 윤정도 · 이 문서는 sgf(SteinsGate Framework) 엔진과 sgfr 튜토리얼 프로젝트의 **전체 지도**입니다.
> 순서대로 읽으면 DX11을 하나도 모르는 상태에서 시작해 2D/3D 게임 엔진의 구조까지 전부 이해할 수 있습니다.

---

## 1. 이 프로젝트는 무엇인가요?

여러분(우리)의 솔루션에는 원래 이런 프로젝트들이 있었습니다.

| 프로젝트 | 역할 |
|---|---|
| **jc** | 직접 만든 C++ 기반 라이브러리 (컨테이너, 이벤트, 싱글톤 등) |
| **jnet** | IOCP 기반 네트워크 라이브러리 |
| **sg** | 게임 공용 기반 라이브러리 |
| **sgcl** | Cocos2d-x 기반 게임 클라이언트 |

여기에 두 개가 추가되었습니다.

| 새 프로젝트 | 역할 |
|---|---|
| **sgf** | jc를 기반으로 만든 **DX11 2D/3D 게임 엔진** (정적 라이브러리) |
| **sgfr** | sgf를 이용해 DX11을 1번부터 31번까지 **순서대로 배우는 튜토리얼** (콘솔 실행 파일) |

### 왜 만들었나요?

sgcl은 지금 Cocos2d-x 엔진 위에서 돌아갑니다. 이 Cocos2d-x를 **우리가 직접 만든 DX11 엔진(sgf)으로 교체**하는 것이 최종 목표입니다.
그래서 sgf는 Cocos2d-x와 구조가 비슷하게(Application, Director, Scene, Renderer) 설계되었습니다.
단, Cocos2d-x의 단점이었던 "addChild를 해야만 그릴 수 있다"는 제약은 없앴습니다. sgf에서는 Renderer2D로 **즉시 그리기**도 가능합니다.

## 4. sgf 엔진의 설계 철학

### 4-1. 단순함이 최우선
- 클래스 개수를 최소로 유지합니다.
- "마법" 없음: 모든 동작은 코드를 따라가면 그대로 보입니다.

### 4-2. jc 컨벤션을 그대로 따름
- 타입: `_s32`, `_u32`, `_f32` …
- 멤버: `m_PascalCase`, 포인터는 `m_pXxx`
- 파라미터: `_camelCase`, 출력용은 `_pOut`
- 구조체 공개 멤버: `name_` (trailing underscore)
- 매크로: `JC_DELETE_SAFE`, `JC_RELEASE_SAFE` 등
- 싱글톤 매크로: `g_cResourceMgr`(ResourceMgr::Get()), `g_cDirector`, `g_cApp`, `g_cWindow`, `g_cDevice`, `g_cInput`, `g_cRenderer2D/3D` 등

### 4-3. Cocos2d-x와의 관계 (sgcl 교체 대비)

| Cocos2d-x | sgf | 비고 |
|---|---|---|
| `Director::getInstance()` | `g_cDirector` | jc 싱글톤 |
| `Scene` | `Scene` | OnEnter/OnExit/OnUpdate/OnRender |
| `Director::runScene/replaceScene` | `RunScene/ReplaceScene` | 씬 생명주기 관리 |
| (없음) | **Renderer2D 즉시 그리기** | addChild 없이 그리기 가능! |

### 4-4. 수학 규약 (아주 중요 — 모든 튜토리얼의 기반)
- **행 우선(row-major)** 행렬, **행 벡터** 곱: `v' = v * M`
- HLSL에서도 `row_major float4x4` + `mul(v, M)` — **전치(transpose) 불필요**
- 결합 순서: `world * view * proj` (왼쪽 것이 먼저 적용)
- **왼손 좌표계(LH)**, NDC z 범위 [0, 1]

## 5. 그림 한 장으로 보는 전체 흐름

```
[내 C++ 코드]
    │  정점 데이터(Vertex), 행렬(mat4), 텍스처(Texture)
    ▼
[GraphicDevice]  ←── GPU와의 전화기 (Device/Context/SwapChain)
    │
    ▼
[렌더링 파이프라인]  IA → VS → RS → PS → OM   (05번에서 상세히)
    │      VS: 정점을 화면 좌표로 (10~13번의 행렬들)
    │      RS: 와이어프레임/컬링 (19번)
    │      PS: 픽셀 색 결정 (14번 라이팅, 15번 텍스처, 17번 샘플링)
    │      OM: 블렌딩(18번), 깊이 판정(13번)
    ▼
[렌더 타깃 (25번)] ── 후보정(26번)/그림자(27번)에 활용
    ▼
[백버퍼] ──Present()──▶ [모니터]   (04번 스왑체인)
```

엔진(sgf)은 위 흐름을 사람이 다루기 쉬운 개념(Application, Scene…)으로 포장한 것뿐입니다.
01~09에서 날것의 DX11을 배우고, 20~24에서 리소스/머티리얼/렌더러라는 엔진 뼈대를 세우고,
25~31에서 상용 엔진이 반드시 갖추는 심화 기능(렌더 타깃·포스트 프로세싱·그림자·씬·애니메이션)까지 전부 익힙니다.

## 6. 빌드 방법

1. `Scripts\BuildProject\sgfr.bat` (또는 프로젝트 생성 배치 `BuildProject\sgfr.bat -P x64`)로 빌드합니다.
2. SVG 튜토리얼(16번)을 온전히 쓰려면 `Projects/sgf/Sources/sgf/_Extern/nanosvg/README.md`의 안내대로
   nanosvg 헤더 2개를 내려받아 넣습니다. 없어도 빌드는 되며, 16번은 대체(fallback) 텍스처로 동작합니다.
3. `Output\x64\Debug\`에 나온 sgfr.exe를 실행하면 콘솔 메뉴가 나옵니다.

## 7. 문서 읽는 규칙

- 각 문서는 템플릿 구조로 통일되어 있습니다:
  **배우는 것 → 실행 화면 → 비유로 개념 이해 → 용어 사전 → 코드 워크스루 → GPU/하드웨어 깊이 → 규칙 요약**
- 어려운 용어는 비유와 함께 풀어서 설명합니다. 비유는 정확하지 않을 수 있지만 감을 잡는 데 우선순위를 둡니다.
- 코드 조각은 실제 sgf/sgfr 코드에서 그대로 가져왔습니다. 파일 경로가 함께 적혀 있으니 꼭 열어서 확인하세요.

## 부록 D. 성능에 대해 기억할 다섯 문장

1. GPU는 "지금 해"가 아니라 "이따가 해"다. CPU와 GPU는 별도의 시계로 움직인다.
2. 비용은 연산보다 **대기와 전환**에서 나온다.
3. 비슷한 것끼리 **묶으면 빨라진다** (인덱스/머티리얼/캐시/정렬/아틀라스/배칭/인스턴싱).
4. 모든 스레드가 **같은 길로 가야** 빠르다 (warp, divergence).
5. **안 그리는 것이 최고의 최적화**다 (컸링, Early-Z, LOD, 저해상도 패스).
