# 00. 전체 로드맵 — sgf 엔진과 DX11 학습 여행의 지도

> 작성자: 윤정도 · 이 문서는 sgf(SteinsGate Framework) 엔진과 sgfr 튜토리얼 프로젝트의 **전체 지도**입니다.
> 순서대로 읽으면 DX11을 하나도 모르는 상태에서 시작해 2D/3D 게임 엔진의 구조까지 전부 이해할 수 있습니다.

---

## 1. 이 프로젝트는 무엇인가요?

여러분(우리)의 솔루션에는 원래 이런 프로젝트들이 있었습니다.

| 프로젝트 | 역할 |
|---|---|
| **jc** | 직접 만든 C++ 기반 라이브러리 (컨테이너, 이벤트, 싱글톤 등) |
| **jnet** | IOCP 기반 네트워크 라이브러리 |
| **sg** | 게임 공용 기반 라이브러리 |
| **sgcl** | Cocos2d-x 기반 게임 클라이언트 |

여기에 이번에 두 개가 새로 추가되었습니다.

| 새 프로젝트 | 역할 |
|---|---|
| **sgf** | jc를 기반으로 만든 **DX11 2D/3D 게임 엔진** (정적 라이브러리) |
| **sgfr** | sgf를 이용해 DX11을 1번부터 22번까지 **순서대로 배우는 튜토리얼** (콘솔 실행 파일) |

### 왜 만들었나요?

sgcl은 지금 Cocos2d-x 엔진 위에서 돌아갑니다. 이 Cocos2d-x를 **우리가 직접 만든 DX11 엔진(sgf)으로 교체**하는 것이 최종 목표입니다.
그래서 sgf는 Cocos2d-x와 구조가 비슷하게(Director, Scene, Sprite, AddChild) 설계되었습니다.
단, Cocos2d-x의 단점이었던 "addChild를 해야만 그릴 수 있다"는 제약은 없샠습니다. sgf에서는 Renderer2D로 **즉시 그리기**도 가능합니다.

## 3. 폴더 구조

```
UltimateHarmony/
├── Documents/                     ← 지금 읽는 학습 문서들 (00~23)
├── Props/
│   ├── base.props                 ← 공통 빌드 설정 (강제 포함 Core.h 등)
│   ├── jc.props                   ← jc 라이브러리 사용 설정
│   └── sgf.props                  ← sgf + d3d11 등 링크 설정 (신규)
└── Projects/
    ├── jc/                        ← 기반 라이브러리 (기존)
    ├── sgf/                       ← ★ 신규: DX11 엔진 (정적 라이브러리)
    │   ├── Project/sgf.vcxproj
    │   └── Sources/sgf/
    │       ├── PCH/               ← 미리 컴파일된 헤더 (Core.h)
    │       ├── Math/              ← vec2/vec3/vec4/mat4/color (SgfMath.h)
    │       ├── Core/              ← Window, FrameTimer, Application
    │       ├── Input/             ← InputManager (키보드/마우스/이벤트)
    │       ├── Graphics/          ← GraphicDevice, Shader, Buffers, Texture,
    │       │                         Vertex, Renderer2D, RenderTarget
    │       ├── Scene/             ← Node, Sprite, Camera, Scene, Director
    │       └── SgfHeader.h        ← 이거 하나만 include하면 전부 사용 가능
    └── sgfr/                      ← ★ 신규: 튜토리얼 (콘솔 앱)
        ├── Project/sgfr.vcxproj   (+ .filters: 01~22 번호순 필터)
        └── Sources/sgfr/
            ├── PCH/Core.h         ← jc + sgf를 포함하는 PCH
            ├── Main.cpp           ← 콘솔 메뉴 (1~22 선택)
            ├── TutorialRegistry.* ← 튜토리얼 목록 등록부
            └── 01_LinearAlgebra/ … 22_SpriteAnimation/
                └── NN_이름_Main.cpp/.h + NN_이름_Function.cpp/.h
```

## 4. sgf 엔진의 설계 철학

### 4-1. 단순함이 최우선
- 클래스 개수를 최소로 유지했습니다. (엔진 전체가 클래스 15개 남짓)
- 상속 깊이는 최대 2단계 (Node → Sprite / Scene).
- "마법" 없음: 모든 동작은 코드를 따라가면 그대로 보입니다.

### 4-2. jc 컨벤션을 그대로 따름
- 타입: `_s32`, `_u32`, `_f32` …
- 멤버: `m_PascalCase`, 포인터는 `m_pXxx`
- 파라미터: `_camelCase`, 출력용은 `_pOut`
- 구조체 공개 멤버: `name_` (trailing underscore)
- 매크로: `jc_assert`, `JC_DELETE_SAFE`, `JC_RELEASE_SAFE`
- 싱글톤: `jc::SingletonStatic<T>` (Director가 사용)

### 4-3. Cocos2d-x와의 관계 (sgcl 교체 대비)

| Cocos2d-x | sgf | 비고 |
|---|---|---|
| `Director::getInstance()` | `Director::Get()` | jc 싱글톤 |
| `Scene` | `Scene` | OnEnter/OnExit/OnUpdate/OnRender |
| `Node`, `addChild` | `Node`, `AddChild` | 부모-자식 변환 전파 동일 |
| `Sprite` | `Sprite` | SetTexture/SetColor/SetSize |
| (없음) | **Renderer2D 즉시 그리기** | addChild 없이 그리기 가능! |

### 4-4. 수학 규약 (아주 중요 — 모든 튜토리얼의 기반)
- **행 우선(row-major)** 행렬, **행 벡터** 곱: `v' = v * M`
- 그래서 HLSL에서도 `row_major float4x4` + `mul(v, M)` — **전치(transpose) 불필요**
- 결합 순서: `world * view * proj` (왼쪽 것이 먼저 적용)
- **왼손 좌표계(LH)**, NDC z 범위 [0, 1]

## 5. 그림 한 장으로 보는 전체 흐름

```
[내 C++ 코드]
    │  정점 데이터(Vertex), 행렬(mat4), 텍스처(Texture)
    ▼
[GraphicDevice]  ←── GPU와의 전화기 (Device/Context/SwapChain)
    │
    ▼
[렌더링 파이프라인]  IA → VS → RS → PS → OM     (04번에서 상세히)
    │      VS: 정점을 화면 좌표로 (07~09번의 행렬들)
    │      RS: 와이어프레임/컸링 (17번)
    │      PS: 픽셀 색 결정 (10·18번 라이팅, 11번 텍스처, 15번 샘플링)
    │      OM: 블렌딩(16번), 깊이 판정(09번)
    ▼
[렌더 타깃(19번)] ── 후보정(20번)/그림자(21번)에 활용
    ▼
[백버퍼] ──Present()──▶ [모니터]                  (03번 스왑체인)
```

엔진(sgf)은 위 흐름을 사람이 다루기 쉬운 개념(Application, Scene, Sprite…)으로 포장한 것뿐입니다.
01~13번에서 날것의 DX11을 배우고, 14번에서 포장된 엔진을 쓰면 **왜 엔진이 필요한지** 체감하게 됩니다.
그리고 15~22번에서 상용 엔진이 반드시 갖추는 심화 기능(샘플링·블렌딩·셰이딩·렌더 타깃·포스트 프로세싱·그림자·애니메이션)까지 전부 익힙니다.

## 6. 빌드 방법

1. 솔루션에 `Projects/sgf/Project/sgf.vcxproj`와 `Projects/sgfr/Project/sgfr.vcxproj`를 추가합니다.
2. 프로젝트 의존성: sgfr → sgf → jc 순서로 빌드되도록 참조/의존성을 설정합니다.
3. (선택) SVG 튜토리얼(12번)을 온전히 쓰려면 `Projects/sgf/Sources/sgf/_Extern/nanosvg/README.md`의 안내대로
   nanosvg 헤더 2개를 내려받아 넣습니다. 없어도 빌드는 되며, 12번은 대체(fallback) 텍스처로 동작합니다.
4. sgfr을 시작 프로젝트로 지정하고 실행하면 콘솔 메뉴가 나옵니다.

> 참고: 저장소의 기존 프로젝트들처럼 sgf/sgfr도 `Props/base.props`, `Props/jc.props`, `Props/sgf.props`를 사용합니다.
> base.props가 `Core.h`를 강제 포함(ForcedIncludeFiles)하므로 각 cpp 첫 줄의 `#include "Core.h"`는 PCH 역할입니다.

## 7. 문서 읽는 규칙

- 각 문서는 **(1) 왜 필요한가 → (2) 개념 설명 → (3) 코드 따라가기 → (4) 직접 해보기** 순서로 구성됩니다.
- 어려운 용어가 처음 나오면 반드시 비유와 함께 설명합니다. 비유는 정확하지 않을 수 있지만 감을 잡는 데 우선순위를 둩습니다.
- 코드 조각은 실제 sgf/sgfr 코드에서 그대로 가져왔습니다. 파일 경로가 함께 적혀 있으니 꼭 열어서 전체를 확인하세요.
