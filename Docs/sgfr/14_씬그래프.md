## 1. 지금까지 배운 것을 엔진으로 묶기

1~13번은 매번 윈도우 만들고, 버퍼 만들고, 행렬 계산하고… 반복 작업이 많았습니다.
이 반복을 묶어 재사용하게 만든 것이 바로 **엔진**입니다. sgf의 구성:

| 클래스 | 역할 | Cocos2d-x 대응 |
|---|---|---|
| `Application` | 윈도우 + 디바이스 + 입력 + 타이머 + 메인 루프 | `AppDelegate` |
| `Director` | 현재 씬 관리, 씬 전환 | `Director` |
| `Scene` | 한 화면 (타이틀, 인게임, 결과창…) + 카메라 보유 | `Scene` |
| `Node` | 위치/회전/크기를 가진 계층 구조의 기본 단위 | `Node` |
| `Sprite` | 텍스처를 그리는 Node | `Sprite` |
| `Renderer2D` | 스프라이트를 모아 한 번에 그리는 배치 렌더러 | (내부 렌더러) |

## 2. 씬 그래프의 핵심 = 07번의 그 한 줄

`Node::AddChild`로 부모-자식 트리를 만들면, 그릴 때 각 노드의 월드 행렬이 자동 계산됩니다.

```cpp
// Node.cpp의 핵심 (07번에서 배운 그 공식 그대로!)
mat4 Node::WorldTransform() const
{
	mat4 local = mat4::SRT2D(m_Scale, m_Rotation, m_Position); // 로컬 = S*R*T
	if (m_pParent) return local * m_pParent->WorldTransform();  // 자식 월드 = 로컬 × 부모 월드
	return local;
}
```

태양-지구-달(07번)을 손으로 곱했던 것을, 이제 `AddChild` 한 번으로 해결합니다.

### 피벗(Pivot) 패턴

14번 예제는 태양계를 씬 그래프로 다시 만듭니다. 이때 빈 Node를 "회전축"으로 쓰는 피벗 패턴이 등장합니다.

```
Sun(스프라이트)
 └─ EarthPivot(빈 노드, 회전만 담당)   ← 이 노드를 돌리면 지구가 공전!
     └─ Earth(스프라이트, x=200 위치)
         └─ MoonPivot(빈 노드)
             └─ Moon(스프라이트, x=60 위치)
```

UI 계층, 보스의 파드 회전직 등 실무에서 매우 자주 쓰는 기법입니다.

## 3. sgf의 설계 포인트: addChild 없이도 그릴 수 있다

Cocos2d-x는 모든 것을 addChild해야만 그려집니다. sgf는 두 가지 방식을 모두 지원합니다.

### 방식 1: 씬 그래프 (유지되는 객체)

```cpp
Sprite* pShip = new Sprite();
pShip->SetTexture(&m_ShipTexture);
AddChild(pShip); // 이제 매 프레임 자동으로 그려짐 (소유권도 넘어감)
```

### 방식 2: 즉시 모드 드로잉 (Scene::OnRender에서 직접)

```cpp
void MyScene::OnRender(Renderer2D* _pRenderer)
{
	// 그냥 함수 호출로 바로 그리기! 디버그 표시, 이펙트, 가이드선에 편리
	_pRenderer->DrawRect(vec2(x, y), vec2(50, 50), color::White());
	_pRenderer->DrawLine(vec2(-400, 0), vec2(400, 0), color(1, 0, 0, 1));
	_pRenderer->DrawCircle(vec2(0, 0), 30.0f, color(0, 1, 0, 1));
}
```

사용자 요구사항이었던 "addChild 없이도 렌더링 가능한 구조"가 바로 이것입니다. 둘 다 내부적으로는 같은 Renderer2D 배치로 모입니다.

## 4. Renderer2D — 배치 렌더링의 원리

스프라이트 100개를 각각 Draw 호출하면 느립니다(드로우 콜 비용).
Renderer2D는 사각형들을 **큰 동적 버퍼(06번!)에 모아두었다가** 텍스처가 바뀌거나 가득 차면 한 번에 그립니다.

```
Begin(뷰투영행렬) → DrawSprite/DrawRect/... (버퍼에 쌓기만) → End()에서 일괄 Flush
```

1~13번 지식 총동원: 동적 버퍼(06) + 상수 버퍼로 VP 행렬 전달(05, 08) + 텍스처/블렌딩(11) + 정점 색 보간(04).

## 5. Application의 메인 루프 — 엔진의 심장

```cpp
// Application::Run() 내부 (단순화)
while (m_Window.PumpMessage())       // 02번: 메시지 처리
{
	m_Timer.Tick();                   // dt 계산
	OnUpdate(dt);                     // 사용자 훅 (상속해서 오버라이드 가능)
	Director::Get()->Update(dt);      // 현재 씬 OnUpdate + 노드 트리 Update
	m_Device.BeginFrame(m_ClearColor);// 03번: 화면 지우기
	Director::Get()->Render(&m_Renderer); // 씬 그래프 그리기 + Scene::OnRender
	OnRender();                       // 사용자 훅
	m_Device.EndFrame(m_bVsync);      // 03번: Present
	m_Input.NextFrame();              // 13번: 입력 상태 이월
}
```

14번 예제의 main은 이제 이만큼 짧습니다:

```cpp
Application app;
app.Initialize(L"씬 그래프", 1024, 768);
Director::Get()->RunScene(new SolarSystemScene(&app));
app.Run();
app.Finalize();
```

이것이 엔진을 만든 보람입니다. 1~13번의 모든 보일러플레이트가 이 네 줄 뒤에 숨어 있습니다.

## 6. 마우스 픽셀 → 월드 좌표 변환 (실전 필수 공식)

14번 예제는 마우스를 따라다니는 사각형을 즉시 모드로 그립니다. 카메라가 원점이고 줌이 1일 때:

## 7. 튜토리얼(14번)에서 직접 확인할 것

1. 태양-지구-달이 씬 그래프로 계층 회전합니다. (07번과 결과 비교!)
