# 08. 메시와 토폴로지 — 정점 조립을 한 덩어리로

> 관련 코드: `Projects/sgfr/Sources/sgfr/08_MeshAndTopology/` (`08_MeshAndTopology_Main.cpp`)
> 관련 엔진: `Projects/sgf/Sources/sgf/Graphics/Mesh.h`, `ShaderProgram.h`, `GraphicContext.h`
> 실행: sgfr 실행 후 콘솔 메뉴에서 **8번** 선택
> 선행 학습: 03. 디바이스와 컨텍스트, 07. 정점/인덱스 버퍼

## 1. 이 장에서 배우는 것

sgf v3의 핵심 새 개념인 **Mesh**를 배웁니다. Mesh는 정점 버퍼 + (인덱스 버퍼) + 입력 레이아웃 + 토폴로지를 한 덩어리로 묶은 "무엇을 그릴지"의 형태 단위로, `mesh.Bind(context)` 한 줄이면 IA 단계 세팅이 끝납니다. 그리고 **토폴로지**의 본질 — "같은 정점 6개도 해석 방법에 따라 삼각형/선/점이 된다"는 것을 키보드 1/2/3 전환으로 직접 실험합니다. 또 v3에서 VertexShader/PixelShader가 별도 클래스로 분리된 구조와, `InvalidateCache()`의 실전 사용을 확인합니다.

## 2. 실행하면 보이는 것

창 제목이 "08. 메시와 토폴로지"로 뜨고, 어두운 배경 위에 **무지개색 육각형 꼭짓점 6개**가 원형으로 배치됩니다. 키를 누를 때마다 창 제목과 그림이 바뀝니다:

- **1**: 삼각형 리스트 — 6정점이 2개 삼각형으로 이어짐 (기본값)
- **2**: 선 스트립 — 6정점이 5개의 이어진 선분이 됨
- **3**: 점 리스트 — 6정점이 점 6개가 됨

창 제목이 "삼각형 리스트"/"선 스트립"/"점 리스트"로 바뀌어 현재 모드가 표시됩니다. ESC로 종료합니다.

## 3. 핵심 개념 — 비유로 먼저 이해하기

### 3-1. 메시 = 형태에 관한 물건 한 묶음

요리에서 "채소 바구니"에 당근, 양파, 감자가 들어 있듯이, 그래픽에서 **메시**에는 그 물체의 형태를 그리는 데 필요한 것들이 다 들어 있습니다: 정점 버퍼(모양을 이루는 점들), 인덱스 버퍼(점을 잇는 번호), 입력 레이아웃(점 데이터의 설명서), 토폴로지(점을 어떻게 이을지). 이제 튜토리얼마다 버퍼/레이아웃/토폴로지를 따로따로 바인딩하던 것을, `mesh.Bind(context)` **한 줄**로 끝냅니다. "무엇을 그릴지"가 완성된 물건으로 존재하는 것입니다.

### 3-2. 토폴로지 = 레고 블록의 조립 도면

같은 레고 블록 6개가 있어도, 도면이 "집"이면 지붕이 되고 "기차"면 이어진 레일이 됩니다. 토폴로지는 정점 데이터가 아니라 **정점을 해석하는 규칙**입니다. 같은 정점 6개를 삼각형 리스트로 읽으면 2개 삼각형(3+3), 선 스트립으로 읽으면 5개 선분(연결형), 점 리스트로 읽으면 점 6개가 됩니다. 데이터는 한 번만 만들어 두고, 해석 규칙만 바꿔가며 보는 것이 이 장의 실험입니다.

### 3-3. 토폴로지는 "기본값"일 뿐 — 언제든 덮어쓸 수 있는 IA 상태

Mesh가 토폴로지를 갖고 있지만, 토폴로지는 결국 IA 단계의 **상태**입니다. 메시를 바인딩할 때 기본값으로 설정될 뿐, 이후 `context.SetPrimitiveTopology()`로 언제든 다른 값으로 덮어쓸 수 있습니다. 집 설계도를 받아도 그 자리에서 "옥상 정원으로 바꿔 주세요"라고 말할 수 있는 것과 같습니다. 이 장은 기본값을 만들고(생성 시 토폴로지) → 매 프레임 키 입력으로 덮어쓰는(렌더 시 토폴로지) 흐름을 보여줍니다.

### 3-4. InvalidateCache = 엔진 밖에서 상태를 바꾼 뒤의 안전망

03번에서 배운 `InvalidateCache()`가 드디어 실전에서 등장합니다. `BeginFrame`은 백버퍼를 지우고 RTV/DSV/뷰포트를 원시 D3D 호출로 설정하므로, GraphicContext의 캐시가 "실제 상태"와 어긋날 수 있습니다. 그래서 `BeginFrame` 직후 캐시를 비워, 이번 프레임의 바인딩이 전부 실제 D3D 호출로 내려가게 합니다. 기억을 지우고 새로 외우게 하는 것과 같습니다.

## 5. 코드 워크스루

`08_MeshAndTopology_Main.cpp`의 `MeshAndTopology_Main()`을 따라갑니다.

### 5-1. 셰이더 소스 (코드 32~58행) — 익명 네임스페이스 상수

```cpp
namespace
{
	const char* PASSTHROUGH_SHADER_SOURCE = R"(
struct VsIn
{
	float3 position : POSITION;
	float2 uv       : TEXCOORD0;
	float4 color    : COLOR0;
};
...
VsOut VSMain(VsIn _in)
{
	VsOut result;
	result.position = float4(_in.position, 1.0f);
	result.color = _in.color;
	return result;
}

float4 PSMain(VsOut _in) : SV_Target
{
	return _in.color;
}
)";
```

셰이더가 이제 Main.cpp 안에 익명 네임스페이스 상수로 상주하며, `VertexPTC`(위치+UV+색) 구조에 맞춰 `POSITION/TEXCOORD0/COLOR0` 세 시맨틱을 받습니다. 여기서 UV(TEXCOORD0)는 아직 쓰지 않지만 VertexPTC의 입력 레이아웃 요구 때문에 선언되어 있습니다.

### 5-2. VS/PS 별도 컴파일 (코드 89~98행) — v3의 분리 구조

```cpp
VertexShader vs;
PixelShader ps;
if (!vs.InitializeFromSource(&device, PASSTHROUGH_SHADER_SOURCE) ||
	!ps.InitializeFromSource(&device, PASSTHROUGH_SHADER_SOURCE))
```

05~07번의 `Shader`(VS+PS+레이아웃 한 덩어리)와 달리, v3는 `VertexShader`와 `PixelShader`가 각각의 클래스입니다(ShaderProgram.h). 같은 소스를 두 번 컴파일하는 이유는 `InitializeFromSource`의 기본 진입점이 각각 `VSMain`/`PSMain`이기 때문입니다. 분리하면 "같은 VS + 다른 PS" 같은 조합이 가능해집니다.

### 5-3. 무지개 육각형 정점 6개 (코드 101~112행)

```cpp
VertexPTC vertices[6];
for (int i = 0; i < 6; ++i)
{
	const _f32 angle = jc_math_pi * 2.0f * (_f32)i / 6.0f + jc_math_pi * 0.5f;
	vertices[i].position_ = vec3(cosf(angle) * 0.7f, sinf(angle) * 0.7f, 0.0f);
	vertices[i].uv_ = vec2(0.0f, 0.0f);
	vertices[i].color_ = color(
		0.5f + 0.5f * cosf(angle),
		0.5f + 0.5f * sinf(angle),
		1.0f - 0.5f * cosf(angle),
		1.0f);
}
```

- 6개의 각도를 360°를 6등분해서 만들고, `cos/sin`으로 원 위의 좌표를 계산합니다(반지름 0.7).
- `+ jc_math_pi * 0.5f`(90°)는 첫 정점이 위쪽(12시)에서 시작하도록 합니다.
- 색도 `0.5 + 0.5*cos/sin`으로 각도마다 다른 무지개색을 생성합니다 — 04번의 RainbowColor와 같은 기법.

### 5-4. 메시 생성 (코드 115~125행)

```cpp
UINT layoutCount = 0;
const D3D11_INPUT_ELEMENT_DESC* pLayoutDescs = VertexPTC::LayoutDescs(&layoutCount);

Mesh mesh;
if (!mesh.Initialize(&device, vertices, sizeof(VertexPTC), 6, pLayoutDescs, layoutCount, &vs))
```

`Mesh::Initialize(&device, 정점, stride, 개수, 레이아웃, 개수, VS)`가 내부에서 **VertexBuffer + InputLayout + 기본 토폴로지(ptTriangleList)**를 만들어 한 덩어리로 묶습니다. 인덱스 인자는 기본값(nullptr)이라 이 메시는 비인덱스 메시가 됩니다. 07번과 달리 `VertexPTC::LayoutDescs`는 `POSITION(오프셋 0) / TEXCOORD(12) / COLOR(20)` 3개 항목입니다.

### 5-5. 렌더 루프 — 토폴로지 전환 (코드 130~160행)

```cpp
PrimitiveTopology topology = PrimitiveTopology::ptTriangleList;
int topologyIndex = 0;

while (window.PumpMessage())
{
	if (input.IsKeyPressed(VK_ESCAPE)) break;
	if (input.IsKeyPressed('1')) { topology = PrimitiveTopology::ptTriangleList; topologyIndex = 0; }
	if (input.IsKeyPressed('2')) { topology = PrimitiveTopology::ptLineStrip;    topologyIndex = 1; }
	if (input.IsKeyPressed('3')) { topology = PrimitiveTopology::ptPointList;    topologyIndex = 2; }
	input.NextFrame();

	window.SetTitle(s_szTopologyNames[topologyIndex]);

	device.BeginFrame(color(0.06f, 0.06f, 0.1f, 1.0f));
	context.InvalidateCache();	// BeginFrame이 원시 상태를 건드렸으므로 캐시를 비운다

	context.SetVertexShader(&vs);
	context.SetPixelShader(&ps);

	mesh.Bind(context);			// IA 세팅 한 줄 완료 (VB+레이아웃+기본 토폴로지)
	context.SetPrimitiveTopology(topology);	// 기본값을 오늘의 해석 규칙으로 덮어쓰기
	mesh.Draw(context);

	device.EndFrame(true);
}
```

- **1/2/3 키** 폴링으로 `PrimitiveTopology`를 교체하고, `Window::SetTitle`로 창 제목을 현재 모드로 바꿉니다.
- `BeginFrame` 직후 `context.InvalidateCache()` — 03번에서 배운 원칙의 실전 적용.
- `context.SetVertexShader/SetPixelShader` — v3 컨텍스트의 Set 계열 API로 셰이더 장착.
- `mesh.Bind(context)` — 한 줄이면 VB/인덱스/레이아웃/기본 토폴로지 모두 IA에 장착됩니다.
- `context.SetPrimitiveTopology(topology)` — "메시의 기본값은 어디까지나 기본값"이라는 주제의 핵심. 이 한 줄이 1/2/3에 따라 삼각형/선/점 해석을 바꿉니다.
- `mesh.Draw(context)` — 인덱스가 없으므로 내부적으로 `Draw(정점 수, 0)` 경로를 탑니다.

### 5-6. 정리 — 생성의 역순 (코드 163~167행)

`mesh.Finalize()` → `ps.Finalize()` → `vs.Finalize()` → `device.Finalize()` → `window.Destroy()`.

## 6. GPU와 DX11, 하드웨어 깊이 보기

### 6-1. 메시의 하드웨어 실체: 하나의 "형태"가 여러 GPU 메모리 영역에 걸쳐 있다

`Mesh`는 CPU 객체이지만, 내부의 버퍼들은 GPU 메모리에 실재합니다. 정점 버퍼(6 × 36바이트 VertexPTC = 216바이트)는 VRAM의 정점 스토리지에, 입력 레이아웃은 드라이버가 만든 정점 디코더 구성 데이터로 존재합니다. `mesh.Bind(context)`가 실제로 하는 일은 `IASetVertexBuffers`(정점 버퍼 주소+stride), `IASetInputLayout`(정점 해석 구성), `IASetPrimitiveTopology`(기본값) 세 가지 D3D 호출을 순서대로 내리는 것입니다. GPU 입장에서 "메시"란 특별한 것이 아니라, IA가 참조할 메모리 주소와 해석 규칙의 조합입니다.

### 6-2. 토폴로지가 바뀌면 IA 하드웨어가 달라지는 방식

`SetPrimitiveTopology(ptLineStrip)`이 내려가면 IA의 **프리미티브 어셈블러**가 정점을 묶는 규칙을 바꿉니다: 삼각형 리스트는 3개씩 비겹침 묶음, 선 스트립은 2개씩 겹침 묶음(정점 1을 두 선분이 공유), 점 리스트는 1개씩입니다. 스트립 계열은 이전 프리미티브의 마지막 정점을 다음 프리미티브의 첫 정점으로 재사용하므로, 같은 정점 수로 더 많은 프리미티브를 만들 수 있습니다 — 이 장의 6정점이 삼각형 2개(리스트) 또는 선분 5개(스트립)가 되는 이유입니다. 프리미티브 생성 자체는 GPU의 고정기능 하드웨어가 하며, 셰이더는 전혀 관여하지 않습니다.

### 6-3. 점/선 프리미티브의 래스터라이제이션: 두께와 픽셀 커버리지

점 리스트와 선 스트립은 픽셀 셰이더를 여전히 실행하지만, 래스터라이저가 생성하는 픽셀 패턴이 다릅니다. D3D11에서 점은 보통 1픽셀, 선은 1픽셀 두께로 래스터화됩니다(래스터라이저 상태에서 확장 가능 — 19번 튜토리얼). 삼각형의 픽셀 수와 비교하면 픽셀 셰이더 부하가 극히 작아, 6정점 실험이 "같은 데이터로 해석만 바꿔도 렌더링 부하가 달라진다"는 것을 보여줍니다. 게임에서 파티클(점), 라인 렌더러(선)로 확장되는 기본기입니다.

### 6-4. SetTitle과 CPU 부하: 매 프레임 문자열 처리의 비용

이 장이 매 프레임 `SetTitle`을 호출하는 것은 교육용 데모지만, 실전에서 창 제목을 매 프레임 바꾸면 Windows의 제목줄 갱신(WM_SETTEXT)이 CPU를 은근히 잡아먹습니다. FPS 카운터(예: `FrameTimer::Fps()`)를 1초에 한 번만 갱신하는 이유이기도 합니다. GPU와 직접 관련은 없지만, CPU 측 렌더 루프의 예산 관리(매 프레임 할 일 vs 가끔 할 일)라는 관점에서 유용한 사례입니다.

### 6-5. v3 셰이더 분리의 드라이버 관점: 같은 컴파일, 다른 객체

`VertexShader`/`PixelShader` 분리는 드라이버에서도 의미가 있습니다. VS 객체는 입력 서명(시그니처) 검증에 쓰이는 **바이트코드를 보관**해야 하고(ShaderProgram.h의 `Bytecode()`), PS 객체는 그럴 필요가 없습니다. 입력 레이아웃을 만들 때 D3D11은 "정점 구조 설명 배열 + VS 바이트코드"를 요구하는데, 이것이 `Mesh::Initialize`가 `VertexShader*`를 인자로 받는 이유입니다. 즉 Mesh 생성 시점에 드라이버는 레이아웃과 VS 입력 서명의 일치를 검증합니다 — 시맨틱 이름이나 형식이 어긋나면 이 단계에서 실패합니다.

### 6-6. 캐시 무효화와 실제 상태의 동기화: 프레임 경계의 정합성

`BeginFrame`이 `ClearRenderTargetView`, `OMSetRenderTargets`, `RSSetViewports` 같은 원시 호출을 한 뒤 `InvalidateCache()`가 캐시를 비우는 것은, **CPU 사이드 상태 추적과 GPU 실제 상태의 이중화를 정합**시키는 장치입니다. 캐시가 틀린 상태로 남아 있으면 "이미 같은 셰이더가 묶였다"고 생략해버려, 이전 프레임의 셰이더가 그대로 쓰이는 사고가 납니다. 이 장의 루프는 매 프레임 이 경계를 정확히 지킵니다. 이 패턴은 이후 20번 머티리얼, 23번 스테이트 캐시 튜토리얼에서 더 깊게 다뤄집니다.

## 7. 핵심 규칙 요약

- [ ] Mesh = 정점 버퍼 + (인덱스 버퍼) + 입력 레이아웃 + 토폴로지 묶음.
- [ ] `mesh.Bind(context)` 한 줄 = IA 세팅 완료 (v3 핵심 편의).
- [ ] 토폴로지는 메시의 "기본값"일 뿐, IA 상태라 `SetPrimitiveTopology`로 언제든 덮어씀.
- [ ] 같은 정점 6개: 삼각형 리스트 = 2개 삼각형, 선 스트립 = 5개 선분, 점 리스트 = 점 6개.
- [ ] 스트립은 앞 프리미티브의 끝 정점을 재사용 (더 많은 프리미티브).
- [ ] v3에서 VS/PS가 별도 클래스 (같은 소스, VSMain/PSMain 진입점 분리).
- [ ] `BeginFrame` 직후 `context.InvalidateCache()` 필수.
- [ ] VertexPTC: 위치(0) + UV(12) + 색(20) 레이아웃, 인덱스 없으면 `Mesh::Draw`는 Draw 경로.
- [ ] 정리 순서: mesh → ps → vs → device → window 역순.
