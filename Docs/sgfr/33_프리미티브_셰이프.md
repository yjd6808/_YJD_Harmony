# 33. 프리미티브 셰이프 — Shape2D/Shape3D, 그리기 코드 없이 도형 배치하기

> 실행: sgfr 실행 후 콘솔 메뉴에서 33번 선택 (SPACE: 씬 전환, ESC: 종료)
> 선행 학습: `29_씬과_사운드.md`(씬 트리/GameObject), `32_프리미티브_메시.md`(리소스 매니저의 단위 메시)

## 1. 이 장에서 배우는 것

32번에서 리소스 매니저의 프리미티브 **메시**를 배웠습니다. 이번에는 그 메시를 감싼 **편의 노드(Shape)**를 배웁니다. `Shape2D`는 **AddChild + SetXXX 두 줄이면 영원히 그려지는 정적 도형**을 만들고, `Shape3D`는 **AddChild + SetShape 한 줄이면 회전/이동 가능한 3D 도형**을 만듭니다. "메시 조회 → 머티리얼 설정 → 셰이더 키 지정 → GPU 초기화" 같은 반복 작업이 전부 사라집니다.

## 2. 실행하면 보이는 것

**씬 1 — 2D 셰이프**: 검은 배경에 사각형/원/선/삼각형 4종이 떠 있습니다. 하나도 움직이지 않는 "UI 패널" 느낌입니다. 창 제목에 **DrawCall: 1**이 표시됩니다 — 도형이 4개인데 GPU 드로우콜은 1번뿐입니다(배칭).

**씬 2 — 3D 셰이프**: SPACE를 누르면 큐브/구/캡슐/원기둥/평면/쿼드 6종이 일렬로 서서 **제자리에서 각자 회전**합니다. Shape2D와 달리 bake가 없으므로 프레임마다 회전각을 바꿔도 즉시 반영됩니다.

```
[33] Shape2DScene::OnEnter — Shape2D 4종 배치 완료
[33] Shape3DScene::OnEnter — Shape3D 6종 배치 완료
```

## 3. 핵심 개념 — 비유로 먼저 이해하기

### 3-1. Shape2D = "벽에 붙이는 스티커"

Shape2D는 **절대좌표를 한 번 bake(구워) 버립니다**. 종이 스티커를 벽에 붙이는 순간 위치가 고정되는 것과 같습니다. `AddChild` 직후 `OnEnter`에서 `Scene2D::DeclareStaticRect/Circle/Line/Triangle`으로 **버텍스가 한 번 생성**되고, 이후 매 프레임은 그 **id만 예약**합니다. 그래서:

- **빠르다**: 버텍스 재계산이 없고, 같은 텍스처끼리 묶여 배칭(드로우콜 1)됩니다.
- **정적이다**: 설정 변경은 `AddChild` 전에만 유효합니다. 움직이지 않는 UI(패널/테두리/HP바 배경)용입니다.

### 3-2. Shape3D = "손에 든 피규어"

Shape3D는 bake가 없습니다. `OnEnter`에서 **메시와 머티리얼을 한 번 구성**해 줄 뿐이고, 매 프레임 `RenderSelf()`가 `Transform`의 위치/회전/스케일을 월드 행렬로 바꿔 그립니다(메시 자동 드로우 경로). 피규어를 든 채 손을 움직이면 자세가 달라지는 것과 같습니다. 3D는 정적인 UI보다 움직이는 오브젝트가 주 용도이므로 이 경로가 정석입니다.

### 3-3. 둘 다 "설정 한 번, 나머지는 엔진이"

두 노드의 공통점은 **그리기 코드가 없다**는 것입니다. `OnRender`를 오버라이드할 필요도 없습니다. 사용자는 "무엇을, 어디에, 어떤 색으로"만 알려주면 됩니다.

| | Shape2D | Shape3D |
|---|---|---|
| 설정 | `SetRect/SetCircle/SetLine/SetTriangle` | `SetShape(타입, 색)` |
| bake | OnEnter에서 절대좌표 1회 bake | 없음 (메시/머티리얼만 구성) |
| 움직임 | 불가 (정적 전용) | Transform으로 자유 (회전/이동/스케일) |
| 그리기 | RenderStatic(id) 예약 → 배칭 | RenderSelf() → Renderer3D 배칭 |
| 용도 | UI 패널, 테두리, HP바 배경 | 게임 오브젝트, 디버그 도형 |

## 4. 초보자 용어 사전

| 용어 | 뜻(쉬운 말) | 비유 |
|---|---|---|
| 프리미티브 (Primitive) | 가장 기본적인 도형 (사각형/원/구/큐브 등) | 레고 기본 블록 |
| 편의 노드 (Shape) | 메시+머티리얼 구성을 감춘 GameObject 파생 | 조립 완료된 완제품 |
| bake (스태틱 선언) | 절대좌표로 버텍스를 한 번 생성해 캐시 | 스티커를 벽에 붙이기 |
| staticId | bake 결과물의 번호 (RenderStatic 예약용) | 벽에 붙인 스티커 목록 번호 |
| 배칭 (Batching) | 여러 도형을 한 번의 드로우콜로 그리기 | 택배 여러 개를 한 차에 싣기 |
| 메시 자동 드로우 | SetMesh만 하면 트래버설 중 자동으로 그려짐 | 자동 조립 라인 |
| baseColor | 머티리얼의 단색 채움색 (b2 상수) | 물감의 기본색 |

## 5. 코드 워크스루

### 5-1. 씬 1 — Shape2D 4종

```cpp
class Shape2DScene : public Scene2D
{
public:
	~Shape2DScene()
	{
		// root_ 트리는 자식을 소유하지 않으므로(분리만) 직접 정리한다.
		for (GameObject* pObj : createdObjects_)
		{
			RemoveChild(pObj);
			delete pObj;
		}
	}

	void OnEnter() override
	{
		GetCamera2D()->SetOrthographic2D(VIEW_WIDTH, VIEW_HEIGHT);
		GetWindow()->SetTitle(L"33. Shape2D - SPACE: 3D 씬 (ESC: 종료)");

		// 사각형 — 채운 사각형 패널 (절대좌표: 왼쪽 위 200,150, 크기 120x90)
		Shape2D* pRect = new Shape2D("Rect");
		pRect->SetRect(rect(200.0f, 150.0f, 120.0f, 90.0f), color(0xFF, 0x6B, 0x6B));
		AddChild(pRect, 0);
		createdObjects_.PushBack(pRect);

		// 원 — 중심 (380, 300), 반지름 60, 기본 32분할
		Shape2D* pCircle = new Shape2D("Circle");
		pCircle->SetCircle(vec2(380.0f, 300.0f), 60.0f, color(0xFF, 0xCC, 0x4D));
		AddChild(pCircle, 0);
		createdObjects_.PushBack(pCircle);

		// 선 — 두께 6의 선분 (절대좌표 두 점)
		Shape2D* pLine = new Shape2D("Line");
		pLine->SetLine(vec2(500.0f, 180.0f), vec2(650.0f, 420.0f), 6.0f, color(0x8A, 0xFF, 0x8A));
		AddChild(pLine, 0);
		createdObjects_.PushBack(pLine);

		// 삼각형 — 절대좌표 세 점
		Shape2D* pTriangle = new Shape2D("Triangle");
		pTriangle->SetTriangle(vec2(200.0f, 420.0f), vec2(260.0f, 300.0f), vec2(330.0f, 440.0f), color(0x6B, 0xD0, 0xFF));
		AddChild(pTriangle, 0);
		createdObjects_.PushBack(pTriangle);
	}
};
```

4개의 패턴이 모두 동일합니다: **new → SetXXX → AddChild**. `AddChild`가 `OnEnter`를 부르고, 거기서 `DeclareStaticXX`로 버텍스가 1회 bake된 뒤 매 프레임 자동 드로우됩니다. 위치가 절대좌표라는 것에 주의하세요 — `SetRect(rect(200, 150, 120, 90))`은 "화면의 (200,150) 지점에 120x90 사각형"이라는 뜻입니다.

### 5-2. 씬 2 — Shape3D 6종 + 자전

```cpp
class Shape3DScene : public Scene3D
{
public:
	void OnEnter() override
	{
		GetCamera3D()->SetPerspectiveDegrees(60.0f, GetWindow()->AspectRatio(), 0.1f, 1000.0f);
		GetCamera3D()->SetLookAt(vec3(0.0f, 2.5f, -8.0f), vec3::Zero());

		const _f32 xs[] = { -5.5f, -3.3f, -1.1f, 1.1f, 3.3f, 5.5f };
		CreateShape("Cube",     PrimitiveMesh3DType::Cube,     vec3(xs[0], 0.0f, 0.0f), 1.1f, color(0xFF, 0x6B, 0x6B));
		CreateShape("Sphere",   PrimitiveMesh3DType::Sphere,   vec3(xs[1], 0.0f, 0.0f), 1.0f, color(0xFF, 0xCC, 0x4D));
		CreateShape("Capsule",  PrimitiveMesh3DType::Capsule,  vec3(xs[2], 0.0f, 0.0f), 1.0f, color(0x6B, 0xD0, 0xFF));
		CreateShape("Cylinder", PrimitiveMesh3DType::Cylinder, vec3(xs[3], 0.0f, 0.0f), 1.0f, color(0x8A, 0xFF, 0x8A));
		CreateShape("Plane",    PrimitiveMesh3DType::Plane,    vec3(xs[4], 0.0f, 0.0f), 1.2f, color(0xFF, 0x8A, 0xD0));
		CreateShape("Quad",     PrimitiveMesh3DType::Quad,     vec3(xs[5], 0.0f, 0.0f), 1.2f, color(0xC0, 0xA0, 0xFF));
	}

	// 매 프레임: 각 도형을 제자리에서 자전시킨다. (bake가 없는 Shape3D의 자유도)
	void OnUpdate(const jc::TimeSpan& _dt) override
	{
		rotateAngle_ += static_cast<_f32>(_dt.GetTotalSeconds()) * 45.0f;	// 초당 45도

		for (_s32 i = 0; i < createdObjects_.Size(); ++i)
		{
			Transform* pTransform = createdObjects_[i]->GetTransform();
			pTransform->SetLocalRotationEuler(
				rotateAngle_ * (0.4f + 0.2f * (_f32)i),
				rotateAngle_ * (0.5f + 0.15f * (_f32)i),
				0.0f);
		}
	}

private:
	Shape3D* CreateShape(const char* _pName, PrimitiveMesh3DType _type,
		const vec3& _position, _f32 _scale, const color& _color)
	{
		Shape3D* pShape = new Shape3D(_pName);
		pShape->SetShape(_type, _color);
		pShape->SetPosition(_position);
		pShape->SetScale(_scale);
		AddChild(pShape, 0);
		createdObjects_.PushBack(pShape);
		return pShape;
	}

	jc::Vector<GameObject*> createdObjects_;	// 소멸자에서 정리할 오브젝트 목록
	_f32 rotateAngle_ = 0.0f;					// 자전 각도 누적 (도)
};
```

`SetShape(타입, 색)` + `SetPosition` + `SetScale` 세 줄이면 완성입니다. `SetPosition/SetScale/SetRotationEuler`는 `GetTransform()`으로 이어주는 **편의 래퍼**라서, 프레임마다 `Transform`을 직접 조작해 자유롭게 움직일 수 있습니다. 3D 프리미티브 6종은 32번에서 본 단위 메시(Cube = 1x1x1, Sphere = 반지름 1 등)와 같으며, 크기는 `SetScale`로 조절합니다.

### 5-3. Shape3D 내부 — OnEnter에서 메시/머티리얼 1회 구성

```cpp
// AddChild 직후 1회 — 프리미티브 메시를 꺼내 셰이더/색을 갖춘 머티리얼과 함께 장착한다.
void Shape3D::OnEnter()
{
	if (pScene_ == nullptr) return;

	Mesh* pMesh = g_cResourceMgr.FindPrimitiveMesh3D(type_);
	if (pMesh == nullptr) return;

	SetMesh(pMesh);

	// 3D 렌더러(Renderer3D)는 재질의 셰이더 키를 해석해 파이프라인을 구성한다.
	Material* pMaterial = GetMaterial();
	pMaterial->SetVertexShaderKey(g_cResourceMgr.GetDefaultVertexShader3DKey());
	pMaterial->SetPixelShaderKey(g_cResourceMgr.GetDefaultPixelShader3DKey());
	pMaterial->SetBaseColor(color_);
	pMaterial->Initialize(pScene_->GetGraphicDevice());	// GPU 상태 초기화
}

// 매 프레임 — 메시 자동 드로우. Transform의 위치/회전/스케일이 월드 행렬로 반영된다.
void Shape3D::OnRender()
{
	RenderSelf();
}
```

`OnEnter`가 하는 일은 32번의 `Create3DObject`와 똑같습니다: 메시 조회 → 셰이더 키 지정 → baseColor → `Material::Initialize`. 이것이 Shape가 감춰주는 "반복 작업"입니다. `OnRender`는 베이스의 `RenderSelf()`만 호출하면 `Scene::RenderNode`가 이미 부르고 있으므로 사실상 자동입니다. 메시는 ResourceMgr 소유(빌림)라 반납할 것이 없고, 머티리얼은 GameObject 베이스가 소유·정리합니다.

## 6. GPU와 DX11, 하드웨어 깊이 보기

**2D 셰이프의 배칭**: Shape2D 4종은 `DeclareStatic`으로 생성될 때 버텍스가 CPU 미러(VertexPTC)로 한 번 만들어지고, 매 프레임 `FlushStatic`이 **같은 흰색 텍스처끼리 묶어** 한 번의 드로우콜로 그립니다. 창 제목의 **DrawCall: 1**이 그 증거입니다. 스태틱 캐시는 순수 증가만 합니다(반납 API 없음) — 정적 UI 수백 개를 만들어도 드로우콜은 늘지 않는 구조입니다.

**3D 셰이프의 경로**: Shape3D는 `RenderSelf → Scene3D::DrawMesh → Renderer3D::Draw(mesh, material, world)`로 이어집니다. Renderer3D는 깊이 테스트가 켜진 파이프라인(b0 프레임/뷰·투영, b1 월드, b2 baseColor)으로 그리므로, 6종이 겹쳐도 앞뒤가 바르게 가려집니다. 회전각을 프레임마다 바꾸면 `Transform`의 월드 행렬이 매번 새로 계산되어 자전이 보입니다.

**bake vs 실시간**: Shape2D가 bake 방식을 택한 이유는 "변하지 않는 화면 요소를 매 프레임 다시 계산하지 않기 위함"입니다. Shape3D가 실시간 변환을 쓰는 이유는 "3D 물체는 원래 매 프레임 변한다"는 전제 때문입니다. 용도에 맞는 도구를 고르면 됩니다.

## 7. 핵심 규칙 요약

1. **Shape2D = 정적 UI**: `SetXXX`는 AddChild 전에만 유효. 절대좌표로 1회 bake, 배칭으로 드로우콜 최소화.
2. **Shape3D = 동적 오브젝트**: `SetShape(타입, 색)` 후 Transform으로 자유 변환. 메시 자동 드로우 경로.
3. **그리기 코드 없음**: OnRender 오버라이드는 원칙적으로 불필요 (베이스가 자동 처리).
4. **소유권**: 메시는 ResourceMgr 빌림, 머티리얼은 GameObject 소유 — Shape 사용자가 신경 쓸 정리는 없음.
5. **씬 정리**: 씬 소멸 시 자식은 소유되지 않으므로 `RemoveChild + delete`를 직접 해야 한다 (32번과 동일 패턴).

## 8. 직접 해보기 — 실험으로 확인하기

1. **정적 확인**: 씬 1에서 Shape2D를 움직이려 해보세요 — `OnUpdate`에서 `SetRect`를 다시 불러도 화면이 안 바뀝니다. bake는 AddChild 때 끝났기 때문입니다.
2. **드로우콜 검증**: Shape2D를 100개 배치해도 창 제목의 DrawCall이 1로 유지되는지 확인해보세요.
3. **3D 자유도**: 씬 2의 `rotateAngle_` 증가율을 45도에서 360도로 바꿔보세요 — 도형이 빙글빙글 돕니다.
4. **회전 축 실험**: `SetLocalRotationEuler`의 인자를 (0, 0, rotateAngle_)로 바꾸면 Z축 회전이 되어 "바닥을 구르는" 모습이 됩니다.
5. **타입 실험**: `SetShape(PrimitiveMesh3DType::Quad, ...)`로 만든 쿼드를 `SetRotationEuler(90, 0, 0)`로 눕혀 바닥 역할을 시켜보세요.
