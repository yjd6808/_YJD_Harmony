# 15. 샘플러와 필터링 — GPU는 텍스처를 어떻게 "읽을까"?

> 튜토리얼: `Projects/sgfr/Sources/sgfr/15_SamplerFiltering/`
> 엔진 코드: `Projects/sgf/Sources/sgf/Graphics/GraphicDevice.h/.cpp` (`SetSampler`)

---

## 1. 왜 필요한가요?

11번(PNG 텍스처)에서 우리는 이미지를 사각형에 붙여 그렸습니다. 그런데 이상한 점이 하나 있습니다.

- 텍스처는 32×32 픽셀짜리 작은 그림인데,
- 화면에서는 400×400 픽셀 크기로 크게 그려집니다.

32개짜리 점을 400칸에 늘려 그리려면 **없는 색을 지어내야** 합니다. 이 "지어내는 방법"이 바로 **필터링(Filtering)**이고,
텍스처에서 색을 꺼내는 행위 자체를 **샘플링(Sampling)**이라고 부릅니다.

> **비유**: 텍스처는 모눈종이에 그려진 점 그림입니다. "모눈 칸 사이의 색은 뭐야?"라고 물었을 때,
> "제일 가까운 칸 색 그대로!"라고 답하는 게 Point 필터, "주변 4칸 색을 섞어서 부드럽게!"라고 답하는 게 Linear 필터입니다.

샘플링 규칙을 담는 DX11 객체가 **샘플러(Sampler State)**입니다. 셀이더 코드의 `Sample(gSampler, uv)`에서 둘째 인자의 동작 방식을 결정하죠.

---

## 2. 개념 설명

### 2-1. 텍셀(Texel)과 픽셀(Pixel)은 다른 말이다

- **픽셀**: 모니터 화면의 점 하나
- **텍셀**: 텍스처 이미지의 점 하나

화면 픽셀 하나를 칠할 때 픽셀 셰이더는 UV 좌표(0~1)로 텍스처의 어느 위치를 읽을지 결정합니다.
그런데 UV가 정확히 텍셀 중앙에 떨어지는 경우는 거의 없습니다. 대부분 텍셀과 텍셀 **사이**에 떨어집니다. 그래서 필터링이 필요합니다.

### 2-2. 필터 모드 — 색을 지어내는 두 가지 방법

| 모드 | 방법 | 결과 | 언제 쓰나 |
|---|---|---|---|
| **Point** (`MIN_MAG_MIP_POINT`) | 제일 가까운 텍셀 1개 색을 그대로 | 각진 모자이크, 도트 느낌 | 도트 게임, 픽셀아트, UI 아이콘 원본 유지 |
| **Linear** (`MIN_MAG_MIP_LINEAR`) | 주변 텍셀 4개를 거리 비율로 섞음(이중 선형 보간) | 부드러움, 다만 확대하면 번짐 | 사진, 배경, 대부분의 3D 텍스처 |

Linear의 계산을 숫자로 보면: UV가 두 텍셀 사이 30% 지점이면 `왼쪽색 × 0.7 + 오른쪽색 × 0.3` 처럼 가중치 평균을 냅니다.
가로·세로 두 방향으로 하므로 총 4개 텍셀이 섞입니다. (그래서 "이중(bilinear)" 선형 보간)

### 2-3. 밀맵(Mipmap) — 멀리 있는 물체가 지지직거리지 않게

반대로 텍스처가 화면에서 아주 작게 그려질 때는(멀리 있는 바닥 등) 픽셀 하나가 텍셀 수백 개를 덮게 됩니다.
이때 1~4개만 읽으면 프레임마다 다른 텍셀이 잡혀 화면이 지지직거립니다(에일리어싱).
그래서 미리 절반씩 줄인 축소본(32→16→8→4…)을 만들어 두고 거리에 맞는 축소본을 읽는 기법이 **밀맵**입니다.
이번 튜토리얼의 텍스처는 밀맵 없이 1장만 사용하지만(확대 위주 관찰), 개념은 꼭 기억해 두세요.

### 2-4. 주소 모드(Address Mode) — UV가 0~1을 벗어나면?

UV는 보통 0~1이지만, 일부러 0~3 같은 값을 쓰기도 합니다. 그때 범위 밖을 어떻게 채울지가 주소 모드입니다.

| 모드 | 동작 | 비유 | 주 용도 |
|---|---|---|---|
| **Wrap** | 0~1을 반복 (타일처럼) | 바닥 타일 깔기 | 바닥/벽 반복 무늬, 스크롤 배경 |
| **Clamp** | 가장자리 색을 잡아당겨 그대로 당김 | 사진 끝을 썼썼 늘림 | UI, 포스트 프로세싱, 그림자 맵(21번!) |
| **Mirror** | 한 번 반복마다 좌우 뒤집음 | 거울 데칼코마니 | 이음새 없는 반복 무늬 |

> 그림자 맵(21번)에서 Wrap을 쓰면 그림자가 엉뚱한 곳에 반복해서 나타나는 버그가 생깁니다. 그래서 그때는 반드시 Clamp를 씁니다.

### 2-5. DX11에서의 실체: `ID3D11SamplerState`

```cpp
D3D11_SAMPLER_DESC desc = {};
desc.Filter   = D3D11_FILTER_MIN_MAG_MIP_LINEAR; // 필터 모드
desc.AddressU = D3D11_TEXTURE_ADDRESS_WRAP;      // U(가로) 방향 주소 모드
desc.AddressV = D3D11_TEXTURE_ADDRESS_WRAP;      // V(세로) 방향 주소 모드
device->CreateSamplerState(&desc, &pSampler);
context->PSSetSamplers(0, 1, &pSampler);         // s0 슬롯에 장착
```

`Filter` 이름의 MIN/MAG/MIP은 각각 축소(Minification)/확대(Magnification)/밀맵 단계에 쓸 방식을 뜻합니다.

## 3. 엔진은 어떻게 감쌀나 — `GraphicDevice::SetSampler`

매번 desc를 채우는 건 번거롭습니다. sgf는 조합별로 한 번만 만들어 캨시해 둡니다(지연 생성).

```cpp
// 사용 예: 필터와 주소 모드만 고르면 끝
device.SetSampler(SamplerFilter::Linear, SamplerAddress::Wrap);
device.SetSampler(SamplerFilter::Point,  SamplerAddress::Clamp);
```

내부는 `(필터 2종) × (주소 3종) = 6종` 조합을 배열에 캨시하고, 이미 만든 조합이면 재사용합니다.
`GraphicDevice.cpp`의 `SetSampler` 함수 주석에 생성·캨시 과정이 한 줄씩 설명되어 있습니다.

## 4. 코드 따라가기 — 15번 튜토리얼

### 4-1. 관찰용 텍스처 만들기 (`15_SamplerFiltering_Function.cpp`)

필터 차이를 극대화하려면 "경계가 뚜렷한 작은 그림"이 최고입니다. 그래서 파일 없이 코드로 32×32 체커보드를 직접 찍어냅니다.

- 4×4 텍셀마다 흰색/회색을 번갈아 칠함 (체커보드)
- 가장자리 1텍셀은 빨간색 테두리 — **주소 모드를 바꾸면 이 테두리가 어디로 가는지**가 핵심 관찰 포인트
- 완성된 RGBA 배열을 `Texture::CreateFromMemory`로 GPU에 올림

### 4-2. UV를 일부러 0~3으로 (`FillQuad`)

사각형 정점의 UV를 0~1이 아니라 **0~3**으로 줍니다. 그래야 Wrap(3×3 반복)/Clamp(가장자리 늘어짐)/Mirror(거울 반복) 차이가 한눈에 보입니다.

### 4-3. 메인 루프 (`15_SamplerFiltering_Main.cpp`)

```
[1] Point 필터   [2] Linear 필터
[3] Wrap  [4] Clamp  [5] Mirror
```

키를 누를 때마다 `device.SetSampler(현재필터, 현재주소)`만 다시 호출하면 끝입니다. 정점/텍스처는 그대로인데 샘플러만 바꿨도 그림이 완전히 달라집니다.
윈도우 제목에 현재 조합이 표시되므로 무엇을 보고 있는지 헷갈리지 않습니다.

## 6. 정리

- 샘플링 = 텍스처에서 색 읽기, 필터링 = 없는 색 지어내기
- **Point** = 가장 가까운 1개 (뚜렷, 도트) / **Linear** = 주변 4개 평균 (부드러움)
- **Wrap** = 반복 / **Clamp** = 가장자리 고정 / **Mirror** = 뒤집으며 반복
- 샘플러는 상태 객체다. 한 번 만들어 캡시하고 갈아끼우며 쓴다. — sgf의 `SetSampler`가 이 패턴을 보여줍니다.

다음 장(16번)에서는 "이미 그려진 화면 위에 새 그림을 어떻게 포개는가" — 블렌딩을 배웁니다.

## 부록: Before/After 비교 뷰

이 튜토리얼은 화면을 세로로 반으로 잘라 샘플러 설정의 차이를 한 화면에서 비교할 수 있도록 되어 있습니다.

| 구분 | 위치 | 내용 |
|---|---|---|
| **Before** | 노란 경계선 왼쪽 | 항상 Point + Wrap (기준) |
| **After** | 노란 경계선 오른쪽 | 키로 선택한 필터/주소 모드 |

### 어떻게 구현했나요?

- 샘플러를 **두 슬롯에 동시에 바인딩**합니다. s0 = Point+Wrap(기준), s1 = 선택한 설정.
- 상수 버퍼 `CbSplit`으로 경계 픽셀 x좌표를 넘기고, 픽셀 셰이더가 `SV_Position.x`를 경계와 비교해 s0/s1 중 하나로 샘플링합니다.
- 경계 근처 픽셀은 노란색으로 칠해 구분선을 그립니다.

### 관찰 포인트

- Linear를 선택하면 경계를 기준으로 왼쪽은 계단처럼 각진 픽셀, 오른쪽은 부드럽게 섞인 픽셀이 한 장면에 동시에 보입니다.
- Clamp/Mirror를 선택하면 UV가 1을 넘는 영역에서 왼쪽(Wrap, 반복)과 오른쪽(늘어짐/거울)의 차이가 극명하게 드러납니다.
- 필터링은 "텍스처 픽셀과 화면 픽셀이 1:1이 아닐 때 색을 어떻게 결정하느냐"의 문제라는 것을 기억하세요.
