# 27. 그림자 매핑 — "빛의 입장에서 안 보이는 곳이 그림자"

> 관련 코드: `Projects/sgfr/Sources/sgfr/27_ShadowMapping/27_ShadowMapping_Main.cpp`, `27_ShadowMapping_Function.cpp`
> 실행: sgfr 실행 후 콘솔 메뉴에서 27번 선택 (창이 뜨면 ESC로 종료)
> 선행 학습: `14_라이팅.md`, `25_렌더_타깃.md`, `26_포스트_프로세싱.md`

## 1. 이 장에서 배우는 것

그림자의 핵심 원리인 **"빛의 입장에서 안 보이는 곳이 그림자"**를 2패스(빛 시점 깊이 기록 → 카메라 시점 깊이 비교)로 구현합니다. 깊이 전용 렌더 타깃(섀도우 맵), 그림자 여드름(acne)과 바이어스, 방향광(태양)에 어울리는 직교 투영까지 — 실무 게임의 그림자 시스템과 같은 구조입니다.

## 2. 실행하면 보이는 것

바닥 위에서 회전하는 주황색 큐브가 보입니다. 화면은 노란 세로선으로 나뉘어 있습니다.

- **왼쪽(Before)**: 그림자 판정이 없는 세상 — 라이팅(램버트 확산광)만 있습니다. 큐브가 바닥에 붙어 있는지 공중에 떠 있는지 구분이 안 됩니다.
- **오른쪽(After)**: 그림자 매핑 적용 — 큐브의 그림자가 바닥에 드리워집니다. 큐브의 높이가 즉시 느껴집니다.

조작법:

- `←`/`→`: 태양(빛) 방향 회전 — 오른쪽의 그림자만 반대편으로 이동합니다.
- `↑`/`↓`: 바이어스 증감 (0 ~ 0.01) — **0으로 내리면 오른쪽 표면에 줄무늬(그림자 여드름)가 생깁니다.**

콘솔 핵심 문장:

```
[그림자 매핑(Shadow Mapping)의 핵심 아이디어]
 "빛의 입장에서 보이지 않는 곳이 그림자다!"
```

## 3. 핵심 개념 — 비유로 먼저 이해하기

### 3-1. 벽의 높이를 "레이저 측정기"로 기록한다

손전등(빛)을 벽에 비추면 손이 닿는 곳은 밝고, 물체가 막고 있는 곳은 어둡습니다. 그림자 매핑은 이 상황을 **수치화**한 것입니다.

1. **패스 1 — 측정**: 빛의 위치에 카메라를 놓고, "빛이 처음 닿은 표면까지의 거리(깊이)"를 텍스처에 기록합니다. 이 텍스처가 **섀도우 맵(그림자 맵)**입니다. (벽 지도에 손전등 도달 거리를 메모한 것)
2. **패스 2 — 판정**: 보통 카메라로 그리면서, 각 픽셀에 대해 "내 위치를 빛 시점으로 재계산했을 때, 내 깊이가 섀도우 맵에 기록된 깊이보다 **더 먼가**?"를 묻습니다. 더 멀다면 = 빛이 나한테 도달하기 전에 다른 물체에 막혔다 = **그림자**!

### 3-2. 방향광(태양)은 직교 투영

태양은 지구에서 봤을 때 무한히 멀리 있습니다. 그래서 모든 광선은 서로 평행합니다. 평행 광선을 받는 장면은 사람 눈의 원근법과 달리 **직교 투영(Orthographic)**으로 보입니다 — 멀어도 크기가 안 줄어듭니다. 그래서 섀도우 맵 패스에는 `mat4::OrthographicOffCenterLH`를 씁니다.

### 3-3. 그림자 여드름(Shadow Acne)과 바이어스

그림자 맵은 픽셀 단위로 깊이를 기록하므로 해상도가 한정됩니다. **자기 자신의 표면**이 기록된 깊이와 약간 다르게 계산될 수 있는데, 이때 자기 자신이 자신을 가렸다고 오판해서 줄무늬 얼룩(여드름)이 생깁니다.

해결책: 깊이 비교에 **작은 여유(바이어스)**를 둡니다. "내 깊이에서 바이어스를 뺀 값이 기록 깊이보다 커야 그림자"라고 비교하면, 오차만큼은 봐줍니다. 단, 바이어스가 너무 크면 그림자가 물체에서 떨어져 보입니다(피터 패닝). 튜토리얼에서는 ↑/↓로 이 균형을 직접 조절해봅니다.

## 4. 초보자 용어 사전

| 용어 | 뜻(쉬운 말) | 비유 |
|---|---|---|
| 섀도우 맵 (Shadow Map) | 빛 시점에서 기록한 깊이 텍스처 | 손전등 도달 거리 지도 |
| 깊이 전용 렌더 타깃 | 색 없이 깊이만 담는 텍스처 | 밝기가 아닌 거리만 적는 지도 |
| 여드름 (Acne) | 자기 표면 오차로 생기는 줄무늬 얼룩 | 복사기 이중 인쇄로 번진 글자 |
| 바이어스 (Bias) | 깊이 비교에 주는 작은 여유 | 자를 잴 때 두는 여유분 |
| 직교 투영 (Orthographic) | 원근감 없는 투영. 멀어도 크기 동일 | 건축 설계도 |
| 방위각 (Azimuth) | 지평면에서 본 회전 각도 | 나침반 각도 |
| NDC→UV 변환 | -1~+1을 0~1로 옮기는 공식 (y는 뒤집음) | 지도를 화면 판 위에 옮겨 붙이기 |
| WVP | 월드×뷰×투영 합성 행렬 | 위치 → 화면 좌표 한 번에 변환 |

## 5. 코드 워크스루

### 5-1. 깊이 전용 렌더 타깃

```cpp
RenderTarget shadowMap;
if (!shadowMap.CreateDepthOnly(&device, 1024, 1024))
```

`CreateDepthOnly`는 **색 텍스처(RTV) 없이 깊이 텍스처(DSV)만** 만듭니다. 1024x1024는 그림자 경계가 선명한 정도와 메모리 비용의 절충입니다. 내부적으로 깊이 텍스처를 TYPELESS 포맷으로 만들어 **DSV로는 D32_FLOAT(깊이 기록), SRV로는 R32_FLOAT(깊이 읽기)**로 해석합니다 — "같은 메모리, 다른 관점"입니다.

### 5-2. 지오메트리: 바닥 + 법선 큐브

- `FillGroundPlane(planeVertices, planeIndices, 3.0f)`: 위를 바라보는 바닥 사각형 (정점 4 + 인덱스 6)
- `FillShadowCube(cubeVertices, cubeIndices)`: **면별 법선**을 가진 큐브 (정점 24 + 인덱스 36)

큐브는 `AddFace` 람다로 6면을 만들며, 면마다 4개의 정점을 (중심점 + 위/오른쪽 접선벡터 조합)으로 생성합니다. 면별 법선은 라이팅에서 각 면이 서로 다른 밝기를 갖게 하는 데 필요합니다 (13~14번 복습).

### 5-3. 셰이더 2종 + 상수 버퍼 3종

- `ShadowDepthShaderSource()`: CbDepth(b0)의 빛 WVP로 **깊이만 기록** — PS는 반환값을 버립니다.
- `ShadowSceneShaderSource()`: t0=섀도우 맵, b0=CbScene, b1=CbLight.

```cpp
// HLSL의 CbLight(b1)와 일치 (48바이트 = 16의 배수)
struct CbLight
{
	vec3 lightDir_;		// 빛이 나아가는 방향
	_f32 shadowBias_;	// 그림자 여드름 방지 보정값
	vec4 baseColor_;	// 물체 기본색
	_f32 splitPixelX_;	// Before/After 경계 픽셀 x
	_f32 padding_[3];
};
```

### 5-4. 빛의 뷰/투영 행렬 계산

```cpp
const vec3 lightDir = vec3(cosf(lightAzimuth), -1.2f, sinf(lightAzimuth)).Normalized();
const vec3 lightPos = lightDir * -8.0f;	// 빛을 거슬러 올라간 가상 위치
const mat4 lightView = mat4::LookAtLH(lightPos, vec3::Zero(), vec3::Up());
const mat4 lightProj = mat4::OrthographicOffCenterLH(-4.0f, 4.0f, -4.0f, 4.0f, 0.1f, 20.0f);
const mat4 lightViewProj = lightView * lightProj;
```

- `lightAzimuth`를 돌리면 빛 방향이 바뀌고(←/→), `lightDir * -8`로 빛이 **내려오는 방향 뒤**에 가상 카메라를 둡니다.
- 방향광이라 직교 투영입니다: `OrthographicOffCenterLH(-4,4,-4,4,0.1,20)`은 x,y를 -4~4, 깊이를 0.1~20으로 잡은 상자입니다.

### 5-5. 패스 1 — 빛 시점에서 깊이만 기록

```cpp
device.SetRenderTarget(&shadowMap);
shadowMap.Clear(&device, color::BLACK);	// 깊이 전용이므로 깊이만 1.0으로 초기화된다

depthShader.Bind(&device);
...
cbD.lightWvp_ = planeWorld * lightViewProj;	// 바닥도 깊이에 포함!
cbDepth.UpdateAndBind(&device, cbD, 0);
planeVb.Bind(&device); planeIb.Bind(&device);
device.Context()->DrawIndexed(6, 0, 0);

cbD.lightWvp_ = cubeWorld * lightViewProj;
cbDepth.UpdateAndBind(&device, cbD, 0);
... DrawIndexed(36, 0, 0);
```

- `shadowMap.Clear(color::Black())`은 깊이를 1.0(=가장 먼 곳)으로 초기화합니다. 색이 없으므로 색 인자는 무시됩니다.
- **바닥도 깊이에 포함**시키는 것이 포인트입니다. 바닥 근처의 다른 물체가 바닥에 그림자를 드리우게 하려면 바닥의 깊이도 섀도우 맵에 있어야 합니다.
- 깊이 전용 셰이더의 PS는 렌더 타깃이 없으므로 출력이 버려집니다. **깊이는 래스터라이저가 자동으로 기록**합니다.

### 5-6. 패스 2 — 카메라 시점으로 그리며 그림자 판정

### 5-7. 그림자 판정 셰이더 — 핵심 코드

```hlsl
float3 N = normalize(_input.normal);
float3 L = normalize(gLightDir);
float diffuseAmount = saturate(dot(N, -L));	// 1) 기본 라이팅 (14번의 램버트)

float shadow = 1.0f;
if (_input.position.x >= gSplitPixelX)		// [After] 오른쪽만 판정
{
	// 투영 좌표 -> NDC (원근 투영이면 w 나누기 필수)
	float3 ndc = _input.lightSpacePos.xyz / _input.lightSpacePos.w;

	// NDC(-1~+1) -> 텍스처 UV(0~1). y는 뒤집는다!
	float2 shadowUv = float2(ndc.x * 0.5f + 0.5f, -ndc.y * 0.5f + 0.5f);

	if (shadowUv.x >= 0.0f && shadowUv.x <= 1.0f &&
		shadowUv.y >= 0.0f && shadowUv.y <= 1.0f &&
		ndc.z >= 0.0f && ndc.z <= 1.0f)
	{
		float storedDepth = gShadowMap.Sample(gShadowSampler, shadowUv).r;

		// 내 깊이가 기록된 깊이보다 더 멀다 = 그늘진 곳!
		if (ndc.z - gShadowBias > storedDepth)
		{
			shadow = 0.35f;
		}
	}
}

// 3) 최종색 = 주변광 + 확산광 x 그림자 계수
float3 color = 0.15f * gBaseColor.rgb + diffuseAmount * shadow * gBaseColor.rgb;
```

주목할 포인트:

1. **NDC → UV 변환에서 y를 뒤집어야** 합니다. NDC는 y 위쪽 +, 텍스처 v는 아래쪽 +이기 때문입니다. `v = 1 - ndc.y` 형태로 `-ndc.y * 0.5 + 0.5`를 씁니다. 이것을 빼먹으면 그림자가 상하로 뒤집혀서 전혀 맞지 않습니다.
2. **바이어스 비교**: `ndc.z - gShadowBias > storedDepth` — 내 깊이에서 여유분을 뺀 뒤 비교합니다.
3. 범위 밖 픽셀(섀도우 맵 밖)은 그림자 판정을 건너뜁니다.
4. `gSplitPixelX`는 픽셀의 화면 x좌표(`SV_POSITION`)와 비교해 왼쪽 절반은 판정 블록 자체를 생략합니다 — Before/After 분할의 핵심입니다.

## 6. GPU와 DX11, 하드웨어 깊이 보기

### 6-1. 깊이 전용 렌더링이 하드웨어에서 도는 법

패스 1은 "색을 쓰지 않는" 패스입니다. D3D11에서 RTV 없이 DSV만 OM에 묶으면(`OMSetRenderTargets(0, nullptr, pDSV)`), GPU는 여전히 전체 파이프라인(IA→VS→래스터라이저→PS→OM)을 실행합니다.

- **VS**는 `mul(position, gLightWvp)`로 빛 시점 클립 좌표를 만듭니다. 이 좌표의 z 성분이 나중에 깊이 버퍼에 기록될 값입니다 (원근 투영이면 w로 나눈 NDC z).
- **래스터라이저**는 각 삼각형을 픽셀로 쪼갭니다. 여기서 **다각형 오프셋(polygon offset)** 같은 상태도 적용 가능합니다 (D3D11의 `DepthBias`).
- **OM/ROP**: 픽셀별로 깊이 테스트를 수행하고, 통과한 픽셀은 **깊이 버퍼에 z를 기록**합니다. 색 기록이 없으므로 ROP의 색 쓰기 유닛은 비활성화됩니다. 메모리 대역폭 측면에서 색 쓰기(32비트)가 빠지므로 오히려 깊이 전용 패스는 저렴합니다.
- **PS**: 렌더 타깃이 없으므로 PS의 반환값은 버려집니다. 이 셰이더의 PS는 그냥 0(`float4(0,0,0,1)`)을 반환합니다. 최신 GPU는 PS 출력이 필요 없음을 알면 픽셀 셰이더 전체를 생략할 수도 있지만, 보수적으로 PS 스텁을 실행하는 것이 일반적입니다.

하드웨어 레벨의 깊이 처리에 관한 디테일: GPU는 **초기 깊이 테스트(Early-Z)**를 픽셀 셰이더 실행 *전에* 수행할 수 있어서, 나중에 그려질 픽셀이 이미 덮인 영역이면 PS 실행 자체를 건너뜁니다. 섀도우 맵 패스는 단일 오브젝트(큐브/바닥)만 그리므로 이 이점은 크지 않지만, 복잡한 장면의 섀도우 맵 생성에서는 이 기법이 큰 성능 차이를 만듭니다.

### 6-2. 깊이 텍스처의 포맷 — D32_FLOAT와 R32_FLOAT

`CreateDepthOnly`는 내부적으로 깊이 텍스처를 `DXGI_FORMAT_R32_TYPELESS`(해석 미정 32비트) 포맷으로 만들고:

- DSV: `DXGI_FORMAT_D32_FLOAT` — 깊이 저장 전용 해석
- SRV: `DXGI_FORMAT_R32_FLOAT` — 셰이더가 "32비트 실수 1채널 텍스처"로 읽는 해석

TYPELESS 포맷은 메모리 레이아웃은 그대로 두고 해석만 바꾸는 D3D11의 기능입니다. 하드웨어에서 D32_FLOAT 깊이 버퍼는 32비트 부동소수점 저장 유닛에, R32_FLOAT 텍스처 읽기는 텍스처 유닛이 처리합니다. "깊이 버퍼를 셰이더로 읽는다"는 것이 D3D11에서 이렇게 표현됩니다 (D3D9 시절에는 이 조합이 사실상 불가능해 셰도우 맵 구현이 고생스러웠습니다).

### 6-3. Point + Clamp 샘플러를 써야 하는 이유

섀도우 맵은 **깊이 값**이지 색이 아닙니다. Linear(이중선형) 필터로 이웃 2x2 텍셀을 평균하면 "두 깊이의 중간"이라는 **물리적으로 존재하지 않는 깊이**가 만들어집니다. 그 중간값은 그림자 경계를 부드럽게 하는 게 아니라 **그림자 자체를 잘못 판정**하게 만듭니다.

- `fmPoint`: 가장 가까운 텍셀 하나만 읽습니다 → 깊이 값이 정확히 보존됩니다.
- `amClamp`: UV가 0~1을 넘으면(섀도우 맵 밖) 가장자리 텍셀로 고정합니다. Wrap(반복)이면 멀리 있는 픽셀들이 반대편 깊이와 비교되어 **엉뚱한 그림자가 생깁니다.**

하드웨어에서 Point 필터는 1개 텍셀 읽기로 끝나므로 텍스처 캐시 트래픽이 가장 낮습니다. 다만 경계가 픽셀 단위로 각질 수 있는데, 실무에서는 PCF(퍼센트 클로즈 필터링, 2x2/3x3 Point 샘플을 비교해서 섞는 방법)를 써서 부드럽게 만듭니다 — 이 튜토리얼은 개념에 집중하기 위해 단순화했습니다.

### 6-4. 그림자 판정 픽셀 셰이더의 연산

패스 2의 픽셀 셰이더는 픽셀마다:

1. `lightSpacePos / w` — 나눗셈 3회 (4벌 부동소수점 유닛)
2. UV 변환 — 곱셈/덧셈
3. `Sample` — 텍스처 캐시 접근 + Point 필터 (LOD 계산 포함)
4. 비교 1회 + 조건부 분기

보간된 `lightSpacePos`는 VS에서 계산된 후 삼각형 내부에서 **선형 보간**됩니다. 원근 투영에서는 위치 보간이 w-나눗셈 전 클립 좌표로 수행되므로 `lightSpacePos.xyz/lightSpacePos.w`가 필요한 것이고, 직교 투영에서는 w=1이라 사실상 생략 가능하지만 코드는 공통 처리를 유지합니다(주석에 명시).

분기(`if`)는 GPU에서 **동적 분기**로 처리됩니다. 셰이더 유닛(32~64개 랜스)에서 모든 픽셀이 같은 경로(그림자 없음)를 타면 하나의 흐름으로 실행되어 매우 빠르고, 그림자 경계 부근처럼 서로 다른 경로가 섞이면 분기 비용이 조금 발생합니다.

### 6-5. 1024x1024 섀도우 맵의 메모리/성능

- 크기: 1024x1024 x 4바이트 = 4MB (VRAM)
- 쓰기: 패스 1에서 매 프레임 4MB 깊이 기록 (Clear 포함)
- 읽기: 패스 2에서 화면 픽셀 수만큼의 캐시된 샘플

해상도를 2048로 올리면 메모리는 4배(16MB)가 되고, 그림자 경계는 두 배로 선명해집니다. 실무에서는 장면의 깊이 범위를 잘게 쪼개는 CSM(Cascaded Shadow Maps)으로 정밀도를 높입니다 — 구조 자체는 이 장과 같습니다.

### 6-6. D3D11 API 대응표

| sgf API | D3D11 API | 하드웨어 |
|---|---|---|
| `CreateDepthOnly(1024,1024)` | `CreateTexture2D(TYPELESS)` + `CreateDepthStencilView` + `CreateShaderResourceView` | 깊이 전용 VRAM |
| `SetRenderTarget(&shadowMap)` | `OMSetRenderTargets(0, nullptr, DSV)` | ROP 깊이 기록 모드 |
| `shadowMap.Clear(Black)` | `ClearDepthStencilView` | 깊이 1.0 채우기 |
| `SetSampler(fmPoint, amClamp)` | `PSSetSamplers` | Point 필터 하드웨어 |
| `shadowMap.BindAsTexture` | `PSSetShaderResources` | 깊이 텍스처 → 셰이더 읽기 |

## 7. 핵심 규칙 요약

- 그림자 = **"빛의 입장에서 안 보이는 곳"** — 2패스(깊이 기록 → 깊이 비교)로 구현.
- 깊이 전용 렌더 타깃은 RTV 없이 DSV만 쓴다. PS 출력은 버려지고 깊이는 래스터라이저가 기록 (`CreateDepthOnly`).
- 섀도우 맵은 **Point + Clamp** 샘플러만 사용 (깊이 보존; Linear는 허상 깊이를 만든다).
- NDC → UV 변환: `u = ndc.x*0.5+0.5`, `v = -ndc.y*0.5+0.5` (**y 뒤집기 필수**).
- 그림자 판정: `ndc.z - bias > storedDepth` → 그늘 (0.35 배율).
- 바이어스 0이면 여드름 발생, 너무 크면 피터 패닝(그림자 분리).
- 방향광(태양)은 무한 원점 → **직교 투영** (`OrthographicOffCenterLH`).
- 바닥도 깊이 패스에 포함시켜야 바닥 위 물체들이 서로 그림자를 주고받는다.
