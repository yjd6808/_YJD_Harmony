# 05. 렌더링 파이프라인 — 화면에 첫 삼각형 그리기

> 관련 코드: `Projects/sgfr/Sources/sgfr/05_RenderingPipeline/` (`05_RenderingPipeline_Main.cpp`, `05_RenderingPipeline_Function.cpp`)
> 관련 엔진: `Projects/sgf/Sources/sgf/Graphics/Vertex.h`, `Buffers.h`, `Shader.h`
> 실행: sgfr 실행 후 콘솔 메뉴에서 **5번** 선택
> 선행 학습: 01. 선형대수, 04. 디바이스와 스왑체인

## 1. 이 장에서 배우는 것

정점 데이터가 화면의 픽셀이 되기까지 거치는 GPU의 조립 라인, **렌더링 파이프라인(IA → VS → RS → PS → OM)**의 5단계를 이해하고, 최소 구성(정점 3개 + 정점 버퍼 + 셰이더 + Draw)으로 첫 삼각형을 그립니다. 정점 색이 삼각형 내부에서 부드럽게 섞이는 **래스터라이저의 보간** 현상도 눈으로 확인합니다.

## 2. 실행하면 보이는 것

콘솔에 NDC 좌표계 설명이 먼저 출력된 뒤, CornflowerBlue(연보라-파랑) 배경의 800×600 창이 뜹니다. 화면 중앙에 **위는 빨강, 오른쪽 아래는 파랑, 왼쪽 아래는 초록** 꼭짓점을 가진 삼각형이 보입니다. 세 꼭짓점 색이 서로를 향해 부드럽게 섞이는 그라데이션이 특징입니다. ESC로 종료합니다.

## 3. 핵심 개념 — 비유로 먼저 이해하기

### 3-1. 파이프라인 = 공장의 컨베이어 벨트

렌더링 파이프라인은 자동차 공장의 컨베이어 벨트와 같습니다. 벨트 위의 물건(정점/픽셀)은 정해진 순서로 여러 작업대를 통과합니다:

1. **IA (Input Assembler)** — 정점 창고(정점 버퍼)에서 정점을 꺼내 삼각형으로 묶는다.
2. **VS (Vertex Shader)** — 정점 하나마다 실행. 위치를 변환한다.
3. **RS (Rasterizer)** — 삼각형이 덮는 픽셀을 찾고, 정점 속성을 픽셀마다 보간한다.
4. **PS (Pixel Shader)** — 픽셀 하나마다 실행. 최종 색을 계산한다.
5. **OM (Output Merger)** — 깊이 테스트/블렌딩을 거쳐 백버퍼에 기록한다.

이번 장은 이 5개 작업대가 처음으로 모두 가동되는 날입니다.

### 3-2. NDC = 화면 크기와 무관한 공용 좌표계

화면이 800×600이든 1920×1080이든, GPU는 항상 **NDC(Normalized Device Coordinates)**라는 좌표계로 일을 합니다. NDC는 가로/세로 -1~+1인 좌표계로, 중앙이 (0,0), 오른쪽 위가 (+1,+1), 왼쪽 아래가 (-1,-1)입니다. 이번 장은 정점을 NDC에 직접 적어서 변환 없이 통과시킵니다. 나중에 행렬 변환(10번)을 배우면 물체 좌표를 이 NDC로 바꾸는 일을 셰이더가 맡게 됩니다.

### 3-3. 시계 방향 = 앞면 (백페이스 컬링)

종이학을 접을 때 접힌 방향을 봐야 앞면을 구분하듯, GPU는 정점이 **어떤 방향으로 감기는지**로 면의 앞/뒤를 판정합니다. DX11의 기본 규칙은 "반시계 방향(CCW) 삼각형은 뒷면이라 안 그린다"입니다. 그래서 이 튜토리얼의 정점은 **시계 방향(CW)** 순서로 적습니다. 뒷면을 미리 걸러내는 것을 **백페이스 컬링(Back-face Culling)**이라 하며, 드로우 부하를 절반 가까이 줄여줍니다.

### 3-4. 정점 버퍼 = GPU 창고에 물건 옮기기

CPU의 배열(우리가 만든 `vertices[]`)은 GPU가 직접 읽을 수 없습니다. 서로 다른 메모리 공간(CPU RAM vs GPU VRAM)에 살기 때문입니다. 그래서 `VertexBuffer::Create`가 데이터를 GPU 메모리로 복사합니다. 이것은 학교 매점의 물건을 학교 창고로 옮기는 것과 같아서, 딱 한 번만 옮기면 이후에는 GPU가 창고에서 바로 꺼내 씁니다.

## 4. 초보자 용어 사전

| 용어 | 뜻(쉬운 말) | 비유 |
|---|---|---|
| 파이프라인 (Pipeline) | 정점→픽셀까지의 고정 작업 순서 | 공장 컨베이어 벨트 |
| IA | 정점 버퍼에서 정점을 꺼내 조립 | 창고 출고대 |
| VS (Vertex Shader) | 정점마다 실행되는 작은 프로그램 | 정점별 검사원 |
| RS (Rasterizer) | 삼각형을 픽셀로 바꾸고 색을 보간 | 도장 찍는 기계 |
| PS (Pixel Shader) | 픽셀마다 최종 색 계산 | 픽셀별 화가 |
| OM (Output Merger) | 깊이/블렌딩 후 백버퍼 기록 | 최종 도장/제출 부서 |
| NDC | -1~+1 공용 좌표계 | 모든 화면의 공통 자 |
| 백페이스 컬링 | 뒷면(CCW) 삼각형 안 그림 | 뒤집힌 면 걸러내기 |
| 입력 레이아웃 | C++ 구조체와 HLSL 입력의 연결 설명서 | 택배 라벨 |
| 정점 버퍼 (VB) | GPU 메모리에 있는 정점 배열 | GPU 창고의 물건 |
| 시맨틱 (Semantic) | 변수의 역할 꼬리표 (POSITION 등) | 이름표 |
| 보간 (Interpolation) | 사이 값을 거리 비율로 섞기 | 물감 섞기 |

## 5. 코드 워크스루

`05_RenderingPipeline_Main.cpp`의 `RenderingPipeline_Main()`을 따라갑니다.

### 5-1. NDC 설명 출력 (코드 36행)

`PrintNdcExplanation()`(Function.cpp)가 콘솔에 NDC 좌표계의 규칙을 출력합니다.

### 5-2. 창/디바이스 준비 (코드 39~55행)

02·04번에서 배운 그대로입니다. `Window::Create`, `ConnectInput`, `device.Initialize(HWND, w, h)`.

### 5-3. 정점 3개 정의 (코드 60~64행) — 시계 방향 주의

```cpp
const VertexPC vertices[] = {
	{ vec3(0.0f,  +0.5f, 0.0f), color(1.0f, 0.0f, 0.0f, 1.0f) },	// 위   (빨강)
	{ vec3(+0.5f, -0.5f, 0.0f), color(0.0f, 0.0f, 1.0f, 1.0f) },	// 오른쪽아래 (파랑)
	{ vec3(-0.5f, -0.5f, 0.0f), color(0.0f, 1.0f, 0.0f, 1.0f) },	// 왼쪽아래  (초록)
};
```

`VertexPC`는 `위치(vec3, 12바이트) + 색(color, 16바이트)` 구조체로, 총 28바이트입니다. 위→오른아래→왼아래 순서는 시계 방향이라 앞면으로 인정됩니다. NDC 좌표이므로 변환 없이 바로 그릴 수 있습니다.

### 5-4. 정점 버퍼 생성 (코드 68~75행)

```cpp
VertexBuffer vb;
if (!vb.Create(&device, vertices, sizeof(VertexPC), 3))
```

`Create(&device, 데이터, stride(정점 1개 바이트), 개수)`가 GPU 메모리로 데이터를 복사합니다.

### 5-5. 셰이더 컴파일 + 입력 레이아웃 (코드 80~90행)

```cpp
UINT layoutCount = 0;
const D3D11_INPUT_ELEMENT_DESC* pLayoutDescs = VertexPC::LayoutDescs(&layoutCount);

Shader shader;
if (!shader.CompileFromString(&device, TriangleShaderSource(), pLayoutDescs, layoutCount))
```

`VertexPC::LayoutDescs`(Vertex.h)는 C++ 구조체의 메모리 배치를 설명하는 배열입니다:

```cpp
{ "POSITION", 0, DXGI_FORMAT_R32G32B32_FLOAT,    0, 0,  D3D11_INPUT_PER_VERTEX_DATA, 0 },
{ "COLOR",    0, DXGI_FORMAT_R32G32B32A32_FLOAT, 0, 12, D3D11_INPUT_PER_VERTEX_DATA, 0 },
```

즉 "0바이트부터 12바이트는 POSITION, 12바이트부터 28바이트는 COLOR"라고 GPU에 알려줍니다. `Shader::CompileFromString`은 HLSL 소스를 런타임에 컴파일해 VS/PS/입력 레이아웃 객체를 만듭니다.

### 5-6. 셰이더 소스 (Function.cpp의 TriangleShaderSource)

```hlsl
struct VSInput
{
	float3 position : POSITION;   // VertexPC::position_
	float4 color    : COLOR0;     // VertexPC::color_
};

VSOutput VSMain(VSInput _input)
{
	VSOutput output;
	output.position = float4(_input.position, 1.0f);	// w=1 동차 좌표, 변환 없이 통과
	output.color = _input.color;
	return output;
}

float4 PSMain(VSOutput _input) : SV_TARGET
{
	return _input.color;
}
```

- `SV_POSITION` — "이 값이 클립 공간 좌표다"라고 GPU에 알리는 특별한 시맨틱.
- `float4(position, 1.0f)` — 01번에서 배운 동차 좌표의 w=1 사용.
- 정점 색의 보간은 PS가 아니라 **래스터라이저가 해주며**, PS는 이미 섞인 색을 받아 그대로 출력합니다.

### 5-7. 렌더 루프 — 그리기 순서 (코드 103~120행)

```cpp
device.BeginFrame(color::CornflowerBlue());

vb.Bind(&device);	// (1) 정점 버퍼를 IA 단계에 묶기
shader.Bind(&device);	// (2) VS/PS/입력레이아웃 장착
device.Context()->IASetPrimitiveTopology(D3D11_PRIMITIVE_TOPOLOGY_TRIANGLELIST);	// (3) 삼각형 해석
device.Context()->Draw(3, 0);	// (4) "정점 3개를 0번부터 사용해 그려라" — 파이프라인 가동!

device.EndFrame(true);
```

그리기 순서의 암기 문장: **"무엇을(VB), 어떻게(Shader), 어떤 모양으로(Topology)"** 설정 후 Draw. `Draw(3, 0)` 한 줄이 위의 모든 설정을 가지고 IA→VS→RS→PS→OM 전체를 가동시킵니다.

### 5-8. 정리 (코드 124~125행)

`device.Finalize()` → `window.Destroy()`. `VertexBuffer`/`Shader`는 소멸자에서 ComPtr이 자동으로 해제됩니다.

### 사용된 sgf API 정리

| API | 역할 |
|---|---|
| `VertexPC::LayoutDescs(&count)` | 정점 구조체 메모리 배치 설명서 |
| `VertexBuffer::Create(&device, data, stride, count)` | 정점 버퍼 생성 (GPU 복사) |
| `VertexBuffer::Bind(&device)` | IA 슬롯 0에 장착 |
| `Shader::CompileFromString(&device, hlsl, layoutDescs, count)` | HLSL 컴파일 + VS/PS/레이아웃 생성 |
| `Shader::Bind(&device)` | VS/PS/입력레이아웃 파이프라인 장착 |
| `device.Context()->IASetPrimitiveTopology(...)` | 토폴로지 설정 (원시 D3D) |
| `device.Context()->Draw(3, 0)` | 정점 3개 그리기 (원시 D3D) |
| `color::CornflowerBlue()` | 배경색 헬퍼 |

## 6. GPU와 DX11, 하드웨어 깊이 보기

### 6-1. IA: 정점 창고에서 프리미티브 조립까지 — 고정기능 하드웨어

Draw 호출이 커맨드 버퍼에 기록되면 GPU의 **고정기능 인풋 어셈블러**가 정점 버퍼를 순회합니다. 이때 `IASetVertexBuffers`로 지정한 stride(28바이트)와 `IASetPrimitiveTopology`가 정점을 묶는 규칙을 정합니다. 하드웨어는 정점 3개를 읽어 삼각형으로 조립하고, 각 정점에 "정점 ID"를 부여합니다. 실제 정점 인출은 **GPU 메모리 시스템(VRAM → L2 → 셰이더 유닛의 L1 캐시)**을 거치며, 같은 정점이 재사용되면 캐시 히트로 성능이 좋아집니다. 이것이 07번 인덱스 버퍼의 하드웨어적 이점과 연결됩니다.

### 6-2. VS: 프로그래머블 셰이더 유닛에서의 실행

VS는 수천 개의 셰이더 코어 중 하나에서 실행되는 작은 프로그램입니다. GPU는 정점들을 **워프(warp, NVIDIA) 또는 웨이브프론트(AMD)**라는 32개 묶음으로 모아 단일 명령으로 병렬 실행합니다(SIMT, Single Instruction Multiple Thread). 이번 VS는 변환이 없어서 실질적으로 "클립 공간 좌표로 내보내는" 역할만 합니다. 클립 공간(clip space)이란 래스터라이저가 카메라 밖 정점을 잘라내기(clipping) 위해 사용하는 좌표 공간입니다. `SV_POSITION`에 담겨 나오는 값이 바로 이 좌표이며, 10·11번에서 행렬을 곱해 세계 좌표→시야→클립 공간으로 바꾸는 실전 변환을 하게 됩니다.

### 6-3. RS: 래스터라이저의 고정기능 유닛과 보간 하드웨어

래스터라이저는 고정기능 하드웨어 유닛으로 다음을 수행합니다.

1. **클리핑** — 화면(클립 공간) 밖으로 나간 삼각형 부분을 잘라냄
2. **백페이스 컬링** — 정점 감김 방향으로 뒷면 판정 후 폐기 (GPU가 유향 삼각형 면적의 부호를 매우 빠르게 계산)
3. **픽셀 생성(스캔 변환)** — 삼각형이 덮는 픽셀들을 찾아 픽셀 중심점 기준으로 내부 판정
4. **속성 보간** — 각 픽셀의 무게중심 좌표(바리센트릭 좌표)를 계산해 세 정점의 색/UV를 거리 비율로 섞음

보간은 하드웨어의 보간기(interpolator)가 수행하며 픽셀마다 거의 무료입니다. 그래서 "빨/초/파 삼각형 사이가 무지개처럼 보이는" 것이 셰이더 코드가 아니라 GPU 고정기능의 연산 결과입니다. 또한 보간된 값은 정수 픽셀 그리드의 부동소수점 좌표로 계산되므로, 정점 색이 픽셀 크기보다 작은 영역에서는 계단 현상이 생길 수 있는데, 이는 나중에 17번 샘플러/텍스처 필터링에서 다루는 주제로 이어집니다.

### 6-4. PS: 픽셀 셰이더 유닛과 SIMT 실행

PS는 삼각형이 덮는 픽셀마다 한 번씩 실행됩니다. 이 튜토리얼 삼각형은 약 0.3 제곱 NDC 면적으로, 800×600 창에서 대략 수천~수만 개의 픽셀을 생성하며, 각 픽셀이 PS를 통과합니다. PS 역시 32개 픽셀 묶음(쿼드 2×2 구성 포함)으로 병렬 실행되며, 픽셀 셰이더의 색 출력은 32비트 RGBA 8비트 포맷(R8G8B8A8_UNORM)으로 백버퍼에 기록됩니다. 색상 값이 0~1 부동소수점에서 0~255 정수로 변환되는 순간이 바로 이 OM 단계입니다.

### 6-5. OM: 아웃풋 머저와 백버퍼 쓰기 — 메모리 대역폭

OM은 PS의 출력 색을 백버퍼에 기록하기 전에 깊이 테스트, 블렌드, 픽셀 포맷 변환을 수행합니다. 이번 튜토리얼은 깊이 테스트가 꺼져 있고 블렌드가 없으므로 단순히 색을 기록합니다. 그럼에도 매 픽셀의 기록은 GPU 메모리 대역폭을 소모하며, 60fps에서 800×600 화면 전체를 매 프레임 다시 쓰면 그것만으로도 초당 약 115MB(800×600픽셀 × 4바이트 × 60프레임)의 쓰기 대역폭이 사용됩니다. 이후 18번 블렌드 상태, 19번 래스터라이저 상태에서 OM의 고정기능 옵션들을 하나씩 켜게 됩니다.

### 6-6. Draw 호출 한 줄이 GPU를 가동시키는 전체 경로

`Draw(3, 0)`는 CPU에서 즉시 실행되지 않습니다. 사용자 모드 드라이버가 커맨드 버퍼에 "IA가 버퍼 슬롯 0에서 stride 28로 3개 정점을 읽어 TRIANGLELIST로 그려라"라는 기록을 추가하고, 이후 `EndFrame(true)`의 Present가 이 커맨드 버퍼를 GPU 커맨드 프로세서에 전송합니다. GPU는 커맨드를 파이프라인 단계별로 실행해 3개의 정점이 수천 개의 픽셀 작업으로 폭발적으로 확장됩니다. CPU(명령 생성)와 GPU(실행)의 비동기 파이프라이닝 덕분에 "Draw 한 줄"의 실제 비용은 미미하며, 진짜 비용은 픽셀 수와 셰이더 복잡도에 비례합니다. 이 균형이 이후 렌더러 최적화(22번 렌더 오브젝트 루프)의 핵심 주제입니다.

### 6-7. 한 걸음 더 — 통합 셰이더와 파이프라인 병렬성

- **통합 셰이더 아키텍처**: 최신 GPU에는 VS 전용/PS 전용 유닛이 따로 없습니다. 하나의 셰이더 코어 풀이 프레임 부하에 따라 정점/픽셀 작업에 동적으로 배분됩니다. 파이프라인의 '스테이지'는 물리 부품이 아니라 역할 이름입니다.

## 7. 핵심 규칙 요약

- [ ] 파이프라인 5단계: IA → VS → RS → PS → OM 순서로 고정.
- [ ] DX11 기본 컬링은 반시계방향(CCW)을 뒷면으로 버림 → 정점은 **시계 방향(CW)**으로.
- [ ] NDC: 가로/세로 -1~+1, 중앙 (0,0). 뷰포트가 픽셀로 매핑.
- [ ] CPU 배열은 GPU가 직접 못 읽음 → `VertexBuffer::Create`로 GPU 메모리 복사 필수.
- [ ] 입력 레이아웃 = C++ 구조체 메모리 배치 ↔ HLSL 입력의 연결 설명서 (시맨틱/오프셋).
- [ ] `SV_POSITION` = 클립 공간 좌표, w=1 동차 좌표로 통과.
- [ ] 정점 색 보간은 PS가 아닌 **래스터라이저**가 수행.
- [ ] 그리기 순서: VB.Bind → Shader.Bind → 토폴로지 → `Draw(3, 0)`.
- [ ] `Draw(3, 0)` = "정점 3개를 0번부터" — 인자 순서 (개수, 시작 정점).
