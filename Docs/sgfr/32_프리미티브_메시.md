# 32. 프리미티브 메시 — 리소스 매니저가 기본 제공하는 단위 도형

> 관련 코드: `Projects/sgfr/Sources/sgfr/32_PrimitiveMesh/32_PrimitiveMesh_Main.cpp` (단일 파일)
> 실행: sgfr 실행 후 콘솔 메뉴에서 32번 선택 (SPACE: 씬 전환, ESC: 종료)
> 선행 학습: `21_리소스_매니저.md`(리소스 매니저/키), `29_씬과_사운드.md`(씬 트리/GameObject), `22_렌더_오브젝트_루프.md`(Renderer3D)

## 1. 이 장에서 배우는 것

리소스 매니저가 **디폴트 리소스로 만들어 둔 프리미티브 메시**를 꺼내 쓰는 법을 배웁니다. `g_cResourceMgr.FindPrimitiveMesh2D/3D` 한 줄이면 사각형/원/삼각형/선(2D)과 큐브/구/캡슐/원기둥/평면/쿼드(3D)를 **직접 버텍스를 만들지 않고** 배치할 수 있습니다. `GameObject`에 `SetMesh`만 하면 렌더 트래버설 중 **자동으로 그려집니다** — 셰이더/머티리얼/GPU 초기화 반복 작업이 사라지는 "메시 자동 드로우"의 시작입니다.

## 2. 실행하면 보이는 것

**씬 1 — 2D 프리미티브**: 검은 배경에 사각형/원/삼각형/선 4종이 정렬되어 있습니다. 창 제목에 **DrawCall: 1**이 표시됩니다 — 도형이 4개인데 GPU 드로우콜은 1번뿐입니다(배칭).

**씬 2 — 3D 프리미티브**: SPACE를 누르면 큐브/구/캡슐/원기둥/평면/쿼드 6종이 일렬로 서 있습니다. 3D 메시는 람버트 조명이 켜진 디폴트 3D 셰이더로 그려져 각 면이 다른 밝기로 보입니다.

```
[32] Primitive2DScene::OnEnter — 2D 프리미티브 4종 배치 완료 (Line: Static bake)
[32] Primitive3DScene::OnEnter — 3D 프리미티브 6종 배치 완료
```

## 3. 핵심 개념 — 비유로 먼저 이해하기

### 3-1. 프리미티브 메시 = "레고 기본 블록"

엔진이 **한 번 만들어 재사용하도록 준비해 둔** 단위 도형 메시입니다. 레고 세트에 기본 블록이 동봉되어 있듯, `ResourceMgr::CreateDefaults`가 초기화 시점에 2D 4종 + 3D 6종을 미리 만들어 **키 테이블**에 등록해 둡니다. 사용자는 매번 큐브 버텍스 24개를 손으로 만들 필요 없이 `FindPrimitiveMesh3D(PrimitiveMesh3DType::Cube)`로 꺼내 씁니다.

- **2D 4종**: Rect(1×1 사각형), Circle(반지름 1 원), Triangle(단위 삼각형), Line(가로 1·두께 1 선분) — `VertexPTC`(위치+UV+색), 2D 배칭용.
- **3D 6종**: Cube(1×1×1), Sphere(반지름 1), Capsule(반지름 0.5·높이 2), Cylinder(반지름 1·높이 2), Plane(XY 1×1, +Z 향), Quad(XY 1×1, +Z 향) — `VertexPNT`(위치+법선+UV), 3D 조명용.

### 3-2. 2D/3D 엄격 분리 = "레고 블록과 테크닉 부품은 따로"

2D enum(`PrimitiveMesh2DType`)과 3D enum(`PrimitiveMesh3DType`)은 **완전히 분리**되어 있습니다. 2D enum으로 3D 메시를 얻거나 그 반대는 **컴파일 타임에 불가능**합니다. enum에 없는 타입을 넘기면 아예 컴파일되지 않으므로, "실수로 2D 렌더러에 3D 메시를 꽂는" 실수를 원천 차단합니다.

### 3-3. SetMesh = "자동 조립 라인에 부품 올리기"

`GameObject`에 `SetMesh(pMesh)`를 호출하면, 이후 렌더 트래버설 중 **씬이 자동으로 그립니다**. 그리기 코드를 작성할 필요가 없습니다. 3D는 재질에 셰이더 키가 있어야 하므로 2D와 달리 `SetVertexShaderKey/SetPixelShaderKey`로 디폴트 3D 셰이더를 지정하고 `Material::Initialize`로 GPU 상태를 만듭니다 — 이 "반복 4줄"을 감춘 것이 다음 장(33번)의 Shape3D입니다.

## 4. 초보자 용어 사전

| 용어 | 뜻(쉬운 말) | 비유 |
|---|---|---|
| 프리미티브 메시 | 엔진이 기본 제공하는 단위 도형 메시 | 레고 기본 블록 |
| 디폴트 리소스 | ResourceMgr가 초기화 시 미리 만들어 둔 리소스 | 동봉된 부품 |
| 키 테이블 | 프리미티브 타입 → 메시 키 매핑 배열 | 부품 카탈로그 |
| 메시 자동 드로우 | SetMesh만 하면 트래버설 중 자동으로 그려짐 | 자동 조립 라인 |
| 2D/3D 엄격 분리 | 타입별 enum 분리 — 교차 사용은 컴파일 불가 | 블록과 테크닉 부품 분리 |
| baseColor | 머티리얼의 단색 채움색 (b2 상수) | 물감의 기본색 |
| 배칭 (Batching) | 여러 도형을 한 번의 드로우콜로 그리기 | 택배 여러 개를 한 차에 싣기 |

### 5-1. 씬 1 — 2D 프리미티브 4종

```cpp
void OnEnter() override
{
	GetCamera2D()->SetOrthographic2D(VIEW_WIDTH, VIEW_HEIGHT);
	GetWindow()->SetTitle(L"32. 2D 프리미티브 - SPACE: 3D 씬 (ESC: 종료)");

	Mesh* pRect = g_cResourceMgr.FindPrimitiveMesh2D(PrimitiveMesh2DType::Rect);
	Mesh* pCircle = g_cResourceMgr.FindPrimitiveMesh2D(PrimitiveMesh2DType::Circle);

	Create2DObject("Circle", pCircle, vec2(350.0f, 300.0f), vec3(80.0f, 80.0f, 1.0f), 0.0f, color(0xFF, 0xCC, 0x4D));
	Create2DObject("Triangle", pTriangle, vec2(500.0f, 300.0f), vec3(140.0f, 120.0f, 1.0f), 0.0f, color(0x6B, 0xD0, 0xFF));
	Create2DObject("Line", pLine, vec2(660.0f, 300.0f), vec3(180.0f, 10.0f, 1.0f), 0.5f, color(0x8A, 0xFF, 0x8A));
}
```

```cpp
GameObject* Create2DObject(const char* _pName, Mesh* _pMesh, const vec2& _position,
	const vec3& _scale, _f32 _radian, const color& _tint)
{
	GameObject* pObj = new GameObject(_pName);
	pObj->SetMesh(_pMesh);
	pObj->GetMaterial()->SetBaseColor(_tint);
	pObj->GetTransform()->SetLocalPosition(_position);
	pObj->GetTransform()->SetLocalScale(_scale);
	pObj->GetTransform()->SetLocalRotationRad(_radian);
	AddChild(pObj, 0);
	createdObjects_.PushBack(pObj);
	return pObj;
}
```

단위 메시는 1×1(또는 반지름 1)이므로 **크기는 `SetLocalScale`로 조절**합니다. Rect 150×100은 "1×1 사각형을 x로 150배, y로 100배"라는 뜻입니다. 2D 프리미티브는 모두 **같은 흰색 텍스처**를 쓰므로 `g_cRenderer2D`가 전부 묶어 **드로우콜 1번**으로 그립니다 — 창 제목의 `DrawCall: 1`(그리고 배칭이 깨질 때 수치가 오르는 것)을 눈으로 확인하세요.

```cpp
GameObject* Create3DObject(const char* _pName, Mesh* _pMesh, const vec3& _position,
	const vec3& _scale, const color& _tint)
{
	GameObject* pObj = new GameObject(_pName);
	pObj->SetMesh(_pMesh);

	// 3D 렌더러(Renderer3D)는 재질의 셰이더 키를 해석해 파이프라인을 구성한다.
	// GameObject 기본 재질에는 키가 없으므로 디폴트 3D 셰이더를 지정해준다.
	Material* pMat = pObj->GetMaterial();
	pMat->SetVertexShaderKey(g_cResourceMgr.GetDefaultVertexShader3DKey());
	pMat->SetPixelShaderKey(g_cResourceMgr.GetDefaultPixelShader3DKey());
	pMat->SetBaseColor(_tint);
	pMat->Initialize(&g_cDevice);		// GPU 상태(파이프라인 상태/상수 버퍼) 초기화

	pObj->GetTransform()->SetLocalPosition(_position);
	pObj->GetTransform()->SetLocalScale(_scale);
	AddChild(pObj, 0);
	createdObjects_.PushBack(pObj);
	return pObj;
}
```

2D와 달리 3D는 **재질에 셰이더 키가 없으면 렌더러가 해석할 수 없습니다**. 그래서 `SetVertexShaderKey/SetPixelShaderKey`로 디폴트 3D 셰이더를 지정하고 `Material::Initialize`로 GPU 파이프라인 상태와 상수버퍼를 만들어 줍니다. 이 4줄이 "3D 메시를 놓기 위한 최소 준비"이고, 다음 장의 Shape3D가 이 반복을 감춥니다.

### 5-3. 자동 드로우의 흐름 — SetMesh가 끝이 아니다

```cpp
// Scene::RenderNode — 트래버설 중 노드마다 OnRender() 호출
pChild->OnRender();		// → GameObject 기본 구현이 pScene_->DrawMesh(...) 호출
```

`SetMesh`만으로 그려지는 이유는 `GameObject::OnRender`가 메시를 들고 있으면 **씬의 DrawMesh 창구로 자동 연결**하기 때문입니다. 2D는 `Scene2D::RenderScene`이 Renderer2D 배칭으로, 3D는 `Scene3D::RenderScene`이 `Renderer3D::BeginScene(frame) → Draw → EndScene`으로 이어줍니다(22번에서 배운 표준 루프). 사용자 코드에는 그리기 호출이 한 줄도 없습니다.

정리: 씬 소멸 시 트리는 자식을 **소유하지 않으므로**(분리만) `RemoveChild + delete`를 직접 합니다 — 29번과 동일한 패턴입니다.

## 6. GPU와 DX11, 하드웨어 깊이 보기

**2D 프리미티브의 배칭**: 2D 메시 4종은 전부 `VertexPTC`(위치+UV+색)이고 같은 **흰색 텍스처**를 참조합니다. Renderer2D의 배칭은 "같은 텍스처끼리 묶어" 한 번의 드로우콜로 그리므로, 4개 도형 = **DrawCall 1**. 씬 2의 3D는 메시마다 월드 행렬이 달라 6회 드로우(각 메시 1회)가 발생합니다 — 배칭의 유무가 드로우콜 수를 결정하는 대표적인 예입니다.

**3D 프리미티브의 파이프라인**: `Scene3D::DrawMesh` → `Renderer3D::Draw(mesh, material, world)` 경로는 22번의 표준 루프와 동일합니다. b0(프레임: 뷰/투영/카메라)는 씬이 1회 갱신하고, b1(월드)은 메시마다, b2(baseColor)는 머티리얼이 가집니다. 디폴트 3D 셰이더는 `lighting = 0.25f + 0.75f * saturate(dot(normal, -lightDir))`의 고정 방향광 람버트이므로, 큐브의 면마다 다른 밝기가 보이는 이유가 여기 있습니다(VertexPNT의 면별 법선 덕분).

**프리미티브 메시의 메모리**: 단위 메시라 용량이 작습니다(큐브 24정점/36인덱스, 구는 분할 수만큼). 디폴트 리소스이므로 **빌려 쓰는 것**입니다 — Release 없이 계속 유효하며, 여러 씬/오브젝트가 같은 메시를 공유합니다.

## 7. 핵심 규칙 요약

1. **꺼내 쓰기**: `FindPrimitiveMesh2D/3D(타입)` 한 줄이면 프리미티브 메시를 얻는다. 직접 버텍스를 만들 필요가 없다.
2. **2D 4종 / 3D 6종**: 2D(Rect/Circle/Triangle/Line, VertexPTC)와 3D(Cube/Sphere/Capsule/Cylinder/Plane/Quad, VertexPNT)는 enum이 분리되어 교차 사용이 컴파일 타임에 불가능.
3. **단위 메시**: 1×1(또는 반지름 1) 크기 — 실제 크기는 `SetLocalScale`로 조절한다.
4. **자동 드로우**: `SetMesh`만 하면 렌더 트래버설 중 자동으로 그려진다. 3D는 셰이더 키 지정 + `Material::Initialize`가 필요.
5. **배칭**: 2D 프리미티브는 흰색 텍스처 공유로 DrawCall 1. 3D는 메시별 드로우.
6. **소유권**: 프리미티브 메시는 ResourceMgr의 디폴트 리소스(빌림) — Release 없음. 씬 정리는 `RemoveChild + delete` 직접.

## 8. 직접 해보기 — 실험으로 확인하기

1. **드로우콜 검증**: 2D 씬에서 도형을 100개로 늘려도 DrawCall이 1로 유지되는지 확인해보세요.
2. **타입 실험**: `PrimitiveMesh2DType`에 없는 타입을 넘기면 컴파일이 안 되는지 확인해보세요 (엄격 분리의 증명).
3. **3D 크기**: 큐브 스케일을 (3, 0.5, 1)로 바꾸면 가로로 길쭉한 판이 됩니다 — 단위 메시 + 스케일의 조합을 느껴보세요.
4. **색 실험**: `SetBaseColor`를 반투명(`color(0xFF, 0x00, 0x00, 0x80)`)으로 바꿔 3D 메시의 블렌딩 동작을 보세요.
5. **셰이더 키 제거**: `SetVertexShaderKey/SetPixelShaderKey`를 빼면 3D 메시가 그려지지 않는 이유를 코드에서 찾아보세요.

## 9. 다음 단계로

프리미티브 **메시**를 배웠으니, 이제 그것을 감싼 **편의 노드**를 배웁니다. 33번의 `Shape2D`(bake + 정적 UI)와 `Shape3D`(SetShape 한 줄 + Transform 자유 변환)는 이 장의 "꺼내서 배치하는" 4줄을 전부 감춥니다. "메시 조회 → 셰이더 키 지정 → baseColor → Initialize"의 반복이 사라지는 모습을 33번에서 확인하세요.
