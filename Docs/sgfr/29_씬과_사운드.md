# 29. 씬과 사운드 — Application과 Director로 게임 루프 조직화하기

> 관련 코드: `Projects/sgfr/Sources/sgfr/29_SceneGraph/29_SceneGraph_Main.cpp`, `29_SceneGraph_Function.cpp`
> 실행: sgfr 실행 후 콘솔 메뉴에서 29번 선택 (창이 뜨면 ESC로 종료)
> 선행 학습: `02_윈도우와_메시지_루프.md`, `28_입력_처리.md`

## 1. 이 장에서 배우는 것

지금까지는 `XXX_Main()` 함수 하나가 윈도우부터 그리기까지 전부 직접 관리했습니다. 이번에는 **Cocos2d-x 스타일 프레임워크**를 배웁니다: `Application` 파생 + `Director`가 씬(Scene)의 생명주기(OnEnter/OnUpdate/OnRender/OnExit)를 돌려주는 구조, 씬 교체, 효과음, 2D 카메라 조작, 서브 윈도우까지 — "게임의 뼈대"를 짜는 법입니다.

## 2. 실행하면 보이는 것

창이 열리면 **태양계 씬**이 나타납니다. 궤도선 위를 지구가, 지구 주위를 달이 공전합니다.

- `SPACE`: 효과음과 함께 **통통 튀는 공 씬**으로 교체. 공 8개가 벽에 부딪힐 때마다 **음이 다른 효과음**이 납니다. 다시 SPACE를 누르면 태양계로 복귀합니다.
- `방향키`: 카메라 이동 / `휠`: 줌 (2D 표준 카메라 조작)
- `M`: **서브 윈도우**가 열리며 그 창에서도 공 씬이 동시에 실행됩니다. 두 창이 각자 다른 씬을 그리는 것을 확인할 수 있습니다.
- `ESC`: 종료

콘솔 설명의 핵심:

```
[씬(Scene)과 디렉터(Director)]
 씬 = 게임의 "화면 하나" (타이틀/인게임/결과창처럼 통째로 교체되는 단위)
 디렉터 = 현재 씬을 들고 있다가 매 프레임 Update/Render를 전달하고,
           ReplaceScene 요청이 오면 프레임 경계에서 안전하게 교체한다.
```

## 3. 핵심 개념 — 비유로 먼저 이해하기

### 3-1. 씬 = 무대의 "장(場)" 하나

연극은 막(장면) 단위로 진행됩니다. **씬(Scene)**은 게임의 한 화면입니다 — 타이틀 화면, 인게임 화면, 결과 화면이 각각 하나의 씬이지요. 씬은 무대에 오르면(OnEnter) 소품(텍스처)을 준비하고, 연기 중에는 매 프레임(OnUpdate) 갱신하고, 무대에 그려지고(OnRender), 내려갈 때(OnExit) 정리합니다.

### 3-2. 디렉터 = 무대 감독

**디렉터(Director)**는 "지금 무대에 어떤 장이 올라와 있는지"를 기억하고 매 프레임 갱신/그리기를 전달하는 감독입니다. 씬 교체 요청(ReplaceScene)을 받으면 **프레임이 끝나는 경계에서 안전하게** 교체합니다. 연극 도중에 소품을 통째로 바꾸면 사고(크래시)가 나니까요.

### 3-3. Application = 공연장 전체

**Application**은 윈도우/디바이스/입력/렌더러/타이머/사운드를 전부 소유하고 "게임 루프"를 돌려주는 엔진의 입구입니다. Cocos2d-x의 AppDelegate와 같은 위치입니다. 파생 클래스에서 `ApplicationDidFinishLaunching`(엔진 준비 완료 후 첫 씬 시작) 훅만 재정의하면 됩니다.

### 3-4. "그리고 싶을 때 바로 그리기" — 즉시 모드 렌더링

v2에서 sgf는 Node/Sprite 부모-자식 계층을 제거했습니다. 씬의 `OnRender()`에서 `g_cRenderer2D.DrawSprite/DrawLine`을 **코드 순서대로** 부르면 그 순서대로 그려집니다. 그림을 그릴 때 물감을 놓는 순서가 겹침을 결정하는 것과 같습니다 — 나중에 그린 것이 위에 옵니다.

## 4. 초보자 용어 사전

| 용어 | 뜻(쉬운 말) | 비유 |
|---|---|---|
| 씬 (Scene) | 게임의 화면 한 장 (타이틀/인게임/결과) | 연극의 막(장면) |
| 디렉터 (Director) | 씬 생명주기를 관리하고 씬을 교체하는 감독 | 무대 감독 |
| Application | 엔진 전체를 소유하고 게임 루프를 돌리는 입구 | 공연장 |
| 생명주기 훅 | OnEnter/OnUpdate/OnRender/OnExit 같은 미리 정해진 콜백 | 무대 등장/연기/무대 그림/퇴장 |
| ReplaceScene | 현재 씬을 새 씬으로 교체 (이전 씬은 delete) | 막 교체 |
| g_c 전역 접근 | g_cDirector/g_cSound/g_cInput 같은 전역 매크로 | 사무실 공용 전화기 |
| PlayTone | 주파수/길이/볼륨으로 즉석 톤(효과음) 재생 | 휘파람으로 신호 보내기 |
| 정사영(직교) 카메라 | 원근감 없는 2D 카메라 | 설계도 보기 |
| 서브 윈도우 | 메인 창 외에 추가로 띄우는 창 (씬 1개씩 가능) | 공연장의 보조 무대 |
| 안티에일리어싱 | 경계의 계단 모양을 부드럽게 처리 | 도화지 가장자리를 지우개로 문지르기 |

## 5. 코드 워크스루

### 5-1. 진입점 — Application 파생으로 최소화

```cpp
void SceneGraph_Main()
{

	if (!app.Initialize(L"29. 씬 & 사운드 - SPACE로 씬 교체 (ESC로 종료)", 800, 600))

	app.Run();

```

직접 메시지 루프를 만들던 이전 장들과 완전히 달라졌습니다. `app.Run()`이 내부적으로 입력 → 갱신 → 그리기 → 사운드 정리를 반복합니다.

```cpp
class DemoApp : public Application
{
protected:
	// 엔진 준비 완료 직후: 첫 씬을 시작한다.
	bool ApplicationDidFinishLaunching() override
	{
		g_cDirector.RunScene(CreateSolarSystemScene());
		return true;
	}

	// 매 프레임: ESC 종료 처리
	// (InputManager가 연결된 창이라 Window의 ESC 자동 닫기는 동작하지 않는다)
	void OnUpdate(const jc::TimeSpan& _dt) override
	{
		if (g_cInput.IsKeyPressed(VK_ESCAPE))
		{
			g_cWindow.Destroy();
		}
	}
};
```

**중요한 학습 포인트**: InputManager가 연결된 창은 Window의 ESC 자동 닫기가 비활성화되므로, 종료 판정은 InputManager(`g_cInput.IsKeyPressed(VK_ESCAPE)`)가 하고 창 파괴는 `g_cWindow.Destroy()`로 직접 유도합니다.

### 5-2. 씬 1 — 태양계 씬

```cpp
class SolarSystemScene : public Scene
{
public:
	void OnEnter() override
	{
		if (!CreateCircleTexture(&g_cDevice, &m_SunTexture, 128, color(1.0f, 0.85f, 0.2f, 1.0f)) ||
			!CreateCircleTexture(&g_cDevice, &m_EarthTexture, 64, color(0.3f, 0.55f, 1.0f, 1.0f)) ||
			!CreateCircleTexture(&g_cDevice, &m_MoonTexture, 32, color(0.8f, 0.8f, 0.8f, 1.0f)))
		{
			printf("원형 텍스처 생성 실패!\n");
			return;
		}

		GetCamera().SetOrthographic2D(kViewWidth_v, kViewHeight_v);
		m_Elapsed = 0.0f;
		GetWindow()->SetTitle(L"29. 태양계 씬 - SPACE: 씬 교체 / M: 서브 윈도우 (ESC로 종료)");
	}
```

- **OnEnter**에서 텍스처를 준비합니다. `CreateCircleTexture`는 파일 없이 CPU에서 원 텍스처를 직접 만듭니다 (아래 5-5절).
- `GetCamera().SetOrthographic2D(800, 600)`로 화면 왼쪽 아래가 (0,0), 오른쪽 위가 (800,600)인 2D 좌표계를 만듭니다.
- `GetWindow()`는 Director가 연결해준 소속 윈도우입니다.

```cpp
	void OnUpdate(const jc::TimeSpan& _dt) override
	{
		m_Elapsed += static_cast<_f32>(_dt.GetTotalSeconds());

		// 방향키 이동 + 휠 줌: 카메라 표준 조작 한 줄 (v2 편의 API)
		GetCamera().DriveDefault2D(g_cInput, _dt);

		// SPACE: 효과음과 함께 다음 씬으로 교체
		if (g_cInput.IsKeyPressed(VK_SPACE))
		{
			g_cSound.PlayTone(660, 120, 0.5f);
			g_cDirector.ReplaceScene(CreateBouncingBallScene());
		}

		// M: 서브 윈도우를 열고 그 창에 "통통 튀는 공" 씬을 띄운다.
		if (g_cInput.IsKeyPressed('M'))
		{
			Window* pSub = g_cApp.CreateSubWindow(L"서브 윈도우", 480, 360);
			if (pSub != nullptr)
			{
				g_cDirector.RunScene(CreateBouncingBallScene(), pSub);
			}
		}
	}
```

- `DriveDefault2D(g_cInput, _dt)` **한 줄**이 방향키 이동 + 휠 줌을 통째로 처리합니다.
- `g_cSound.PlayTone(660, 120, 0.5f)` = 660Hz(대략 "E5" 음)를 120밀리초, 볼륨 0.5로 재생. 파일 없이 신시사이저처럼 즉석 톤을 만듭니다.
- **`ReplaceScene`은 이전 씬을 delete하므로 씬은 반드시 `new`로 만들어야** 합니다 (함수 주석에도 명시).
- `CreateSubWindow` + `RunScene(pScene, pSub)`가 멀티 윈도우를 만듭니다. Director는 윈도우마다 씬 슬롯을 관리합니다.

```cpp
	void OnRender() override
	{
		...
		const _f32 earthAngle = m_Elapsed * 0.6f;	// 지구 각속도
		const _f32 moonAngle  = m_Elapsed * 2.4f;	// 달 각속도 (4배 빠름)
		...
		DrawOrbit(sunPos, earthOrbit, color(0.3f, 0.3f, 0.4f, 1.0f));
		DrawOrbit(earthPos, moonOrbit, color(0.3f, 0.3f, 0.4f, 1.0f));

		g_cRenderer2D.DrawSprite(&m_SunTexture, sunPos, vec2(120.0f, 120.0f));
		g_cRenderer2D.DrawSprite(&m_EarthTexture, earthPos, vec2(56.0f, 56.0f));
		g_cRenderer2D.DrawSprite(&m_MoonTexture, moonPos, vec2(26.0f, 26.0f));
	}
```

- 지구/달의 위치는 **각도 누적 → 삼각함수**로 직접 계산합니다 (`cos/sin` 공전). 궤도는 `DrawOrbit`이 48개 선분으로 원을 근사합니다.
- `DrawSprite(텍스처, 중심, 크기)`가 **코드 순서대로** 겹쳐집니다.

### 5-3. 씬 2 — 통통 튀는 공 씬

```cpp
void OnUpdate(const jc::TimeSpan& _dt) override
{
	const _f32 dt = static_cast<_f32>(_dt.GetTotalSeconds());

	for (_s32 i = 0; i < kBallCount_v; ++i)
	{
		m_PositionsX[i] += m_VelocitiesX[i] * dt;
		m_PositionsY[i] += m_VelocitiesY[i] * dt;

		bool bBounced = false;

		// 좌우 벽 충돌: 위치를 벽 안으로 되돌리고 속도 부호를 뒤집는다.
		if (m_PositionsX[i] < m_Radii[i])
		{
			m_PositionsX[i] = m_Radii[i];
			m_VelocitiesX[i] = -m_VelocitiesX[i];
			bBounced = true;
		}
		else if (m_PositionsX[i] > kViewWidth_v - m_Radii[i]) { ... }

		// 상하 벽 충돌 (동일 패턴) ...

		// 반사 순간 효과음: 공마다 음을 다르게 해 누가 부딪혔는지 귀로도 구분된다.
		if (bBounced)
		{
			g_cSound.PlayTone(440 + i * 40, 60, 0.35f);
		}
	}
	...
}
```

- 위치 += 속도 × dt, 벽을 넘으면 위치 보정 + 속도 부호 반전 = **반사**.
- 공마다 `440 + i*40` Hz로 음이 달라서, 귀로도 어느 공이 튀었는지 구분됩니다.
- `OnRender()`는 테두리 4개 선(`DrawLine`) + 공 8개(`DrawSprite`)를 그립니다.


- `Texture::CreateFromMemory`로 CPU 픽셀 버퍼를 GPU 텍스처로 올립니다 (30번에서 자세히).

## 6. GPU와 DX11, 하드웨어 깊이 보기

### 6-1. 이 장의 렌더링은 "2D 배치 렌더러"가 담당한다

`g_cRenderer2D`(Renderer2D)는 **즉시 모드 렌더러**입니다. 내부는 `BatchRenderer` 베이스가 처리하며, 핵심은 **배치(Batch)**입니다.

- `DrawSprite/DrawLine` 호출 시 즉시 GPU 명령을 내리지 않고, **CPU 배열(vertices_)에 정점을 쌓아둡니다.**
- 텍스처가 바뀌는 순간 또는 `End()`/`Flush()` 시점에 쌓인 정점을 **한 번의 DrawIndexed**로 GPU에 보냅니다. 드로우 콜(그리기 명령) 하나는 수천~수만 클록의 고정 비용이 있어, 모아서 한 번 보내는 것이 성능의 핵심입니다.
- 태양계 씬은 궤도선 96개 정점 + 스프라이트 3장 × 4정점 + 인덱스가 **단 몇 번의 드로우 콜**로 합쳐집니다. 흩어 그리면 수십 개의 드로우 콜이 될 것을 배치가 줄여주는 것입니다.

### 6-2. 스프라이트가 GPU 파이프라인을 타는 길

스프라이트 한 장이 화면에 그려지는 하드웨어 경로:

1. **CPU**: `DrawSprite`가 4개의 정점(VertexPTC: 위치/UV/색)을 계산해 배치 배열에 push. 위치 계산은 이미 2D 월드 좌표 → 뷰프로젝션 행렬 적용이 끝난 결과입니다 (배치 Begin 시 행렬이 곱해짐).
2. **버스/메모리**: Flush 시점에 배치의 DYNAMIC 정점 버퍼가 Map(WRITE_DISCARD) → PCIe → VRAM으로 올라갑니다.
3. **IA → VS**: Input Assembler가 정점을 읽어 VS로 보내고, VS는 사전 변환된 위치를 NDC로 통과시킵니다.
4. **래스터라이저**: 삼각형 → 픽셀.
5. **PS**: 텍스처의 UV 위치를 **샘플러(텍스처 캐시)**에서 읽어 틴트 색과 곱합니다.
6. **OM/ROP**: 알파 블렌드(기본 2D)가 수행되어 반투명 원이 배경과 섞입니다.

원 텍스처의 부드러운 경계(5-5절의 알파 기울기)는 **블렌드 유닛**과 합쳐져야 비로소 매끄럽게 보입니다. 텍스처에 알파가 그대로 있어도, 불투명 블렌드(bmNone)면 경계가 톱니로 보이기 때문입니다.

### 6-3. Director가 매 프레임 돌리는 것들

`Application::Run()`의 게임 루프는:

1. **입력 처리**: 윈도우 메시지 펌프 (`PumpMessage`)
2. **갱신**: `g_cDirector.Update(dt)` — 각 윈도우 슬롯의 씬에 대해 예약된 교체 처리 + `Scene::OnUpdate(dt)`
3. **그리기**: 창마다 `BeginFrame(클리어) → 씬 카메라의 ViewProjection으로 2D/3D 배치 Begin → Scene::OnRender() → 배치 End → EndFrame(Present)`
4. **사운드**: `g_cSound.Update()` — 재생이 끝난 XAudio2 SourceVoice 회수

셔터 누르는 순서가 정해져 있으므로, 프레임 경계에서의 씬 교체(`ReplaceScene`)가 "그리는 도중에 씬이 사라지는" 크래시를 원천 차단합니다.

### 6-4. 사운드의 하드웨어 여행 (XAudio2)

`g_cSound.PlayTone(660, 120, 0.5f)`는:

1. CPU에서 660Hz 사인파의 **PCM 샘플 배열**을 즉석 합성합니다 (보통 44100Hz 샘플레이트).
2. XAudio2의 `SourceVoice`(재생기)에 버퍼를 제출(Submit)합니다.
3. XAudio2 **믹서 스레드**가 모든 활성 SourceVoice를 섞어 `MasteringVoice`(최종 출력 관문)로 보냅니다.
4. 사운드 카드(오디오 코덱)가 PCM을 아날로그 신호로 변환(DAC)해 스피커로 보냅니다.

"발소리 없는 PC에서도 동작"한다는 주석은 이 엔진이 **창이 없는 오디오 디바이스에도 장치 대신 그릴 가상 기기**로 톤을 출력할 수 있게 처리해두었다는 뜻입니다. 사운드 엔진 초기화가 실패해도 게임은 계속 돌도록 설계되어 있습니다.

### 6-5. D3D11 API 대응표

| sgf API | D3D11 API | 하드웨어 |
|---|---|---|
| `Renderer2D::Flush` | `Map(WRITE_DISCARD)` + `DrawIndexed(배치 크기)` | 배치 → 드로우 콜 절감 |
| `DrawSprite` | 배치 정점 push (텍스처 전환 시 flush) | 텍스처 스위치 최소화 |
| `Texture::CreateFromMemory` | `CreateTexture2D` + `UpdateSubresource` | CPU 픽셀 → VRAM 업로드 |
| `Scene::OnRender` | 배치 Begin/End (카메라 행렬) | 뷰프로젝션 적용 |
| `SoundEngine::PlayTone` | XAudio2 SubmitSourceBuffer | 믹서 → DAC → 스피커 |

## 7. 핵심 규칙 요약

- 씬 생명주기: **OnEnter(준비) → 매 프레임 OnUpdate/OnRender → OnExit(정리)**.
- `ReplaceScene`은 이전 씬을 delete → **씬은 반드시 `new`로 생성**.
- `ApplicationDidFinishLaunching`에서 첫 씬을 `g_cDirector.RunScene`으로 시작.
- ESC 처리: InputManager 연결된 창은 Window 자동 닫기 비활성 → `g_cInput.IsKeyPressed(VK_ESCAPE)` + `g_cWindow.Destroy()`.
- `DriveDefault2D(g_cInput, _dt)` 한 줄 = 방향키 이동 + 휠 줌.
- `RunScene(pScene, pSubWindow)`로 서브 윈도우에 씬을 띄운다. (Director가 윈도우별 슬롯 관리)
- `PlayTone(주파수, ms, 볼륨)` = 파일 없는 즉석 효과음. 공마다 다른 음으로 구분.
- OnRender의 그리는 순서 = 코드 순서 (즉시 모드).
- 이벤트 등록/리소스는 생명주기와 짝을 맞춰 정리한다.
