# 07. 정점/인덱스 버퍼 — 정점을 재활용해 사각형 그리기

> 관련 코드: `Projects/sgfr/Sources/sgfr/Tutorial/07_VertexIndexBuffer/` (`07_VertexIndexBuffer_Main.cpp`, `07_VertexIndexBuffer_Function.cpp`)
> 관련 엔진: `Projects/sgf/Sources/sgf/Graphics/Buffers.h` (VertexBuffer/IndexBuffer)
> 실행: sgfr 실행 후 콘솔 메뉴에서 **7번** 선택
> 선행 학습: 05. 렌더링 파이프라인, 06. HLSL

## 1. 이 장에서 배우는 것

GPU는 오직 **삼각형만 그린다**는 사실에서 시작해, 사각형을 삼각형 2개로 쪼개는 방법과 **인덱스 버퍼(Index Buffer)**로 정점을 재활용하는 원리를 배웁니다. 인덱스 버퍼가 메모리를 얼마나 아껴주는지 바이트 단위 계산으로 확인하고, `Draw` 대신 **`DrawIndexed`** 호출을 배웁니다. 결과적으로 빨/초/파/노 4색 사각형이 그려집니다.

## 2. 실행하면 보이는 것

콘솔에 인덱스 버퍼의 메모리 절약 계산이 출력됩니다:

- `인덱스 없이: 정점 6개 x 16바이트 = 96바이트`
- `인덱스 있음: 정점 4개 x 16바이트 + 인덱스 6개 x 4바이트 = 88바이트`

그리고 CornflowerBlue 배경 위에 **왼쪽 위 빨강, 오른쪽 위 초록, 왼쪽 아래 파랑, 오른쪽 아래 노랑**의 네 꼭짓점 색이 보간된 사각형이 보입니다. ESC로 종료합니다.

## 3. 핵심 개념 — 비유로 먼저 이해하기

### 3-1. GPU는 삼각형 밖에 못 그린다

GPU는 원, 사각형, 별을 그리는 법을 모릅니다. 오직 삼각형만 그릴 줄 아는 꼼꼼한 공장입니다. 그래서 사각형을 만들려면 **삼각형 2개를 이어 붙여** 사각형처럼 보이게 합니다. 대각선을 그어 보면 알 수 있습니다 — 사각형은 항상 삼각형 2개로 나뉩니다. 우리가 "사각형이 그려졌다"고 보는 것은 사실 삼각형 2개가 나란히 그려진 것입니다.

### 3-2. 인덱스 버퍼 = 동창회 명단의 번호표

두 삼각형은 **가운데 대각선의 양 끝 정점(1번과 2번)을 공유**합니다. 만약 인덱스가 없으면 같은 정점 데이터를 두 번 써서 총 6개의 정점을 저장해야 합니다. 그런데 어차피 정점 4개가 전부인 상황에서, "삼각형 A는 0번, 1번, 2번 정점으로, 삼각형 B는 2번, 1번, 3번 정점으로"라고 **번호로 가리키면** 정점 데이터는 4개만 저장하면 됩니다. 이것이 인덱스 버퍼입니다 — 데이터는 한 번, 사용 방법(번호)은 따로. 동창회 명단을 한 장만 만들고 "1번~3번 앉아라"처럼 번호로 부르는 것과 같습니다.

### 3-3. 인덱스의 숨은 이득 = 정점 셰이더 계산 재활용

메모리 절약만 있는 게 아닙니다. 같은 정점은 **정점 셰이더를 한 번만 통과**합니다. 인덱스가 없으면 공유 정점 1번과 2번은 VS를 두 번씩 통과하는데, 인덱스 버퍼를 쓰면 한 번만 계산됩니다. 정점 셰이더에 변환 행렬 계산(10번부터)이 붙으면 이 이득은 성능으로 직결됩니다.

## 4. 초보자 용어 사전

| 용어 | 뜻(쉬운 말) | 비유 |
|---|---|---|
| 인덱스 버퍼 (Index Buffer) | 정점 번호 목록 (정점을 재사용하는 명단) | 동창회 번호표 |
| DrawIndexed | 인덱스를 따라 그리기 명령 | 명단 번호 순서로 부르기 |
| 인덱스 (Index) | 정점의 번호 (0부터 시작) | 학생 번호 |
| stride | 정점 1개의 바이트 크기 | 명단 1줄의 칸 수 |
| BaseVertex | 인덱스에 더할 정점 시작 번호 | 원점 이동 오프셋 |
| 시작 인덱스 (StartIndex) | 인덱스 버퍼의 시작 위치 | 명단 펼칠 시작 번호 |
| 감김 순서 (Winding) | 정점을 잇는 방향 (CW/CCW) | 앞면 판정 방향 |
| 비인덱스 드로우 | 정점을 순서대로 그리기 (재활용 없음) | 명단 없이 일렬 호명 |
| R32_UINT | 32비트 부호 없는 정수 인덱스 포맷 | 번호표 종이 규격 |

## 5. 코드 워크스루

`07_VertexIndexBuffer_Main.cpp`의 `VertexIndexBuffer_Main()`을 따라갑니다.

### 5-1. 메모리 절약 계산 출력 (코드 36행)

`PrintIndexBufferBenefit()`(Function.cpp)이 위의 바이트 계산을 출력합니다. `VertexPC`가 16바이트임을 확인할 수 있는데, `vec3(12바이트) + color(4바이트, R8G8B8A8_UNORM)`로 정확히 16바이트이며 별도 정렬 여유가 필요 없습니다.

### 5-2. 정점 4개 정의 (코드 59~64행)

```cpp
const VertexPC vertices[] = {
	{ vec3(-0.5f, +0.5f, 0.0f), color(0xFF, 0x00, 0x00, 0xFF) },	// 0: 왼쪽위 (빨강)
	{ vec3(+0.5f, +0.5f, 0.0f), color(0x00, 0xFF, 0x00, 0xFF) },	// 1: 오른쪽위 (초록)
	{ vec3(-0.5f, -0.5f, 0.0f), color(0x00, 0x00, 0xFF, 0xFF) },	// 2: 왼쪽아래 (파랑)
	{ vec3(+0.5f, -0.5f, 0.0f), color(0xFF, 0xFF, 0x00, 0xFF) },	// 3: 오른쪽아래 (노랑)
};
```

사각형의 4개 꼭짓점만 정의합니다.

```
0 ---- 1        삼각형 A: 0 -> 1 -> 2   (시계 방향!)
|    / |        삼각형 B: 2 -> 1 -> 3   (시계 방향!)
|  /   |
2 ---- 3
```

### 5-3. 인덱스 6개 정의 (코드 68~71행)

```cpp
const _u32 indices[] = {
	0, 1, 2,	// 삼각형 A
	2, 1, 3,	// 삼각형 B
};
```

삼각형 A는 정점 0→1→2, 삼각형 B는 정점 2→1→3을 사용합니다. **둘 다 시계 방향(CW)**이어야 앞면으로 인정됩니다. 감김 순서를 확인해 보세요: 화면 좌표계에서 0→1→2는 시계 방향입니다. 만약 `0, 1, 2` 다음에 `1, 2, 3`처럼 쓰면 한 삼각형이 반시계 방향이 되어 컬링으로 사라질 수 있습니다.

### 5-4. 버퍼 생성 (코드 73~82행)

```cpp
VertexBuffer vb;
IndexBuffer ib;
if (!vb.Create(&device, vertices, sizeof(VertexPC), 4) ||
	!ib.Create(&device, indices, 6))
```

`IndexBuffer::Create(&device, indices, 6)`은 32비트 인덱스(`R32_UINT`) 6개로 GPU 버퍼를 만듭니다.

### 5-5. 렌더 루프 — DrawIndexed (코드 108~117행)

```cpp
vb.Bind(&device);
ib.Bind(&device);		// 인덱스 버퍼도 IA 단계에 묶는다.
shader.Bind(&device);
device.Context()->IASetPrimitiveTopology(D3D11_PRIMITIVE_TOPOLOGY_TRIANGLELIST);

// Draw 대신 DrawIndexed!
// "인덱스 6개를 0번부터 사용해 그려라. 정점 번호에 더할 값(BaseVertex)은 0"
device.Context()->DrawIndexed(6, 0, 0);
```

`DrawIndexed(인덱스 개수, 시작 인덱스, 베이스 정점)`의 세 인자:

1. `6` — 인덱스 6개를 사용 (삼각형 2개 × 3)
2. `0` — 인덱스 버퍼의 0번부터 시작
3. `0` — 인덱스 값에 더할 정점 번호 오프셋(BaseVertex). 여러 메시가 하나의 정점 버퍼를 공유할 때 사용하며, 지금은 0

IA는 인덱스 버퍼에서 번호를 꺼내 정점 버퍼에서 해당 정점을 읽어 삼각형을 만듭니다.

### 5-6. 정리 (코드 123~124행)

`device.Finalize()` → `window.Destroy()`.

### 사용된 sgf API 정리

| API | 역할 |
|---|---|
| `VertexBuffer::Create(&device, data, stride, count)` | 정점 버퍼 생성 |
| `IndexBuffer::Create(&device, indices, count)` | 인덱스 버퍼 생성 (R32_UINT) |
| `VertexBuffer::Bind(&device)` | 정점 버퍼 IA 장착 |
| `IndexBuffer::Bind(&device)` | 인덱스 버퍼 IA 장착 |
| `Shader::CompileFromString/Bind` | 셰이더 컴파일/장착 |
| `device.Context()->DrawIndexed(6, 0, 0)` | 인덱스 6개로 그리기 |

## 6. GPU와 DX11, 하드웨어 깊이 보기

### 6-1. IA의 인덱스 메모리 트래픽: 접두사 합(Prefix Sum)과 캐시

`DrawIndexed`에서 GPU의 IA 유닛은 인덱스 버퍼를 읽어 정점 버퍼를 간접 참조합니다. 인덱스 버퍼는 작고 연속적이라 VRAM에서 적은 트래픽으로 읽히며, GPU 메모리 시스템은 **정점 페치 유닛(Vertex Fetch)**이 정점 버퍼를 캐시에 올려둡니다. 특히 삼각형 A의 마지막 두 정점(1, 2)이 삼각형 B의 첫 두 정점(2, 1)과 겹치므로, 이 정점들은 L2/L1 캐시 히트로 재사용됩니다 — 비인덱스 드로우였다면 이 6번의 페치가 전부 미스였을 것입니다. 인덱스 순서가 좋을수록(예: 0,1,2,2,1,3) 캐시 지역성이 높아져 성능이 좋아집니다.

### 6-2. 32비트 vs 16비트 인덱스: 대역폭과 정점 수의 트레이드오프

D3D11은 R16_UINT(16비트)와 R32_UINT(32비트) 두 인덱스 포맷을 지원합니다. 이 튜토리얼은 sgf 기본값인 32비트를 쓰는데, 16비트는 최대 65536개 정점까지만 가리킬 수 있는 대신 인덱스당 2바이트라 대역폭을 절반 아낍니다. 실전에서는 정점 수가 적은 메시는 16비트, 큰 메시(수십만 정점)는 32비트를 선택합니다. `IndexBuffer`가 `R32_UINT` 고정인 이유는 교육용 단순성과, 대형 메시에서 인덱스 부족 문제를 겪지 않게 하기 위함입니다.

### 6-3. BaseVertex의 하드웨어 의미: 정점 버퍼 공유와 행렬 배칭

`DrawIndexed(6, 0, 0)`의 세 번째 인자 BaseVertex는 인덱스에 더해지는 정점 오프셋입니다. 예를 들어 인덱스 값 `0`과 BaseVertex `1000`이면 정점 버퍼의 1000번째 정점을 가리킵니다. 이 기능의 실전 용도는 **여러 모델을 한 정점 버퍼에 모아두고(대량 할당), 드로우마다 BaseVertex만 바꿔** 드로우 콜당 바인딩 오버헤드를 줄이는 기법입니다. 이 배칭(batching) 개념은 22번 렌더 오브젝트 루프에서 실제로 등장합니다.

### 6-4. Draw vs DrawIndexed의 파이프라인 차이

`Draw`는 IA가 "정점 버퍼를 0번부터 순서대로 count개" 읽으며 정점 번호는 버퍼 위치 그 자체입니다. `DrawIndexed`는 "인덱스 버퍼를 읽고, 그 값을 베이스 정점과 더한 번호의 정점을 페치"합니다. 하드웨어 IA의 두 번째 경로가 하나 더 생기는 셈이라, 인덱스 버퍼도 IA 슬롯에 장착해야 합니다(`IASetIndexBuffer`). sgf의 `IndexBuffer::Bind`가 내부적으로 호출하는 것이 바로 이 함수입니다.

### 6-5. 셰이더 재사용의 가속: 정점 셰이더 통과 횟수 감소

비인덱스 드로우에서 6개 정점을 그리면 VS가 6번 실행됩니다. 인덱스 드로우에서도 삼각형 수는 같지만, **공유 정점(1, 2)은 한 번만 변환**되므로 실제 VS 실행은 4회입니다. 변환 행렬이 추가되고 정점이 수백만 개가 되면, 이 차이는 GPU 셰이더 유닛의 실행 시간을 줄이는 실질적 최적화입니다. 인덱스의 하드웨어적 가치는 "메모리 절약 + 캐시 히트 + 셰이더 계산 절약" 3종 세트입니다.

### 6-6. 메모리 예산 관점의 계산 확인

`VertexPC` 16바이트 × 4개 = 64바이트 + 인덱스 4바이트 × 6개 = 24바이트, 합계 88바이트 vs 인덱스 없이 16 × 6 = 96바이트. 사각형 하나는 8바이트 차이지만, 10만 삼각형짜리 캐릭터 모델은 정점 5만 개(공유율 50%) 기준으로 **약 80만 바이트(0.8MB) 절약**되며 정점 셰이더 실행도 절반 수준으로 줄어듭니다. VRAM 대역폭과 셰이더 처리량 두 축에서 모두 이득이므로, 실전 엔진은 거의 모든 메시를 인덱스 버퍼로 만듭니다.

### 6-7. 인덱스가 만들어진 것과 만들지 않은 것: 삼각형의 결함

인덱스 순서는 단순한 재활용이 아니라 **삼각형의 형태를 정의**합니다. `{0,1,2},{2,1,3}`이면 대각선이 1-2 사이(오른쪽 위에서 왼쪽 아래로)의 사각형이지만, `{0,1,2},{0,2,3}`으로 바꾸면 대각선이 0-2 사이(왼쪽 위에서 왼쪽 아래로)인 사각형이 됩니다. 어느 쪽이든 두 삼각형의 시계 방향을 유지해야 합니다. 또 하나 중요한 개념은 **퇴화 삼각형(degenerate triangle)**입니다 — 두 정점이 같은 위치이거나 일직선이면 면적이 0이 되어 아무것도 그려지지 않습니다. 스트립 토폴로지에서 삼각형 사이에 이 퇴화 삼각형을 끼워 넣어 "점프"하는 기법이 전통적으로 쓰였습니다. 이 장의 순서가 단순해 보여도, 이 규칙들이 이후 3D 모델(13번 큐브)과 2D 스프라이트(15번 텍스처)에서 모두 적용됩니다.

### 6-8. 꼭짓점 데이터의 "진짜" 위치: 로컬 좌표와 월드 좌표

이 장까지 정점은 NDC 좌표(-1~+1)를 직접 적었습니다. 실전에서 정점 좌표는 모델 자체의 로컬 좌표이며, 월드 변환 행렬(10번)이 그것을 매 프레임 화면 좌표로 옮깁니다. 이때 흥미로운 점은 **정점 버퍼는 여전히 로컬 좌표로 고정**되어 있다는 것입니다 — 변환은 셰이더의 상수 버퍼 행렬이 담당합니다. 06번의 "정점 데이터 불변" 원칙이 행렬 변환과 만나면, 캐릭터가 이동해도 GPU 메모리의 정점 데이터는 한 번도 갱신되지 않습니다. 이것이 상수 버퍼의 등장 이후 자연스럽게 이어지는 아키텍처입니다.

## 7. 핵심 규칙 요약

- [ ] GPU는 오직 삼각형만 그린다 — 사각형 = 삼각형 2개 (대각선 분할).
- [ ] 두 삼각형 모두 시계 방향(CW)이어야 앞면 (백페이스 컬링 주의).
- [ ] 인덱스는 정점의 번호 — `{0,1,2}` + `{2,1,3}` = 사각형.
- [ ] `DrawIndexed(indexCount, startIndex, baseVertex)` = "인덱스 N개를 M번부터, 정점 오프셋 K".
- [ ] 인덱스 재활용: 6×16=96B vs 4×16+6×4=88B (여기서 8B 절약).
- [ ] 인덱스의 숨은 이득: 정점 셰이더 계산 결과 재사용 (6회 → 4회).
- [ ] 정점 버퍼와 인덱스 버퍼 모두 IA 단계에 Bind 필수.
- [ ] 16비트 인덱스는 65536 정점 제한, 32비트는 제한 없음 (sgf는 32비트 고정).

## 8. 직접 해보기 — 실험으로 확인하기


1. 인덱스를 `{0,1,2, 2,1,3}`으로 바꿔보세요. 반직만 그려지는 이유를 19번(컬링) 예습으로 설명해보세요.
2. 정점 4개로 삼각형 2개 말고, 정점 5개로 별 모양을 인덱스로 만들어보세요.
3. 정점 구조체에서 color를 뺌 때와 넣을 때의 ByteWidth 차이를 계산해보세요.

## 9. 다음 단계로
