# 02. 윈도우와 메시지 루프 — 그림을 그릴 '종이' 만들기

> 관련 코드: `Projects/sgf/Sources/sgf/Core/Window.h/.cpp`, `Projects/sgfr/Sources/sgfr/02_WindowAndMessageLoop/`
> 실행: sgfr 메뉴에서 **2번**

---

## 1. 왜 윈도우부터 만드나요?

DX11은 "화면에 그리는 도구"입니다. 그런데 그리려면 먼저 **그릴 곳(종이)**이 있어야겠죠?
Windows에서 그 종이가 바로 **윈도우(HWND)**입니다. DX11은 나중에(03번) 이 윈도우에 연결됩니다.

---

## 2. 윈도우가 만들어지는 4단계

sgf의 `Window::Create()`가 하는 일을 그대로 따라가 봅시다.

### 단계 1: 윈도우 클래스 등록 (`RegisterClassEx`)

"윈도우 클래스"는 C++ 클래스가 아닙니다! 윈도우의 **설계도/양식**입니다.
"이런 모양의 창문을 만들 거고, 이벤트는 이 함수(WndProc)가 받을 거야"라고 Windows에 미리 신고하는 것입니다.

### 단계 2: 윈도우 생성 (`CreateWindowEx`)

등록한 양식으로 실제 창문을 띄웁니다. 이때 반환되는 것이 `HWND`(윈도우 핸들)입니다.

> 핸들(Handle)이란? Windows가 관리하는 물건의 **번호표**입니다. 우리는 직접 윈도우 메모리를 만지지 못하고, 번호표를 제시하며 "이 창문 크기 바꿔줘" 하고 부탁합니다.

### 단계 3: 클라이언트 영역 보정 (`AdjustWindowRect`)

"800×600 윈도우"를 만들면 제목 표시줄과 테두리까지 포함해 800×600이 되어버립니다.
우리가 원하는 건 **그림 그리는 안쪽 영역(클라이언트 영역)**이 800×600이되는 것이므로,
테두리 두께를 계산해 윈도우를 그만큼 더 크게 만듭니다. sgf는 이걸 자동으로 처리합니다.

### 단계 4: 표시 (`ShowWindow`)

만들어도 기본은 숨어있는 상태라 명시적으로 보여달라고 해야 합니다.

## 3. 메시지 루프 — Windows 프로그램의 심장박동

### 3-1. 메시지란?

Windows는 모든 사건을 **메시지**로 알려줍니다.

| 사건 | 메시지 |
|---|---|
| 키를 누름 | `WM_KEYDOWN` |
| 마우스를 움직임 | `WM_MOUSEMOVE` |
| 창 닫기 버튼 클릭 | `WM_CLOSE` → `WM_DESTROY` |
| 프로그램 종료 요청 | `WM_QUIT` |

메시지는 프로그램마다 있는 **메시지 큐(우편함)**에 쌓입니다.
우편함을 안 열어보면? 프로그램이 "응답 없음"이 됩니다. 그래서 계속 꺼내서 처리해야 하고, 그 반복이 메시지 루프입니다.

### 3-2. 게임용 메시지 루프: PeekMessage 방식

일반 앱은 `GetMessage`(메시지 올 때까지 잠들기)를 쓰지만, 게임은 메시지가 없어도 매 프레임 그려야 하므로 `PeekMessage`(있으면 꺼내고 없으면 바로 리턴)를 씁니다.

sgf의 `Window::PumpMessage()` 구조:

```cpp
// 모아둔 메시지를 전부 처리하고, 계속 실행해도 되면 true를 반환한다.
// WM_QUIT을 받았다면 false를 반환 → 게임 루프 종료.
while (PeekMessage(&msg, nullptr, 0, 0, PM_REMOVE)) {
    if (msg.message == WM_QUIT) return false;
    TranslateMessage(&msg);   // 키 입력을 문자 메시지로 변환 (WM_CHAR 생성)
    DispatchMessage(&msg);    // WndProc으로 메시지 배달
}
return true;
```

그래서 모든 튜토리얼의 기본 골격은 이렇습니다:

```cpp
while (window.PumpMessage()) {   // 메시지 처리. 창이 닫혔으면 탈출
    // 여기서 게임 로직 + 그리기 (매 프레임 실행됨)
}
```

### 3-3. WndProc — 메시지 받는 전화 교환원

`DispatchMessage`가 배달한 메시지는 윈도우 클래스에 등록해둔 함수 `WndProc`으로 들어옵니다.

sgf의 WndProc은 두 가지만 합니다.

1. `WM_DESTROY`를 받으면 `PostQuitMessage(0)` 호출 → 메시지 큐에 `WM_QUIT`이 들어감 → 다음 PumpMessage가 false 반환 → 게임 루프 종료
2. 키/마우스 메시지는 연결된 `InputManager::HandleMessage`로 전달 (13번에서 상세히)
3. 그 외는 기본 처리(`DefWindowProc`)에 맡김

> 중요 연결 고리: `window.ConnectInput(&input)`을 호출해야 윈도우가 받은 입력 메시지가 InputManager에 전달됩니다.

## 4. 튜토리얼(2번)에서 직접 확인할 것

1. 윈도우가 뜨고, 콘솔에 윈도우 생성 과정이 출력됩니다.
2. 키를 누를 때마다 어떤 키인지 콘솔에 출력됩니다. (이벤트 방식)
3. 매 프레임 키 상태를 검사해 출력하는 방식도 함께 보여줍니다. (폴링 방식)
4. 창을 닫으면 루프가 종료되고 메뉴로 돌아옵니다.

이벤트 vs 폴링의 차이는 13번 튜토리얼에서 제대로 다룹니다. 지금은 "둘 다 가능하구나" 정도만 기억하세요.

## 5. 자주 헷갈리는 것들 (Q&A)

**Q. WM_CLOSE / WM_DESTROY / WM_QUIT 차이는?**
- `WM_CLOSE`: "닫기 버튼이 눌렸어요" (아직 안 닫힘. 여기서 '저장하시겠습니까?' 같은 처리 가능)
- `WM_DESTROY`: "윈도우가 실제로 파괴되는 중" (정리 작업을 하고 PostQuitMessage 호출)
- `WM_QUIT`: "프로그램 자체를 끝내자" (메시지 루프 탈출 신호)

**Q. 왜 콘솔과 윈도우가 동시에 떠 있나요?**
- sgfr은 콘솔 앱(SubSystem: Console)으로 빌드되지만, 콘솔 앱도 윈도우를 얼마든지 만들 수 있습니다. 목차/설명은 콘솔에, 그림은 윈도우에 출력하는 학습용 구조입니다.

**Q. 메시지 루프가 멈추면 어떻게 되나요?**
- 창이 "응답 없음" 상태가 됩니다. 그래서 게임 로직이 오래 걸리면 안 됩니다. (한 프레임 안에 끝내야 함)

## 6. 정리
