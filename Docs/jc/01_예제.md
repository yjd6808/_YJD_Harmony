## 1. Uri — 경로/스킴 파싱

```cpp
jc::Uri a("C:/assets/texture.png");          // usFile, path = C:/assets/texture.png
jc::Uri b("file:///C:/assets/a.txt");        // usFile
jc::Uri c("http://cdn.example.com/file.dat");// usHttp, host=cdn.example.com, port=80
jc::Uri d("https://cdn.example.com:8443/q?x=1"); // usHttps, port=8443, pathAndQuery=/q?x=1

bool valid = c.IsValid();     // true
bool remote = c.IsRemote();   // true (http/https만)
jc::String pathQ = d.GetPathAndQuery(); // "/q?x=1"
jc::UriScheme s = d.GetScheme(); // usHttps

// 파일 존재 여부와 분리됨 — 파싱 실패 시 IsValid()==false
jc::Uri bad("::::");
assert(!bad.IsValid());
```

## 2. MemoryStream — 메모리 버퍼

```cpp
// 2-1. 소유 버퍼 (자동 확장)
auto sp = jc::MakeShared<jc::MemoryStream>(1024);
sp->Write("hello", 5);
sp->Write(" world", 6);
jc::String s((char*)sp->GetData(), sp->GetSize()); // "hello world"

// 2-2. 비소유 래핑 (외부 버퍼 소유권 없음, 확장 시 jc_assert)
_byte buf[64] = {};
auto sp2 = jc::MakeShared<jc::MemoryStream>(buf, 64, false);
sp2->Write("abc", 3);
assert(sp2->GetSize() == 3);
assert(sp2->GetData() == buf);

// 2-3. Read (내부 offset 이동)
char out[6] = {};
sp->Read(out, 5); // readOffset_ 이동, 다시 Read 시 다음 데이터
```

## 3. FileLoader — 동기 로드/다운로드

```cpp
jc::FileLoader loader;
jc::FileLoaderConfig cfg;
cfg.workerCount_ = 2;
cfg.memoryLimit_ = 64 * 1024 * 1024;
loader.Initialize();

// 3-1. 동기 메모리 로드 (파일 전체를 MemoryStream으로)
auto result = loader.Load(jc::Uri("C:/assets/config.json"));
if (result->IsSuccess()) {
    jc::MemoryStream* body = result->GetBody(); // 또는 TakeBody()로 소유권 이전
    printf("bytes=%u\n", body->GetSize());
} else {
    printf("failed: %d\n", (int)result->GetError()); // leOpenFailed 등
}

// 3-2. 동기 다운로드 (원자적 커밋: .part.N에 쓴 뒤 Move)
auto dl = loader.Download(jc::Uri("C:/assets/big.dat"), jc::String("C:/temp/big.dat"));
if (dl->IsSuccess()) {
    // C:/temp/big.dat 생성됨, 실패 시 .part 파일은 자동 삭제
}

// 3-3. 메모리 제한 초과 시 실패
cfg.memoryLimit_ = 1; // 1 byte 제한 — 10KB 파일도 실패
// → LoadResult::GetError() == leMemoryLimit
```

## 4. FileLoader — 비동기 로드/다운로드 + 콜백/리스너 + 진행률/취소

```cpp
class MyListener : public jc::ILoadListener {
public:
    void OnProgress(const jc::LoadProgress& p) override {
        printf("progress %u %lld/%lld state=%d\n", p.handle_, p.loadedBytes_, p.totalBytes_, (int)p.state_);
    }
    void OnCompleted(jc::LoadResult& r) override { printf("completed %u\n", r.GetHandle()); }
    void OnFailed(jc::LoadResult& r) override    { printf("failed %d\n", (int)r.GetError()); }
    void OnCancelled(jc::LoadResult& r) override { printf("cancelled\n"); }
};

jc::FileLoader loader;
loader.Initialize();

MyListener listener;
loader.SetListener(&listener, false); // false = 소유권 이전 안 함

// 4-1. 콜백 우선, 리스너는 Update()에서 다음에 호출됨
jc::LoadHandle h = loader.LoadAsync(jc::Uri("C:/assets/a.txt"),
    [](jc::LoadResult& r){
        if (r.IsSuccess()) {
            auto body = r.TakeBody(); // SharedPtr로 소유권 취득
        }
    });

// 4-2. 프레임 루프에서 진행률 펌핑
while (loader.GetActiveCount() > 0) {
    loader.Update(); // 큐에 쌓인 OnProgress/OnCompleted를 메인 스레드에서 호출

    jc::LoadProgress prog;
    if (loader.GetProgress(h, prog)) {
        // prog.loadedBytes_, prog.totalBytes_ (totalBytes_==-1이면 길이 미상)
    }

    jc::Vector<jc::LoadProgress> snap;
    loader.GetActiveSnapshot(snap); // 전체 활성 Job 스냅샷
    jc::Thread::Sleep(16);
}

// 4-3. 취소
jc::LoadHandle h2 = loader.LoadAsync(jc::Uri("C:/assets/big.dat"));
jc::LoadHandle h3 = loader.DownloadAsync(jc::Uri("C:/assets/big.dat"), jc::String("C:/temp/out.dat"));
loader.Cancel(h2);                 // 단일 취소 — pending이면 즉시 lsCancelled, running이면 cancelRequested
loader.CancelAll();                // 전체 취소
loader.Update(); // 취소된 Job도 Update()에서 OnCancelled로 통지됨

// 4-4. 다운로드 취소 시 .part 파일 자동 삭제 보장
// 4-5. 스레드풀 공유
jc::ThreadPool sharedPool(4);
jc::FileLoaderConfig cfg2;
cfg2.pSharedPool_ = &sharedPool;
jc::FileLoader loader2(cfg2);
loader2.Initialize();
// loader2.Shutdown()은 sharedPool을 Join하지 않음 — 소유권이 loader2에 없으므로

loader.Shutdown();
```

## 5. 커스텀 DataSource 등록

```cpp
class MyDataSource : public jc::IFileDataSource {
public:
    bool Open(const jc::Uri& uri, jc::FileDataSourceInfo& info) override { /* ... */ return true; }
    int  Read(void* buf, int len) override { /* ... */ return 0; }
    void Close() override {}
    jc::LoadError GetLastError() const override { return jc::LoadError::leNone; }

loader.RegisterFileDataSource(jc::UriScheme::usFile, []{ return jc::MakeShared<MyDataSource>(); });
// 이후 loader.Load("file:///C:/...")는 MyDataSource를 통해 열림
```

## 6. 오류 코드 요약

| LoadError | 의미 |
|---|---|
| `leInvalidUri` | 파싱 실패 또는 IsValid()==false |
| `leUnsupportedScheme` | 팩토리 미등록 스킴 (예: http 로드 시 jnet 미연동) |
| `leOpenFailed` | 파일 없음, 권한 실패 |
| `leSourceFailed` | Read 중 실패 |
| `leWriteFailed` | Download 시 파일 쓰기 실패 |
| `leMemoryLimit` | `memoryLimit_` 초과 |
| `leCancelledByUser` | `Cancel` |
| `leShutdown` | `Shutdown()` 중 들어온 요청 |

## 7. 라이프사이클 규칙

- `Initialize()` 이후 `Load/Download` 가능, `Shutdown()` 이후 모든 `GetState/GetProgress`는 `lsNone/false` 반환
- `Shutdown()`은 내부 워커 Job이 끝날 때까지 대기 후 `Join(WaitOnlyRunningTask)` — `Update()`에서 미소비한 완료는 버려짐
- `LoadResult::TakeBody()`는 한 번만 성공(두 번째 호출 시 nullptr) — `LoadResult` 소멸 시 미-Take된 Body는 자동 해제
