# 02. 2D 렌더링 파이프라인 — Renderer2D가 그리는 법

> 대상: `Projects/sgf/Sources/sgf/Graphics/Renderer2D.*`, `Scene/Scene2D.*`, `Graphics/Fill.*`

2D 그리기는 크게 **스태틱(정적, 1회 bake)** 과 **다이나믹(매 프레임)** 그리고 **메시(자동 드로우)** 세 길이 있습니다.
어느 길이든 결국 배치 버퍼(Quad/Triangle)에 정점을 쌓고, 텍스처가 바뀔 때마다 Flush하는 **같은 렌더러**를 통과합니다.

---

## 1. 2D 그리기의 세 길

```
게임 코드
  │
  ├─ [스태틱 길] Scene2D::DeclareStaticRect(...) 등  ← 1회만 선언 (OnEnter에서)
  │     │  반환: staticId (_u64)
  │     ▼
  │  Scene2D::RenderStatic(staticId)   ← Scene2D.cpp:83 — 그릴 때마다 id만 예약
  │     ▼
  │  Renderer2D::RenderStatic(id)      ← Renderer2D.cpp:187 — 캐시된 버텍스 픽업
  │     ▼
  │  Renderer2D::FlushStatic()         ← Renderer2D.cpp:206 — 한 번에 전송
  │
  ├─ [다이나믹 길] Scene2D::RenderDynamic(region, Fill, ...)  ← Scene2D.cpp:89
  │     │     ▼
  │     │  Renderer2D::RenderDynamic(RenderParams) ← Renderer2D.cpp:197
  │     │     ▼
  │     │  Renderer2D::BuildFill(Fill, params, out) ← Renderer2D.cpp:255
  │     │     │   (Fill 콜백이 버텍스 생성 — 색/텍스처/9-패치/게이지/커스텀)
  │     │     ▼
  │     │  Renderer2D::PushTriangles() / PushQuad() ← Renderer2D.cpp:274/308
  │     │     ▼
  │     └─ Renderer2D::FlushDynamic()  ← Renderer2D.cpp:230 — 한 번에 전송
  │
  └─ [메시 길] GameObject::SetMesh(2D 프리미티브 메시)  ← 움직이는 도형의 권장 경로
        │     (Mesh 2D 팩토리: Rect/Circle/Triangle/Line — VertexPTC, 단위 크기)
        ▼
     트리 순회 중 RenderSelf() → Scene2D::DrawMesh → Renderer2D::DrawMesh GPU 변환 즉시 드로우
        ▼
     로컬 정점 → GPU(b1 월드 행렬 변환) → DrawIndexed (오브젝트당 1콜, 배치와 독립)
```

> **비유**: 스태틱은 "메뉴판을 미리 만들어 두고 번호만 부르는 것", 다이나믹은 "주문할 때마다 요리사에게 직접 말하는 것",
> 메시는 "트랜스폼을 가진 배우"입니다. **움직이는 도형은 메시 길(SetMesh + Transform), 가만히 있는 UI/테두리는 스태틱**이 정석입니다.
> 스태틱은 버텍스가 1회만 만들어져 **매 프레임 재계산이 없어** 빠릅니다.

스태틱의 편의 노드로 **`Shape2D`** 가 있습니다. `SetRect/SetCircle/...` 후 `AddChild`만 하면
OnEnter에서 자동으로 bake하고 매 프레임 자동으로 그려줍니다. (04_씬_시스템과_카메라.md 참고)

## 2. 한 프레임의 2D 렌더링 (Scene2D::RenderScene)

`Scene2D::RenderScene()` — `Scene2D.cpp:167`

```
RenderScene()
  ├─ ① g_cRenderer2D.BeginScene(this)      ← Renderer2D.cpp:155 — 배치 시작, 뷰포트/카메라 준비
  ├─ ② 트리 순회 (Scene::RenderNode)       ← Scene.cpp:100
  │     └─▶ GameObject::RenderSelf()        ← GameObject.cpp:165
  │           ├─ 렌더 훅이면 RenderStatic(id) 예약
  │           └─ SetMesh 노드면 DrawMesh(...) 예약
  ├─ ③ OnRender() 훅 — 게임 코드가 즉시 그리기 (RenderStatic/RenderDynamic)
  ├─ ④ g_cRenderer2D.EndScene()            ← Renderer2D.cpp:166
  │     └─▶ 남은 배치 전부 Flush
  └─ (SetMesh 노드의 2D 메시는 Renderer2D::DrawMesh로 GPU 변환 즉시 드로우 — Renderer2D.cpp:455)
```

**BeginScene → (예약/즉시 그리기) → EndScene** 이 2D 프레임의 전체입니다.
`BeginScene`이 카메라 뷰/투영을 렌더러에 주입하고, `EndScene`이 GPU 전송을 마무리합니다.

> Renderer2D와 Renderer3D는 이 **Begin/End/Flush 공통 흐름을 `BatchRenderer` 베이스**에서 공유합니다.
> (셰이더 초기화·뷰프로젝션 저장·남은 배치 플러시가 공용 — 각 렌더러는 자신의 버퍼/드로우콜만 구현, `Graphics/BatchRenderer.*`)

## 3. 스태틱 선언 (Scene2D)

`OnEnter()`에서 한 번만 선언하고, 반환된 `staticId`를 기억해 두었다가 `RenderStatic(id)`로 그립니다.

| 선언 함수 | 위치 | 그리는 것 |
|---|---|---|
| `DeclareStaticRect(region, color)` | `Scene2D.cpp:111` | 사각형 |
| `DeclareStaticImage(texture, region)` | `Scene2D.cpp:116` | 이미지 (텍스처) |
| `DeclareStaticImage(texture, region, sliceL, T, R, B)` | `Scene2D.cpp:121` | 9-패치 이미지 (모서리 분할) |
| `DeclareStaticLine(p1, p2, thickness, color)` | `Scene2D.cpp:128` | 선분 |
| `DeclareStaticCircle(center, radius, color, segments)` | `Scene2D.cpp:134` | 원 |
| `DeclareStaticPolygon(points, count, color)` | `Scene2D.cpp:140` | 다각형 |
| `DeclareStaticTriangle(p1, p2, p3, color)` | `Scene2D.cpp:146` | 삼각형 |

그 외의 채움(게이지, 커스텀 등)은 **범용 선언** `DeclareStatic(Fill, region, ...)` — `Scene2D.cpp:153` 을 사용합니다.
게이지처럼 **bake 시점에 비율이 고정되는** 채움은 선언 시 적용됩니다.

> staticId는 `OnEnter` 시점에 1회 "굽기(bake)"됩니다. **런타임에 값이 바뀌는 채움은 다이나믹으로 그리세요.**
> 이 선언+bake 과정을 노드로 포장한 것이 `Shape2D`입니다. (SetRect 등 → AddChild → 자동)

## 4. Fill 시스템 (다이나믹 채움)

`Graphics/Fill.h` — "이 영역을 어떻게 채울지"를 값으로 만든 것.

| 내장 채움 | 설명 |
|---|---|
| `Fill::Solid(color)` | 단색 |
| `Fill::Texture(texture, rect)` | 텍스처 원본 영역 |
| `Fill::NinePatch(texture, ...)` | 9-패치 (모서리/가장자리/중앙 분할) |
| `Fill::Gauge(...)` | 게이지 (비율에 따라 조절) |
| `Fill::Custom(callback)` | 사용자 정의 콜백 (버텍스 직접 생성) |

**동작 원리**: `Fill` + `RenderParams`(영역, UV, 회전, 색, 레이어)를 넘기면
`Renderer2D::BuildFill` — `Renderer2D.cpp:255` 가 채움 콜백을 호출해 **버텍스를 생성**합니다.
이 버텍스가 배치 버퍼에 쌓이고, 다음 텍스처 전환/Flush 시점에 GPU로 나갑니다.

> **공용 기하 빌더**: 사각형/원/선분/다각형/삼각형의 정점 생성 로직은
> `Graphics/PrimitiveBuilder.*` — 순수 함수 모음입니다. 엔진 내장 채움(스태틱 선언들)과
> 2D 프리미티브 메시 팩토리(Mesh 2D)가 같은 로직을 공유해 중복이 없습니다. (GPU 무접촉 — 정점만 생성)

레이어는 `RenderLayer` 열거형 (`rlBottom` / `rlDefault` / `rlTop`) — `GraphicsEnums.h`로,
같은 레이어 안에서는 예약 순서대로 그립니다.

## 5. 배칭 — 왜 빠른가

```
개나리 사각형 10개 + 같은 텍스처
  └─▶ PushQuad × 10 → 배치 버퍼에 정점 40개 누적 → 텍스처 같음 → Flush 없이 계속 누적
  └─▶ 1 DIP (Draw call 1번)으로 10개 전부 그림
```

텍스처가 바뀌는 순간 그때까지 쌓인 배치를 Flush하고 새 배치를 시작합니다.
(같은 텍스처를 연속으로 그리면 GPU 드로우콜이 최소화됩니다 — 23번 튜토리얼의 주제)

## 7. 요약 — 기억할 다섯 문장

1. 2D 그리기는 **세 길**: 스태틱(1회 bake + id 예약) / 다이나믹(매 프레임 버텍스) / 메시(SetMesh + Transform 자동 드로우).
2. **가만히 있는 도형은 스태틱(또는 Shape2D), 움직이는 도형은 메시 길**이 정석이다.
3. 스태틱/다이나믹(비메시)은 **배치 버퍼**를 통과한다. 같은 텍스처끼리 모여 1 DIP. 메시는 GPU 변환 즉시 드로우 (오브젝트당 1콜).
4. Fill은 "채움 설명서"이고, BuildFill이 그 설명서로 버텍스를 만든다. (기하 로직은 PrimitiveBuilder 공유)
5. Renderer2D/3D는 BatchRenderer 베이스로 Begin/End/Flush 흐름을 공유한다.
