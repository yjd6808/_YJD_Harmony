# 04. 씬 시스템과 카메라 — 무대, 배우, 그리고 촬영감독

> **이 문서 하나로**: Director/Scene/GameObject/Transform/Camera가 각각 무슨 역할인지, 씬 전환과 오브젝트 트리·수명주기 훅이 어떻게 도는지, 그리고 Transform의 "게으른 행렬 캐시"가 왜 빠른지를 실제 코드와 함께 이해합니다.
>
> 관련 소스: `Scene/Director.h/.cpp`, `Scene/Scene.h/.cpp`, `Scene/GameObject.h/.cpp`, `Scene/Transform.h/.cpp`, `Scene/Camera.h/.cpp`

---

## 1. 큰 그림 — 연극 무대의 비유

씬 시스템의 등장인물은 연극에 그대로 대응됩니다.

| 클래스 | 연극에서의 역할 | 하는 일 |
|---|---|---|
| **Director** (`g_cDirector`) | 극장 지배인 | 어떤 씬을 올릴지 결정, 씬 교체, 매 프레임 Update/Render 지휘 |
| **Scene** | 무대(공연 하나) | 오브젝트 트리의 루트, 카메라 보유, 렌더러 예약 창구 |
| **GameObject** | 배우 | 트리 노드. 자식을 가지고, 매 프레임 갱신/그리기 훅을 받음 |
| **Transform** | 배우의 위치표 | 위치·회전·크기. 부모를 따라가는 계층 변환 |
| **Camera** | 촬영감독 | 어디서 어떻게 찍을지(View/Projection) 결정 |

```cpp
// Scene/Director.h
/*
 * [디렉터란?]
 * Cocos2d-x의 Director에 해당한다. "지금 어떤 씬을 실행 중인가"를 관리하고
 * 매 프레임 현재 씬의 Update/Render를 호출해주는 매니저다.
 *
 * [바뀐 점 - 윈도우별 씬 슬롯]
 * 메인 윈도우와 서브 윈도우가 각각 서로 다른 씬을 동시에 실행할 수 있다.
 * (예: 메인 창은 게임 씬, 서브 창은 미니맵/디버그 씬)
 */
```

사용법은 두 줄입니다. 첫 씬을 올리고, 필요하면 교체합니다.

```cpp
// 앱 시작 시 (ApplicationDidFinishLaunching)
g_cDirector.RunScene(dbg_new TitleScene());

// 게임 중 씬 전환 — 다음 프레임 Update 직전에 안전하게 교체된다
g_cDirector.ReplaceScene(dbg_new BattleScene());
```

`ReplaceScene`이 **즉시 교체하지 않는** 점이 중요합니다. 씬 코드 한가운데서 자기 자신을 삭제하면 위험하므로(자기 발밑의 사다리 치우기), 요청만 기록해두고 다음 프레임 Update 직전에 안전한 시점에 교체합니다. 이전 씬은 OnExit 후 삭제되고, 새 씬은 OnEnter를 받습니다.

## 2. Scene — 무대는 트리의 루트다

```cpp
// Scene/Scene.h
/*
 * [씬(Scene)이란?]
 * "타이틀 화면", "게임 플레이", "결과 화면"처럼 화면 단위 하나를 담당하는 클래스.
 *
 * [바뀐 점 요약]
 * - Scene은 추상 클래스다. Scene2D/Scene3D가 카메라 종류를 결정한다.
 * - 씬은 root_ GameObject를 가지며 모든 오브젝트는 이 트리에 매달린다.
 * - 카메라도 GameObject 파생이라 트리에 넣을 수 있다. (캐릭터 추적 카메라 등)
 * - 씬이 렌더러 예약 창구를 겸한다: DeclareStatic*/RenderStatic/RenderDynamic/DrawMesh
 * - OnRender()는 인자가 없다. 예약 API가 내부에서 렌더러로 전달한다.
 * - DataMap으로 씬 간 데이터 전달. (이전 씬이 남긴 값을 다음 씬이 읽는다)
 */
```

구조를 그림으로 보면 이렇습니다.

```
Scene (root_)
 ├─ Background      (zOrder 0)
 ├─ Monster A       (zOrder 10)
 │   ├─ HP Bar      (zOrder 0)   ← 부모를 따라다닌다
 │   └─ Shadow      (zOrder -1)
 ├─ Player          (zOrder 10)
 └─ Camera2D        (zOrder 0)   ← 카메라도 트리의 일원
```

**zOrder 규칙**: 형제끼리는 zOrder 오름차순으로 갱신/그리기 순서가 정해집니다. `AddChild(child, zOrder)` 삽입 시점에 정렬된 위치에 들어가므로(내부적으로 `_u64` 키로 안정 정렬), 매 프레임 정렬 비용이 없습니다. 부모-자식은 "부모 먼저, 그다음 자식" 순서입니다.

### 2-1. 수명주기 훅 — 언제 무엇이 불리나

```cpp
// Scene/GameObject.h
/*
 * [수명주기 훅]
 * OnEnter  : 트리에 붙고 씬이 실행 중일 때 1회. (리소스 준비, 스태틱 선언)
 * OnUpdate : 매 프레임. (이동/로직)
 * OnRender : 매 프레임. (그리기 예약)
 * OnExit   : 트리에서 떨어지거나 씬이 끝날 때 1회. (정리)
 */
```

호출 순서를 한 프레임 기준으로 정리하면:

```
Director::Update ─ root부터 트리 순회 ─ 각 노드 OnUpdate(dt)   (zOrder 순)
Director::Render ─ BeginScene ─ 트리 순회 ─ 각 노드 OnRender() ─ Flush ─ EndScene
```

> **자주 하는 실수**: OnEnter에서 해야 할 일(리소스 로드, DeclareStatic)을 생성자에서 하면 안 됩니다. 생성자 시점에는 아직 트리에 붙지 않았고 씬이 실행 중이 아닐 수 있습니다. 반대로 OnExit에서 해제할 것을 소멸자에서만 해제하면, 트리에서 잠깐 떼었다 붙이는 경우에 리소스가 새거나 이중 해제됩니다.

## 3. Transform — 게으른 행렬 캐시

오브젝트가 1,000개면 월드 행렬 계산도 1,000번일까요? sgf는 "필요할 때, 바뀐 것만" 계산합니다.

```cpp
// Scene/Transform.h
/*
 * [행렬 캐시 + 게으른(lazy) 갱신] (B-5)
 * position/rotation/scale이 바뀔 때마다 행렬을 다시 만들지 않는다.
 * "더러움(dirty)" 표시만 해두고, 행렬이 실제로 필요해지는 순간
 * (GetWorldMatrix 호출) 딱 한 번 계산해서 캐시한다.
 *
 * 부모가 움직이면 자식의 월드 행렬도 낡은 값이 된다.
 * 이를 자식에게 일일이 전파(재귀 순회)하는 대신, 전역 시계(dirty stamp)를
 * 이용해 "내 캐시가 부모 캐시보다 오래됐나?"를 비교하는 방식으로 해결한다.
 */
```

실제 구현의 핵심 두 줄은 이렇습니다.

```cpp
// Scene/Transform.cpp
void Transform::SetDirty()
{
	// 전역 시계를 한 칸 올리고 내 스탬프에 기록만 한다.
	// 자식들을 순회하며 전파하지 않는다! (SetPosition이 O(1)이 되는 이유)
	dirtyStamp_ = ++s_globalDirtyClock;
}

const mat4& Transform::GetWorldMatrix()
{
	// 필요해진 순간에만: 내 캐시가 낡았거나, 부모 것이 나보다 새것이면 재계산
	world_ = pParent_->GetWorldMatrix() * local_;   // 부모 먼저 (재귀적으로 신선해짐)
	...
}
```

**왜 이 방식이 좋은가?** `SetPosition`을 한 프레임에 100번 불러도 행렬 계산은 0번입니다(표시만 100번). 화면에 그릴 때 `GetWorldMatrix`가 불리는 순간 1번만 계산합니다. 또 부모가 움직였을 때 자식 1,000명을 찾아다니며 "너희도 낡았어"라고 알리는 비용(O(자식 수))이 없습니다. 자식이 스스로 "부모 스탬프가 내 것보다 새것이네? 다시 계산하자"라고 판단합니다.

회전은 2D용(`SetRotation2D(radian)` — Z축 회전 편의 함수)과 3D용(쿼터니언/오일러)을 모두 제공합니다.

## 4. Camera — 카메라도 GameObject다

```cpp
// Scene/Camera.h
/*
 * [왜 GameObject 파생인가?]
 * 카메라를 씬 트리에 넣으면 "캐릭터를 따라다니는 카메라"가 공짜로 된다.
 * (캐릭터의 자식으로 붙이면 부모 Transform을 따라가므로)
 *
 * [View/Projection 계약]
 * View()       : Transform의 역행렬. "카메라가 오른쪽으로 가면 세상이 왼쪽으로"
 * Projection() : Camera2D는 직교(Orthographic), Camera3D는 원근(PerspectiveFovLH)
 * (B-6) 두 행렬 모두 Transform처럼 dirty 캐시로 필요할 때만 재계산
 */
```

View가 **역행렬**인 이유는 한 번 생각해볼 가치가 있습니다. 카메라를 오른쪽으로 3m 옮기고 세상을 찍으면, 화면 속 세상은 왼쪽으로 3m 밀려 보입니다. 즉 "카메라의 이동"과 "세상이 받는 변환"은 정확히 반대 — 그래서 카메라 Transform의 역행렬이 곧 View 행렬입니다.

### 4-1. 조작 편의 함수

매번 LookAt과 투영을 손으로 설정하기 귀찮으니 자주 쓰는 세팅이 준비되어 있습니다.

```cpp
// 2D: 좌상단 원점, 픽셀 단위 좌표계 (UI/2D 게임 표준)
GetCamera2D()->SetOrthographic2D(1280, 720);

// 3D: 위치·타깃 지정 + 원근 투영
GetCamera3D()->SetLookAt(vec3(3, 2, -3), vec3(0, 0, 0), vec3(0, 1, 0));
GetCamera3D()->SetPerspectiveDegrees(60.0f, 1280.0f/720.0f, 0.1f, 100.0f);

// 마우스/키보드 기본 조작(우클릭 드래그 회전, WASD 이동 등)이 필요하면
GetCamera3D()->DriveDefault3D(dt);   // OnUpdate에서 한 줄
```

`DriveDefault2D/3D`는 "툴/예제/디버그용 기본 카메라 조작"을 한 줄로 제공하는 함수입니다. 실제 게임에서는 게임 규칙에 맞는 카메라 로직을 직접 작성하게 되지만, 엔진을 배우는 단계에서는 이 한 줄이 씬을 자유롭게 둘러보게 해줍니다.

## 5. 씬 간 데이터 전달 — DataMap

"결과 화면에 점수를 넘기고 싶다" 같은 요구는 DataMap으로 해결합니다. 이전 씬이 `SetData("score", 1200)`으로 남기면 다음 씬이 OnEnter에서 읽습니다. 전역 변수를 만들지 않고 씬 사이에만 흐르는 좁은 통로를 쓰는 것이 의도입니다.

## 6. 자주 묻는 질문

**Q. AddChild한 오브젝트는 누가 삭제하나요?**
트리가 소유합니다. `AddChild(dbg_new Player(), 10)` 하고 나면 삭제 책임은 부모에게 넘어갑니다. 씬이 끝나면 루트부터 재귀적으로 OnExit → 삭제됩니다. 직접 delete하면 이중 해제입니다.

**Q. 서브 윈도우에 다른 씬을 띄우려면?**
`Window* pSub = g_cApp.CreateSubWindow(L"미니맵", 400, 300); g_cDirector.RunScene(dbg_new MiniMapScene(), pSub);` — Director가 윈도우별 씬 슬롯을 관리하므로 메인/서브가 서로 다른 씬을 동시에 돌립니다. (01 문서의 메인 루프에서 서브 윈도우 렌더 구간 참고)

**Q. 카메라를 캐릭터에 붙이면 흔들림도 따라가나요?**
네. 부모 Transform의 모든 변화(이동/회전/스케일)가 View에 반영됩니다. 추적은 되 회전은 싫다면 카메라를 트리 루트에 두고 OnUpdate에서 위치만 복사하는 방식을 쓰세요.

## 7. 요약 — 기억할 다섯 문장

1. **Director는 극장 지배인** — 씬 실행/교체를 관리하고, 교체는 다음 프레임 경계에서 안전하게 일어난다.
2. **Scene은 트리의 루트이자 렌더러 예약 창구** — 오브젝트도 카메라도 전부 root_ 트리에 매달린다.
3. 형제 순서는 **zOrder 오름차순**(삽입 시 정렬), 부모-자식은 부모 먼저 — 갱신도 그리기도 같은 순서다.
4. **Transform은 게으르다** — SetPosition은 표시(dirty stamp)만 하고, 행렬은 GetWorldMatrix가 불리는 순간 한 번만 계산된다. 부모 변경은 자식에게 전파하지 않고 전역 시계 비교로 감지한다.
5. **카메라도 GameObject** — View는 카메라 Transform의 역행렬이고, 트리에 붙이면 추적 카메라가 공짜다.
