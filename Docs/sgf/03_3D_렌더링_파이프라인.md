# 03. 3D 렌더링 파이프라인 — Renderer3D가 그리는 법

> 대상: `Projects/sgf/Sources/sgf/Graphics/Renderer3D.*`, `Scene/Scene3D.*`, `Graphics/Mesh.*`, `Graphics/DefaultShaders.h`

3D 그리기는 "메시 + 머티리얼 + 월드 행렬" 3가지를 넘기는 것이 전부입니다.
Renderer3D가 이를 배치하고, 프레임 공통 상수(b0)와 오브젝트 상수(b1)를 채워 GPU로 보냅니다.

---

## 1. 3D 그리기의 출발점 — Mesh와 Material

| 개념 | 클래스 | 역할 | 위치 |
|---|---|---|---|
| 메시 | `Mesh` | 정점+인덱스+입력레이아웃 묶음 (모양) | `Mesh.h` |
| 머티리얼 | `Material` | 셰이더+블렌드+샘플러+텍스처 묶음 (재질) | `Material.h` |
| 월드 행렬 | `mat4` | 어디에/얼마나 회전·확대했는지 (위치) | jc Math |

```
그리고 싶은 것 = Mesh(모양) + Material(재질) + world(위치)
```

**메시 만들기** — 프리미티브 생성은 Mesh가 직접 지원합니다 (`Mesh.cpp`):
구/큐브/캡슐/원기둥/평면/쿼드 등을 1줄로 만들 수 있고,
리소스 매니저가 `g_cResourceMgr.GetPrimitiveMesh3DKey(PrimitiveMesh3DType::Cube)`로 이미 만들어 둔 것을 줍니다.

**게임 오브젝트에 붙이기** — `GameObject::SetMesh(Mesh*)` — `GameObject.cpp:151`:
씬 트리 트래버설 중에 자동으로 그려집니다 (메시 자동 드로우).

## 2. 한 프레임의 3D 렌더링 (Scene3D::RenderScene)

```
RenderScene()
  ├─ ① 프레임 상수 준비: view/projection/cameraPosition (b0)
  ├─ ② g_cRenderer3D.BeginScene(frame)     ← Renderer3D.cpp:113
  │     └─▶ b0(프레임) 상수버퍼 갱신
  ├─ ③ 그리기 예약 (둘 중 하나)
  │     ├─ 게임 코드: scene.DrawMesh(mesh, material, world)  ← Scene3D.cpp (예약 창구)
  │     │     └─▶ Renderer3D::Draw(Mesh*, Material*, world)  ← Renderer3D.cpp:177
  │     └─ 트리 트래버설: GameObject::RenderSelf가 SetMesh 노드에 대해 동일하게 예약
  │     └─ RenderObject 방식: Renderer3D::Draw(RenderObject) ← Renderer3D.cpp:147
  ├─ ④ g_cRenderer3D.EndScene()            ← Renderer3D.cpp:137
  └─ ⑤ (사실 EndScene에서) Flush()         ← Renderer3D.cpp:223 — GPU로 전송
```

**BeginScene → Draw(...) 예약들 → EndScene(Flush)** 이 3D 프레임의 전체입니다.

> 3D에도 **두 파이프라인**이 있습니다: (1) 메시 파이프라인 `BeginScene(frame)/Draw/EndScene` — b0/b1 상수 사용,
> (2) 디버그 배치 파이프라인 `Begin(viewProj)/DrawCube 등/End` — 6번 섹션의 도형들.
> 둘 다 `BatchRenderer` 베이스의 공통 흐름(Begin/End/Flush)을 공유합니다 (`Graphics/BatchRenderer.*`).

## 3. RenderObject (묶음 예약)

`Renderer3D::Draw(const RenderObject&)` — `Renderer3D.cpp:147`

게임 오브젝트 방식이 아닌 **데이터 지향 예약**도 지원합니다.
`RenderObject`는 `{ mesh, material, world }` 한 건이며, 그리기 목록을 통째로 만들어 넘길 수 있습니다.
(22번 튜토리얼 — 렌더 오브젝트 루프의 주제)

## 4. 프레임 상수 (b0) — 카메라의 산출물

`Renderer3D::BeginScene(const FrameConstants& _frame)` — `Renderer3D.cpp:113`

FrameConstants (b0 슬롯) — `DefaultShaders.h`:

```hlsl
cbuffer ConstantBufferFrame : register(b0)   // 프레임당 1회 갱신
{
    row_major float4x4 view_;
    row_major float4x4 projection_;
    float4 cameraPosition_;
}
```

| 멤버 | 제공자 | 비고 |
|---|---|---|
| `view_` | `Camera::View()` | 카메라가 바라보는 변환 |
| `projection_` | `Camera::Projection()` | 직교(2D)/원근(3D) 투영 |
| `cameraPosition_` | 카메라 위치 | 라이팅(14/24번)에 사용 |

**누가 만드나**: 씬이 `selectedCamera_`의 View/Projection을 모아 FrameConstants를 만들어 넘깁니다.
카메라는 GameObject 파생이므로, 씬 트리에 카메라를 넣고 `Scene::SelectCamera(GameObject*)`로 고르면 됩니다.

## 5. 메시가 GPU로 가는 길 (Mesh::Bind/Draw)

```
Mesh::Bind(context)      ← Mesh.cpp:544
  ├─▶ IA 단계 세팅: VertexBuffer + IndexBuffer + InputLayout + 토폴로지
  └─▶ (버텍스/인덱스 버퍼가 없으면 D3D에서 즉석 생성)
Mesh::Draw(context)      ← Mesh.cpp:556
  └─▶ DrawIndexed 호출 (정점 수만큼 GPU 파이프라인 통과)
```

실제로는 Renderer3D가 배치 단위로:
`바인딩 캐시 → 머티리얼 바인딩(셰이더/상태/텍스처) → b1 오브젝트 상수 갱신 → Mesh::Draw` 순서로 진행합니다.
같은 머티리얼/메시 연속 예약은 상태 전환을 생략해 드로우콜을 줄입니다.

## 7. 프리미티브 메시 종류

`PrimitiveMeshType.h` — 모두 단위 크기(반지름 1 등)로 만들어지며, `Transform::SetLocalScale`로 크기를 정합니다.

| 종류 | 2D용 (`PrimitiveMesh2DType`) | 3D용 (`PrimitiveMesh3DType`) |
|---|---|---|
| Rect / Circle / Triangle / Line | ✅ (VertexPTC — 2D 배칭) | — |
| Cube / Sphere / Capsule / Cylinder / Plane / Quad | — | ✅ (VertexPNT) |

> 2D/3D 타입은 **엄격 분리**입니다. 2D enum은 2D 메시만, 3D enum은 3D 메시만 가리킵니다.
> 2D enum으로 3D 메시를 얻거나 그 반대는 컴파일 타임에 불가능합니다. (`GetPrimitiveMesh2DKey` / `GetPrimitiveMesh3DKey` 각각 별도 키 테이블)

---

## 8. 요약 — 기억할 다섯 문장

1. 3D 그리기 = `Mesh + Material + world` 한 건씩 예약하는 것.
2. 프레임 상수(b0)는 카메라가 만들고, 오브젝트 상수(b1)는 예약 건마다 갱신된다.
3. `GameObject::SetMesh`만 하면 트래버설 중 **자동으로** 그려진다.
4. 같은 머티리얼 연속 예약은 상태 전환을 생략한다 (드로우콜 최소화).
5. 프리미티브는 단위 크기로 제공되니 크기는 스케일로 조절한다.
