# 03. 3D 렌더링 파이프라인 — 메시, 머티리얼, 그리고 세 개의 상수버퍼

> **이 문서 하나로**: 3D 오브젝트 하나가 그려지는 데 필요한 세 가지 재료(메시/머티리얼/월드 행렬), 프레임·오브젝트·머티리얼로 3단 분리된 상수버퍼 규약(b0/b1/b2), 그리고 디버그 도형(그리드/축/큐브)을 그리는 배치 경로를 실제 코드와 함께 이해합니다.
>
> 관련 소스: `Graphics/Renderer3D.h/.cpp`, `Graphics/DefaultShaders.h`, `Graphics/Mesh.h`, `Graphics/Material.h`

---

## 1. 큰 그림 — 3D 그리기는 "세 가지 재료"다

sgf에서 3D 오브젝트 하나를 그리는 데 필요한 것은 딱 셋입니다.

| 재료 | 답하는 질문 | 예 |
|---|---|---|
| **Mesh** | *무엇을* 그릴까 (형태) | 큐브, 구, 캐릭터 모델 |
| **Material** | *어떻게* 그릴까 (재질) | 빨간 불투명, 반투명 유리, 텍스처 입힌 벽돌 |
| **world 행렬** | *어디에* 그릴까 (배치) | "(0, 0.5, 0)에 1.5배 크기로 45도 돌려서" |

메시와 머티리얼을 분리하는 이유는 조합 폭발을 막기 위해서입니다. 같은 큐브 메시를 벽돌 재질로도, 금속 재질로도 그릴 수 있고, 같은 재질을 큐브에도 구에도 입힐 수 있습니다. "형태 × 재질 × 위치"를 독립된 축으로 두는 것 — 이것이 모든 상용 엔진(Unity/Unreal)과 sgf가 공유하는 구조입니다.

그리는 코드는 이 세 재료를 넘기는 한 줄입니다.

```cpp
// Docs/sgf/06_예제_코드_모음.md 예제 6 — 3D 큐브
void OnRender() override
{
	Mesh* pCubeMesh = (Mesh*)g_cResourceMgr.Find(
		g_cResourceMgr.GetPrimitiveMesh3DKey(PrimitiveMesh3DType::Cube));
	Material* pMat = g_cResourceMgr.GetDefaultMaterial3D();

	mat4 world = mat4::CreateScale(1.5f) * mat4::CreateRotationY(jc_math_deg2rad(45.0f))
	           * mat4::CreateTranslation(0, 0.5f, 0);

	DrawMesh(pCubeMesh, pMat, world);      // Scene3D의 예약 창구 → Renderer3D

	// 디버그: 바닥 그리드 + 축
	g_cRenderer3D.DrawGrid(10, 1.0f, color(60, 60, 80));
	g_cRenderer3D.DrawAxis(2.0f);
}
```

world 행렬의 곱셈 순서 `Scale × Rotation × Translation`(SRT)에 주목하세요. sgf는 행우선 + 행벡터(`v*M`) 규약이므로 **왼쪽부터 순서대로 적용**됩니다: 먼저 키우고, 그다음 돌리고, 마지막에 옮깁니다. 순서를 바꾸면 "돌린 뒤 옮기기"와 "옮긴 뒤 돌리기"의 차이만큼 결과가 달라집니다.

## 2. 상수버퍼 3단 분리 — b0/b1/b2 규약

셰이더가 필요로 하는 데이터는 "얼마나 자주 바뀌는가"가 서로 다릅니다. sgf는 갱신 빈도에 따라 상수버퍼를 세 슬롯으로 나눕니다. 이 규약은 엔진 전체(2D/3D/커스텀 셰이더)가 공유하는 헌법입니다.

```cpp
// Graphics/DefaultShaders.h
/*
 * [상수버퍼 슬롯 규약] (FR-19)
 * b0 = 프레임 공통 (view/projection/카메라 위치. Renderer3D가 소유)
 * b1 = 오브젝트 공통 (world. Renderer3D가 오브젝트마다 갱신)
 * b2 = 머티리얼 (baseColor. Material이 소유)
 */
```

| 슬롯 | 내용 | 갱신 주기 | 소유자 |
|---|---|---|---|
| **b0** FrameConstants | view, projection, cameraPosition | **프레임당 1번** (카메라가 바뀔 때) | Renderer3D |
| **b1** ObjectConstants | world | **오브젝트마다** | Renderer3D |
| **b2** MaterialConstants | baseColor 등 재질 값 | **재질이 바뀔 때** | Material |

왜 나눌까요? 100개의 오브젝트를 그릴 때 view/projection은 한 번만 올리면 되는데, 상수버퍼가 하나로 뭉쳐 있으면 오브젝트마다 전부 다시 올려야 합니다. 갱신 빈도별로 쪼개면 **바뀐 것만 올리는** 최소 갱신이 가능해집니다.

셰이더 쪽에서 실제로 이렇게 선언되고 사용됩니다.

```hlsl
// Graphics/DefaultShaders.h — 3D 디폴트 셰이더 (발췌)
cbuffer ConstantBufferFrame : register(b0)
{
	row_major float4x4 view_;
	row_major float4x4 projection_;
	float4 cameraPosition_;
};

cbuffer ConstantBufferObject : register(b1)
{
	row_major float4x4 world_;
};

cbuffer ConstantBufferMaterial : register(b2)
{
	float4 baseColor_;
};

PSInput VSMain(VSInput input)
{
	PSInput output;
	float4 worldPos = mul(float4(input.position_, 1.0f), world_);      // 로컬 → 월드
	output.position_ = mul(mul(worldPos, view_), projection_);         // 월드 → 뷰 → 투영
	...
}
```

정점 하나의 여행이 그대로 보입니다: **로컬 좌표 × world(b1) × view(b0) × projection(b0)**. 이 체인은 sgfr 튜토리얼 10~13장에서 단계별로 배운 그 체인과 정확히 같습니다.

3D 디폴트 셰이더의 픽셀 단계는 람버트 디렉셔널 조명 + 앰비언트(빛 방향 고정)로 음영을 넣습니다. 법선이 필요하므로 3D 정점은 VertexPNT(위치+법선+UV)입니다.

## 3. 메시 파이프라인 — BeginScene / Draw / EndScene

씬이 매 프레임 하는 일은 이렇게 요약됩니다.

```
Scene3D::RenderScene()
  ├─ 카메라에게 view/projection을 받아 FrameConstants 구성
  ├─ g_cRenderer3D.BeginScene(frameData)    ← b0 업로드 (프레임당 1번)
  ├─ (트리 순회하며 OnRender → DrawMesh 예약들)
  │     Draw(mesh, material, world)          ← 오브젝트마다 b1/b2 갱신 + 드로우
  └─ g_cRenderer3D.EndScene()
```

헤더 주석의 사용법 그대로입니다.

```cpp
// Graphics/Renderer3D.h
/*
 * [사용 법]
 * // 메시 파이프라인 (Scene3D::RenderScene이 자동 호출)
 * renderer3d.BeginScene(frameData);   // b0 갱신
 * renderer3d.Draw(mesh, material, world);
 * renderer3d.Draw(renderObject);
 * renderer3d.EndScene();
 */
```

`Draw(renderObject)` 오버로드가 눈에 띄죠. RenderObject는 "메시 키 + 머티리얼 키 + 월드 행렬"을 값으로 묶은 구조체로, 포인터 대신 데이터로 그리기 요청을 표현하는 **데이터 지향** 경로입니다. 나중에 렌더 큐/멀티스레드로 확장할 때(RnD 문서들의 주제) 이 형태가 기반이 됩니다.

### 3-1. StaticLevel — "이 오브젝트는 이제 안 움직여요"

월드 행렬 계산조차 아끼고 싶은 완전 정적인 배경 오브젝트를 위해 GameObject에는 `SetMeshStaticLevel(slStatic)`이 있습니다. 호출 시점의 월드 행렬을 고정해 이후 Transform 조회/합성을 건너뜁니다. 기본값은 `slDynamic`(매 프레임 Transform에서 월드 행렬을 가져옴)입니다. 정적/동적 개념은 Mesh가 아니라 **GameObject가 전담**합니다 — 같은 메시를 정적 오브젝트와 동적 오브젝트가 동시에 공유할 수 있어야 하기 때문입니다.

## 4. 디버그 배치 경로 — 선과 면을 모아 그리기

"바닥 그리드 좀 보고 싶다", "충돌 박스를 와이어로 표시하고 싶다" 같은 요구는 메시/머티리얼을 갖추기엔 너무 가볍습니다. 그래서 Renderer3D에는 Renderer2D와 같은 원리의 **즉시 배치 경로**가 함께 있습니다.

```cpp
// Graphics/Renderer3D.h
/*
 * [왜 3D도 배치(batch) 방식인가?]
 * GPU에게 "그려라(DrawCall)"라고 말을 건네는 비용은 생각보다 비싸다.
 * 상자 100개를 그릴 때 100번 말을 거는 것보다,
 * 정점을 큰 버퍼에 모아두었다가 한 번에 그리는 게 훨씬 빠르다.
 *
 * [Renderer2D와의 차이]
 * - 정점이 VertexPC(위치+색). 텍스처 없이 단색 면/선으로 그린다.
 * - 깊이 테스트를 켠다. (앞뒤 가림이 있어야 3D다워 보인다)
 * - 삼각형 배치와 선 배치를 따로 모았다가 따로 그린다.
 *   (GPU는 한 번의 DrawCall에 한 가지 도형 종류만 그릴 수 있으므로)
 */
```

마지막 항목이 중요합니다. DrawCube는 삼각형을, DrawGrid/DrawLine은 선분을 만듭니다. GPU의 한 DrawCall은 토폴로지(삼각형 or 선)가 하나뿐이라 **삼각형 통과 선 통을 따로** 모았다가 각각 그립니다. 그래서 큐브 100개 + 그리드 1개는 DrawCall 2번이면 끝납니다.

제공되는 디버그 도구들: `DrawCube`(단색 상자), `DrawGrid`(바닥 격자), `DrawAxis`(XYZ 축 — 빨강X/초록Y/파랑Z), `DrawLine`(선분). 모두 `Begin(viewProjection) ~ End()` 사이에서, 또는 Scene3D 안이라면 씬이 관리하는 구간에서 호출합니다.

## 5. 3D 프리미티브 메시 — 단위 크기의 표준 부품

ResourceMgr가 부팅 시 만들어두는 3D 프리미티브(Cube/Sphere/Capsule/Cylinder/Plane/Quad)는 전부 **단위 크기**(예: 한 변 1의 큐브)입니다. 크기는 Transform의 scale로 조절하는 것이 규약입니다. "큰 큐브 메시"와 "작은 큐브 메시"를 따로 만들지 않고 하나를 모두가 공유합니다.

2D 프리미티브(VertexPTC)와 3D 프리미티브(VertexPNT)는 정점 구조가 다르므로 키 체계도 엄격히 분리되어 있습니다: `GetPrimitiveMesh2DKey(...)` / `GetPrimitiveMesh3DKey(...)`. 2D 키로 3D를 그리려 하면 셰이더 입력이 맞지 않습니다 — 이 실수를 컴파일 타임에 가깝게 막으려고 enum 타입부터 `PrimitiveMesh2DType` / `PrimitiveMesh3DType`으로 나뉘어 있습니다.

## 6. 카메라와의 연결 — FrameConstants는 어디서 오나

b0에 올라가는 view/projection은 씬의 현재 카메라(Camera3D)가 만듭니다. 카메라는 GameObject 파생이라 Transform을 갖고, `View()`는 그 Transform의 역변환, `Projection()`은 원근 투영(PerspectiveFovLH)입니다. 예제 6에서 본 두 줄이 그 설정입니다.

```cpp
GetCamera3D()->SetLookAt(vec3(3, 2, -3), vec3(0, 0, 0), vec3(0, 1, 0));
GetCamera3D()->SetPerspectiveDegrees(60.0f, 1280.0f / 720.0f, 0.1f, 100.0f);
```

뷰·투영의 수학적 원리는 sgfr 튜토리얼 11장(카메라)과 13장(3D 큐브)이 처음부터 설명합니다. 씬-카메라 관계(왜 카메라가 GameObject 파생인지 등)는 04 문서에서 다룹니다.

## 7. 요약 — 기억할 다섯 문장

1. 3D 그리기 = **Mesh(무엇을) + Material(어떻게) + world 행렬(어디에)** 세 재료를 Draw에 넘기는 것이다.
2. 상수버퍼는 갱신 빈도로 3단 분리된다: **b0 프레임(view/projection), b1 오브젝트(world), b2 머티리얼(baseColor)** — 바뀐 것만 올린다.
3. 정점의 여행은 `로컬 × world × view × projection`이며, 행우선 + `v*M` 규약이라 SRT는 **왼쪽부터 적용**된다.
4. 디버그 도형(그리드/축/큐브)은 VertexPC 배치 경로로 그려지며, 삼각형 통과 선 통을 따로 모아 각각 1 DrawCall로 처리한다.
5. 프리미티브 메시는 **단위 크기**로 하나만 존재하고 크기는 Transform scale로 — 2D(VertexPTC)와 3D(VertexPNT)는 키부터 엄격히 분리된다.
