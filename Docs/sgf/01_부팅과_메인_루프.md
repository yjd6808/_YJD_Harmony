# 01. 부팅과 메인 루프 — Application이 하는 일

> 대상: `Projects/sgf/Sources/sgf/Core/Application.*`, `Window.*`, `GraphicDevice.*`, `FrameTimer.*`

게임이 시작되면 누가 뭐부터 하는지, 한 프레임에 무슨 일이 일어나는지 순서대로 따라갑니다.

---

## 1. 부팅 순서 (Application::Initialize)

`Application::Initialize(wchar_t* 제목, 가로, 세로)` — `Application.cpp:41`

사용하는 쪽(sgfr 등)은 `Application`을 상속받고 `ApplicationDidFinishLaunching()`만 구현한 뒤,
`main()`에서 `g_cApp.Initialize(...)` → `g_cApp.Run()`을 호출합니다.

```
main()
  └─▶ g_cApp.Initialize(제목, W, H)          ← Application.cpp:41
        │
        ├─ 1. jc::ApplicationBase 초기화      (콘솔/파일 로거 등)
        ├─ 2. GraphicDevice 초기화            ← g_cDevice.Initialize() / Application.cpp:63
        │     └─▶ CreateDeviceOnly()          ← GraphicDevice.cpp:173 (창과 분리된 디바이스만)
        ├─ 3. ResourceMgr 초기화              ← g_cResourceMgr.Initialize(&g_cDevice) / ResourceMgr.cpp:98
        │     └─▶ CreateDefaults()            ← ResourceMgr.cpp:388 (디폴트 셰이더/머티리얼/흰 텍스처)
        ├─ 4. 메인 윈도우 + 그리기 표면 생성   ← g_cWindow.Create(...) / Window.cpp
        │     └─▶ CreateSwapChainForWindow()  ← GraphicDevice.cpp:210 (스왑체인+깊이버퍼)
        ├─ 5. 렌더러 초기화                   ← g_cRenderer2D.Initialize(&g_cDevice)
        │                                        g_cRenderer3D.Initialize(&g_cDevice)
        ├─ 6. 사용자 훅                        ← ApplicationDidFinishLaunching() / Application.h:110
        └─ 7. 메인 루프 시작                  ← Run()
```

**초기화 순서가 중요한 이유**: Renderer2D/3D는 디바이스가 있어야 만들 수 있고, 씬은 렌더러가 있어야 그릴 수 있습니다.
`ApplicationDidFinishLaunching()`에서 첫 씬을 만들 때 `g_cDirector.RunScene(씬)`을 호출하면 됩니다.

### 디바이스와 창은 왜 분리했나요?

- **디바이스**: GPU 공장 그 자체. GPU와 대화하는 전화기 (D3D11Device + Context)
- **창**: 그릴 종이. 창마다 **스왑체인(앞/뒤 무대) + 깊이버퍼**를 소유

이렇게 분리하면 **서브 윈도우를 추가로 만들 수 있습니다** (멀티 윈도우 지원).
`g_cApp.CreateSubWindow(...)` — `Application.h:83` 로 창을 더 만들고, 그 창에 다른 씬을 띄울 수 있습니다.

## 3. 어디서 진짜로 "그리는" 걸까요? (렌더링 위임 구조)

`Application::Run`은 **직접 그리지 않습니다**. 렌더링은 전부 씬에게 위임됩니다.

```
Director::Render(윈도우)                ← Director.cpp:223
  └─▶ Scene::RenderScene()             ← Scene2D.cpp:167 / Scene3D.cpp (파생이 구현)
        ├─▶ 배치 렌더러 BeginScene      ← Renderer2D::BeginScene / Renderer3D::BeginScene
        ├─▶ 트리 순회 (RenderNode)      ← Scene.cpp:100 — GameObject 트리만큼
        │     └─▶ GameObject::RenderSelf() ← GameObject.cpp:165
        │           ├─ SetMesh된 노드 → DrawMesh 예약 (3D) / 렌더훅 호출 (2D)
        │           └─ OnRender() 훅
        ├─▶ OnRender() 훅 (씬 최상위 수동 그리기)
        └─▶ 렌더러 Flush                ← Renderer2D::Flush / Renderer3D::Flush — GPU로 전송
```

> **핵심**: 게임 코드는 "무엇을(메시/도형) 어떻게(머티리얼/채움) 어디에(월드)"만 알려주면,
> 렌더러가 배치(모아 보내기) + 상태 전환을 알아서 처리합니다.

## 5. 프레임 타이머 (FrameTimer)

`FrameTimer.cpp:50`(`Reset`) / `FrameTimer.cpp:65`(`Tick`)

| API | 반환 | 설명 |
|---|---|---|
| `Delta()` | `jc::TimeSpan` | 직전 프레임과의 경과 시간 |
| `Total()` | `jc::TimeSpan` | 앱 시작 이후 누적 시간 |
| `DeltaTime()` | `float` | Delta를 초 단위로 (편의) |
| `TotalTime()` | `float` | Total을 초 단위로 (편의) |
| `Fps()` | `float` | 평균 FPS |

QPC(고성능 카운터) 기반이며, **델타 타임이 250ms를 넘으면 클램프**됩니다.
(중단점으로 멈췄다 이어갈 때 물리 계산이 튀는 것 방지)

## 6. 요약 — 기억할 다섯 문장

1. `Initialize()`가 **모든 싱글톤을 올바른 순서로** 준비한다.
2. `Run()`은 **메시지 → 타이머 → 입력 → 갱신 → 렌더 → 사운드** 순서의 반복이다.
3. 렌더링은 전부 **씬으로 위임**된다. (Director::Render → Scene::RenderScene)
4. 창은 스왑체인을 소유하고, 디바이스는 GPU와의 전화기다. (창 ≠ 디바이스)
5. 게임 코드가 만지는 건 Application 상속 + 씬 + 게임 오브젝트뿐이다.
