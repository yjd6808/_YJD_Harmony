# 05. 리소스 관리와 머티리얼 — GPU 자산의 도서관

> 대상: `Graphics/ResourceMgr.*`, `Mesh.*`, `Material.*`, `Texture.*`, `Fill.*`,
> `RenderStates.*`, `PipelineState.*`, `RenderTarget.*`, `GraphicsEnums.h`, `IResource.h`

텍스처/메시/머티리얼/셰이더는 GPU 메모리를 먹는 자산입니다. 이 자산들을 **도서관(ResourceMgr)**에서 관리합니다.

---

## 1. IResource와 리소스 키

`Graphics/IResource.h` — 모든 리소스의 공통 인터페이스.

| 항목 | 설명 |
|---|---|
| `ResourceType` | rtTexture / rtMaterial / rtMesh / rtVertexShader / rtPixelShader / rtInputLayout / rtRenderTarget / rtSpriteAnimationClip |
| 키 | `_u64` — `INVALID_RESOURCE_KEY(0)`은 없음 |
| 생성 규약 | `SGF_RESOURCE_TYPE` 매크로로 타입 태그 |

리소스는 **키로만 참조**합니다. 누가 들고 있는 포인터가 아니라, "도서관에 맡긴 책 번호"입니다.
파괴는 소유자(ResourceMgr)가 합니다.

- 흰색 1x1 텍스처 (기본 머티리얼용)
- 프리미티브 메시 전부 (2D 4종, 3D 6종 — 단위 크기, 2D/3D 별도 키 테이블)
- 디폴트 머티리얼

> **패턴**: `_u64 key = g_cResourceMgr.Add(리소스);` → 이후 `(Type*)g_cResourceMgr.Find(key)` 로 사용.
> 키 재사용은 `IdProviderReuse` — 반납된 키가 재발급될 수 있습니다 (요청 시점 기준).

`Mesh.h/.cpp`

|---|---|---|
| 정점 버퍼 생성 | `VertexBuffer::Create(...)` | `Buffers.cpp` |
| 인덱스 버퍼 생성 | `IndexBuffer::Create(...)` | `Buffers.cpp` |
| 입력 레이아웃 설정 | `Mesh::SetInputLayout(...)` | `Mesh.h` |
| IA 바인딩 | `Mesh::Bind(context)` | `Mesh.cpp:544` |
| 그리기 | `Mesh::Draw(context)` | `Mesh.cpp:556` |
| 프리미티브 생성 | `Mesh::GeneratePrimitive(...)` 등 | `Mesh.cpp` (2D 4종 / 3D 6종) |

메시는 "어떤 모양"일 뿐, "어떻게 칠할지"는 모릅니다. 그것은 머티리얼 몫입니다.

### 3-1. StaticLevel — 메시 렌더 모드 (B 기본 / A 명시 전환)

메시는 두 가지 렌더 모드를 가집니다. (`GameObject` — `StaticLevel`)

| 모드 | 동작 | 전환 방법 |
|---|---|---|
| `slDynamic` (B — 기본) | 매 프레임 현재 월드 행렬 사용 — Transform이 그대로 반영 (움직이는 오브젝트) | 기본값, `SetMeshStaticLevel(slDynamic)` 복귀 |
| `slStatic` (A) | 전환 시점의 월드 행렬을 고정 보관 — 이후 트랜스폼 무시 (위치 고정) | `SetMeshStaticLevel(slStatic)` |

- **게임 오브젝트 기본은 B**입니다. A는 명시적 호출로만 전환합니다.
- **`SetMeshStaticLevel` 하나로 동작**합니다 — 전환 시점의 "현재 월드 행렬"을 고정 (이동 → 원하는 위치 도달 → `slStatic` 전환 = 그 자리에 고정).
- **정점은 어느 쪽이든 GPU(b1 월드 행렬)로 변환**됩니다 — A/B는 "월드 행렬 출처"만 다릅니다. (정점을 구우는 bake 개념은 없음)
- 고정은 위치/회전/스케일만 적용되며, 색(틴트)은 매 프레임 재질에서 적용됩니다. (색 애니메이션 가능)
- 다시 움직이려면 `slDynamic` 전환 후 이동 → 원하는 위치에서 `slStatic` 재전환 (새 위치 재고정).
- 레벨 검사는 `GetMeshStaticLevel()` 반환값 비교로 충분합니다. (`IsBaked`/`Unbake` 등은 없음)
- 2D/3D 모두 지원됩니다 — 3D도 월드 행렬 전달(b1)이 정상 경로이므로 동일하게 동작.

```cpp
// B (기본) — Transform이 매 프레임 반영
GameObject* pObj = ...;
pObj->GetTransform()->SetLocalPosition(...);   // 움직임

// A (명시적 전환) — 현재 월드 행렬 고정 → 위치 고정
pObj->SetMeshStaticLevel(StaticLevel::slStatic);
pObj->GetTransform()->SetLocalPosition(...);   // 무시됨 (화면 위치 고정)
```

## 4. Material — 재질 (그리는 법)

`Material.h/.cpp`

```
Material
├─ shaderProgram_   (VS+PS 쌍)
├─ blendState_ / depthState_ / rasterizerState_ / samplerState_
├─ textures_[슬롯]  (텍스처 슬롯 — 디퓨즈 등)
└─ baseColor 등 상수
```

| 함수 | 위치 | 설명 |
|---|---|---|
| `Finalize()` | `Material.cpp:55` | 파괴 (리소스 참조 해제) |
| `SetTextureKey(slot, key)` | `Material.cpp:61` | 슬롯에 텍스처 지정 |

**"한 밥상" 비유**: 메시가 "무엇을"이라면 머티리얼은 "어떻게"입니다.
셰이더, 블렌드, 깊이, 샘플러, 텍스처가 한 세트로 묶여 있어, 그리기 전에 이것만 바인딩하면 됩니다.
(20번 튜토리얼 — 머티리얼의 주제)

상수버퍼 규약: b0=프레임(뷰/투영/카메라), b1=오브젝트(world), b2=머티리얼(baseColor 등). 16바이트 정렬 필수.

## 5. 상태 객체 — 봉인된 설정

### RenderStates (플라이웨이트 캐시)

`RenderStates.h/.cpp` — 같은 설정의 상태 객체는 **하나만** 만들고 공유합니다 (도서관의 책 한 권).

| 함수 | 설명 |
|---|---|
| `GetBlendState(...)` | 블렌드 상태 캐시 |
| `GetDepthState(...)` | 깊이 상태 캐시 |
| `GetRasterizerState(...)` | 래스터라이저 상태 캐시 |
| `GetSamplerState(filter, address)` | 샘플러 상태 캐시 |

### PipelineState (독립 객체)

`PipelineState.h/.cpp` — 렌더러를 거치지 않고 **직접 만들고 들고 다니는** 상태 객체 래퍼.

```
BlendState / DepthState / RasterizerState / SamplerState
└─ 각각 D3D 상태 객체를 소유
└─ FillBlendDesc / FillRasterizerDesc ... — 설정 생성 헬퍼
```

사용 예: `BlendState bs; bs.Create(...); context.SetBlendState(&bs);`
(9번 튜토리얼 — 파이프라인 상태 객체의 주제)

### 열거형 (GraphicsEnums.h)

| 상태 | 열거형 | 값 예 |
|---|---|---|
| 블렌드 | `BlendMode` | `bmNone`(불투명), `bmAlpha`(반투명), `bmAdd`(가산), `bmMultiply`(곱셈) |
| 컬링 | `CullMode` | `cmNone`, `cmFront`, `cmBack` |
| 채움 | `FillMode` | `fmSolid`, `fmWireframe` |
| 앞면 판정 | `FrontFace` | `ffClockwise`, `ffCounterClockwise` |
| 깊이 | `DepthMode` | `dmDisabled`, `dmReadWrite`, `dmReadOnly` |
| 필터 | `FilterMode` | `fmPoint`, `fmLinear`, `fmAnisotropic` |
| 주소 모드 | `AddressMode` | `amClamp`, `amWrap`, `amMirror` |

## 9. 요약 — 기억할 다섯 문장

1. 리소스는 **키(_u64)**로만 참조한다. 소유권은 ResourceMgr에 있다.
2. 디폴트 리소스(셰이더/흰 텍스처/프리미티브 메시)는 엔진이 미리 만든다.
3. 메시=모양, 머티리얼=재질. 둘이 합쳐져야 그려진다.
4. 상태 객체는 RenderStates(공유 캐시) 또는 PipelineState(독립 소유)로 만든다.
5. 렌더 타깃으로 화면 밖 그림을 만들고, 그 결과를 텍스처로 다시 쓸 수 있다.
