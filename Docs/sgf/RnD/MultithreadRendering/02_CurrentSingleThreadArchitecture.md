# 02. 현재 엔진(싱글스레드)의 한 프레임 해부

> 개조를 하려면 먼저 지금 구조를 정확히 알아야 합니다.
> 이 문서는 sgf v2의 `Application::Run()` 한 바퀴를 단계별로 해부하고,
> 각 단계가 어느 스레드 소속이 될 수 있는지 표시합니다.

---

## 1. 한 프레임의 전체 흐름 (Application::Run 내부)

```
(1) window_.PumpMessage()      : 윈도우 메시지 처리 (키/마우스 이벤트 발생)
(2) timer_.Tick()              : 경과 시간을 jc::TimeSpan으로 측정
(3) g_cDirector.Update(dt)     : 현재 씬의 OnUpdate (게임 로직)
(4) OnUpdate(dt)               : 앱 훅
(5) device_.BeginFrame(color)  : 백버퍼/깊이버퍼 지우기 <-- D3D 호출 시작
(6) g_cDirector.Render(r2d)    : 씬의 OnRender -> Renderer2D에 정점 쌓기 -> Flush
(7) OnRender()                 : 앱 훅 (디버그 오버레이 등)
(8) device_.EndFrame(vsync)    : Present (화면 표시)          <-- D3D 호출 끝
(9) input_.NextFrame()         : 입력 상태를 다음 프레임으로
(10) g_cSound.Update()         : 끝난 재생기 회수
```

---

## 2. 단계별 “스레드 소속” 분석

| 단계 | 지금 하는 일 | 멀티스레드화 가능? | 이유 |
|---|---|---|---|
| (1) PumpMessage | Win32 메시지 처리 | **불가. 메인 전용** | 윈도우는 만든 스레드만 메시지를 받을 수 있다 (Win32 규칙) |
| (2) Tick | 시간 측정 | 메인 유지 | 로직의 기준 시간이므로 로직과 같은 곳 |
| (3)(4) Update | 게임 로직 | 메인 유지 (또는 로직 스레드) | 입력을 읽으므로 (1)과 같은 쪽이 편하다 |
| (5)~(8) 렌더 | D3D 호출 전부 | **렌더 스레드로 이동 가능** | 즉시 컨텍스트는 한 스레드가 전담하면 된다 |
| (9) NextFrame | 입력 플래그 이동 | 메인 유지 | 입력은 메시지(메인)와 한 몸 |
| (10) Sound | 슬롯 회수 | 아무 쪽 (XAudio2는 스레드 안전 설계가 쉬움) | 내부적으로 이미 별도 믹서 스레드 사용 |

핵심 관찰: **D3D를 건드는 코드는 (5)~(8)에 전부 모여 있습니다.**
이게 바로 v2에서 구조를 정리해둔 덕분이며, 이 덩어리를 통째로 다른 스레드로 옮길 수 있습니다.

---

## 3. 지금 구조의 암묵적 약속들 (개조 시 깨지는 것들)

싱글스레드라서 공짜로 성립하던 약속들입니다. 멀티스레드화하면 전부 직접 지켜줘야 합니다.

1. **“Update가 끝난 뒤에 Render가 시작된다”**
   씬이 위치를 바꾸는 중에 그리는 일이 없음 → 찢짐 현상 없음.
   병렬화하면 렌더가 “쓰는 중인 데이터”를 읽을 수 있음 → 더블 버퍼링으로 해결해야 함.
2. **“ReplaceScene은 프레임 경계에서만 일어난다”**
   Director가 pNextScene_으로 미루는 현재 설계는 멀티스레드에서도 그대로 유효한 좋은 패턴.
   단, “이전 씬을 delete하는 순간”에 렌더 스레드가 그 씬 데이터를 그리고 있으면 안 됨.
3. **“리소스(텍스처/버퍼) 생성은 아무 때나 해도 된다”**
   `ID3D11Device`는 원래 스레드 안전(생성 계열)이지만, `ID3D11DeviceContext`(즉시)는 아닙니다.
   지금 코드는 둘을 구분 없이 쓰고 있으므로, 개조 시 “누가 컨텍스트를 만지나”를 전수조사해야 합니다.
4. **“Renderer2D::Begin/End 사이는 한 프레임 안에 끝난다”**
   배치 버퍼(정점 벡터)가 프레임마다 재사용되므로, 로직/렌더가 같은 버퍼를 공유하면 안 됩니다.

---

## 4. 데이터 흐름 관점에서 본 현재 구조

```
[InputManager] --읽기--> [Scene::OnUpdate] --상태 변경--> (씬 멤버 변수들)
(씬 멤버 변수들) --읽기--> [Scene::OnRender] --DrawXXX--> [Renderer2D 배치]
[Renderer2D 배치] --Flush--> [즉시 컨텍스트] --> GPU
```

싱글스레드에서는 이 화살표가 전부 한 줄로 순차 실행됩니다.
멀티스레드화의 본질은 가운데 화살표(씬 상태 → 그리기)를 **끓어서 사이에 우편함(렌더 큐)을 놓는 것**입니다.
그러면 왼쪽(로직)과 오른쪽(렌더)이 서로 다른 시점에 돌 수 있게 됩니다.
