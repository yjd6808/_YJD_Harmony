## 기초 용어

### 스레드 (Thread)
프로그램 안에서 일하는 “일꾼 한 명”입니다.
지금 우리 엔진은 일꾼이 한 명(메인 스레드)이라서 요리(게임 로직)도 하고 설거지(렌더링 명령 제출)도 합니다.
멀티스레드 = 일꾼을 여러 명 고용해서 역할을 나누는 것.

### 메인 스레드 / 워커 스레드
- 메인 스레드: 프로그램이 시작될 때 자동으로 생기는 첫 일꾼. 윈도우 메시지는 반드시 이 일꾼이 받아야 합니다.
- 워커(Worker) 스레드: 우리가 추가로 고용한 일꾼. 렌더 스레드도 워커의 일종입니다.

### 경쟁 상태 (Race Condition)
두 일꾼이 같은 그릇(메모리)을 동시에 만지는 사고.
한 명이 읽는 동안 다른 한 명이 덮어쓰면 어떤 값이 나올지 아무도 모릅니다. 멀티스레드 버그의 90%가 이것입니다.

### 동기화 (Synchronization)
일꾼들이 서로 부딪히지 않도록 순서와 규칙을 정하는 것.
대표 도구: 뮤텍스, 세마포어, 이벤트, 원자적 연산.

### 뮤텍스 (Mutex) / 임계 영역 잠금
화장실 열쇠입니다. 열쇠를 쥐 사람만 들어갈 수 있고, 다음 사람은 열쇠가 돌아올 때까지 기다립니다.
안전하지만 “기다림 = 느려짐”이므로 남발하면 멀티스레드의 이득이 사라집니다.

### 원자적 연산 (Atomic Operation)
“중간에 끊기지 않는 한 방” 연산. 예: 숫자 1 증가를 누가 끼어들 수 없게 한 번에 처리.
C++의 `std::atomic`, Windows의 `InterlockedIncrement`가 이것입니다. 자물쇠 없이도 안전한 가장 싼 도구.

### 교착 상태 (Deadlock)
일꾼 A는 열쇠1을 들고 열쇠2를 기다리고, 일꾼 B는 열쇠2를 들고 열쇠1을 기다림 → 둘 다 영원히 멈춤.
예방법: 열쇠를 항상 같은 순서로 집기.

## 렌더링 용어

### 드로우 콜 (Draw Call)
“이 삼각형들을 그려!”라고 GPU에게 내리는 주문서 한 장. `DrawIndexed(...)` 호출 한 번 = 드로우 콜 한 번.
주문서를 쓰는 데도 CPU 시간이 들기 때문에 드로우 콜이 많으면 CPU가 병목이 됩니다.

### 커맨드 (Command) / 커맨드 버퍼
주문서 한 장이 커맨드, 주문서 묶음이 커맨드 버퍼입니다.
“이 색으로 칠해라 / 이 텍스처 써라 / 그려라” 같은 명령들이 순서대로 담깁니다.

### 즉시 컨텍스트 (Immediate Context)
D3D11에서 GPU에게 직접 주문을 넣는 창구. **프로그램 전체에 단 하나**이고, 동시에 여러 스레드가 만지면 안 됩니다.
우리 엔진의 `GraphicDevice::Context()`가 바로 이것입니다.

### 지연 컨텍스트 (Deferred Context)
D3D11이 주는 “가짜 주문 창구”. 여기에 내린 명령은 바로 실행되지 않고 커맨드 리스트로 녹음됩니다.
스레드마다 하나씩 만들 수 있어서 “주문서 작성” 작업을 병렬화할 수 있습니다. (실행은 결국 즉시 컨텍스트가 함)

### 커맨드 리스트 (Command List, `ID3D11CommandList`)
지연 컨텍스트가 녹음을 끝내고(`FinishCommandList`) 내놓는 완성된 주문서 묶음.
메인/렌더 스레드가 `ExecuteCommandList`로 즉시 컨텍스트에서 재생합니다.

### 더블 버퍼링 (Double Buffering) / 프레임 버퍼링
공책 두 권을 번갈아 쓰는 기법. 일꾼 A는 1번 공책에 이번 프레임 내용을 쓰고,
일꾼 B는 지난 프레임에 완성된 2번 공책을 읽습니다. 다음 프레임에 서로 교환.
같은 공책을 동시에 만지지 않으므로 자물쇠 없이 안전합니다. 멀티스레드 렌더링의 핵심 기법!

### 렌더 큐 (Render Queue) / 커맨드 큐
게임 로직이 “뭐를 그려야 하는지”를 적어 넣는 줄 서기 줄(큐).
렌더 스레드는 이 줄에서 하나씩 꺼내 실제 D3D 호출로 바꿉니다.

### 파이프라이닝 (Pipelining)
공장 컸베이어. 프레임 N의 그리기와 프레임 N+1의 로직을 동시에 진행하는 것.
대신 화면에 보이는 건 항상 한 프레임 전 내용이라 입력 지연(레이턴시)이 약간 늘어납니다.

### VSync (수직동기화)
모니터가 화면을 갈아끼우는 박자(보통 60Hz)에 맞춰 Present를 기다리는 것.
기다리는 동안 CPU는 놀기 때문에, 이 놀는 시간을 다른 스레드에게 주는 것도 멀티스레드화의 이유가 됩니다.
