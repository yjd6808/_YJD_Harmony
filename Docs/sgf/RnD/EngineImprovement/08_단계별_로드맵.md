## 1. 이 로드맵의 목적

이 시리즈(01~07)가 제안한 개선들은 **각각은 도구이지만 함께면 엔진**입니다.
이 문서는 그것들을 서로 얽힌 의존성 순서로 배치해 "언제 무엇을, 몇 주 안에, 어떻게 끝냈는지
판정할 수 있게" 하는 하나의 실행 계획입니다. 최종 목표는 하나뿐입니다:

> **sgcl(Cocos2d-x 게임 클라이언트)을 sgf로 완전히 대체하고,
> 이후 Unity/Unreal급 구조(병렬 렌더 + 에셋 파이프라인 + 에디터)로 확장한다.**

## 2. 개선 항목 우선순위와 의존성

각 문서의 항목들을 한 표로 모았습니다. 화살표는 "위가 선행 필요"입니다.

```
01 진단 ──► 02 설계도(목표 아키텍처) ──► 03 렌더 커맨드/배칭 ──► 04 컴포넌트·직렬화
                                               │                       │
                                               ▼                       ▼
                                         05 멀티스레드           06 에셋 파이프라인
                                               │                       │
                                               └───────────┬───────────┘
                                                           ▼
                                                    07 에디터/도구
                                      (08 로드맵은 이 모두를 배치하는 실행 계획)
```

핵심 원리: **데이터(큐/포맷) → 동작(병렬) → 보관(파이프라인) → 대화(에디터)** 순서입니다.
순서를 바꾸면 (예: 에디터부터) 직렬화가 없어 저장이 안 되고, (병렬부터) 03의 렌더 커맨드 큐가
없으면 나눌 재료가 없습니다.

### 2-1. 우선순위 판정 기준 (왜 이 순서인가)

| 기준 | 설명 | 사례 |
|---|---|---|
| 회귀 위험 | 기존 31개 튜토리얼을 깨뜨릴 확률 | 위험이 낮은 것부터 (도구 0단계 → 커맨드화) |
| 베이스 커버리지 | 뒤 단계가 필요로 하는 재료 | 커맨드 큐(03)는 멀티스레드(05)와 에디터(07)의 전제 |
| 실제 체감 | 중간 진행이 몰래 이득이 되는가 | 로딩 스레드 하나만으로도 로딩 병목 제거 |
| 외부 압박 | sgcl의 실무 요구 | Phase E는 언제든 당겨 오지 말 것 — 기반이 무너지면 확장 불가 |

즉, A~E는 "작은 것부터 안전하게, 그리고 실제 책임의 사다리" 순서입니다.
하나의 예외: **도구 0단계(07)** 는 어느 Phase와도 병행 가능하므로 로드맵의 시작 시간 슬롯을
항상 확보해 둡니다 (프레임 루프에 카운터 두 개를 꽂는 비용뿐).

| 항목 | 문서 | 우선순위 | 선행 |
|---|---|---|---|
| 렌더 커맨드/배칭 (렌더 아키텍처) | 03 | **A** | 그래픽 현 상태(v2.1), 01~02 진단/설계 |
| 컴포넌트/씬 구조 | 04 | A | 03 |
| 씬 직렬화 포맷 | 04 | B | 04의 컴포넌트 구조 |
| 도구 0단계(통계) | 07 | B (항상 진행 가능) | GraphicContext 통계 |
| 멀티스레딩(로딩→렌더) | 05 | **C** | A 완료(03) |
| 에셋 파이프라인 | 06 | D | 05(업로더 큐), 04(포맷) |
| 에디터 1~3단계 | 07 | D-E | 04, 06 |
| sgcl 마이그레이션 완료 | 25/26 + 23(리워드) | **E** | A~D 전부 |

## 3. 5단계 실행 계획 (Phase A ~ E)

### Phase A — 렌더 큐 / 배칭 정비 (예상 3~4주)
**목표**: 그리기 코드가 "즉시"가 아니라 "커맨드 큐" 위에서 도는 구조로.
- 씬의 `OnRender`가 Renderer2D 직접이 아니라 `RenderCommand` 벡터 기록
- 카메라/클리어 색이 커맨드에 스냅샷으로 포함 (05-2의 FrameRenderData 골격)
- 텍스처 스위치 오버헤드 확인 → 스프라이트 정렬(배칭 그룹) 시작

**변경 파일 영역**: `Graphics/`(신규 `RenderCommand/FrameRenderData`), `Scene/Scene.h`, `Graphics/Renderer2D.h`
**위험**: 기존 31개 튜토리얼 전부를 바꾸면 범위가 커짐 → **신규 렌더러와 구 렌더러를 병행(듀얼 패스)**
후 1:1 동치 검증으로 레거시 전환
**완료 판정**: `sgfr` 전 튜토리얼 화면 1픽셀 차이 없음 + 1000스프라이트 씬에서 드로우 콜 수가 배치 그룹 수 이하

### Phase B — 컴포넌트/씬 직렬화 (3~4주)
- **목표**: 씬을 "코드 상수"가 아닌 데이터로 저장/복원 (파일: 06 포맷 재사용)
- 컴포넌트 목록(위치/렌더링 속성) 정의, 트리 직렬화 (04)
- 도구 0단계(07) 통계 카운터 확장을 이번에 함께 (프레임 루프 훅 2개)
- **변경 파일**: `Scene/` 신규 `Component/SceneSerializer`, `App/` 에 로더
- **완료 판정**: 씬 하나를 저장→로드했을 때 바이트 동일(Diff) + 화면 동일

### Phase C — 멀티스레딩 (5~6주, 가장 위험)
- **목표**: 로딩 스레드(06과 공동) → 프레임 더블 버퍼 → 렌더 스레드 분리
- 05 문서의 단계 1→2→3 순서 그대로, `SGF_SINGLE_THREAD_RENDER` 복귀 스위치 유지
- **변경 파일**: `Core/`(Application 루프), `Graphics/` (소유권 이전), `Audio/` (호출 지점 정리)
- **위험**: 경쟁/교착. "구조 변경과 스레드 도입 분리" 규율 위반 금지
- **완료 판정**: 렌더 스레드 분리 후 05의 검증 실험(각 측 8ms 지연 주입) 통과 + GPU 시간 0손실, 레이턴시 +1프레임 수용 문서화

### Phase D — 에셋 파이프라인 + 에디터 1단계 (6~8주)
- **목표**: 
  1. 오프라인 셰이더 컴파일(레지스터 계약서) + 텍스처 가공 밉맵/압축/아틀라스 (06)
  2. 외부 도구 앱(프로파일러 + 리소스 탐색기) = 07 단계 1 (WPF, 파이프)
  3. 임베디드 오버레이 UI = 07 단계 2 (F2 토글)
- **변경 파일**: `Assets/` (Loader/Format), `Tools/` (C# 신규 솔루션 — SteinsGate-Tools 계열에 추가), `Graphics/`
- **완료 판정**: 큰 PNG 로드 중 FPS 유지 / 밉맵 포함 DDS형 포맷 로드 / 외부 앱에서 FPS·프레임 실시간 그래프

### Phase E — sgcl 마이그레이션 완성 + 확장 (8주+)
- **목표**: cocos2d 호출(Play2d, Director, Scene) 치환 완료 (23 리워드 + 25 포팅 가이드 사용),
  에디터 3단계(씬 뷰포트+인스펙터+하이어라키) 부팅
- **내용**:
  - `sgcl/`의 AppDelegate→Application, Scene 100여 개 이전
  - 서버 연동(이제 sgf가 클라) — sgcl 씬 라이브러리를 떼어내고 sgf를 올린 뒤 별도 서브 프로젝트로 전환
  - 3D 확장(24~31 개념)은 별도 스트림으로 계속
- **완료 판정**: sgcl의 실행되는 게임 시나리오가 sgf 클라이언트에서 동일 동작. Cocos2d-x 의존 0건.
  (마지막엔 `ThirdParty/Cocos2d-x` 링크 제거까지)

## 6. 회귀 방지 — 로드맵이 성공하려면 "깨지지 않는 것"이 먼저

각 Phase 완료 시 아래를 기본으로 수행한다.

1. **벤치마크 씬 고정**: 대표 시나리오(31 튜토리얼 합성 씬)를 `BenchMarks/`로 고정하고,
   Phase 시작 전/후의 프레임 타임·드로콜·메모리를 기록한다.

2. **같은 화면 확인**: 자동 스크린샷을 뽑아 이전 Phase의 저장본과 픽셀 diff
   (마스터로 두는 기준: "사람이 보는 화면은 변하지 않는다")

3. **복귀 스위치 유지**: 멀티스레드 진입 후에도 `SGF_SINGLE_THREAD_RENDER 1`로 원복 가능 —
   회귀 의심 시 즉시 전환 후 원인만 남긴다

4. **커밋 분리**: 렌더 로직 변경과 23통계 등은 별도 커밋으로 쪼개서, "어느 커밋이 화면을
   바꿨는지"가 항상 단일 커밋이 되도록 한다.

이 규준은 "Phase 완료 = 아무것도 안 깨진 상태"를 강제하므로, A~C 각각이 끝나면
언제든 게임을 납품 가능한 상태가 유지된다.

## 7. 결론 — "차곡차곡"의 가치

이 로드맵의 핵심은 **각 Phase가 "셀프 컨테이너" 완료 판정을 가진다는 것**입니다.
"중간에 멈추더라도 A~C의 산출물은 이미 자산" — sgcl의 마이그레이션이 끝나지 않아도 sgf는
그 자체로 렌더러/에셋 도구가 되는 체계입니다. Unity고 Unreal이고, 오늘 새벽 2시의 sgf가
**한 일꾼에서 여러 일꾼(멀티스레드), 파일 하나에서 패킷 하나(에셋), 창문에서 조종석(에디터)**으로
가는 것이 이 로드맵 전체입니다.

> **진행 원칙**: 각 Phase 시작 전에 (기존 AGENTS.md 규칙대로) plan 문서를 만들고,
> 끝나면 /done으로 기록하자. 이 로드맵 자체도 `Docs/sgf/RnD/EngineImprovement/` 아래에서
> 살아 숨 쉬는 체크리스트가 되어야 한다.
