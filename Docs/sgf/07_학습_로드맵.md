# 07. 학습 로드맵 — sgf 코드를 읽는 순서

> 대상: 엔진 문서(00~06)와 sgfr 튜토리얼(Docs/sgfr)을 어떻게 조합해 공부할지에 대한 지도.

sgfr 튜토리얼(01~31)은 **DX11 개념**을 가르칩니다. sgf 엔진은 그 개념을 **포장한 제품**입니다.
두 가지를 아래 순서로 오가며 보면 구조가 자연스럽게 잡힙니다.

---

## 3. 엔진 핵심 코드를 읽는 순서 (미니 투어)

튜토리얼과 무관하게 엔진만 순수하게 읽는다면:

```
1. SgfHeader.h                    ← 무슨 부품이 있는지 목록
2. Core/Application.cpp:41        ← 부팅 (모든 싱글톤 초기화)
3. Core/Application.cpp:192       ← 메인 루프 (한 프레임 전체)
4. Scene/Director.cpp:89/116      ← 씬 시작/교체
5. Scene/Scene.cpp:100            ← 트리 순회 (RenderNode)
6. Scene/GameObject.cpp:165       ← 노드가 그려지는 법 (RenderSelf)
7. Scene/Scene2D.cpp:167          ← 2D 한 프레임 (RenderScene)
8. Graphics/Renderer2D.cpp:155/166 ← 2D 배치 시작/끝
9. Scene/Scene3D.cpp:49           ← 3D 한 프레임 (RenderScene)
10. Graphics/Renderer3D.cpp:113/137 ← 3D 배치 시작/끝
11. Graphics/GraphicContext.cpp:312 ← 진짜 GPU 호출 (Draw)
12. Input/InputManager.cpp:122     ← 입력 (NextFrame — 폴링/이벤트 원리)
```

이 순서로 읽으면 **"내가 만든 씬의 코드 한 줄이 GPU 호출 몇 번이 되는지"** 머릿속에 그려집니다.

## 4. 이해 점검 체크리스트

마지막에 이 질문들에 답할 수 있으면 엔진 구조를 이해한 것입니다.

- [ ] `g_cApp.Initialize`가 준비하는 것 5가지를 순서대로 말할 수 있다
- [ ] 한 프레임에서 "갱신"과 "렌더"가 어떻게 나뉘는지 설명할 수 있다
- [ ] 왜 렌더링이 Application이 아니라 씬으로 위임되는지 설명할 수 있다
- [ ] 스태틱 그리기가 다이나믹보다 빠른 이유를 버텍스 관점에서 설명할 수 있다
- [ ] Fill이 버텍스를 만드는 과정(BuildFill)을 설명할 수 있다
- [ ] 같은 텍스처 연속 그리기가 왜 1 DIP인지 설명할 수 있다
- [ ] 메시와 머티리얼의 역할 차이를 설명할 수 있다
- [ ] b0/b1/b2 상수버퍼가 각각 언제 갱신되는지 안다
- [ ] 카메라가 FrameConstants를 만드는 과정을 설명할 수 있다
- [ ] GameObject::OnEnter/OnExit가 언제 1회 호출되는지 안다
- [ ] Shape2D(정적)와 SetMesh(이동)의 차이를 고를 수 있다
- [ ] 폴링(IsKeyDown)과 이벤트(onKeyPressed)를 언제 구분해 쓸지 안다
- [ ] Transform을 바꿨을 때 월드 행렬이 언제 재계산되는지(dirty) 안다
- [ ] 리소스 키(_u64)의 의미와 소유권을 설명할 수 있다
- [ ] RenderTarget으로 화면 밖에 그린 뒤 화면에 다시 그리는 흐름을 안다
- [ ] 서브 윈도우에 다른 씬을 띄우는 법을 안다
- [ ] 드로우콜을 줄이는 방법 3가지를 말할 수 있다
