# 07. 학습 로드맵 — 어디서부터 읽을지 막막할 때

> **이 문서 하나로**: 내 배경에 맞는 학습 경로를 고르고, 문서 → 소스 순서로 따라가며, 마지막 체크리스트로 이해를 점검합니다.

---

## 1. 나는 어느 입구로 들어가야 하나

사람마다 출발점이 다릅니다. 세 가지 입구 중 가까운 곳을 고르세요.

| 입구 | 이런 분께 | 추천 경로 |
|---|---|---|
| **A. DX11이 처음** | 디바이스? 스왑체인? 단어부터 낯설다 | `Docs/sgfr` 튜토리얼 00→34를 먼저. 그다음 이 문서로 복귀 |
| **B. 엔진 구조가 궁금** | DX11은 알지만 sgf가 어떻게 생겼는지 모른다 | 이 폴더 00→09 순서대로 + 아래 소스 읽기 순서 |
| **C. 일단 만들어보고 싶다** | 돌아가는 걸 먼저 보고 싶다 | 06 예제 모음을 복사해 실행하며 막힐 때마다 해당 장으로 |

RnD 문서(`RnD/EngineImprovement`, `RnD/MultithreadRendering`)는 "다음 단계의 엔진"을 설계하는 연구 노트입니다. 엔진 구조가 익은 뒤에 읽으면 재미있고, 먼저 읽으면 과적입니다.

## 2. 문서 로드맵 (입구 B 기준)

```
00 엔진 개요          "등장인물과 지도"          ─ 30분
01 부팅과 메인 루프    "심장이 어떻게 뛰는가"      ─ 1시간
02 2D 파이프라인      "사각형 하나의 여정"        ─ 1시간

03 3D 파이프라인      "메시/머티리얼/b0b1b2"     ─ 1시간
```

각 문서 마지막의 "요약 — 기억할 다섯 문장"만 모아 읽어도 전체 그림이 복원되도록 썬습니다. 복습할 때 활용하세요.

## 3. 소스 읽기 순서 — 문서 다음에는 코드다

문서는 지도일 뿐, 진짜 이해는 소스에서 나옵니다. 아래 순서로 읽으면 의존 방향을 거슬러 올라가지 않아도 됩니다. 각 파일은 먼저 헤더 상단의 큰 주석만 읽고, 그다음 본문을 보세요.

**1단계 — 골격 (심장과 무대)**
1. `Core/Application.h/.cpp` — Initialize 순서와 Run() 루프. 엔진 전체의 목차다.
2. `Core/Window.h/.cpp` — 창 생성 4단계, PeekMessage 루프, 창이 표면을 소유하는 구조.
3. `Scene/Director.cpp` — RunScene/ReplaceScene의 지연 교체, Update/Render 지휘.
4. `Scene/Scene.h`, `Scene/GameObject.h/.cpp` — 트리/zOrder/수명주기 훅.
5. `Scene/Transform.h/.cpp` — dirty stamp 재울단 행렬 캐시. GetWorldMatrix부터 역추적하면 빠르다.

**2단계 — 그래픽 토대**
6. `Graphics/GraphicDevice.h/.cpp` — 디바이스(수명)/컨텍스트(바인딩) 분리, BeginFrame/EndFrame.
7. `Graphics/GraphicContext.h/.cpp` — 바인딩 캐시(같은 값 재바인드 생략), InputLayout 지연 결합.
8. `Graphics/SwapChain.h` — 더블버퍼링과 Present.

**3단계 — 렌더러**
9. `Graphics/BatchRenderer.h` — 2D/3D 공통 베이스. Initialize/Begin/End/Flush 규약.
10. `Graphics/Renderer2D.cpp` — BeginScene→예약→FlushStatic/FlushDynamic. PushTriangles의 배칭 분기점.
11. `Graphics/Renderer3D.cpp` — BeginScene(b0)→Draw(b1/b2)→디버그 배치 Flush.
12. `Graphics/Fill.h` — 콜백 기반 채움과 RenderLayer 버킷.

**4단계 — 리소스와 입력**
13. `Graphics/ResourceMgr.cpp` — 키 발급/경로 중복 방지/CreateDefaults.
14. `Graphics/Material.h`, `Graphics/Mesh.h` — 키 참조 규약, 프리미티브 팩토리.
15. `Input/InputManager.h/.cpp` — 상태 배열 두 장과 NextFrame 스냅숏.
16. `Graphics/VertexDeclaration.h`, `Graphics/Vertex.h` — 정점 선언 인턴과 Decl() 패턴.

> **읽기 요령**: 함수를 위에서부터 순서대로 읽지 말고, "한 프레임"을 따라가세요. Run()의 한 바퀴에서 시작해 g_cDirector.Update → 트리 순회 → OnUpdate, 그리고 g_cDirector.Render → BeginScene → OnRender → Flush까지 호출 스택을 따라 내려가면 엔진 전체가 한 줄로 꿰집니다.

## 4. 이해 점검 체크리스트

아래 질문에 막힘없이 답할 수 있다면 sgf를 "아는" 상태입니다. 괄호는 답이 있는 문서입니다.

**부팅/루프**
- [ ] Initialize가 윈도우 → 디바이스 → 리소스 → 표면 순서인 이유를 설명할 수 있다 (01)
- [ ] PeekMessage와 GetMessage의 차이를 설명할 수 있다 (01)
- [ ] dt를 곱하지 않은 이동 코드가 왜 문제인지 안다 (01)
- [ ] 250ms 클램프가 없으면 무슨 일이 생기는지 안다 (01)

**2D/3D 렌더링**
- [ ] 스태틱/다이나믹/메시 세 경로의 선택 기준을 말할 수 있다 (02)
- [ ] "같은 텍스처는 한 배치"가 왜 DrawCall을 줄이는지 설명할 수 있다 (02)
- [ ] 단색 도형들이 자동으로 한 배치가 되는 이유(흰 텍스처)를 안다 (02·05)
- [ ] b0/b1/b2가 각각 무엇이고 왜 분리되어 있는지 말할 수 있다 (03)
- [ ] world = S×R×T 순서와 행우선 v*M 규약의 관계를 안다 (00·03)
- [ ] 삼각형 배치와 선 배치를 따로 모으는 이유를 안다 (03)

**씬/트리**
- [ ] ReplaceScene이 즉시 교체하지 않는 이유를 설명할 수 있다 (04)
- [ ] OnEnter에서 해야 할 일을 생성자에서 하면 안 되는 이유를 안다 (04)
- [ ] Transform dirty stamp가 자식 전파 없이 부모 변경을 감지하는 원리를 안다 (04)
- [ ] 카메라 View가 왜 Transform의 역행렬인지 설명할 수 있다 (04)

**리소스/입력/심화**
- [ ] 리소스를 포인터가 아니라 키로 참조하는 이유 두 가지를 말할 수 있다 (05)
- [ ] IsKeyDown과 IsKeyPressed의 차이와 NextFrame의 역할을 안다 (08)
- [ ] InputLayout이 왜 Draw 시점에 결정되는지(몸과 옷) 설명할 수 있다 (09)

## 5. 다 익혔다면 — 다음 여정

- **기초를 다지고 싶다**: `Docs/sgfr` 31장 "파이프라인 여행"은 정점 하나가 픽셀이 되는 전 과정을 한 편으로 묶은 복습용 명편입니다.
- **엔진을 발전시키고 싶다**: `RnD/EngineImprovement` — 현재 구조의 한계와 개선 로드맵(렌더 큐, 머티리얼 시스템 확장 등).
- **멀티스레드 렌더링이 궁금하다**: `RnD/MultithreadRendering` — 왜 Update/Render 분리가 전제 조건인지부터 출발합니다.
