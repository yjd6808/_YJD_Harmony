# 08. 입력 시스템 — 묻는 방식과 받는 방식

> **이 문서 하나로**: 키보드/마우스 입력을 다루는 두 가지 스타일(펴링/이벤트)의 선택 기준, 그리고 "막 눌림" 판정이 동작하는 내부 원리(상태 배열 두 장 + NextFrame)를 실제 코드와 함께 이해합니다.
>
> 관련 소스: `Input/InputManager.h/.cpp`

---

## 1. 큰 그림 — 같은 입력, 두 가지 소비 방식

입력을 쓰는 코드는 크게 둘로 나뉩니다. 이동처럼 "누르고 있는 동안 계속" 반응하는 코드와, 클릭처럼 "발생 순간 한 번" 반응하는 코드입니다. sgf는 둘 다 지원합니다.

```cpp
// Input/InputManager.h
/*
 * [두 가지 사용 방식]
 * 1. 펴링(Polling): 매 프레임 묻는다. "지금 A키 눌려 있어?"
 *    if (g_cInput.IsKeyDown('A')) { ... }        // 이동 같은 지속 동작
 *
 * 2. 이벤트(Event): 일어날 때 알려달라고 등록한다.
 *    g_cInput.OnKeyDown += [](_u32 vk) { ... };   // 메뉴/버튼 같은 단발 반응
 *
 * [동작 원리]
 * Window의 WndProc이 받은 입력 메시지를 HandleMessage로 넘겨받아
 * 상태 배열을 갱신하고, 이벤트를 즉시 발사한다.
 * 매 프레임 끝에 Application이 NextFrame()을 불러
 * "직전 프레임 상태"를 저장한다. (Pressed/Released 판정용)
 */
```

**선택 기준은 간단합니다**: 상태를 묻는다면(이동, 차지, 조준) 펴링, 사건에 반응한다면(클릭, 단축키, 메뉴 이동) 이벤트. 펴링은 로직이 OnUpdate 한 곳에 모여 읽기 쉬우며, 이벤트는 발생 빈도가 낮은 사건을 매 프레임 검사하지 않아도 되어 교흑합니다.

## 2. 상태 판정 3종 세트 — Down / Pressed / Released

펴링 API는 세 가지 질문에 답합니다.

| 함수 | 질문 | true가 되는 구간 |
|---|---|---|
| `IsKeyDown(vk)` | 지금 눌려 있나? | 누르고 있는 모든 프레임 |
| `IsKeyPressed(vk)` | 이번 프레임에 막 눌렸나? | 눌린 그 프레임 딱 1번 |
| `IsKeyReleased(vk)` | 이번 프레임에 막 뗄쓰나? | 뗄 그 프레임 딱 1번 |

내부 구현은 상태 배열 **두 장**입니다.

```
현재 프레임:  keys_[vk]      ← WndProc/HandleMessage가 실시간 갱신
직전 프레임:  keysPrev_[vk]  ← NextFrame()이 프레임 끝에 복사

IsKeyDown     =  keys_[vk]
IsKeyPressed  =  keys_[vk] && !keysPrev_[vk]   // 지금은 눌림 + 직전엔 안 눌림
IsKeyReleased = !keys_[vk] &&  keysPrev_[vk]   // 지금은 떨어짐 + 직전엔 눌림
```

그래서 **NextFrame의 호출 위치가 중요**합니다. 메인 루프(01장)에서 Update와 Render가 모두 끝난 뒤에 불리므로, 한 프레임 안에서는 언제 물어도(OnUpdate든 OnRender든) 같은 답을 받습니다. 만약 NextFrame이 Update 앞에 있다면 Pressed 판정이 프레임마다 달라지는 버그가 납니다.

```cpp
// Core/Application.cpp — Run() 루프 끝부분 (발췌)
// 7. 입력 상태를 다음 프레임으로 넘긴다.
// (IsKeyPressed 같은 "막 눌림" 판정이 이 호출에 의존한다)
input_.NextFrame();
```

## 3. 마우스 — 버튼, 위치, 휠

키보드와 완전히 같은 3종 판정이 마우스 버튼에도 적용됩니다.

```cpp
// Input/InputManager.h
enum class MouseButton { Left, Right, Middle, Max };

g_cInput.IsMouseButtonDown(MouseButton::Left);     // 눌림 유지 중 (드래그)
g_cInput.IsMouseButtonPressed(MouseButton::Left);  // 막 클릭 (선택)
g_cInput.GetMousePosition();                       // vec2, 클라이언트 좌표(좌상단 원점)
g_cInput.GetMouseWheelDelta();                     // 이번 프레임 휠 이동량 (줌 등)
```

마우스 위치는 클라이언트 좌표(창 좌상단 원점, 픽셀)입니다. `SetOrthographic2D(1280, 720)`처럼 창 크기와 같은 직교 카메라를 쓰면 마우스 좌표와 월드 좌표가 1:1이라 변환 없이 바로 비교할 수 있습니다. 카메라를 줌/이동했다면 카메라 역변환을 거쳐야 합니다.

## 4. 이벤트 방식 — 구독하고, 반드시 해지하라

```cpp
// 구독 (OnEnter에서)
void MyScene::OnEnter()
{
	keyHandle_ = g_cInput.OnKeyDown += [this](_u32 vk)
	{
		if (vk == VK_ESCAPE) { g_cDirector.ReplaceScene(dbg_new TitleScene()); }
	};
}

// 해지 (OnExit에서 — 잊으면 죽은 씬을 향해 이벤트가 날아간다!)
void MyScene::OnExit()
{
	g_cInput.OnKeyDown -= keyHandle_;
}
```

> **가장 흔한 사고**: 씬 A가 구독만 하고 해지 없이 사라지면, 다음 입력 때 이미 삭제된 씬의 람다가 호출되어 크래시가 납니다. **OnEnter에서 구독했으면 OnExit에서 해지** — 짝을 맞추는 습관을 들이세요.

이벤트는 WndProc → HandleMessage 경로에서 **즉시** 발사됩니다. 즉 OnUpdate 밖의 타이밍(메시지 펌프 중)에 핸들러가 불릴 수 있으므로, 핸들러 안에서는 상태 변경 정도만 하고 무거운 작업(씬 교체는 예약이라 안전)은 피하는 것이 좋습니다.

## 5. 실전 패턴 모음

```cpp
// 패턴 1: WASD 이동 (펴링 + dt)
vec3 dir(0, 0, 0);
if (g_cInput.IsKeyDown('W')) dir.y_ -= 1;
if (g_cInput.IsKeyDown('S')) dir.y_ += 1;
if (g_cInput.IsKeyDown('A')) dir.x_ -= 1;
if (g_cInput.IsKeyDown('D')) dir.x_ += 1;
pos += dir * speed * (_f32)_dt.TotalSeconds();

// 패턴 2: 차지 공격 (Down으로 충전, Released로 발사)
if (g_cInput.IsKeyDown(VK_SPACE))     { charge_ += dt; }
if (g_cInput.IsKeyReleased(VK_SPACE)) { Fire(charge_); charge_ = 0; }

// 패턴 3: 클릭 위치로 오브젝트 집기 (Pressed — 누르는 순간 1회만)
if (g_cInput.IsMouseButtonPressed(MouseButton::Left))
{
	vec2 pos = g_cInput.GetMousePosition();
	/* pos로 히트 테스트 */
}
```

## 6. 요약 — 기억할 다섯 문장

1. 입력 소비는 두 가지다 — 지속 상태는 **펴링**(IsKeyDown), 단발 사건은 **이벤트**(OnKeyDown +=).
2. 판정 3종: **Down은 누르는 내내, Pressed는 누른 프레임  1번, Released는 뗄 프레임 1번**.
3. Pressed/Released는 현재/직전 프레임 상태 배열 비교로 구현되며, 그 스냅숏은 루프 끝의 **NextFrame()**이 찍는다.
4. 이벤트는 **OnEnter 구독 / OnExit 해지**를 짝으로 — 해지를 잊으면 죽은 씬으로 이벤트가 날아간다.
5. 마우스 좌표는 클라이언트 픽셀 좌표다 — 창 크기와 같은 직교 카메라에서는 월드 좌표와 1:1이다.
