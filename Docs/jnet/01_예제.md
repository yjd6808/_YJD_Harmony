## 1. User-Agent 설정 — 3가지 방법

```cpp
// 1-1. 클라이언트 기본 User-Agent (모든 요청에 적용)
jnet::HttpClientConfig cfg;
cfg.userAgent_ = "MyGame/1.0 (Windows; +https://example.com)";
cfg.connectTimeoutMs_ = 5000;
cfg.receiveTimeoutMs_ = 10000;
jnet::HttpClient client(cfg);
client.Initialize();
// 내부: WinHttpTransport::Initialize() → WinHttpOpen(L"MyGame/1.0", ...)

// 1-2. 요청별 헤더로 덮어쓰기 (가장 높은 우선순위)
jnet::HttpRequest req(jc::Uri("https://api.example.com/v1/ping"));
req.SetHeader(jc::String("User-Agent"), jc::String("MyGame/1.0-custom"));
// 내부: WinHttpAddRequestHeaders("User-Agent: MyGame/1.0-custom") → WinHTTP가 세션 UserAgent보다 우선 적용

// 1-3. 빈 문자열이면 기본값 "jnet-http/1.0"으로 폴백
cfg.userAgent_ = jc::String(); // → WinHttpTransport가 "jnet-http/1.0" 사용
```

> 검증: `WinHttpTransport.cpp:186` `ToWide(config_.userAgent_.IsEmpty() ? "jnet-http/1.0" : config_.userAgent_)`
> `WinHttpTransport.cpp:283` `headers.GetMap()` 순회하며 `WinHttpAddRequestHeaders(..., WINHTTP_ADDREQ_FLAG_ADD|WINHTTP_ADDREQ_FLAG_REPLACE)`로 주입 — `User-Agent`도 일반 헤더처럼 처리되므로 요청별 덮어쓰기가 세션 기본값을 교체한다.

## 2. GET — 동기

```cpp
jnet::HttpClient client;
client.Initialize();

// 2-1. 가장 간단 — Get 헬퍼
auto res = client.Get(jc::Uri("https://httpbin.org/get"));
if (res != nullptr && res->IsSuccess()) {
    printf("status %d\n", res->GetStatusCode()); // 200
    jc::MemoryStream* body = res->GetBody();
    jc::String text((char*)body->GetData(), body->GetSize());
}

// 2-2. Request 빌더로 커스텀 헤더/타임아웃 추가
jnet::HttpRequest req(jc::Uri("https://httpbin.org/get"));
req.SetHeader(jc::String("X-Custom"), jc::String("hello"))
   .SetHeader(jc::String("Accept"), jc::String("application/json"))
   .SetReceiveTimeout(5000)   // 이 요청만 5초 제한 (cfg.receiveTimeoutMs_ 덮어쓰기)
   .SetConnectTimeout(2000);

auto res2 = client.Send(req); // 기본 hcContentReceived — 헤더+바디 모두 수신 후 반환
if (res2 == nullptr) {
    jnet::HttpError e = client.GetLastSendError(); // heTimeout / heConnectFailed / heInvalidUri 등
}

// 2-3. 헤더만 먼저 받기 (스트리밍)
auto res3 = client.Send(req, jnet::HttpCompletionOption::hcHeadersReceived);
if (res3 != nullptr) {
    int code = res3->GetStatusCode();
    _s64 len = res3->GetHeaders().GetContentLength(); // Content-Length 없으면 -1
    // 바디는 아직 안 읽힘 — ReadBody로 직접 소비
    _byte buf[4096];
    int n;
    while ((n = res3->ReadBody(buf, sizeof(buf))) > 0) { /* 처리 */ }
    res3->CloseBody();
}

// 2-4. 응답 헤더 조회 (대소문자 무시)
jc::String ct;
if (res->GetHeaders().TryGet(jc::String("Content-Type"), ct)) {
    // "application/json" 등 — 키 정규화가 lower-case이므로 "CONTENT-TYPE"도 동일
}
```

## 3. POST / PUT / PATCH — 바디 전송

```cpp
// 3-1. POST + String 바디 (text/json)
jnet::HttpRequest req(jc::Uri("https://httpbin.org/post"));
req.SetMethod(jnet::HttpMethod::hmPost)
   .SetHeader(jc::String("Content-Type"), jc::String("application/json"))
   .SetBody(jc::String("{\"id\": 123, \"name\": \"alice\"}"));
auto res = client.Send(req);
assert(res && res->IsSuccess());

// 3-2. POST + 바이너리 바디 (MemoryStream)
auto body = jc::MakeShared<jc::MemoryStream>(1024);
const char raw[] = { 0x00, 0x01, 0x02, 0x03 };
body->Write(raw, sizeof(raw));
jnet::HttpRequest req2(jc::Uri("https://httpbin.org/post"));
req2.SetMethod(jnet::HttpMethod::hmPost)
    .SetHeader(jc::String("Content-Type"), jc::String("application/octet-stream"))
    .SetBody(body);
auto res2 = client.Send(req2);

// 3-3. PUT / PATCH / DELETE / HEAD 도 동일 패턴
jnet::HttpRequest put(jc::Uri("https://httpbin.org/put"));
put.SetMethod(jnet::HttpMethod::hmPut).SetBody(jc::String("update"));
client.Send(put);

jnet::HttpRequest del(jc::Uri("https://httpbin.org/delete"));
del.SetMethod(jnet::HttpMethod::hmDelete);
client.Send(del);

// 3-4. 빈 바디 POST — SetBody(jc::String())는 nullptr 바디로 처리되어 Content-Length 0으로 전송
```

> 내부: `WinHttpTransport::Open`에서 `pData = request.GetBody()->GetData()`를 `WinHttpSendRequest(..., pData, len)`로 전달. `SetMethod`는 `HttpMethodName()` → wide verb → `WinHttpOpenRequest(hConnect, wVerb, wPath, ...)`로 매핑. GET/POST/PUT/DELETE/HEAD/PATCH 6종 모두 지원(`HttpDefine.h:18`).

## 4. 다운로드 — 파일 원자적 커밋

```cpp
// 4-1. 동기 다운로드
auto res = client.Download(jc::Uri("https://cdn.example.com/patch.zip"), jc::String("C:/temp/patch.zip"));
// 내부: ".part.<handle>"에 쓰고 성공 시 Move, 실패/취소 시 Delete
if (res && res->IsSuccess()) {
    // C:/temp/patch.zip 생성됨
} else {
    jnet::HttpError e = client.GetLastSendError(); // heHttpStatusFailed(404 등) / heWriteFailed 등
    // 404는 res==nullptr + heHttpStatusFailed — Download는 2xx만 성공으로 간주

jnet::HttpHandle h = client.DownloadAsync(jc::Uri("https://cdn.example.com/patch.zip"),

                                              else printf("failed %d\n", (int)r.GetError());
                                          });
// 프레임 루프에서
while (client.GetActiveCount() > 0) {
    client.Update(); // 콜백 + 리스너 호출
    jc::Thread::Sleep(16);
}
```

## 5. 비동기 — SendAsync / 콜백·리스너 순서 / 진행률 / 취소 / 공유 풀

```cpp
class MyHttpListener : public jnet::HttpEventListener {
public:
    void OnProgress(const jnet::HttpProgress& p) override {
        printf("progress %u %lld/%lld\n", p.handle_, p.receivedBytes_, p.totalBytes_);
    }
    void OnCompleted(jnet::HttpResult& r) override { printf("completed %d\n", r.GetStatusCode()); }
    void OnFailed(jnet::HttpResult& r) override    { printf("failed %d\n", (int)r.GetError()); }
    void OnCancelled(jnet::HttpResult& r) override { printf("cancelled\n"); }
};

jnet::HttpClient client;
client.Initialize();
MyHttpListener listener;
client.SetEventListener(&listener);

// 5-1. 콜백 → 리스너 순서 보장 (HttpClient::Update에서 콜백 먼저, 리스너 다음)
jnet::HttpHandle h = client.SendAsync(jc::Uri("https://httpbin.org/delay/2"),
    [](jnet::HttpResult& r){ printf("callback\n"); });

// 5-2. 진행률 폴링 (Update와 독립적으로도 조회 가능)
while (client.GetActiveCount() > 0) {
    client.Update();
    jnet::HttpProgress prog;
    if (client.GetProgress(h, prog)) {
        // prog.receivedBytes_, prog.totalBytes_, prog.state_ (hsReceiving 등)
    }
    jc::Vector<jnet::HttpProgress> snap;
    client.GetActiveSnapshot(snap);
    jc::Thread::Sleep(16);
}

// 5-3. 취소
client.Cancel(h);        // 단일 — pending이면 hsCancelled로 즉시 전이, receiving이면 cancelRequested 플래그
client.CancelAll();      // 전체

// 5-4. 스레드풀 공유
jc::ThreadPool pool(4);
jnet::HttpClientConfig cfg2;
cfg2.pSharedPool_ = &pool;
jnet::HttpClient client2(cfg2);
client2.Initialize();
// client2.Shutdown()은 pool을 Join하지 않음
```

## 6. FileLoader 브리지 — `http://`를 FileLoader로 통일

```cpp
// 6-1. 설치 (HttpClient가 Initialize된 뒤)
jnet::HttpClient httpClient;
httpClient.Initialize();

jc::FileLoader loader;
loader.Initialize();
jnet::InstallHttpDataSource(loader, &httpClient);
// 내부: loader.RegisterFileDataSource(usHttp, []{ return MakeShared<HttpDataSource>(&httpClient); });
//       loader.RegisterFileDataSource(usHttps, 동일)

// 6-2. 이후 FileLoader API로 로컬+HTTP 투명 처리
loader.LoadAsync(jc::Uri("C:/assets/config.json"), [](jc::LoadResult& r){ /* 로컬 */ });
loader.LoadAsync(jc::Uri("https://cdn.example.com/config.json"), [](jc::LoadResult& r){
    if (r.IsSuccess()) {
        auto body = r.TakeBody(); // HttpDataSource가 헤더 수신 후 ReadBody로 채운 MemoryStream
    } else {
        jc::LoadError e = r.GetError(); // heConnectFailed → leOpenFailed 등으로 매핑
    }
});
loader.DownloadAsync(jc::Uri("https://cdn.example.com/patch.zip"), jc::String("C:/temp/patch.zip"));

// 6-3. 라이프사이클 — FileLoader가 HttpClient보다 먼저 Shutdown되어야 함
loader.Shutdown();
httpClient.Shutdown();
```

## 7. 타임아웃 / 리다이렉트 / 오류 처리

```cpp
jnet::HttpClientConfig cfg;
cfg.connectTimeoutMs_ = 3000;
cfg.receiveTimeoutMs_ = 5000;   // 기본 5초
cfg.maxRedirects_ = 2;          // 2회 초과 시 heTooManyRedirects
jnet::HttpClient client(cfg);
client.Initialize();

// 7-1. 요청별 타임아웃 덮어쓰기
jnet::HttpRequest req(jc::Uri("https://slow.example.com/big"));
req.SetReceiveTimeout(1000); // 이 요청만 1초
auto res = client.Send(req);
if (res == nullptr && client.GetLastSendError() == jnet::HttpError::heTimeout) { /* 재시도 */ }

// 7-2. 리다이렉트 — WinHTTP가 자동 추적 (301/302), maxRedirects_ 초과 시 실패
//     비동기는 HttpResult::GetError()==heTooManyRedirects, 동기는 GetLastSendError()

// 7-3. 오류 코드 요약
// heInvalidUri      — Uri 파싱 실패 또는 IsRemote()==false
// heConnectFailed   — DNS/TCP 실패 (127.0.0.1:1 등)
// heTlsFailed       — HTTPS 인증서/핸드셰이크 실패
// heTimeout         — connect/receive 타임아웃 (future wait + WinHttpSetTimeouts 이중 보장)
// heTooManyRedirects— 리다이렉트 루프
// heHttpStatusFailed— Download에서 4xx/5xx (일반 Send는 status로 반환, Download만 실패 처리)
// heWriteFailed     — 파일 쓰기 실패
// heMemoryLimit     — memoryLimit_ 초과
// heCancelledByUser / heShutdown

// 7-4. 비동기 오류는 HttpResult / GetError로, 동기는 GetLastSendError()로 조회
auto h2 = client.SendAsync(jc::Uri("http://127.0.0.1:1/"), [](jnet::HttpResult& r){
    if (!r.IsSuccess()) assert(r.GetError() == jnet::HttpError::heConnectFailed);
});
```

## 9. 라이프사이클 규칙

- `Initialize()` → `Send/Download` → `Shutdown()` 순서. `Shutdown()`은 진행 중 워커가 끝날 때까지 대기 후 `Join(WaitOnlyRunningTask)`
- `Update()`는 메인 스레드에서 호출 — 콜백과 `HttpEventListener`가 이 시점에 실행됨
- `HttpResponse::TakeBody()`는 한 번만 성공, `HttpResult` 소멸 시 미-Take 바디는 자동 해제
